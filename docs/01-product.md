# 问阶：产品设计基线

日期：2026-11-03。状态：供用户审阅的产品与交互方案，尚未实现正式应用。

## 1. 产品决定

**工作名：问阶 · Interview Studio。**“问”是追问和求证，“阶”是准备过程中的逐步提升。

定位为面试与求职准备工作台。主线是**围绕目标岗位，用个人材料和实际练习发现准备缺口，再通过复盘推动下一次练习**。

起步覆盖 Java 后端方向，能力标签和训练模板保留扩展方式。个人经历、岗位要求、训练状态可以共享，但不把所有职业成长和社区功能塞进同一个产品。

## 2. 主旅程

```text
添加一个目标岗位
→ 确认 JD 要求和自己的项目事实
→ 选择知识、项目或系统设计演练
→ 作答、追问、调整方案
→ 复盘原回答与具体证据
→ 生成可执行的复练任务
→ 返回同一目标岗位继续准备
```

用户不必先制作完美简历才能开始训练。可以直接选择一道题或架构演练；待需要个人上下文时再补充材料。

## 3. 模块与入口

| 主模块 | 用户任务 | 输入 | 输出 | 与其他模块的连接 |
|---|---|---|---|---|
| 准备空间 | 看见当前目标、继续上次练习、开始最值得做的一步 | 当前岗位、未完成练习、复练任务 | 明确的下一步动作 | 所有训练入口 |
| 目标岗位 | 管理目标、确认岗位要求和轻量阶段 | JD、备注、准备／投递／面试状态 | 版本化要求、能力标签 | 材料和练习上下文 |
| 个人材料 | 整理简历摘要和可讲清的项目事实 | 用户填写或授权导入的材料 | 已确认事实与待补充项 | 项目答辩与报告依据 |
| 题库与练习 | 针对某知识点练答，保存不足 | 题目、提示、用户答案 | 作答记录、复练状态 | 模拟面试与下一步任务 |
| 模拟面试 | 在知识／项目模式中接受连续追问 | JD、材料、练习目标、回答 | 问答轮次与反馈候选 | 复盘与复练 |
| 架构演练 | 画方案、解释取舍、修改设计 | 题目约束、图结构、解释 | 图版本、针对节点的追问 | 复盘定位、复练任务 |
| 复盘与复练 | 找出具体未解释事项并再次练习 | 原回答、图版本、反馈依据 | 可确认的改进任务 | 准备空间、题库、面试 |
| 模型与数据 | 管理未来模型授权、预算、导出和清理 | 连接配置、授权选择、本地／服务端资产 | 设置与数据出口 | 所有 AI 任务与保存机制 |

原型展示八个可切换视图。架构演练是特色体验，不是唯一训练方式；题库是训练资源，不以内容数量作为产品完成标准。

## 4. 关键产品行为

### 4.1 一个目标岗位提供共享上下文

切换当前目标后，材料关联、练习入口和复盘任务跟随目标变化。历史会话使用创建时的岗位快照，不能因修改 JD 而倒改旧报告。

JD 的技能提取必须能定位原文，并允许用户修正。不要把模型预测包装成该企业一定会问的问题。

### 4.2 项目事实先确认，再进入个性化提问

事实包含作者输入、出处、用户确认状态和适用范围。系统区分“本人负责”“参与了解”“待核实”，不把了解的模块写成负责经历。

模型可以提出补充问题，但不能生成虚假的工作经历、生产流量、薪资、故障或成绩。个人材料默认私密。

### 4.3 训练不是标准答案生成器

用户作答在先；提示和解析可展开，但不默认把参考答案盖在用户答案上。知识题可由标准条件验证的部分与开放表达评价分开。

项目和系统设计反馈至少回链一个具体回答片段、事实、约束或图节点。允许不确定判断和多种合理方案。

### 4.4 白板和对话使用同一版本

白板节点、连线和属性以结构化数据保存。模型收到的是当前图快照、题目约束和用户说明，而不是只收到一句“帮我看架构”。

每轮追问绑定 `diagramVersionId`。用户改图后，旧追问保留原版本并标出是否已处理。报告可以点击问题回到当时的图和回答。

本轮原型采用可点击节点与预置方案修订示例；正式自由绘制、拖动、缩放、连接和语音训练尚未实现。

### 4.5 复盘产生动作，不制造精确评分幻觉

报告优先显示问题证据、解释缺口、可行建议和后续动作。综合分数只有在评价标准、样本和稳定性经过验证后才考虑加入。

同一反馈重复加入复练要去重。复练后保留新旧回答，不能只打“已完成”而丢失变化依据。

## 5. 范围安排

**首阶段：**目标岗位、个人材料、精选自拟题、文字模拟、项目模式、节点型架构演练、证据式复盘、复练和数据导出。

**后续按实际使用决定：**实时语音训练、更多岗位模板、简历 PDF 排版、授权导入面试记录、更完整的求职阶段记录。

**不纳入主线：**公共面经社区、招聘爬取和自动投递、薪资预测、录用概率、正式面试暗中代答、监考规避或隐身操作。

这不是否定求职或社区题材，而是保持当前产品的核心旅程清晰。

## 6. UI 主张

以内容和练习为中心，避免把主页做成统计仪表盘。每个视图都有一个清楚的主动作：继续练习、添加目标、确认材料、回答问题、调整架构或开始复练。

两类高频工作区：

- **问答工作区：**原题、个人上下文、作答、追问与记录。
- **白板工作区：**题目约束、架构图、节点追问、版本与复盘。

材料和报告采用可阅读的卡片／索引布局，反馈能定位到原文。求职阶段仅做轻量状态，不另造一套 CRM。

## 7. 数据与合规

- 简历、薪资、企业信息和录音具有敏感性；提供用户可见的数据传输与删除机制。
- 上传企业资料前需要用户授权与脱敏，不读取用户电脑中其他项目资料作为默认上下文。
- 调用外部模型前说明发送范围，不将完整问答与简历默认写入普通日志。
- API 密钥放服务端加密配置，原型不收集或存储真实密钥。
- 只使用自拟、授权或许可证允许的题目，不复制商业题库。
- 若未来处理录音或真实面试记录，须获得相关参与方同意，另做保留期限和转写数据边界设计。

## 8. 可验证目标

1. 未填写简历也能开始一次基础训练。
2. 切换目标岗位后，新训练上下文变化，旧会话和报告不被改写。
3. 未确认项目事实不进入个性化评价。
4. 每条项目或架构反馈能定位原回答、事实或图版本；没有依据时显示不确定性。
5. 重试不会重复保存回答、报告或复练任务。
6. 同一任务完成复练后保留新旧记录，可比较改进点。
7. 语音／模型不可用时可以继续使用文字与材料整理功能。
