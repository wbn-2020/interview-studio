# 准备来源知识更正传播契约

版本：v1.1 · 2026-11-12。状态：代码完成待验证；后端打包、正式业务入口专项检查与独立静态复核通过，整仓前端构建仍失败。未执行数据库、HTTP、模型或交互验收。适用于 S8 第十批；与[知识采用多跳传播](知识采用多跳传播契约.md)、[表达素材依据复核](表达素材依据复核契约.md)共同使用。

## 1. 业务边界

岗位、项目、事实、表达的来源代次前进后，保留真实准备根事件，并使已采用该来源生成的知识及后续采用知识进入人工复核。一次来源更正不代表已确定哪一段知识错误，不修改历史原文、AI 清单、授权摘要或评分。人工复核只结束所选影响，不能恢复旧任务、回忆排程或历史证据。

首版创建不产生更正事件。已有对象保存新版、设置归档／恢复状态、事实确认／撤回、表达依据显式确认各产生一个事件；即使状态或决定与之前相同，只要原命令确实提升来源代次仍登记。收藏及焦点变化不产生事件。表达保存的 `SAVED_BASIS` 是同次保存的基线，不重复造根。

## 2. 来源与路径

只纳入 `KNOWLEDGE_DRAFT` 且有 `ADOPTED` 决定的实际采用；固定来源身份必须匹配 `ai_preparation_source` 与当时完整 manifest。任务创建、未采用候选、题目／表达候选和普通组织链接不属于知识采用。

第一跳允许四种真实依赖：

| dependencyKind | 根与固定 AI 输入 |
|---|---|
| DIRECT | 根就是 TARGET／PROJECT／FACT／EXPRESSION 输入 |
| PROJECT_FACT | 根项目是固定 FACT 输入所属项目 |
| FACT_EXPRESSION | 固定 EXPRESSION 的完整 FACT_BASIS 包含根事实 |
| PROJECT_EXPRESSION | 固定 EXPRESSION 的 FACT_BASIS 中存在属于根项目的事实 |

表达路径使用**当时采用的表达版本**，不能仅检查今日当前版或今日重新确认的基线。完整有序 `factChecks`、正文 `factVersionIds` 与固定 `FACT_BASIS` 相互核对；项目身份取事实所属项目。旧来源代次来自固定 manifest，不以今日查询补造。多个事实命中同一实际采用边时，保存按原事实顺序找到的第一条真实途经事实；这是可追溯路径，不是全部依赖清单。

FACT／PROJECT 根先分页核对具有固定 EXPRESSION 输入的已采用知识任务，再判断实际途经事实；不能仅凭待核验的 FACT_BASIS 关系预先排除任务。缺关系或错用途须报告完整性错误并回滚，而非静默当成无依赖。这个保守候选集合的真实查询成本和30秒事务预算待服务器检查。

第一跳登记完后，再按最小深度扩展真实 `ai_knowledge_source` 采用边。下限为父目标的**原采用版本号**，不是目标当前版。每事件按域、任务、实际输入对象／版本去重；菱形、循环和同对象不同版本都不按对象提前截断。每页最多100条，全量分页，不静默截断扇出。所有影响与根事件在原 owner 写锁和原命令事务中原子提交。

## 3. 存储与消费者

新增 V71，分别建立 `preparation_knowledge_event` 和 `preparation_knowledge_impact`。根版本外键指向准备版本；目标版本始终指向知识版本。影响使用互斥的准备来源列／知识来源列，分别通过 owner 复合外键绑定实际来源登记，不能让同一列的 UUID 隐式兼任两种身份。第一跳无父影响；后续知识输入必须绑定同事件真实父目标。处理字段保留 0→1 单次决定。

根保存前后确切正文版本、版本号、来源代次、元数据修订、状态、事实核实状态及根项目身份。`after.sourceGeneration=before.sourceGeneration+1`，同版的状态／核实／表达确认也有真实事件；`CONTENT_SAVED` 必须版本前进，其他类别版本不变。

新根时间严格晚于同 owner 的 AI 任务创建、回忆尝试开始、RATE 时间、知识根事件及准备根事件的最大冻结点；时间相等或回拨返回409并整体回滚。全部后代使用同一根时间。人工处理时间不得早于影响时间。

独立准备影响须同时参加以下既有查询：知识 `pending`／`changedAfter`、共同 `latestFrozenAt`、回忆卡来源待复核、按影响 ID 的来源历史校验、旧评分的冻结后上游变化。历史变化查询包含已处理影响，不能通过确认恢复旧任务。每条新影响调用既有 `MemoryInvalidation.knowledgeUpstreamChanged` 和 `ReviewedBasisInvalidation.knowledgeUpstreamChanged`；不改它们的历史 DTO／hash。

## 4. API 契约

四个接口均为 owner 隔离且受独立训练资料访问守卫约束，响应 `no-store`：

- `GET /api/v1/lifecycle/preparation/{itemId}/knowledge-impacts`
- `GET /api/v1/lifecycle/knowledge/{itemId}/preparation-impacts`
- `GET /api/v1/lifecycle/preparation-knowledge-impacts/{impactId}`
- `POST /api/v1/lifecycle/knowledge/{itemId}/preparation-impacts/{impactId}/resolve`

两个目录接受且只接受单值 `state=PENDING|ALL`、可选 `limit=1..20`、绑定 owner／context／itemId／state 的时间与 ID 游标。详情不接受查询参数；按真实 `parentImpactId` 一次读一跳。处理采用原六字段 `KnowledgeRevalidationResolve` 和原五字段 `KnowledgeRevalidationResolution`，使用独立操作路径和幂等键。旧知识影响 API、16字段回执和旧成功回执均不改变。

新增响应形状（nullable 字段仍必须出现）：

```text
PreparationKnowledgeObservation {
  versionId, versionNumber, sourceGeneration, revision, status, verification
}
PreparationKnowledgeRoot {
  kind, itemId, title, projectId, changeKind, before, after
}
PreparationKnowledgeFact { itemId, title, versionId, versionNumber }
PreparationKnowledgeSource {
  domain, kind, itemId, title, versionId, versionNumber, dependencyKind, viaFact
}
PreparationKnowledgeImpact {
  id, revision, eventId, root, source, taskId,
  targetItemId, targetTitle, targetVersionId, targetVersionNumber,
  depth, parentImpactId, createdAt, resolution
}
PreparationKnowledgePage { context, itemId, state, items, nextCursor }
```

`context=PREPARATION|KNOWLEDGE`；根 `kind=TARGET|PROJECT|FACT|EXPRESSION`；`changeKind=CONTENT_SAVED|STATUS_SET|FACT_DECIDED|EXPRESSION_BASIS_CONFIRMED`。来源 `domain=PREPARATION|KNOWLEDGE`；准备来源 kind 为四种准备类型，知识来源 kind 为 `KNOWLEDGE`，后者 `dependencyKind=KNOWLEDGE`。只有两种表达间接路径具有非空 `viaFact`。`verification` 仅 FACT 非空（UNVERIFIED／CONFIRMED／WITHDRAWN）；`projectId` 仅 FACT 非空。

处理目标必须是当前确切发布版与元数据修订、无未发布草稿；保留原内容／发布更新／归档三种结论及正文确已改变的约束沿用既有知识复核。未知字段、重复字段、非整数修订、错误根类型／来源域／路径、越权和不一致父路径均拒绝。

## 5. 前端与恢复

准备详情显示该根导致的知识影响；知识详情独立显示准备来源待复核／全部影响，支持固定版本跳转、逐跳查看、分页、处理理由和显式确认。根与第一跳准备输入跳准备历史，后续知识输入跳知识历史。不得统称“根知识”。

复核理由、选中项、处理基线、确切原请求及幂等键纳入现有保稿／未决恢复。冲突、请求结果未知、资料访问变化、面板收起及迟到响应不能自动提交、覆盖理由或抬升旧基线；确认选中后须重新读取目标当前发布版。两个知识复核面板的写锁须互斥，不能把子组件自身锁反馈为其外部锁而死锁。不新增本地服务或单元测试。

## 6. 待服务器场景

下列场景当前全部未执行：

1. PKR-01：直接岗位／项目／事实／表达保存后，仅命中实际已采用知识；首版／收藏／未采用／出题不造影响。
2. PKR-02：事实改后改回、同值确认／撤回仍有新代次事件；原文、旧决定和授权保持。
3. PKR-03：项目归档／恢复影响固定事实输入与固定表达依据，目标组织链接不扩散。
4. PKR-04：旧表达版本采用后更换当前依据，再更正旧事实仍命中；今日确认不能抹掉历史采用。
5. PKR-05：多个匹配事实只保留一条真实第一跳，逐跳标明途经事实及非完整依赖语义。
6. PKR-06：多于100条扇出、菱形、循环、自来源及不同原采用版，所有实际边完成且父路径最短。
7. PKR-07：历史表达缺失或错用途关系、任一来源核验／写入／回忆或审阅钩子失败，根及全部后代共同回滚；跨家族同 owner／影响 ID 冲突须拒绝，不因另一条已处理而掩盖。
8. PKR-08：知识新任务受待复核限制，冻结后变化含已处理记录，旧任务不会因人工处理恢复。
9. PKR-09：卡片 gate、开放尝试、排程暂停和旧评分变化；核对确切采用版本范围，不影响更早版。
10. PKR-10：标准审阅／受审观察追加上游变更，原评分、摘要、原文和历史回执保持。
11. PKR-11：两目录分页／方向／owner／state 游标隔离，外账号详情／父路径不泄露。
12. PKR-12：三种处理、正文实际更新、未发布草稿、归档状态及双标签目标竞争。
13. PKR-13：结果未知后的原键恢复；字段／重复键／范围／时间相等与回拨拒绝并回滚。
14. PKR-14：资料访问、收起重开、迟到响应、换对象与两个复核面板并发时保稿及写锁。
15. PKR-15：升级不补造接入前事件；新更正可核对有完整固定来源的旧采用，不能重写历史 manifest、迁移或回执。
