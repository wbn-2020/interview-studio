# 面后回忆记录与题目来源契约

日期／版本：2026-11-08 · v1.1。状态：S6 第五批代码、独立静态复核与前后端构建通过，待服务器验收。对应 [PRD](../需求文档/产品需求文档.md) EVENT-03、EVENT-04、RET-03；依赖[面试安排](附件与安排接口与数据契约.md)及既有题库。实际进度统一见[开发记录](../开发记录/开发阶段与进度.md)。

## 1. 回忆的业务身份

- 一条记录对应一个回忆的问题，可从面试安排进入，也可独立创建。用户手工填写问题、可选回答片段、回忆的反馈、不确定性和自己认为的知识缺口；均标为个人回忆，不冒称逐字实录、面试官原话、已确认项目事实或技术结论。
- 明确选择 `RECOLLECTION`（有回答片段）或 `NONE`（没有旧回答）。前者必须有片段，后者片段必须为空；不从空字符串猜测类型。两类都保留问题和不确定性，不能进入正式双答案 AI 比较。
- 内容版本不可覆盖。编辑追加新版本；归档／恢复只改变对象修订和可用状态。保留旧版本及题目来源，不把后来的补记倒写为面试当时的回答。
- 本批完成回忆记录、版本阅读和显式整理为待审题。动作来源、回忆基线空白复练及来源判断在下一批接入原动作／复练体系；不另建平行动作系统，不关闭完整 S6。

## 2. 对象、字段与保存

`Recollection` 有稳定 UUID、owner、ACTIVE／ARCHIVED 状态、从 0 开始的对象 revision、当前版本身份及创建／更新时间。`Version` 有独立 UUID、从 1 开始的 number、内容、可空的固定面试安排摘要、创建时间。对象修订最高 1000，内容最多 1000 版；归档及恢复增加 revision，不产生内容版本。

| Content 字段 | 规则（长度为 Unicode 码点） |
|---|---|
| title | 1–200，必填 |
| question | 1–10000，用户记得的问题 |
| type | 复用 QuestionType，只表达整理分类 |
| conditions | 0–5000，记得的约束或上下文 |
| baselineKind | RECOLLECTION／NONE，必填字符串枚举 |
| answerFragment | 0–20000；RECOLLECTION 必填，NONE 必须为 `""` |
| feedback | 0–5000，明确标注为回忆的反馈 |
| uncertainty | 1–2000，说明记不清之处；完全确定时也由用户写明其判断 |
| gap | 0–2000，用户提出的待补内容，不自动认定缺陷 |

所有文本禁止 NUL 和孤立代理，不修剪或改写用户正文。单版本内容及面试摘要 JSON 各有明确字节上限（内容 192 KiB，摘要 8 KiB）；越限拒绝，不截断。

面试关联提交 `interview: {eventId, revision} | null`。服务端从 owner 所属 `interview_event_history` 的确切修订提取 eventId、revision、title、round、startAt、zoneId、status、targetId、targetVersionId；不复制地点、会议链接、备注及材料正文。界面明确显示所选历史修订，安排之后改期或取消不重写既有回忆版本。摘要用 owner/eventId/revision 复合外键关联，不能只信任客户端文字。修改回忆可保留原安排修订，或显式重新选择；不隐式把历史时间换为当前安排。

写命令使用既有 owner 锁、Idempotency-Key 与修订比较。创建、内容版本、元数据、来源绑定、回执同事务；失败回滚。响应丢失保留原请求与原键；冲突时保留输入，用户重读后明确采用最新修订，不能自动覆盖。

## 3. 整理为题目及来源

- 用户在已保存且 ACTIVE 的当前回忆版本上明确打开整理表单，题目初值仅取标题、问题、分类和约束。回答片段、回忆反馈和 gap 不自动填入参考答案或检查点；用户可编辑完整既有 QuestionInput。
- 提交包含 expectedRevision、versionId 和编辑后的题目 content。事务内核对回忆仍为同一活动版本，调用现有 `QuestionService.createWithinCommand`；标准继续为 PERSONAL_UNREVIEWED，并记录明确的编写曝光。
- 一个回忆版本最多采用为一个题目。不同幂等键重复采用返回冲突并提供已采用入口；原键返回原回执。题目、版本、曝光、回忆来源绑定及回执一起提交，任一失败不留半成品。
- 来源绑定保留 owner、回忆及版本 ID、题目及其初始版本 ID、createdAt。题库当前版与历史版都能读取对应确切版本的来源：返回回忆版本及来源 CURRENT／SUPERSEDED／ARCHIVED 状态。绑定只属于当次产生的题目版本，后续人工编辑可经题目历史回溯。回忆后续补记或归档只影响来源提示，不改旧题，也不把题目重新标成受审。
- 本批不调用模型，不新增外发授权。后续使用该题出题、训练或评价，仍按原模块单独确认范围和条件。

## 4. 接口与持久化

| 路径（前缀 `/api/v1`） | 行为 |
|---|---|
| GET `/review/recollections` | status 默认 ACTIVE；可选 interviewId、query 标题筛选；UUID 游标，limit 1–50 默认 20；只返回摘要 |
| POST `/review/recollections` | `{interview,content}`，201 返回 Recollection |
| GET／PUT `/review/recollections/{id}` | 读取当前对象／以 `{expectedRevision,interview,content}` 追加内容版本 |
| GET `/review/recollections/{id}/versions` | number 倒序摘要，before 排他、limit 1–20 默认 10 |
| GET `/review/recollections/{id}/versions/{versionId}` | 读取确切不可变版本 |
| POST `/review/recollections/{id}/archive`、`/restore` | `{expectedRevision}`；同状态请求仍须匹配修订，返回原对象且不增加修订 |
| POST `/review/recollections/{id}/question` | `{expectedRevision,versionId,content}`；201 返回新题及固定来源绑定 |
| GET `/review/recollections/{id}/versions/{versionId}/question` | 读取该版本已采用题目身份，未采用返回 null 信封 |
| GET `/bank/questions/{id}/versions/{versionId}/recollection-source` | 读取题目的确切回忆来源，普通手工／AI 题返回 null 信封 |

V32 新增 `review_recollection`、`review_recollection_version`、`review_recollection_question`。版本与采用关系使用 owner 复合外键及每版本唯一采用约束；不修改 V1–V31。新接口由既有 `/review`／`/bank` 资料守卫保护，进行中的独立训练不能借回忆入口读取旧片段或反馈。

请求字段严格白名单，必填空字段显式传 `""`／null，拒绝数值枚举、浮点修订、遗漏或多余字段。沿用 INVALID_REQUEST、REVISION_CONFLICT、REVISION_LIMIT、ITEM_ARCHIVED、资料守卫错误；新增 RECOLLECTION_NOT_FOUND、RECOLLECTION_QUESTION_EXISTS。历史版本或题目来源归属不符返回 404，不泄露其他 owner 内容。

## 5. 界面与待服务器验收

复盘增加“面后回忆”入口，面试安排详情提供“记录这次面试的回忆”。列表、编辑、版本、题目整理与来源各自区分 loading／empty／error；读取失败不当作无记录。现有脏输入、未决写入、登录代次和辅助遮挡规则继续适用；原键恢复前不清空表单，历史阅读不替换草稿。
