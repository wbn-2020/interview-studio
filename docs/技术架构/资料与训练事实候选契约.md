# 资料与训练事实候选契约

版本：v1.0 · 2026-11-09。状态：**S5 第十九批代码、独立静态复核及前后端构建通过，待服务器验收。**适用 [PRD](../需求文档/产品需求文档.md) MAT-02／03／06、REV-06。本文统一规定本批来源、外发、候选及采用规则；事实核实沿[准备与资料契约](准备与资料接口与数据契约.md)，任务费用与通用恢复沿[AI 任务与外发契约](AI任务与外发契约.md)。实际完成项和检查证据以[开发阶段与进度](../开发记录/开发阶段与进度.md)为准。

## 1. 业务与输入

用户明确选择资料摘录或同一确切训练提交的片段 → 预览完整外发内容、用途、模型及费用 → 单次授权 → 查看带引用的一条事实候选 → 编辑七个内容字段并选择当前 ACTIVE 项目 → 明确采用为新事实 → 通过普通事实编辑与核实流程另行确认。

每任务只整理一条事实候选，purpose 为 `FACT_DRAFT`，promptVersion 为 `fact-draft-1`。证据不足的场景、问题、动作、结果或技术字段可为空，limitations 必填；引用定位不能证明经历真实、指标准确、语义充分支持或本人责任。训练回答可能是假设、练习或转述，资料也不证明用户参与过对应项目，模型不得补造数字或把“参与”提升为“主导”。

模型候选不直接写准备事实。采用只新建一个 FACT 及首版，不覆盖或追加已有事实；责任边界和核实状态均为 `UNVERIFIED`。采用不确认经历、不记录训练或准备任务完成、不改变能力结论。核实必须另行编辑责任并执行原核实命令，不能在 AI 采用中捎带确认。

预览请求为 `{instruction,source}`，source 精确为 `{kind,excerptIds,training}`。instruction 是必须提供的字符串，可为空，最多 1000 个 UTF-16 码元，禁止 NUL 和不完整代理对。两种来源互斥，不自动混选或扩展关联资料：

| 模式 | 选择与固定输入 |
|---|---|
| MATERIAL | 1–5 个有序、不同的本人摘录 ID，training 明确为 null。按请求顺序固定完整 MaterialAiExcerpt；附件必须 READY，摘录与附件摘要相符，PARSED 摘录还核确切成功解析执行、片段及原文区间 |
| TRAINING | excerptIds 必须为 []；training 精确为 `{sessionId,questionId,answerId,fragments}`，固定同一已提交回答的 1–8 个片段，不能提交未保存草稿、另一回答或反馈片段 |

资料固定字段为 excerptId、attachmentId、fileName、sha256、origin、runId、segmentId、locator、text、startOffset、endOffset。MANUAL 的解析身份与偏移明确为 null；PARSED 的偏移与文字长度、代理对边界及原解析片段一致。正文为所选完整摘录，最多 10000 UTF-16 码元；文件名最多 200、定位说明最多 500。历史摘录和训练选区保持原有 `isBlank` 边界，不因本批新增候选的 Unicode 空白规则改判合法旧来源。

训练 fragment 为 `{field,elementId,start,end,quote}`，只允许 ANSWER_TEXT、ANSWER_NODE_LABEL、ANSWER_NODE_DESCRIPTION、ANSWER_EDGE_LABEL。ANSWER_TEXT 的 elementId 为 null，其他三类为原图元素的确切 UUID；同字段／元素的区间不可重叠，允许相邻，单片段 quote 最多 8000 UTF-16 码元。start／end 是原回答字段的绝对左闭右开整数位置，quote 逐字匹配原文，不拆代理对。

训练适配复用确切提交及选区校验，feedback 固定 null。既有适配器可在本地读取题目快照核验提交归属；最终授权投影只保留 sessionId、questionId、answerId、answerNumber、answerCondition、fragments，不包含题面、评价、个人参考、其他回答或关联资料。answerCondition 保留 LEARNING／BEFORE_ASSISTANCE／ASSISTED 原条件，不把有辅助作答改标独立证据。

适配器核验历史题面或反馈时沿其原 Unicode 码点容量及 Java `isBlank` 规则；本批选区偏移和候选容量仍按 UTF-16，不因历史 emoji 等补充字符把合法提交误判为损坏。采用时读取旧 PROJECT 的 source.excerptIds 缺省按空数组兼容，不改写历史项目或扩大本次材料来源。

## 2. Manifest、唯一外发投影与兼容

Manifest 在末尾增加可空 `factDraft`，精确为 `{kind,materials,training}`。MATERIAL 固定材料列表、training=null；TRAINING 固定窄训练输入、materials=[]。FACT_DRAFT 要求 sources=[]，所有旧用途的专属输入为空；旧用途必须 factDraft=null。

Chat Completions、Responses、输入 allowance 与费用预留共用唯一业务投影：

```json
{"purpose":"FACT_DRAFT","instruction":"用户整理要求","factDraft":{"kind":"MATERIAL","materials":[],"training":null}}
```

上例只展示键结构；MATERIAL 实际 materials 必须有 1–5 条完整选中摘录。投影序列化后的 UTF-8 JSON 总量最多 **32 KiB**，包括指令、身份、文件名／定位及正文。超限原样拒绝，不裁剪、自动拆分或改用未预览内容。项目只在采用时选择，不进入预览／生成请求、Manifest 或模型外发；供应商配置、预算和授权摘要不混入业务投影。

预览完整列出实际授权内容、来源身份、供应商与费用。输入模式、选区、摘录顺序、instruction、配置或访问条件变化后撤销旧预览和同意，重新预览才可创建。普通保存、事实核实和历史生成授权不代表本次模型外发同意。

旧数据兼容仅扩展新增尾字段的空值规则：

1. factDraft 缺省按 null 读取；计算实时摘要时，仅在 factDraft==null 时移除该键，再按既有规则分别省略空 cardDraftType、空 reviewDraft。其他 null、既有字段和数组顺序保持，不尝试多套宽松摘要。
2. 非空 factDraft 保留在本用途清单摘要中。保存的旧 Manifest、manifest_hash、候选、决定与回执不写回、不重算覆盖；旧请求 DTO、操作字符串及幂等请求摘要协议不变。
3. Task 末尾追加 factCandidate／factDecision，ModelGateway.Result 末尾追加 factCandidate。旧用途允许新增尾字段缺省或 null，但拒绝非空事实分支；新用途只接受本批候选及决定，不混入知识、题目、JD 或其他结果。

## 3. 候选结构与引用

模型原始结果只含 content、materialCitations、trainingCitations、limitations；服务端再加入固定 validationNote。content 精确七字段，禁止责任、核实状态、项目、source、采用状态、正式事实 ID 或其他新增键。

| 字段 | 规则；长度均按 UTF-16 码元 |
|---|---|
| title | 1–200，非全空白 |
| scenario／problem／action／result | 各 0–10000；证据不足可为空，局限中明确说明 |
| technology | 0–2000 |
| tags | 0–20 个不同字符串，每项 1–40，非全空白 |
| limitations | 1–2000，非全空白 |
| materialCitations／trainingCitations | 两数组均必需；合计 1–12 条不同引用，只有当前输入模式的数组非空，另一数组必须为 [] |

所有新增候选及最终编辑文字禁止 NUL、不完整代理对；必填文本的空白判断包括 Unicode 空格。不补造缺失事实，不因字段允许为空而生成没有任何引用的成功候选。固定 validationNote 为：`AI 事实候选仅整理所选原文，不证明经历或责任；采用后仍须人工核实。`

| 引用 | 精确结构与位置 |
|---|---|
| 资料 | `{excerptId,start,end,quote}`；excerptId 必须在本次材料列表，区间相对于该摘录完整 text，从 0 起算，不使用原文件、解析片段或外层 JSON 的偏移 |
| 训练 | `{field,elementId,start,end,quote}`；只限四种 ANSWER 字段，field／elementId 必须与一个所选 fragment 对应，绝对区间完整落在该单个选区内，不能跨越未选文字或用选区内部相对坐标替代 |

两类 quote 均为 1–1000 UTF-16 码元的非全空白连续原文，逐字等于区间，不拆代理对。资料以 excerptId／start／end、训练以 field／elementId／start／end 去重，不能更改 quote 后重复引用同一位置。引用只核原文出处，不要求覆盖每个所选摘录，也不认证最终编辑的每句话。

模型解析、持久候选读回和采用前均复核字段、文字、模式、引用及固定未审说明，不因 candidate_json 已保存而跳过。原候选、引用与用户最后编辑内容分别保留，用户改写不能被标为模型原答。候选和采用请求保留原文字；正式 FACT 保存沿既有规则去除标题及各标签两端的 Java 空白，标签按去除后结果判重，新候选校验提前拒绝归一后重复。

上述正式保存沿 `PreparationService` 的 `title.strip()`／各 `tag.strip()` 执行；预览、模型候选和采用请求不提前改写原文。标签判重基于 strip 结果，既不折叠大小写，也不对其他正文做 Unicode 归一化。

## 4. 采用、来源与核实

采用请求精确为 `{expectedRevision,projectId,expectedProjectVersionId,expectedProjectRevision,content,confirmed}`，content 使用上述七字段。任务须 SUCCEEDED、候选合法且尚无决定；expectedRevision 匹配任务修订。项目须本人所有、类型 PROJECT、ACTIVE，expectedProjectVersionId 是其当前确切版本，expectedProjectRevision 匹配对象修订。前端刷新不得擅自抬升用户已选择的项目基线。

服务端构造普通 FactContent，责任固定 UNVERIFIED，并按下表构造 Source；客户端不能传入或改写这些值：

| Source 字段 | 固定取值 |
|---|---|
| title | `AI 事实候选` |
| url | 空字符串 `""` |
| note | 本契约固定 candidate.validationNote，须与服务端未审说明逐字一致 |
| excerptIds | MATERIAL 为本次**全部所选摘录 ID，顺序不变**；TRAINING 为 []，训练出处另存于生成／采用来源中 |

因此不能仅保存实际被引用的材料子集、添加未选摘录，或把训练 answerId 伪装成材料 ID。资料模式同时沿准备域保存正式材料引用关系；训练模式没有准备材料关系。

在同一个 owner 命令锁和事务内，准备域 `createFactWithinCommand` 以 MANDATORY 加入外层 AI 命令：

1. 复核任务／来源绑定、候选、当前来源、双修订及项目确切版本。
2. 按普通事实规则校验最终内容和固定来源，生成新 factId、versionId。
3. 新建 ACTIVE、revision=0、versionNumber=1、verification=UNVERIFIED 的 FACT，归属选中项目，保存责任 UNVERIFIED 和材料关系。
4. 写一次 ADOPTED 决定、确切项目／事实／首版，递增任务修订，保存通知及幂等回执。

以上一起提交或回滚，不产生无采用决定的孤立事实，不另开第二份准备域命令。任务／项目冲突、来源失效或容量错误均保留人工稿；关闭 AI 不阻止本地采用仍有效候选。采用新事实不改变输入材料或训练提交。

原键同请求恢复原回执，异正文同键拒绝，换键不能重复采用；采用／忽略互斥。忽略不要求来源当前，不新建事实，决定中的 targetProjectId／targetItemId／targetVersionId 全部为空。采用之后的改稿、归档和人工核实沿普通事实流程，不删除原首版和 AI 来源；责任仍 UNVERIFIED 时，原核实命令继续拒绝确认。

## 5. API、权限与恢复

[FactDraftDtos](../../backend/src/main/java/com/wenjie/studio/ai/FactDraftDtos.java) 统一请求、窄输入、候选、决定及来源 DTO，新增四个操作：

| 方法与路径 | 请求／响应边界 |
|---|---|
| POST `/api/v1/ai/fact-drafts/preview` | `{instruction,source}`；返回完整 Manifest、摘要和预算，不创建任务或调用模型 |
| POST `/api/v1/ai/fact-drafts/tasks` | 创建字段再加 expectedManifestHash、consentConfirmed，持 Idempotency-Key；创建持久任务、首次尝试及固定来源关系 |
| POST `/api/v1/ai/tasks/{id}/adopt-fact` | 采用七字段内容及明确项目基线，持 Idempotency-Key；返回 Task 与事实采用决定 |
| GET `/api/v1/ai/facts/{factId}/versions/{versionId}/origins` | before／limit 分页，返回专用 OriginPage 元数据 |

三个新 POST 从原始字节严格解析，请求体最多 262144 字节；拒绝重复键、尾随内容、未知／缺失字段及类型强转，逐层校验 source、training、fragment 和 content。新请求中所需可空字段必须显式为 null。修订为 JSON 整数并受 JS 安全整数上限约束，区间为可转换为 Int 的 JSON 整数；授权值必须 Boolean，枚举／ID／文字／标签成员必须字符串，不能把字符串数字、小数或数字枚举转换后接收。

权限与当前性分别处理。新创建、发送、接纳和采用要核来源当前；历史读取、原键回执及忽略仍执行 owner 和训练资料访问守卫，但不能因正常来源后续变化伪装命令从未执行。创建原键回执还核对其固定任务与清单；任务重试、取消和费用核对的历史回执按发出时快照核验，合法旧回执解除未决后保留较新候选、决定及来源状态，再查询当前任务。

输入、配置或权限变化撤销预览同意，保留本地选区和人工稿。未决写入固定原请求／原键，禁止迟到查询覆盖新稿，登录代次或访问窗口变化后暂缓接收。导航守卫保留 pending；普通查询继续拒绝固定 Manifest 变化、不可变候选或决定消失。取消、租约、未知费用、重试次数与迟到费用沿现有 AI 状态机，不因源变化自动退款或重发。

## 6. 固定绑定与 V46

[V46](../../backend/src/main/resources/db/migration/V46__ai_fact_drafts.sql) 在 V45 后扩展 purpose CHECK，保留全部旧用途并加入 FACT_DRAFT，新增三表；不改旧迁移，不回写旧数据：

| 表 | 固定关系与约束 |
|---|---|
| ai_fact_draft_source | 每任务一行 MATERIAL／TRAINING；owner 复合外键指向任务。MATERIAL 的训练身份全空；TRAINING 的 session／question／answer 全部必需，并通过复合外键约束确切提交 |
| ai_fact_draft_material | 仅 MATERIAL；同任务摘录 ID 与 ordinal 分别唯一，ordinal 1–5；复合外键关联同种类来源行及本人摘录 |
| ai_fact_draft_decision | 每任务至多一条终态决定；ADOPTED 项目／事实／首版全非空，IGNORED 全空；复合外键关联来源、项目对象与所属事实版本，采用事实目标唯一 |

服务层逐阶段核 task、purpose、Manifest、hash、专属来源行和材料顺序。MATERIAL 必须恰有清单数量的绑定且 ordinal 从 1 连续；TRAINING 必须没有材料绑定，并精确匹配 session／question／answer。普通用途不得夹带本批孤立来源或决定，不借旧知识来源关系隐式兼容。

采用决定须指向同 owner、正确 PROJECT 下的 FACT 首版，核原首版责任 UNVERIFIED、固定 Source 及材料关系；不能以目标后来的当前核实状态替代首版检查。后续人工改稿和核实不会使合法历史被误判损坏。

普通来源变化与完整性错误分开：材料不再可用或确切训练来源无法正常读取使当前性失败；绑定缺失／重复／错序、错误模式、摘要矛盾、非法持久 JSON、决定目标不符和依赖故障不能吞成 source changed、空来源或费用释放条件。确切训练提交不会因后来新答案或会话代次变化自动被替换；仍核授权窄输入及现行访问条件。迁移和 SQL 仅编写，约束与数据库行为待服务器验证。

训练来源的跨 Bean 只读输入调用使用 `MANDATORY`，对 `ApiException` 声明 `noRollbackFor`，使上层当前性检查可以接收明确的来源失效，而不把外层事务意外标为 rollback-only。上层仅将 `AI_TRAINING_SOURCE_NOT_FOUND`、`AI_SOURCE_CHANGED`、`AI_EVALUATION_ACCESS_REQUIRED` 转为 false；其他业务异常、数据库及 JSON 异常继续传播。该静态修正不代表事务行为已经运行验证，错误分类与事务回滚须在服务器分别验收。

## 7. 来源历史

专用 Origin 包含 taskId、targetProjectId、targetItemId、targetVersionId、targetVersionNumber、adoptedAt、direct、sourceKind、materialSources、trainingSource。查询先核本人 FACT／版本确切归属，再按请求版本号上界倒序查询本版及此前采用，before 为排他版本号游标；direct 仅表示采用首版等于请求版本。后续改写版本仍能看到更早采用，direct=false。

来源响应不返回事实正文、原答全文、选区文字、候选正文或引用 quote。材料元数据复用 MaterialOriginSource，含确切摘录／附件／解析身份、文件名／定位与偏移，不含 text，状态为 CURRENT／UNAVAILABLE。训练元数据精确为 `{sessionId,questionId,answerId,answerNumber,answerCondition,state}`，当前性不因后来回答而自动过期；不可访问时保留身份与适用状态，不补读其他答案。

来源记录用于解释生成与采用发生在何处，不认证事实内容。后续事实改写、项目或事实归档、责任修改和核实决定不抹去采用历史，也不能让新文字继承“原 AI 已支持”的声明。查看来源与正式核实分别沿原资料访问边界执行。
