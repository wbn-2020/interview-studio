# Linux 容器部署与验收

版本：v1.0 · 2026-11-13。适用：用户明确授权的个人单实例首次部署。实际发布结果和未完成验证只在[开发阶段与进度](../开发记录/开发阶段与进度.md#首次服务器部署--2026-11-13)记录；本文件不自动授权安装、迁移、清理或修改服务器。

## 1. 运行组合和隔离

[Compose](../../deploy/compose.yaml)包含专属MySQL8.4、Java21应用、Nginx及按需执行的独立迁移服务。前端使用本次独立构建目录；服务器不需要Node、npm、Maven或本地模型。数据库和应用不发布宿主端口，只由Web提供同源页面与`/api/`代理。

- Web：30081为HTTPS入口，30080跳转至该入口；公网NAT须实际核对，不能只依据服务器监听或控制台截图。
- 数据库：独立命名卷和仅授予本项目库权限的账号，不复用其他项目库、账号或卷。
- 应用：以UID/GID `10001:10001`运行，只读挂载发布目录；独立挂载材料、搜索索引、导出目录及隐私账本。
- 内存上限：数据库2GiB、应用2GiB、Web256MiB、按需迁移512MiB；这是部署限制，不是容量或性能验收结论。
- 日志采用每容器10MiB、3份轮转。材料和导出配额不等于整个磁盘已有自动清理；不删除唯一副本或备份。

实例约定为专属根目录下的`config/`、`tls/`、`releases/<发布编号>/`、`data/`、`privacy-ledger/`和`records/`。实例根目录与配置目录仅管理者可访问；释放给应用的四个数据目录须归UID10001，发布文件须能由该UID读取。

## 2. 配置和凭据

实例配置不提交Git。当前任务的本机私有资料位于Git忽略的`.cache/deployment-20261113/`，操作流水位于`.cache/deployment-session-20261113.jsonl`；后续先读发布记录，不能猜测私有配置位置。

Compose的`release.env`保存部署根路径、发布路径和三种镜像的**实际摘要固定值**，可用`STUDIO_APPLICATION_ENV`指定本次专属应用配置，默认读取实例的`config/application.env`；应用配置使用`format: raw`，BCrypt中的`$`不得插值，值也不得加shell引号。应用必需：

- 数据库URL、专属用户名和密码；
- 规范化owner UUID、管理员名和成本10–14的BCrypt哈希；
- 材料、搜索、独立隐私账本及导出绝对目录，并按需启用解析、检索和归档；
- 未配置第三方API时保持`STUDIO_AI_ENABLED=false`，不借用其他项目或工具的密钥。

MySQL使用两份独立`*_FILE` secret。宿主配置父目录保持0700；两份secret以只读方式挂载，文件权限须支持镜像中mysql用户读取。不能通过打印密码或完整`compose config`检查是否加载成功，使用`config --quiet`并做真实登录验证。

当前应用的会话Cookie固定`Secure`。没有域名时可以使用含公网IP SAN的自签名证书作为初次测试入口，但浏览器会提示不受信任，不等于公开可信HTTPS。私钥仅存于服务器本项目TLS目录；HTTP检查使用精确下载的公钥证书验证，不关闭全局TLS校验，也不修改本机系统证书库。

## 3. 制品与显式迁移

发布前以开发记录中的最终制品清单核对JAR、全部前端文件、迁移runner class及部署脚本；不发布旧`dist`累计残留。文件上传中断时先核对远端大小及对应前缀摘要，再恢复，不在不完整制品上启动。

[制品准备脚本](../../deploy/prepare-release.py)只接受本项目专属发布目录，验证JAR、229份前端和部署文件摘要，再从已核对JAR提取依赖及V1–V89，输出目录／文件均拒绝覆盖。须以`umask 022`执行，保证UID10001可读。部分失败保留现场，禁止盲目重跑或清理后假装首次执行。

**当前JAR没有Boot Flyway自动配置模块。**`SPRING_FLYWAY_ENABLED=true`不能代替迁移步骤。[Migrate.java](../../deploy/Migrate.java)用Java21编译，使用同一JAR中提取的Flyway／MySQL依赖，显式按版本迁移，禁用clean且不自动baseline。

在已约定实例路径上，管理员执行顺序为：

1. 只读检查专属目录／卷是否首次使用、端口是否空闲、镜像来源和实际摘要、磁盘以及既有服务基线。
2. 上传并校验配套制品，准备受限配置及证书；运行Compose配置检查。
3. 只启动`database`并等到健康，核实真实MySQL版本。
4. 显式运行`maintenance` profile中的`migrate`，检查退出码、目标89以及`flyway_schema_history`全部success；失败停止，不在失败DDL上盲目重放或repair。
5. 迁移成功后启动`application`，检查实际启动日志，再启动`web`并执行`nginx -t`。
6. 执行HTTPS、登录、CSRF和业务读取检查，保存脱敏结果；最后与既有服务基线比较。

首次真实迁移发现并修正了V15的同名外键重建、V32／V33顶层`COALESCE`需要显式布尔比较、V33的JSON数值范围比较，以及V69重建外键时与旧自动索引名冲突的问题。首次部署失败的空库和发布制品保留，在新的本项目专属空库从V1重新验证；未通过`repair`或手工改账本将失败标成成功。这些SQL修正仅适用于当前尚未成功应用对应版本的首次部署，不能据此直接改写其他既有实例的已应用迁移；其他实例须先核对真实版本、校验和及结构，再确定升级方案。

Compose命令都显式指定本项目`--env-file`与`-f`。迁移服务保留退出容器作为记录，不通过`down -v`删除数据库卷。已有实例发版必须另行确认备份和回退边界；独立隐私账本不得随旧业务数据库快照一起回退。

## 4. 部署检查与回退

[HTTP检查脚本](../../deploy/smoke.py)只连接显式HTTPS地址，读取指定的本项目初始账号文件和公钥证书；不读取浏览器凭据、SSH认证文件、netrc或环境代理配置。结果仅保存状态码和检查结论，不输出密码、CSRF或Cookie。

检查包括：

- HTML及其直接资源返回正确内容；API不误落到前端HTML。
- 匿名会话和未登录读取拒绝；登录204、会话建立、Secure／HttpOnly Cookie。
- 初始空环境通过显式`--initialize-ledger`建立GENESIS及数据库检查点，确认账本READY；不为已有业务自动确认历史基线。请求前将幂等UUID存入报告同目录的`ledger-initialization-key`，或显式指定`--ledger-key-file`；未知结果须复用原键，不能换键重复初始化。
- 知识目录、星图状态、题库、准备列表、训练列表／活动会话、今日概览、搜索状态／查询和AI设置的真实JSON读取；报告仅保存AI开关、配置是否齐备及协议，不保存密钥或来源正文。
- 缺CSRF写入403、带合法CSRF退出204、会话随后失效。

这些仅是部署冒烟检查，不替代FIN-01–26、全部专题场景、模型兼容／费用、并发恢复和视觉交互验收。关闭AI时必须明确告知尚未配置，不能称为真实AI训练已验收。

首次部署失败的可逆退路是停止本项目`web`和`application`，保留数据库、材料、账本、配置、发布文件与日志供排查；不停止另一项目，不删卷、不回退独立账本。需要数据恢复、清理或改变系统安全设置时重新确定具体目标及授权。
