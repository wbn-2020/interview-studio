# AI知识来源冻结资格契约

版本：v0.2 · 2026-11-13。范围：S8第三十七批四类AI用途清单直接知识，以及第三十八批SOURCE_QA显式知识来源。两批均静态检查通过待服务器验收；AKF16项、AKQ12项服务器场景全部未执行。实际证据见[开发阶段与进度](../开发记录/开发阶段与进度.md)。

## 1. 适用范围

本契约约束`AiSources.current(owner, manifest, frozenAt)`中调用`knowledgeReady`的三处分支：

| 用途 | 本批核对的知识 |
|---|---|
| `KNOWLEDGE_DRAFT`／`QUESTION_DRAFT` | 通用整理／出题分支中清单直接选择的`NOTE`／`CONCEPT` |
| `MEMORY_CARD_DRAFT` | 固定清单全部直接知识来源 |
| `RELATION_DRAFT` | 固定知识端点；材料、训练、复盘、回忆及AI反馈等模式仍独立满足原专用守卫 |

训练片段或复盘片段整理可提前进入专用分支，不能仅凭用途名认定经过本条检查。表达生成、评价、追问、比较、改写等专用分支及完整间接祖先资格不由本契约认证；跨域问答的显式知识由§6单独约束，其他域不随之扩展。

## 2. 冻结时间与复核规则

每条知识仍先满足所属分支既有的归属、类型、ACTIVE状态、确切当前发布版等条件。草稿、收藏、主题和布局不能替换任务固定的发布内容。

- 新预览／未提供冻结点的当前检查：沿用`pending`，任一适用影响未处理则不可作为就绪输入。
- 已有任务：使用原`ai_task.created_at`，复用`reviewRequired`。对目标版本号不晚于本次确切来源版的适用记录，只要`revision=0`、`created_at >= frozenAt`或`decided_at >= frozenAt`任一成立，就不可继续使用这份旧任务。
- 三类影响分别来自知识、准备和材料更正。处理时间须严格早于冻结点才可能通过本条；正文不变、处理后保留当前内容、后续人工版、重试时间或重新授权均不刷新旧任务基线。
- 不改变`changedAfter`及其其他调用语义，不新增表、迁移、配置、依赖或清单字段。

例如：一份任务固定了知识B。即使B正文始终不变，只要适用上游影响的处理时间不早于该任务创建时间，旧任务就不能因“已处理”而重新获得资格。用户核对完来源后，可重新预览并创建新任务；新任务仍须满足全部原有条件。该例用于说明守卫，当前没有真实服务器数据复现；正常写入还有owner锁及冻结时钟守卫。

## 3. 接入与历史边界

现有调用链已在再次授权、重试、发送前、结果接纳和采用时传入原任务创建时间，本批只替换共用知识检查。普通资格失配仍沿原`AI_SOURCE_CHANGED`路径；任务详情及关系候选图投影的`sourcesCurrent`使用原任务时间反映该结果，不代表预算足够、许可有效或候选语义正确。

历史清单、摘要、原始回答、候选和采用记录不因来源失效重写。已有历史内容仍受其原读取权限限制；历史目录的其他专用状态不自动纳入本批。已进入网络的请求不能被本地资格检查撤回；正常结果接纳拒绝仍沿原费用结算路径保留已发生用量，不承诺费用归零。

`reviewRequired`沿既有规则验证时间、确切知识版号和存储错误。非法持久冻结时间及数据库错误不作为正常`false`吞掉。`null`明确表示既有无冻结点调用，不补造历史时间；本批不新增针对缺失任务时间的全局迁移或修复。

OpenAPI累计版本为7.65.0；更新授权、重试以及任务／关系图`sourcesCurrent`说明，HTTP字段、类型、路径及状态形状保持，生成类型配套。静态说明和构建不替代真实MyBatis／MySQL、事务、HTTP、费用或页面验收。

## 4. 服务器场景

以下AKF场景全部未执行。需在已授权服务器使用受控数据验证；故障／等时数据只能在隔离验证数据中构造，不能据此断言正常命令链必然产生这些历史状态。

| 编号 | 场景与应观察结果 |
|---|---|
| AKF-01 | 四种用途各以正常当前知识完成新预览／建任务；无适用影响时本条不额外拒绝，其他守卫仍生效。 |
| AKF-02 | 分别存在知识、准备、材料未决影响，新预览及旧任务均拒绝将受影响的确切知识作为就绪来源。 |
| AKF-03 | 三域分别构造创建时间早于冻结点、处理时间晚于冻结点的适用影响；正文不变且已处理，旧任务仍失效。 |
| AKF-04 | 创建时间早于冻结点、处理时间恰等于冻结点，旧任务仍失效；晚／早1微秒的边界分别核对。 |
| AKF-05 | 影响创建时间恰等于冻结点，即使已处理也失效；核对MySQL微秒映射及UTC往返。 |
| AKF-06 | 影响创建及处理均严格早于任务，且无未决影响、知识仍ACTIVE确切当前版，本条允许；不能因此略过其他用途限制。 |
| AKF-07 | 影响目标版号晚于本次确切来源版，不由本条向前污染；相同及更早目标版号仍纳入。不同owner／知识对象不串用。 |
| AKF-08 | 对受影响旧任务新建持续授权，返回原来源错误；恢复来源并创建新任务后仍须新的显式预览和授权。 |
| AKF-09 | 旧任务重试沿原任务时间拒绝，不新增可发送尝试；原幂等键回放保持原回执与原费用记录。 |
| AKF-10 | 排队后来源失效，发送前拒绝外发；记录实际请求数、任务／尝试状态、预留结算及恢复结果。 |
| AKF-11 | 请求在途后来源失效，结果不能作为成功候选接纳；已发生用量按原路径结算，不宣称供应商取消或免费。 |
| AKF-12 | 原成功候选在采用前失效，知识／题目／卡片／关系采用分别拒绝；验证目标、决定、来源台账及幂等回执原子性。 |
| AKF-13 | 任务详情及关系图`sourcesCurrent`按原创建时间为false，历史候选可在原权限下读取；不自动发布、采用或清除历史。 |
| AKF-14 | 同一来源处理完成后重新预览／建新任务，使用新任务自己的冻结点；原任务继续失效，重试／重新授权不改原时间。 |
| AKF-15 | 归档、非当前版、错类型等原检查继续拒绝；专用分支及无冻结点调用保持各自规则，不宣称完整间接祖先已核验。 |
| AKF-16 | 非法持久时间、缺确切版本及数据库故障沿原错误退出；不吞错或返回部分许可。核对owner并发、事务、三域查询计划／耗时及界面提示。 |

## 5. 验证与剩余

第三十七批静态核对确认仅局部helper变化、三处调用和858份其他源码保持，既有三域SQL与调用链不变；当批OpenAPI仅版本与四说明差异，生成类型配套。后端417Java以release21离线打包通过，未编译或运行单元测试；完整前端类型检查及生产构建通过。868项输入无漂移、75迁移保持、78份XML禁外部解析通过，2153个JAR业务条目与target/classes逐SHA一致，200个前端输出文件及两入口直接资源核对通过。`javap -p -c`仅静态检查编译后的helper分支，未执行Java业务逻辑。真实数据覆盖、历史回放、数据库执行计划、异常恢复、并发、费用与视觉均待服务器。

其他AI专用分支、训练／题面闭包其他来源角色、完整祖先动态资格、材料未支持出口及归档恢复、完整历史核验、概念合并、回收站／清除与独立账本、文件交换、备份恢复及最终交付继续按唯一开发记录推进。

## 6. 跨域问答显式知识 · S8第三十八批

`SOURCE_QA`由`AiSources.current`原样传递冻结点到`SourceQaSources.current`。本批只对用户手选的`Domain.KNOWLEDGE`接入§2的`reviewRequired`；既有问答仍以原`ai_task.created_at`复核知识、准备和材料三域影响，未决或创建／处理时间不早于冻结点均失效。新预览与创建重建仍沿原`capture/check`检查`pending`，不能因选区正文相同或确认保留当前内容恢复旧任务。

原来源重建、固定选区／完整限定、`requireForward`代次校验和完整input比较保持。冻结检查只针对直接知识，不展开其笔记双链、图谱邻居或训练／题目来源，也不将另外七域自动转为知识输入；原材料用途与知识材料祖先守卫仍独立满足。不改变任何原文、Manifest／scope摘要、绑定、模型投影、引用范围或32KiB上限。

再次授权、重试、领取与最终发送前、结果接纳、暂态正文和任务详情沿现有原任务时间链生效；正常失配沿原`AI_SOURCE_CHANGED`或`sourcesCurrent=false`路径，时间／完整性和存储错误不新增为可吞掉的正常状态。历史任务与原键回执依旧核固定绑定和读取权限，不因来源失效创建新任务；SOURCE_QA仍无采用／完成记录。已外发请求和发生费用按原流程处理，不能由本条撤回或归零。

OpenAPI累计7.66.0仅补版本、问答预览／创建、授权／重试和任务`sourcesCurrent`说明，HTTP形状保持；生成类型配套，无新迁移、依赖、配置或业务源码。静态对照已定位规则缺口，真实数据下是否存在触发记录尚未验证。

以下AKQ场景全部未执行。等时、时钟或损坏数据仅在隔离验证数据中构造；不据此推断正常写入必然产生此类状态。

| 编号 | 场景与应观察结果 |
|---|---|
| AKQ-01 | 显式选择当前NOTE／CONCEPT，并与其他域混选；无影响时本条不额外阻断，预览仅包含原选区和必要限定。 |
| AKQ-02 | 三域分别存在适用未决影响，新预览／创建和既有任务均拒绝知识输入；不自动删失效来源、换最新版或切GENERAL。 |
| AKQ-03 | 三域分别构造影响创建早于任务、处理晚于任务且正文不变的记录，旧任务仍失效。 |
| AKQ-04 | 创建或处理恰等于冻结时间仍失效；逐一核对早／晚1微秒、UTC往返与MySQL映射。 |
| AKQ-05 | 适用影响均已处理且创建、处理严格早于原任务，来源仍满足当前版／代次等原条件时，本条允许。 |
| AKQ-06 | 相同／更早目标版纳入，晚于确切知识来源版的不由本条向前污染；不同owner／对象隔离。 |
| AKQ-07 | 旧问答再授权或重试仍用原任务时间拒绝；失败不新增可发送尝试，新尝试或授权时间不刷新基线。 |
| AKQ-08 | 排队、领取与最终发送之间失效，实际网络请求数不增加；状态、预留与原键恢复保持原流程。 |
| AKQ-09 | 在途后失效阻止成功接纳，已发生费用沿原路径保留；暂态正文按原权限和当前性检查停止提供。 |
| AKQ-10 | 旧任务详情`sourcesCurrent=false`，旧结果和原键回执按原读取权限可核对；新预览／新任务有自己的时间，旧清单／摘要不重算。 |
| AKQ-11 | 固定身份／选区／代次损坏、非法持久时间或数据库故障沿原错误退出；不能吞成普通过期或部分来源许可。 |
| AKQ-12 | 其他七域、两协议投影与引用、资料／原答评价许可及迟到正文守卫保持；不引入隐式知识或采用。核对三域查询耗时、并发／费用恢复和服务器界面提示。 |
