# AI 单次尝试暂态正文流契约

日期：2026-11-10。版本：v1.0。状态：S5 第三十一批静态检查通过待服务器验收，独立静态复核与前后端构建完成；服务器场景全部未执行。适用 PRD AI-03、AI-04、AI-06、TRN-08。持久任务、费用与授权沿[AI任务与外发契约](AI任务与外发契约.md)及[持续范围授权与撤回](AI持续范围授权与撤回契约.md)，进度仅维护在[开发记录](../开发记录/开发阶段与进度.md)；机器接口及四种事件以[累计OpenAPI](openapi-s7.json)为准。

## 1. 用户行为与结果边界

用户照常选择资料、预览外发清单并主动提交。服务端流式配置启用后，可在当前任务的当前尝试中点击“查看实时预览”，只读查看供应商正在返回的文本。停止查看、隐藏页面或网络断开不会取消任务，不创建新尝试、不再次外发；取消任务仍使用原独立命令。

所有用途目前要求结构化 JSON。实时预览可能是不完整的 JSON，只以纯文本展示，明确标注“生成中，尚未校验”；不渲染其中的 Markdown、HTML 或链接，不把其中的评分、引用或建议作为正式报告。最终完整输出通过结构、用途、引用、来源与许可检查后，才由原任务详情发布候选或报告。采用、忽略、决定、追问入场及人工草稿保持各自原规则。

暂态正文仅在服务器进程有界内存及当前页面内存存在，不进入数据库、状态通知、Query 结果缓存或浏览器持久存储。失败、取消、终态、进程重启或内存过期后不可承诺找回。重新连接从当前缓冲快照开始；最终状态与已校验结果从原 GET 接口恢复，预览内容不构成恢复依据。

## 2. 配置、范围与费用

新增 `studio.ai.streaming`，环境变量 `STUDIO_AI_STREAMING`，默认 `false`。关闭时公开 `Configuration.streaming` 缺省，旧配置字段、清单摘要、指纹及既有回执保持兼容；开启时输出 `streaming: true` 并纳入本次清单及完整配置指纹。切换配置需要重新预览，持续许可不能跨配置借用。该开关不启用 AI 本身，不更改模型、提示词、预算或授权方式。

Chat Completions 与 Responses 使用各自流式协议，接收增量文本并核对协议身份和终态。Chat 请求用量回执；Responses 保持 `store=false`。不显示 reasoning、工具调用、拒绝载荷或原始错误对象；不从暂态长度估算 token 或费用。协议不兼容、截断、超时或响应损坏后不自动改协议或另发非流式请求；同一次 HTTP 若返回完整 JSON，可沿原严格解析读取，无伪造逐字动画。

输入仍使用完整已预览投影，实际协议请求字节继续核预算。最终正文上限维持 256 KiB；供应商线上总字节限 4 MiB，单行及单帧限 512 KiB，累计输出文本限 256 KiB UTF-8，最多 16 项 item／part，防止逐事件封套使缓冲无界。供应商用量与候选是否合法分别核算：已收到的可核实用量可保留，无法确认时仍为 UNKNOWN，不因预览断开或校验失败显示零费用。同一流出现矛盾用量时永久取消该次自动核账资格，不能选择第一份金额；相同重复回执可接受。最终费用与迟到补账沿原任务规则。

## 3. 正文权限与身份

新增普通资料出口 `GET /api/v1/ai/tasks/{id}/attempts/{attemptId}/draft-events`。它包含未校验正文，不能沿[状态通知](AI任务状态推送与恢复契约.md)或授权元数据的精确例外放行，也不能沿训练专用追问的白名单元数据接口放行。独立训练须先按原流程确认资料；评价、改写、比较、复盘及反馈来源继续核各自原答访问条件。

连接核本人 owner、确切任务与当前尝试、固定清单与来源绑定、当前配置／进程、持续许可、来源当前性及运行租约。只允许当前 QUEUED、RUNNING、VALIDATING 继续预览；取消请求与终态结束预览，旧尝试不自动切到新尝试。正文读取不执行恢复调度、不改变任务／费用，不把“最后发送检查”用于已经发送的尝试。

建立时及每轮读取前后核原 HTTP session、会话身份及当前资料条件；数据读取使用短检查，向浏览器写入不持有数据库事务或 owner 锁。权限变化、退出、会话替换、来源或许可失效后结束连接。检查与实际网络发送仍有窗口，不能承诺撤回已经显示或已经在传输中的文本。

前端固定登录代次、资料访问代次、任务、尝试及连接代次；每个事件均核身份和顺序。隐藏、退出、权限检查／受阻、任务切换、组件停用及卸载时关闭连接并清除文本，迟到事件不能更新新页面。重新登录或恢复可见不自动展示旧正文，须重新主动查看。

## 4. SSE 与资源边界

接口只读、已认证、同源 cookie，不在 URL 放凭据。响应为 `text/event-stream`、`Cache-Control: no-store, no-transform`、`X-Accel-Buffering: no`。不发送 SSE id；提供 `Last-Event-ID` 拒绝，不持久重放旧暂态。每次连接先 snapshot，不能把旧前缀与新快照相加。

| 事件 | data | 处理 |
|---|---|---|
| snapshot | `{taskId, attemptId, sequence: 0, text}` | 覆盖本连接的暂态文本；尚无缓冲时可为空 |
| delta | `{taskId, attemptId, sequence, offset, text}` | sequence 顺序递增，offset 等于已接收文本的 UTF-16 长度，追加纯文本 |
| heartbeat | `{taskId, attemptId}` | 只表示连接活跃，不代表进度或通过校验 |
| closed | `{taskId, attemptId, reason}` | reason 为 FINISHED／UNAVAILABLE／ACCESS_CHANGED／RECONNECT；清正文，最终状态回原详情读取。FINISHED 包含 CANCEL_REQUESTED，仅表示过程预览结束，不证明任务已终态、成功或费用已结算 |

每个增量最多 8192 个 UTF-16 代码单元，不切开代理对；服务器每尝试缓冲最多 256 KiB UTF-8。缓冲绑定 owner、task、attempt、认领令牌及进程代次，结束只清本次身份。最多四项缓冲，使用单调时钟到期；不能挤出其他活跃尝试后静默复用旧身份。

当前界面只在确切任务及当前尝试均 RUNNING 时提供主动连接；QUEUED 等待处理，VALIDATING 回正式结果查询。服务端允许三种活动态用于握手竞争和等待；非活动态可在任何 snapshot 之前直接发 closed。每次新连接不带查询参数或历史事件 ID，任何非空查询参数及 `Last-Event-ID` 都拒绝。JSON 转义后的事件外壳允许膨胀，解析后再核正文 UTF-8 上限，不把 JSON Schema 的字符计数当 UTF-16 长度。

正文最多四条连接，与无正文通知使用独立的执行器和额度；每约 500ms 检查，空闲约 10 秒心跳，约 90 秒轮换，emitter 超时 95 秒。慢读及容器实际断开释放仍需服务器验证，超时值不等于任意网络下强制终止写入。浏览器连接退出或额度不足只影响预览；供应商协议或缓冲接纳失败可使本次生成失败，按原任务及费用处理，不授权额外模型请求。错误不返回原供应商正文、凭据、SQL 或堆栈；建立后的断开不在流尾追加 problem JSON。

解析器的暂态回调在同步临界区执行，当前调用链只允许有界、快速的内存校验与追加；不能在回调中执行数据库或网络等待，否则可能阻塞超时后的账单快照和资源关闭。SSE 网络写入由另一执行器读取快照完成，不在该回调或缓冲锁中执行。
