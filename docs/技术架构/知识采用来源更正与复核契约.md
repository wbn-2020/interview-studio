# 知识采用来源更正与复核契约

版本：v1.2 · 2026-11-11。状态：S8 第七批规则已静态交付，第八批多跳扩展代码完成待验证；后端及业务入口专项检查已通过，整仓前端构建受独立参考界面缺失组件阻塞，运行与界面尚未验收。

业务依据：[产品需求 §7](../需求文档/产品需求文档.md)、[系统架构与数据边界](系统架构与数据边界.md)。实施状态、检查证据和剩余范围只维护在[开发阶段与进度](../开发记录/开发阶段与进度.md)。

## 1. 本批业务范围

接通一条已登记的路径：知识 A 的发布版本 → AI 知识整理任务 → 人工采用的知识 B 的确切发布版 → 以 B 为依据的当前回忆卡和标准审阅。采用来源表示整理出处，不证明每一句内容均由该来源支持。

A 的原始发布正文发生变化或 A 被归档时，同一 owner 命令事务追加更正事件和采用影响。标题改版、草稿保存、主题、一般关系和收藏不产生此类事件。恢复 A 或改回原文不消除已产生的待复核记录。

影响保留根事件、实际输入的 A 版本、原任务、采用的 B 版本。B 后续人工版本可能沿用历史内容，也可能已经独立改写；系统只提示“历史采用来源需核对”，不推断具体段落、不替换正文。待处理影响对不早于采用版的 B 版本采用保守守卫；采用前的 B 版本不受此记录阻塞。

第七批先处理知识输入到知识采用的一跳；第八批沿真实版本采用链的扩展及逐跳查看规则见[知识采用多跳传播契约](知识采用多跳传播契约.md)。两批均不扫描任意正文或普通关系图。事实／表达／摘录来源、完整删除清单、清除、合并和最新独立撤权账本继续开发。新机制记录接入后的实际事件；迁移不把旧版本差异虚构成已发生并已处理的事件，接入前历史回填仍为待办。

## 2. 处理规则

用户在知识详情主动展开“来源更正与复核”，可查看该对象作为源头或采用目标的待处理及全部记录。目录只返回标识、版本、标题、状态、时间和用户处理说明，不读取 AI 清单、候选正文、模型响应、费用或训练原文。

处理在原知识编辑器完成，再单独提交确认：

| choice | 条件与结果 |
|---|---|
| `KEEP_CURRENT` | 目标当前有效；用户确认已经核对此次影响，保留当前内容并填写理由。不删除历史采用来源，不宣称历史版本或技术结论已经认证。 |
| `PUBLISHED_UPDATE` | 目标当前有效；当前发布版晚于原采用版，且原始发布正文与原采用版不同。用户确认修改已处理此次影响，保存处理后的确切版；不由系统自动改稿。 |
| `ARCHIVED` | 目标已经归档；保存当前版本与归档处理说明，不在本命令中执行归档。 |

三个选择都必须提供影响修订、目标元数据修订、当前发布版本、明确确认和 1–1000 字理由。目标存在未发布草稿时拒绝处理，避免把当前发布版的结论套到尚未发布的改写。处理单向从 `PENDING` 到 `RESOLVED`，同一影响只保留一次决定；更晚的源事件产生独立的新影响，不能被旧决定覆盖。

源和目标版本在提交时重新核对 owner、对象与版本关系。原键回放返回原决定；新请求不能凭旧基线覆盖他人处理。断网保留原请求和幂等键，在核实结果前不构造第二个决定。处理来源影响不创建复习、训练完成或能力证明记录。

## 3. 下游守卫

- 新的来源影响使使用相应 B 版本的当前回忆卡追加 `SOURCE_UPSTREAM_CHANGED` 历史，推进 gate、暂停已有排程、终结开放尝试。历史 `upstreamImpactId` 保留本次采用影响 ID，`source=null`；不能伪装为 B 正文已经改变，也不补造根知识的直接引用。
- 回忆来源快照加入 `upstreamReviewRequired`，当前可访问来源必须返回具体布尔值，不可访问时为 null；接入前不可变历史允许缺字段或 null，保留未知，不重写快照或摘要。普通来源复核、排程启用／恢复、开始／继续／揭示／评分均不得绕过 `SOURCE_UPSTREAM_REVIEW_REQUIRED`。新增卡片来源和卡片改版也检查这一标志。
- 处理 B 仅解除对应采用影响，不清除卡片 gate、不恢复排程。用户仍须检查卡片参考和确切来源，明确复核，再显式恢复排程。旧卡仍绑定已变化的 B 旧正文时，原直接正文守卫继续生效。
- 标准审阅的直接来源账本追加 `KNOWLEDGE_UPSTREAM_CHANGED`，前后均为目标当时当前知识版本与同一真实状态，不伪造正文差异。事件另存原采用版范围，只对不早于采用版的确切证据生效；采用前版本仍保留原资格。旧审阅及由其形成的受审观察保持适用的失效依据。新建／修订审阅不能选入仍待处理的知识版本。成长沿用来源资格查询，不重写旧证据。
- AI 新任务、再次授权、发送前、结果接纳与本地采用重新核对知识版本的待处理影响；未处理时不把该知识作为已就绪来源。既有任务还检查其创建基线后发生过的适用影响，包括已处理记录；处理不能让旧任务恢复有效。更正处理本身不调用模型、不恢复外发授权、不改变历史费用。
- 旧回忆评分按评分时固定卡版本的真实知识来源查询之后发生过的适用影响，包括已处理记录。知识处理、卡片复核与恢复排程不恢复旧评分的当前依据资格；原评分事实继续保留，不回写旧事件。

## 4. 接口与事务

新增路径使用 `/api/v1/lifecycle/knowledge`：

| 接口 | 语义 |
|---|---|
| `GET /{itemId}/revalidation-impacts` | `direction=SOURCE\|TARGET`，`state=PENDING\|ALL`，`limit=1..20`，可选 `cursor`；对象级历史目录，稳定时间／ID分页。 |
| `POST /{itemId}/revalidation-impacts/{impactId}/resolve` | 仅影响的目标知识可处理；原 owner 幂等命令，返回处理后的完整窄记录。 |

页回执包含 `itemId,direction,state,items,nextCursor`。影响记录包含 `id,revision,eventId,rootItemId,rootTitle,rootPreviousVersionId,rootCurrentVersionId,changeKind,sourceVersionId,taskId,targetItemId,targetTitle,targetVersionId,targetVersionNumber,createdAt,resolution`。`changeKind` 为 `BODY_CHANGED` 或 `ARCHIVED`。`sourceVersionId` 表示本跳实际输入版；多跳时须通过独立 lineage 接口核对所属知识，不能与根知识 ID 直接拼成来源链接。原 16 字段回执保持兼容。

`resolution` 为 null，或包含 `choice,reason,targetVersionId,targetRevision,decidedAt`。修订为 0 时待处理、1 时已处理；时间使用微秒 UTC。根事件的新旧版本与实际引用版本分开，归档事件的新旧指针可以相同。标题是显示元数据，不参与版本正确性的判断。

请求字段为 `expectedRevision,expectedTargetRevision,expectedTargetVersionId,choice,reason,confirmed`；拒绝未知字段、重复字段、错误类型、过大请求和非法标识。CSRF、会话、owner 锁、请求摘要、CAS、业务写入和幂等回执沿用现有基础设施。

新窄表保存根事件与采用影响，复合 owner 外键绑定真实知识版本、AI 采用决定和任务。按根知识、目标知识／版本、状态、时间／ID建索引。每次根事件与采用路径唯一，重复命令不追加影响。分页仅限制一次读取数量，不截断事务中的实际扇出；超时或任一登记失败回滚原知识变更。第八批的逐层展开按真实采用边去重，循环、自来源与不同版本范围的规则另见多跳契约。

### 4.1 时间与兼容边界

根事件时间须严格晚于同 owner 已有 AI 任务创建时间、回忆尝试开始时间、`RATE` 评分时间和先前根事件的最大值；相等或回拨返回 `409 KNOWLEDGE_REVALIDATION_CLOCK_CONFLICT`，回滚本次知识命令。只读取真实冻结点，不把本事务刚写入的 `INVALIDATE` 当成既有评分。该检查在 owner 写锁内执行，因此适用影响的事件时间严格晚于旧任务／旧评分基线，不能在处理影响后利用时钟回拨恢复旧资格。同 owner 不相关任务的未来时间也会阻止新的根事件；标题单改不进入该检查。四个 MAX 子查询的执行计划与规模成本须在服务器测量。

处理时间不得早于原影响时间，相等允许。自来源采用在目标发布之后才登记本次采用路径，不把建立路径的同一次发布追溯为该路径的更正；已存在的自来源路径照常参与后续事件。

V66 创建更正事件与采用影响表；V67 扩展审阅变更范围与约束；V68 扩展记忆来源历史原因。第七批累计基线为 OpenAPI 7.37.0，原 V1–V68 保持；第八批配套 V69 与 OpenAPI 7.38.0，增加独立逐跳回执，不修改原处理请求与成功回执形状。后端 DTO、前端严格校验及生成类型须配套；历史可空尾字段只用于兼容读取，不能作为当前门禁已经满足的证明。

审阅的动态资格回执新增 `BasisCheck.upstreamChangeCount` 和 `EvidenceCheck.firstUnreviewedUpstreamChange`。前者区分对象级上游事件与仍然失效的直接事件，后者绑定每条证据确切版本的适用上游事件；不同检查项引用同一知识的不同版本时分别判断。`DirectChange` 仍为八字段，标准历史快照、受审观察绑定及其固定摘要不扩字段。当前回忆管理 GET 使用严格 `MemoryCurrentRecallState`，来源复核 POST 沿用兼容历史尾字段的 `MemoryRecallState`；成功旧回执不能直接建立当前资格，须另行 GET。

前后端与新增迁移须配套部署。所有数据库执行、事务并发、HTTP、模型和视觉结果均待服务器；静态构建不替代验收。
