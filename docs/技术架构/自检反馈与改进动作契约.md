# 自检反馈与改进动作契约

日期／版本：2026-11-07 · v1.0。适用 S6 第一批。状态：静态检查与前后端构建通过，待服务器验收；实际证据见[开发记录](../开发记录/开发阶段与进度.md)。关联 [PRD](../需求文档/产品需求文档.md) REV-01–05、RET-05 与[评价契约](训练评价与证据报告契约.md)。本批完成确切提交、自检／外部意见、独立决定、有来源和验证条件的动作；空白复练、比较结论、面后记录及完整结束报告后续接续，不关闭 S6。

## 1. 入口与访问

- `/review` 是独立复盘工作区，支持训练历史、确切提交和动作列表。来源必须传入 `sessionId/questionId/answerId`，不以最新提交替换旧答。
- 打开包含个人参考的复盘上下文，复用训练 `evaluations/access` 的逐答案明确确认。确认不调用模型，不需要 AI 已配置；独立训练的后续辅助条件、提前反馈和已结束训练的曝光沿用既有规则。自检页面说明会同时打开原答、题目及个人参考。
- `/api/v1/review/**` 全部进入资料守卫；HTTP 入站、读响应发出前、幂等回执恢复前均校验。前端将 `/review` 纳入参考响应代次检查；跨场独立训练时遮挡且停止读取。
- 反馈和动作的原文只来自同 owner 的确切版本。新操作不得从客户端提交来源快照冒充已保存依据。读取失败、无记录、来源不可访问分别处理。

## 2. 自检与手工意见

- 来源类型为 `SELF_CHECK` 和 `EXTERNAL_FEEDBACK`；外部意见另填 `authorLabel`，是用户录入的称呼，不验证作者身份。AI 报告仍使用原有 AI 对象，不复制一份可编辑 AI 原报告。
- 每个反馈保存 `kind/authorLabel/dimension/coverage/observation/condition/basis/limitation/suggestion/citations`。观察 1–2000 码点；条件 0–1000；依据、局限、建议各 1–1000；称呼 0–120（外部意见必填，自检为空）。维度、coverage、引用结构复用评价契约；引用 0–6 个、quote 1–500 码点，UTF-16 半开区间逐字校验及代理对边界检查。MENTIONED 须有答案证据；NOT_MENTIONED 不得含答案引文且须有题面／条件／参考依据；UNCERTAIN 可无引用，局限必填。
- 首次保存为修订 1；修改追加不可变修订，最多 100 版。类型和外部作者身份可随新修订更正，历史保留；原答不变。每次修改携带 `expectedRevision`。
- 接受／争议／忽略绑定确切反馈修订，独立追加决定（每版本最多 20 次）；争议原因必填，原因最多 1000 码点，可写补充资料说明。新反馈版本没有继承旧决定，历史版仍可查看或决定。无决定为待处理，不代表缺陷。
- 动作可引用待处理或任何已决定的反馈；创建动作是单独的用户操作，不强制接受、不改变反馈可信等级。

## 3. 改进动作与合并

- 动作有 `id/revision/title/detail/status/mergedInto/createdAt/updatedAt`；标题 1–200、说明 0–2000 码点。状态本批只开放 `OPEN` 和 `MERGED`；不提供手工完成或提升结论。
- 一条动作创建时选择 1–10 个来源，合并后总数最多 20。每来源有稳定 `id`、`originActionId`、确切提交三元组、反馈身份与修订、采用时用户决定、服务器保存的观察快照，以及独立 `verification`（1–2000 码点）、`tracking`（TRACKING／DROPPED）、`trackingReason`（0–1000，DROPPED 必填）。
- 人工来源用 `feedbackId + feedbackRevision`；AI 来源用 `taskId + observationId`，限定 SUCCEEDED 的 ANSWER_EVALUATION 及报告内真实反馈。来源 kind 为 MANUAL 或 AI_EVALUATION，请求无关身份字段必须为 null。创建携带 `expectedDecisionRevision`（无决定为 0），防止跨标签变化后误认当时决定。选择人工历史版本是明确操作，不自动换当前版。
- 来源快照包含原观察与其身份，不复制整份答案／参考；展示原文通过确切上下文读取。人工来源保留类型和作者称呼；AI 来源始终标为 AI_UNREVIEWED。后续反馈改写或改判不修改动作采用时快照，可回看来源当前记录。
- 本批允许编辑动作描述和来源验证条件、来源级停止／恢复跟踪，记录完整动作历史。不再追踪不是完成；恢复不删除历史。所有编辑带动作 expectedRevision，同一修订下的来源内容作为整体并发边界。
- 合并请求包含目标和被合并动作的 expectedRevision，每次合并一个 OPEN 动作到另一个 OPEN 动作。owner 锁事务内校验两端、容量和状态，移动全部来源的归属，保留原来源 ID、originActionId、验证条件、跟踪状态及历史；源动作标 MERGED 并保存去向，目标和源均追加历史。禁止自合并、合并已合并动作。
- 同一反馈允许在不同动作中具有不同验证条件；合并时这些来源实例全部保留，不按题号或反馈身份吞掉其中一份。新建动作内不接受同一反馈修订重复选择。
- 后续复练将保存所选来源 ID 和当时验证条件，逐来源判断已处理／部分／未处理／无法判断；本批没有对应判断 API，不用普通准备任务完成替代。

## 4. API 与存储

前缀 `/api/v1/review`，写入均要求 Idempotency-Key，原请求摘要、owner 锁、CAS、业务变化和回执同事务。响应丢失恢复原键；异常或双标签冲突保留输入，不自动采纳服务器内容。UUID 小写标准格式、整数修订、JSON 字段与枚举严格校验。

| 方法／路径 | 输入 → 输出 |
|---|---|
| GET `/context?sessionId=&questionId=&answerId=` | → 既有 AiEvaluationInput；必须已有对应访问确认 |
| GET `/feedback?sessionId=&questionId=&answerId=&cursor=&limit=` | → ReviewFeedbackPage（当前版本摘要）；三元组全部必填，limit 1–50 |
| POST `/feedback` | ReviewCreateFeedback → ReviewFeedback（201） |
| GET `/feedback/{id}?revision=` | → ReviewFeedback；省略为当前版，含该版本决定历史 |
| PUT `/feedback/{id}` | ReviewSaveFeedback → ReviewFeedback；追加修订 |
| GET `/feedback/{id}/history?before=&limit=` | → ReviewFeedbackHistoryPage；修订倒序 |
| POST `/feedback/{id}/decisions` | ReviewDecideFeedback（feedbackRevision、expectedRevision、choice、reason）→ ReviewFeedback |
| GET `/actions?status=&cursor=&limit=` | → ReviewActionPage（摘要，不展开全部来源），limit 1–50 |
| POST `/actions` | ReviewCreateAction（title、detail、sources）→ ReviewAction（201） |
| GET `/actions/{id}` | → ReviewAction（含全部来源） |
| PUT `/actions/{id}` | ReviewSaveAction（expectedRevision、title、detail）→ ReviewAction |
| PUT `/actions/{id}/sources/{sourceId}` | ReviewSaveSource（expectedRevision、verification、tracking、trackingReason）→ ReviewAction |
| POST `/actions/{id}/merge` | ReviewMergeAction（expectedRevision、sourceActionId、sourceExpectedRevision）→ ReviewAction（目标） |
| GET `/actions/{id}/history?before=&limit=` | → ReviewActionHistoryPage（动作快照）；limit 1–20 |

新增 V28：feedback 实体、不可变 feedback_revision、feedback_decision、action、action_source、action_history 六表；owner 复合外键关联确切 training_answer、反馈版本、AI task。AI 反馈 ID 由业务核对所属报告，不能因 task 存在就接受任意反馈编号。源动作合并后不删除，来源 originActionId 不改变；历史快照保存编辑／跟踪／合并前后可追踪版本。动作修订从 0 起，最多 1000；容量错误不提交部分变更。无新增依赖或模型用途。

专用错误：404 `REVIEW_NOT_FOUND`；409 `REVIEW_REVISION_CONFLICT`、`REVIEW_DECISION_CONFLICT`、`REVIEW_ACTION_MERGED`；422 `REVIEW_LIMIT`、`REVIEW_EVIDENCE_INVALID`；请求类型／字段 400 `INVALID_REQUEST`。访问错误沿用训练／评价既有码。
