## 1. 源码与检查边界

- `frontend/`：Vue 工作区和静态构建，API 类型由本地 OpenAPI 生成。
- `backend/`：Java 21／Spring MVC／MyBatis，代码按 `common/security/knowledge/search/recent/graph/board/prepare/material/schedule/planning/bank/training/ai/review/memory/today/growth` 分包。
- `backend/src/main/resources/db/migration/`：不可随意改写已应用版本的 Flyway SQL 迁移。
- `design/`：历史独立原型，不混入真实业务存储或正式源码。

执行约束以[AGENTS.md](../../AGENTS.md)为准。检查前先阅读 `frontend/package.json`、`backend/pom.xml` 与引用脚本，确认只有类型、生成和构建动作。禁止启动任何本地前端／后端／静态预览服务，不生成或执行单元测试。

## 2. 本地构建

以下为构建方式，具体执行结果在开发记录维护。每条命令使用 PowerShell 7，工作目录明确设为相应已存在的绝对目录，检查 `$LASTEXITCODE`。依赖缓存写在本仓库 `.cache/`，不检查或输出用户级私服／认证配置。不要执行 `clean` 或任何目录清理。

前端：依赖安装须先确认不会 prune 既有目录；`npm install` 也可能自动删除不再声明的包，`--ignore-scripts` 只关闭生命周期脚本，不能保证无删除。S2 已发生一次自动 prune，影响与处置记录在开发记录，当前停止后续安装。不要使用会先清空既有依赖目录的 `npm ci`。使用现有依赖运行 `npm run generate:api`、`npm run typecheck`、`npm run build`。未来新增依赖应先明确独立安装位置及无清理方案，并使用项目公开 registry 配置与项目缓存，不盲目启用全部脚本。

Vite 配置固定 `emptyOutDir:false`，避免构建隐式清空目录；重复构建会留下旧哈希文件。服务器发布阶段必须提供本次制品清单或使用新的独立构建输出目录，不能把 dist 的全部历史文件直接当作当前版本；本机不执行清理命令。

后端：在 `backend/` 下使用以下参数执行已审查的编译／打包插件，不启动应用、不连接数据库：

```powershell
mvn -s maven-settings.xml -gs maven-settings.xml '-Dmaven.repo.local=C:\AI\vibecoding\interview-studio\.cache\maven' '-Dmaven.test.skip=true' package
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
```

首次构建需要联网取得公开制品。`package-lock.json` 固定前端依赖；Maven 的 Boot BOM 和显式版本固定后端直接／管理依赖，实际依赖树与编译结果需记录。不要把两种机制都简称为“所有运行依赖已验证”。构建成功只证明当前工具链可处理代码。

## 3. 服务器配置契约

以下仅列配置键与用途，不含实际配置值。用户部署时通过服务器受控环境提供；Agent 不自动读取或设置真实凭据。

| 配置 | 用途与约束 |
|---|---|
| STUDIO_OWNER_ID | 稳定 UUID；表示唯一用户的数据归属，初始化后保持不变 |
| STUDIO_ADMIN_USERNAME | 登录名；没有默认账号或公开注册 |
| STUDIO_ADMIN_PASSWORD_HASH | BCrypt 哈希（成本 10–14）；不保存明文或提供默认密码，缺失／非法时拒绝启动 |
| STUDIO_DATABASE_URL | MySQL 8.4 JDBC 地址；数据库、主机和 TLS 配置由服务器环境提供 |
| STUDIO_DATABASE_USERNAME | 应用数据库账号；与迁移账号的权限分离在部署时落实 |
| STUDIO_DATABASE_PASSWORD | 运行环境注入的数据库凭据，不进入仓库、命令输出或文档 |
| STUDIO_HTTP_PORT | 应用内部监听端口，默认 8080；不构成本地启动授权 |
| STUDIO_SEARCH_ENABLED | 默认 false；服务器显式设为 true 才执行索引后台任务；关闭时 API 返回 DISABLED，标题列表仍可使用 |
| STUDIO_SEARCH_DIRECTORY | 启用检索时指定服务器可写绝对目录；不接受符号链接根／代际目录，不进入公开仓库；旧代目录不会自动清理 |
| STUDIO_MATERIAL_ENABLED | 默认 false；服务器显式启用附件域及上传租约恢复任务 |
| STUDIO_MATERIAL_DIRECTORY | 附件启用时必须提供已存在、可写、绝对且由运行账号独占写入的私有目录；逐段拒绝符号链接，不使用原文件名拼路径 |
| STUDIO_MATERIAL_PARSER_ENABLED | 默认 false；启用后才接受并消费解析任务，使用同一可执行 JAR 的独立 ParserMain |
| STUDIO_MATERIAL_QUOTA_BYTES | 默认 1073741824（1 GiB）；范围 20 MiB 至 JS 安全整数；所有上传尝试和解析执行保守预留，失败／旧结果继续计入 |
| STUDIO_AI_ENABLED | 默认 false；关闭时拒绝新外发，但继续将旧进程未决记录恢复为未发送失败或未知 |
| STUDIO_AI_PROTOCOL | 默认 CHAT_COMPLETIONS；可选 RESPONSES，协议变化须递增配置修订、重新预览授权 |
| STUDIO_AI_PROVIDER／STUDIO_AI_MODEL | 供应商显示名与确切模型标识，无预设值；实际支持需服务器核对 |
| STUDIO_AI_ENDPOINT | 对应协议的完整 HTTPS 地址，无 userinfo／query／fragment；不自动拼接路径，不跟随重定向或失败切换协议 |
| STUDIO_AI_API_KEY | 仅由本应用服务器环境注入；不进入公开配置、日志、清单或前端表单，不读取其他应用认证文件 |
| STUDIO_AI_CONFIG_VERSION／STUDIO_AI_PRICE_VERSION | 必填公开修订标识；换端点／协议／模型／密钥或价格时更新对应修订，旧任务不能默用新配置 |
| STUDIO_AI_CURRENCY | 必填三位大写币种；不同币种的未结费用或当日支出会阻止新发送，不自动换算 |
| STUDIO_AI_INPUT_PRICE_MICROS_PER_MILLION／STUDIO_AI_OUTPUT_PRICE_MICROS_PER_MILLION | 每百万输入／输出 token 的整数微单位单价；缺省 -1 表示未配置，可明确配置 0；按固定单价估算，不推断缓存折扣或账单 |
| STUDIO_AI_DAILY_BUDGET_MICROS | 默认 0（不可发送），启用需正整数微单位；UTC 日，未知预留跨日期占用，金额最大 JS 安全整数 |
| STUDIO_AI_MAX_OUTPUT_TOKENS | 默认 1024；范围 1–16384，部署时须同时满足供应商上限 |
| STUDIO_AI_TIMEOUT_SECONDS | 默认 60；范围 1–120，覆盖完整响应体等待；HTTP 连接独立上限 10 秒 |
| STUDIO_AI_MAX_TOKENS_FIELD | Chat Completions 默认 max_tokens，可改 max_completion_tokens；Responses 固定使用 max_output_tokens，此配置对其无效 |
| STUDIO_AI_JSON_MODE | 默认 false；开启后 Chat Completions 使用 response_format.type=json_object，Responses 使用 text.format.type=json_object；部署时先核对供应商支持 |
| STUDIO_AI_STREAMING | 默认 false；开启后两协议接收暂态增量，Configuration 追加 streaming:true 并纳入清单／授权指纹，需重新预览；关闭时省略新字段，保留旧摘要。真实流式及用量兼容待服务器核对，不自动降级重发 |

前端与 `/api/v1` 通过同源 HTTPS 提供。Session Cookie 为 Secure、HttpOnly、SameSite=Lax；服务器必须支持 HTTPS。反向代理不得让外部直接绕过同源策略访问内部管理端点，不能因使用代理而盲目信任任意转发头。

数据库连接使用 UTC。应用禁用自动 SQL 初始化与 Flyway 启动迁移；用户的服务器发布流程必须先用匹配版本的 Flyway 显式应用迁移、验证成功，再启动业务应用。MySQL DDL 不能假设完整事务回滚；发布前需约定备份与失败恢复。本阶段不生成生产发布脚本，不操作服务器。
