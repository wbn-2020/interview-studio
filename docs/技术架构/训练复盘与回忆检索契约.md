# 训练、复盘与回忆检索契约

版本：v1.1 · 2026-11-11。状态：统一检索第二批静态检查通过待服务器验收，本批接口引入于 OpenAPI 7.27.0。适用范围：正式训练提交、获准人工反馈及面后回忆的只读搜索；沿用[统一检索第一批契约](跨模块统一检索契约.md)的字面候选、分页、原文坐标、错误及普通资料守卫，当前AI扩展见[第三批契约](AI评价观察检索契约.md)，实际进度见[开发阶段与进度](../开发记录/开发阶段与进度.md)。

## 1. 来源与身份

统一接口增加 TRAINING_ANSWER、REVIEW_FEEDBACK、RECOLLECTION。每次只查询一个域，不混排或提供精确总数，继续采用有界字面候选、白名单原文回验和确切来源查看，不调用模型、不创建曝光／访问许可或 AI 外发授权。

| 域 | id／versionId／versionNumber | status／currentVersion | 正文白名单 |
|---|---|---|---|
| TRAINING_ANSWER | id=answerId，versionId=answerId，versionNumber=该题正式提交编号；没有为提交创建另一个版本 UUID | SUBMITTED；currentVersion 表示是否仍为该题最新提交，不改变旧提交内容 | text、diagram.nodes[].label／description、diagram.edges[].label |
| REVIEW_FEEDBACK | id=feedbackId，versionId=feedbackId，versionNumber=明确的反馈修订号；确切身份必须同时包含修订号 | RECORDED；currentVersion 表示该修订是否为反馈当前修订 | observation／condition／basis／limitation／suggestion |
| RECOLLECTION | id=回忆对象 ID，versionId=真实回忆版本 ID，versionNumber=版本号 | ACTIVE／ARCHIVED；currentVersion 比较当前版本指针 | title／question／conditions／answerFragment／feedback／uncertainty／gap |

TRAINING_ANSWER 查询所有本人正式提交，包含当前较早提交；没有答案草稿或未提交画布。题目标题仅用于识别，不搜索题面或将题目参考并入答案。图字段按数组位置投影为 diagram.nodes.0.label 等，保留原始文字；结构 ID、坐标、reference、boardSource 及导入引用不参与搜索或返回。图结构请回原提交查看，不把平铺文本说成完整图形。

REVIEW_FEEDBACK 只检索每条反馈的当前修订；历史详情必须明确指定确切旧修订。类型保留 SELF_CHECK／EXTERNAL_FEEDBACK、作者称呼只是用户录入信息，不认证身份。citations 可能包含参考／检查项引文，本批不搜索、不返回；完整引用回原评价页查看。不搜索当前决定的理由，也不把决定混进反馈正文坐标。

RECOLLECTION 仅有 RECOLLECTION／NONE 两种基线；NONE 的回答回忆片段为空，uncertainty 始终完整保留。它不能变成正式回答、独立表现或已核实外部反馈；旧作答模式、计时和辅助条件未知，保存时间不代表面试作答时间。不搜索 interview_json、安排正文或结构关联 ID。

训练回答和人工反馈没有归档字段，ARCHIVED 查询返回 applicable=false 空页；ENDED 不是 ARCHIVED。回忆仍按 ACTIVE／ARCHIVED 筛选。训练和反馈可读集合仅限 RUNNING／PAUSED／ENDED 会话，当前独立训练未确认资料查阅时普通资料守卫优先阻断整个搜索。

## 2. 作答条件与反馈访问

Hit 增加三个可选尾字段 training／feedback／recollection；不适用时省略，旧四域的响应形状保持。TRAINING_ANSWER 必须有 training，REVIEW_FEEDBACK 必须有 training 和 feedback，RECOLLECTION 必须有 recollection。

- training={answer,sessionStatus,feedbackTiming,conditions}。answer 为确切 sessionId／questionId／answerId。conditions 使用现有安全 RecordedAnswerConditions Java 类型的窄投影，包含 mode、answerCondition、assistanceEventSequence、priorExposure、questionKind、answerNumber、answerCreatedAt、technology、scenario、questionConditions；不含背景、完整题面、标准正文或图引用。新机器契约使用独立 UnifiedSearchAnswerConditions，允许 MAIN／FOLLOW_UP／REPLAY，不扩大原受审观察仅 MAIN／REPLAY 的资格。
- 提交条件和曝光来自当次训练提交，技术／场景／条件来自该训练题固定快照，不能用会话当前 materialAccess 重算。BEFORE_ASSISTANCE 仍可能有编写、看参考或评价的先前曝光，不能称为从未见过。mode、条件与辅助事件序列的相容性、编号、时间及曝光数须静态规则和服务器运行共同核验。
- feedback={kind,authorLabel,dimension,coverage,condition,basis,limitation,decision}。condition／basis／limitation 在列表和详情均完整保留，决定为所选反馈修订当前最新的独立决定或 null；不把用户接受视为技术认证，NOT_MENTIONED 表示可能未提及，不等于错误或能力缺陷。详情 fields 仍完整返回五个白名单字段。
- recollection={baselineKind,questionType,uncertainty}。列表与详情均显式显示个人回忆身份、有回答回忆片段／无旧答，以及完整不确定性。正文同名 uncertainty 不改写。

正式回答可按原训练读取规则查看，不要求评价区访问；全局搜索仍需要普通资料读取条件。人工反馈另要求精确 owner／session／question／answer 的 ai_evaluation_access，不能只按 owner、会话或题目检查。

SQL 在匹配反馈正文前先限制精确访问四元组、有效会话状态、模式与答案条件、有效反馈时机和提前查看标记：未结束且 AFTER_SESSION 时 early_feedback 必须为真。不存在访问记录的反馈不进入候选、摘要、额外命中、分页和扫描上限计数，不返回隐藏数量。不得先读全库反馈正文再逐条过滤。

来源投影及返回正文前复用 ReviewDraftSources.requireAnswerAccess，在调用方短事务中重新核对精确身份、当次条件、访问时间和提前反馈确认。不能复用 readFeedbackSource 读取历史，因为它会要求当前修订；本批读取指定修订后另做白名单投影。普通 TrainingReadAdvice 继续核全局资料条件，新增搜索专用返回检查对反馈来源再次复核，不调用 grantAccess，不写授权或曝光事件。

当前访问表是追加记录，尚无撤回流程；本批不声称实现 S8 的对象用途撤回或最新独立账本。返回前复核与实际网络发送仍有时间窗口，不承诺远端已收到的数据可被收回。

## 3. API 与分页兼容

继续使用两个 GET，不新建写命令：

```text
GET /api/v1/search?domain=REVIEW_FEEDBACK&q=缓存&status=ACTIVE&offset=0&limit=20
GET /api/v1/search/sources/REVIEW_FEEDBACK/{feedbackId}?versionId={feedbackId}&revision=3&q=缓存
```

详情新增可选 revision 整数参数：仅 REVIEW_FEEDBACK 必填，范围 1–100，且 versionId 必须等于 id。该域禁止省略修订后回退最新版；其他域传 revision 返回 400。原四域详情请求保持原语义。前端反馈选中键、请求参数、回执身份和迟到响应校验必须包含修订号；不能仅凭两个相同 UUID 认定同版。

q／status／limit／offset 的既有验证不变。新三域按稳定对象／提交 ID 降序，单批最多 100、累计最多 4096，offset 按最终可见匹配计数，额外有效命中才 hasMore，分页上限 1000。不改变第一批知识分词及旧数据库回验。候选所有 SELECT 为 5 秒超时，编排事务 20 秒；限制候选数不代表限制数据库实际扫描行数，SQL 计划及字符比较仍待服务器验证。

匹配和详情使用同一白名单字段；命中片段、UTF-16 半开区间、完整代理对及 CRLF／CR／LF 行号沿第一批。必要条件单独显示，不自动参与正文匹配或成为证据选区。损坏来源返回 SEARCH_SOURCE_INVALID，不静默丢弃整批中的记录导致提前结束分页。缺身份／修订／权属返回 SEARCH_SOURCE_NOT_FOUND；未满足原答评价访问沿原访问错误，不伪装为空正文。

## 4. 页面与恢复

搜索页增加三种来源，保留原四域查询方式。反馈范围始终固定提示“只检索已在复盘确认开放的人工反馈”，提供通用复盘入口；不根据隐藏匹配动态提示有多少未开放内容，不在搜索页复制评价授权写流程。

TRAINING_ANSWER 标签为正式提交编号；旧提交提示同题已有更新提交，不能说原文已被覆盖。反馈标签为明确 rN 修订；当前决定与旧正文分别呈现。回忆标签为个人回忆版本，始终显示不确定性。新增无归档域的空页说明按来源生成，不能继续使用固定“资料摘录”文案。

会话、资料、列表／详情请求代次、查询和所选身份变化继续拒绝迟到响应并清正文；反馈身份还包含修订号。恢复后主动重新查询，不把隐藏页面当成查询已停止；不进入持久存储或 Query 正文缓存。条件及限定使用普通文本展示，不使用 v-html。

| 来源 | 确切回链 |
|---|---|
| 正式回答 | training：item=sessionId、question=questionId、answer=answerId |
| 人工反馈 | review：sessionId、questionId、answerId、feedbackId、feedbackRevision |
| 面后回忆 | recollections：item=recollectionId、versionId |

继续经过既有路由保稿守卫和原模块访问确认；原模块尚无通用 offset 高亮，不宣称跳转后按搜索区间自动高亮。查看反馈不改变回答的历史条件，搜索不创建复练、回忆或训练完成记录。
