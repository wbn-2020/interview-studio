# 知识采用准备来源历史核对契约

版本：v1.1 · 2026-11-12。状态：代码完成待验证；独立静态复核、最终后端打包与正式业务入口专项检查通过，完整前端构建仍受独立参考界面缺四组件阻塞。本契约只补充既有采用来源目录的历史代次核对，不新增事件、影响表或处理接口。实际实施与检查证据见[开发阶段与进度](../开发记录/开发阶段与进度.md)。

## 1. 目的与边界

S8 第十批开始登记准备来源更正事件以前，已经采用的知识／题目任务仍需要在查看来源时判断其固定授权代次是否已经落后。该核对不能把过去没有登记的变化补造成事件，也不能把当前状态重新写入旧 Manifest、候选、采用决定或回执。

本批复用现有 `AiService` 的采用历史分页、`ai_task.manifest_json`、`ai_preparation_source` 和 `PreparationSources.check`：

- 不增加数据库表、迁移、HTTP 路径或响应字段；
- 不产生 `preparation_knowledge_event`、`preparation_knowledge_impact` 或知识更正影响；
- 不改变采用门禁、回忆卡 gate、审阅资格、评分历史或旧任务状态；
- 只在知识／题目采用历史的准备来源，以及表达生成采用历史的事实来源中显示当前核对结果。

## 2. 固定来源核对

每条采用历史先按现有规则核对 Manifest 结构、来源顺序、`ai_preparation_source` 的身份／版本／版本号／标题／类型和数量；含准备来源的知识／题目任务及表达生成任务还按原专用规则核对用途与检查快照。

- 检查快照缺失、绑定缺失、额外绑定、顺序错位或固定字段不一致，视为历史结构完整性错误；
- 不能把结构损坏降级成 `UNAVAILABLE` 或 `REVIEW_REQUIRED`，也不能继续展示一个未经核对的来源；
- 旧任务中没有准备来源字段的纯知识任务继续按原兼容规则读取，不补造准备授权。

来源目录保留原历史读取及摘要协议。本批不校验通用目录的持久 `manifest_hash`，不以当前 Manifest 形状重算早期清单摘要；原 17／19／20 字段清单等历史摘要兼容核验仍是后续事项。旧 JSON、摘要与回执保持。

## 3. 代次状态

对固定 `TARGET`、`PROJECT`、`FACT` 或 `EXPRESSION` 来源，读取当前确切版本的 `SourceCheck`，并与 Manifest 中保存的 `preparationChecks`／`expressionChecks` 比较。

| 当前读取结果 | 历史来源显示 |
|---|---|
| 直接 TARGET／PROJECT／FACT 当前状态不是 `CURRENT` | 保留当前明确状态，例如 `SUPERSEDED`、`ARCHIVED`、`WITHDRAWN`、`PROJECT_ARCHIVED`、`UNVERIFIED` 或 `UNAVAILABLE` |
| 当前状态为 `CURRENT`，固定来源代次不一致 | `REVIEW_REQUIRED` |
| 当前状态为 `CURRENT`，身份、版本和来源代次均与固定检查一致 | `CURRENT` |

`FACT` 必须同时比较事实自身 `sourceGeneration` 和所属项目 `projectGeneration`。`EXPRESSION` 的事实依据按表达 Manifest 中的固定顺序逐项比较；表达来源已有的整组 `expressionChecks` 规则继续生效。当前再次匹配只代表“当前核对与固定基线一致”，不代表系统能够证明接入前没有发生过改后改回。

固定检查与来源绑定的身份不一致属于结构错误，不能降级成待复核。表达自身为 `UNVERIFIED` 时沿用原规则显示 `REVIEW_REQUIRED`，其他非 `CURRENT` 表达状态原样保留。

代次不一致只改变来源目录显示，不自动创建影响、不自动恢复授权、不自动改变历史正文。用户需要处理更正时，使用现有来源更正／复核流程；本批不为接入前差异补造可处理记录。

## 4. 采用范围

本批覆盖：

- 知识采用历史中的 `KNOWLEDGE_DRAFT`；
- 题目采用历史中的 `QUESTION_DRAFT`；
- 两类任务中的直接准备来源和表达固定事实依据；
- 表达生成采用历史 `EXPRESSION_DRAFT` 中的固定 FACT 来源，比较当时事实及项目代次。

JD 要求、事实候选、回忆卡、关系候选、资料摘录和训练片段继续使用各自契约的来源读取规则，不在本批扩大统一状态模型。材料、删除、回收站、墓碑、文件交换、备份恢复和全量更正传播仍由 S8 后续批次处理。

## 5. 待服务器验收

以下场景全部未执行：

| 编号 | 场景与预期 |
|---|---|
| PHS-01 | 旧采用任务的固定 TARGET／PROJECT／FACT 仍为当前版本且代次相同，目录显示 `CURRENT`。 |
| PHS-02 | 来源同版归档／恢复或事实撤回／重确认，当前状态重新为 `CURRENT` 但代次不同，目录显示 `REVIEW_REQUIRED`。 |
| PHS-03 | FACT 的所属项目改版、归档后恢复或代次变化，事实状态仍可读时按 `projectGeneration` 显示 `REVIEW_REQUIRED`。 |
| PHS-04 | 当前来源已改版、归档、撤回、未核实或项目不可用时，保留对应明确状态，不覆盖成 `REVIEW_REQUIRED`。 |
| PHS-05 | 固定 EXPRESSION 的任一事实依据代次变化，知识／题目采用来源显示 `REVIEW_REQUIRED`；当前表达自身规则仍逐项生效。 |
| PHS-06 | 准备检查快照、来源绑定、顺序或固定元数据异常时，查询失败并暴露结构错误，不伪装为来源不可用。 |
| PHS-07 | 纯知识旧任务无准备检查字段时仍按旧兼容规则读取，不凭空增加准备来源。 |
| PHS-08 | 分页、确切历史版本跳转、跨 owner 和资料访问守卫保持现有行为；不写入事件、影响或处理记录。 |
| PHS-09 | 表达生成采用历史的固定 FACT 自身或父项目代次变化后，显示 `REVIEW_REQUIRED` 并能跳到原事实版本；非 FACT 来源仍拒绝。 |

数据库、HTTP 并发、真实旧数据、前端交互、性能和视觉验收由用户部署服务器后执行。

## 6. 静态交付说明

本批最终后端仅修改 `AiService`，`AiRows`、`AiMapper`、`AiSources` 及 V1–V71 原文与第十批冻结输入一致。前端复用既有状态，只泛化待复核文案、允许表达生成的 FACT 待复核状态跳转到原版本，并在三个来源面板说明历史覆盖与授权边界。

累计 OpenAPI 7.40.1 只改变版本号及两处来源状态说明；路径、枚举、响应形状保持，生成类型与当前规格逐字节一致。后端最终 `package` 通过，测试源码编译与测试执行均跳过；正式业务入口的类型检查及打包通过，不能代替完整前端或服务器验收。PHS-01–09 全部未执行。
