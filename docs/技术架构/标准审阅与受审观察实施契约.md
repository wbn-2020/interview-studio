## 2. 业务含义与不变量

`StandardReview` 记录“某位被说明的审阅者，在某日期、限定范围及条件下，对这份确切题目标准的若干检查项作过什么审阅，有什么可追溯记录”。录入者是本人的工作区用户；审核人说明和证据真实性是用户提供的信息，平台不认证身份、资质、技术语义或审阅真的发生过。只有技术文章、自己勾选已审、AI 建议或接受反馈，没有实际审阅记录时，继续使用原个人／未审路径。

`ReviewedObservation` 记录“某次确切提交，在某一确切审阅修订所支持的某检查项及条件下，有哪些原文或未提及情况，记录者作了什么结论”。一条观察只针对一个 checkpoint；多项观察分别保存，避免某项失效使整份答卷被误称全部通过。它不等于真实生产能力、岗位整体胜任或平台认证。

固定身份与变化规则：

- StandardReview 的 questionId／questionVersionId 创建后不可改；一个题目版本可有多份真实审阅记录。不同审阅者、不同范围或相反意见不自动合并成统一结论。
- ReviewedObservation 的 answer 三元身份和 checkpointId 创建后不可改。编辑可以明确选择同一题目版本、同一 checkpoint 的另一份有效审阅修订，生成新的观察修订；旧观察仍指原审阅。
- `revision` 从0开始，所有新对象、来源变更号和历史序号为 `0..9007199254740991` 的安全整数；增加前核上限。不得沿用旧 feedback 的1–100上限当作新对象规则。
- 状态只有 `ACTIVE|WITHDRAWN`，ACTIVE 表示这条记录未撤回，不等于所有检查项均支持或当前有效。撤回必须有理由，追加修订；WITHDRAWN 为终态，不提供恢复开关。新的实际审阅或观察可另建记录，原记录继续可追溯。
- 不物理删除记录、历史、已引用题目版本、答案或来源。未来 S8 的删除／脱敏规则需要显式联动本域，不能绕过当前外键或仅删当前行。
- 编辑与撤回不修改训练快照、旧参考、答案、AI 报告、自检、动作判断、卡片排程或目标覆盖判断。

例：题库“缓存双写一致性”v3有检查项K。用户录入审阅者给出的审阅邮件摘录，以及该审阅引用的知识版本／文档，结论只支持“允许短暂不一致、异步重试有幂等”场景。之后对训练答案A17创建K的观察，引用A17的具体句子。答案遗漏补偿逻辑可记 `NOT_MENTIONED + INSUFFICIENT`，不能补造一句不存在的回答。题目v4更正标准或该知识正文更正后，A17与原观察保留，当前观察标待复核；下一次复练的新答另有 answerId。

## 4. 审阅内容与来源校验

### 4.1 范围和真实审阅记录

- 审阅问题及版本须为本人存在的题目与版本，题目当前 ACTIVE。允许对已被新版替代的确切旧版本补录真实审阅，但必须明确显示“审阅旧版本”，当前 head／直接变更号进入基线，绝不应用到新版本。
- checkpoints 为1–30项不同 checkpointId，必须是确切版本中的原检查项，顺序是该版本 checkpoint 顺序的子序列。没有 checkpoint 的旧标准不能凭此接口临时造检查项，应在题库正常编辑生成新版。
- reviewer.label 1–120码点、description 1–2000；reviewContext 1–2000；每项 conditions／conclusion／limitations 各1–2000；总 limitations 1–2000。不能只填“已审核”作为结构上唯一的审阅内容；仍须下述完整证据链。平台不会靠关键词认证这些文字的语义。
- 每项 evidenceIds 为1–12个不同引用，须全部存在于本次 evidence；其 roles 并集同时包含 REVIEW_RECORD 和 TECHNICAL_BASIS。每条 evidence 至少被一项使用，最多12条；同 kind＋确切来源＋区间／外部定位不得重复建不同 id。角色有重叠时用同一条的 roles 表达。
- REVIEW_RECORD 的 provenanceNote 必须说明该次真实审阅如何取得、记录位置及与所声明审核人／范围的关系；纯技术资料不能在产品文案中当作“此人审核过”的证明。TECHNICAL_BASIS 的 useReason 说明为何支持或限制该检查项。两字段均1–2000码点。
- reviewedOn／capturedOn 均为1000–9999年合法日期，不晚于服务器在 reviewZoneId 下的当天；区域沿 PlanningRules 的 IANA／UTC 规则。reviewedOn 是用户记录的实际审阅日期，createdAt 是系统录入时间，不相互冒充；可能先有外部审阅、后有本地导入，不以审阅日期早于本地创建直接拒绝。
- 补录取得的是录入时的来源基线，不能据此推断审阅者已经看过之后发生的更正；用户仍须记录实际审阅对象、日期及限制。平台只展示该声明与结构检查，不把录入日期或新基线当作审阅真实性证明。
- 所有文字拒绝 NUL、孤立代理与纯空白必填，长度按 Unicode 码点；原字面值保留，不自动 strip／Unicode 归一化改变证据。数组不自动去重或排序掩盖无效请求。

### 4.2 知识与材料

知识 citation 必须精确属于 owner 的 NOTE／CONCEPT 发布版本；0≤start<end≤原版 body.length，边界不能切开代理对，quote 必须等于原文 UTF-16 子串，quote 为1–2000码点。创建／编辑时来源必须 ACTIVE。允许保留旧发布版，明确版本已替代及当前正文是否不同；不能改成 currentVersionId 再假称仍是原引文。草稿不是审阅依据版本。

材料 citation 复用 excerptId 与 UTF-16 子串，quote 同上。通过 MaterialSources 的真实摘录校验读取，1–12条证据中的不同 excerptId 最多5个，以符合现有服务边界；无需读取原文件或重新解析。保存附件 id／sha256 的服务端基线，MANUAL／PARSED 原性质在 UI 显示。新解析执行不改变旧摘录；附件描述变化也不能作为原文变更。附件配置未启用或数据库读取失败返回实际错误，不能降级为“无依据”。本域只检查已保存摘录和元数据，不声称磁盘文件本次已复核。

引用同一知识／附件多次时直接基线按对象去重，引用各自仍指确切版本／摘录／区间。外部用户输入不能将本人的另一个 sourceId 偷换进来源摘要。

### 4.3 外部依据的建议取舍

**主会话采纳 EXTERNAL_QUOTE，仅记录，不抓取。** 实际审阅可能在公开审阅记录、勘误、规范页面中；强制先生成一份知识全文会造成多余副本。ExternalQuote 必须同时提供 URL、标题、明确 locator、摘录 quote、capturedOn 与 sourceDescription；useReason／provenanceNote 仍必填。URL仅语法核验为含 host、无 userInfo／控制字符的 HTTP(S)，最多2000码点；标题1–200、locator1–500、quote1–2000、sourceDescription1–2000。UI 以普通外链打开，禁止自动抓取、预览脚本、URL转附件或跟随下载。

这个路径不能检测网站后来更正、验证摘录真的出自该页或证明审核人身份，固定显示 EXTERNAL_CONTENT_NOT_FETCHED。外部引文不伪造为 AiDtos.Citation，也没有平台已定位命中的标记。只有 URL 没有摘录／来源说明不能保存；用户发现更正时修订或撤回审阅。采用这一能力的理由是保留真实外部审阅的可追溯入口；其在线可用性与真实性始终未知，不能把自由文本作为等价已核内部引用。

## 5. 受审观察的资格和引文

预览和保存都先复用 `ReviewService.context`／`TrainingEvaluations` 的确切答案访问。answerId 必须来自已提交答案；草稿、回忆片段、仅题目、latestAnswer占位不能替代。题实例自身须满足：

1. MAIN 或有题库来源的 REPLAY，sourceQuestionId 与 sourceVersionId 同时非空；它们与 StandardReview.question 逐字段相等。
2. FOLLOW_UP 及无题库来源 REPLAY 拒绝 `OBSERVATION_STANDARD_MISMATCH`，不查询父问／根问标准，也不根据同标题／相似题意推断匹配。
3. 所选 StandardReview 必须 ACTIVE 且是当前最新 revision；所选 checkpoint 在该修订范围内且 decision=SUPPORTED_WITHIN_SCOPE，当前直接资格通过。历史审阅仍可读，但不能用于新增观察。
4. 条件里同时保留当时模式、辅助条件、历史曝光、题实例种类、确切技术／场景／题面条件及答案提交时间。审阅可以在答案之后发生，界面注明“事后审阅依据”，不谎称当时作答已有受审标准。

citations 为1–6条，复用 EvaluationCitation；本接口只允许 ANSWER_TEXT／ANSWER_NODE_LABEL／ANSWER_NODE_DESCRIPTION／ANSWER_EDGE_LABEL／CHECKPOINT。CHECKPOINT.elementId 必须等于对象 checkpointId，原文取确切题库版本的该检查项；至少一条 CHECKPOINT 引文。其余 elementId 与确切答案图节点／边逐项核对，文本字段 elementId=null。引用区间按现有 ReviewRules 的 UTF-16 与代理边界规则，quote1–500码点；同类型／元素／区间不得重复。不接受任意 REFERENCE 引文借整段参考突破受审范围。

| coverage | 必须满足 | 可用 conclusion |
|---|---|---|
| MENTIONED | 至少一条原答／原图文字引用，另有确切 CHECKPOINT 引文 | 四种均可；CONTRADICTS 仍是记录者的条件化判断 |
| NOT_MENTIONED | 只有检查项引文，无回答引文；statement 明确这是对确切提交文字和图中标签／说明的人工未提及观察 | 仅 INSUFFICIENT；不能把缺项转换为技术错误 |
| UNCERTAIN | 有检查项引文，可有相关原答引文；限制说明为何无法判断 | INSUFFICIENT 或 DISPUTED |

statement／conditions／limitations／observerDescription 各1–2000码点，必填。observedOn 同样限定1000–9999年合法日期，使用 observationZoneId 的当地日期，不早于答案 createdAt 所在当地日、不晚于服务器当前当地日；这只是时间一致性，不证明记录者实际何时阅读。原答可以部分辅助、处于学习模式或此前看过参考，不据此丢失观察，但不能改写为独立首次表现。

旧 SELF_CHECK／EXTERNAL_FEEDBACK、AI_UNREVIEWED、ACCEPTED／HANDLED 保持原对象和层级。可以在新表单中人工另写一条符合本契约的观察，但不增加“升级报告”或“一键认证”；新观察必须独立保存完整审阅引用和原答证据。AI 不创建或批准 StandardReview，也不自动发布 ReviewedObservation。

## 6. 当前资格与直接更正链

### 6.1 读取资格与不可变历史

StandardReviewSnapshot／ReviewedObservation 保存当时内容与基线；当前资格是同一读取快照中的独立投影，不能覆盖历史 snapshot.status／content／binding。`StandardEligibility` 对每个 checkpoint 单独给 eligible 与 reasons，`ObservationEligibility.eligibleAsReviewedObservation` 只是“当前可按这条受审链展示限定观察”，不表示 conclusion 为正向或能力已经掌握。

审阅检查项 eligible 的必要条件：查询修订仍为该记录最新修订、当前 ACTIVE、decision 为 SUPPORTED_WITHIN_SCOPE、确切题目 ACTIVE、所有该项 evidenceIds 的内部直接来源可用、它们与题目的直接变更号未越过该审阅基线。其他检查项引用的独立来源失效不拖累本项；题目自身更正影响全部范围。缺依据或 DISPUTED／INSUFFICIENT 的范围可以真实记录，但不能成为新增受审观察的依据。

观察 current eligible 还要求自身最新修订、ACTIVE、所指确切审阅仍满足上段条件、conclusion 不是 DISPUTED。CONTRADICTS／INSUFFICIENT 的有效观察仍是有限证据，不能自动统计为“掌握”。旧修订标 RECORD_REVISED；标准已编辑标 STANDARD_REVISED，撤回标 STANDARD_WITHDRAWN；不能因为新标准还支持同文字就替换观察引用。

### 6.2 直接来源变更号

建议新增 `review_basis_generation` 与追加式 `review_basis_change`。每个 owner＋DirectRef 一条当前变更号；不存在时为0。源写命令在同 owner 事务中实际变更后、提交前调用只依赖本域 Mapper 的 `ReviewedBasisInvalidation`，只增加该来源一个变更号并记事件。读路径不落库、不遍历所有被引用观察；审阅保存基线，观察读取沿审阅检查基线。这样一个来源改后改回仍有变更历史，无需给成百上千条观察另造编辑修订。

| 直接来源事件 | 推进规则 | 不推进的操作 |
|---|---|---|
| 题目新增发布版本 | QuestionService.save 成功产生新 question_version 后推进 QUESTION_VERSION_CHANGED；保守地要求旧范围重核，不比较技术语义 | 收藏、查参考、曝光；新建无历史依赖题目从0开始 |
| 题目归档／恢复 | 仅实际状态变化推进相应原因；即使恢复到同状态也不把已有旧基线重写 | 同状态请求无额外来源事件 |
| 知识发布 | 两个真实发布入口：publish 与 publishWithinCommand；原发布正文和新正文不同时推进 KNOWLEDGE_BODY_CHANGED | 草稿、主题、关系、布局；仅标题发布不推进 |
| 知识归档／恢复 | 实际变化均推进；恢复后 generation 仍大于旧基线 | 同状态请求 |
| 附件／摘录 | 当前 READY 原件及摘录不可替换，无正常内容编辑钩子；读取核固定摘要和执行链 | 附件描述、新解析、读取；不能拿临时磁盘故障制造内容更正事件 |
| 将来 S8 使附件失效／撤回／替换 | 必须在其真实命令中接 MATERIAL_BASIS_CHANGED；未接入前不开放会绕过受审链的删除／替换 | 不预先声称当前已有附件撤回能力 |

变更事件要保存 previous/current版本、状态、原因、generation、服务端时间；只有适用字段非空。新来源变更号与事件的插入、原源写、原回执一起成功或回滚；不得异步晚补导致更正后还能短暂看到旧的当前有效资格。变更号溢出或时钟早于该变更号行 updatedAt 时原命令整体失败，使用 `REVIEW_BASIS_LIMIT`／`REVIEW_CLOCK_CHANGED`，不饱和到最大值。

新增钩子不得改旧命令 operation、请求摘要或回执类型。没有发生 C3 直接语义事件时不落新记录。不得接成 KnowledgeService → StandardReviewService → KnowledgeService 的 Bean 环；钩子只写自身表，读取服务只依赖来源 Mapper／已有只读解析器。

### 6.3 重核与恢复

- 基线变更、归档后恢复、正文改回都保持 DIRECT_BASIS_CHANGED。只有追加新的真实审阅修订并保存其当前基线，才可让该审阅记录的新修订重新具备资格；旧观察仍指旧审阅并待复核，须人工编辑观察选择新修订。
- 当编辑是在清除已发生的直接变更时，不能只改理由或点“我已确认”。每个受影响且在新修订仍要记录为 SUPPORTED_WITHIN_SCOPE 的 checkpoint，其 REVIEW_RECORD 引用集合必须与原修订不同（来源版本／摘录身份、区间或外部定位／摘录实际不同），并提供对应的新审阅说明／日期；只改另一个检查项的证据不能解除本项失效。结构上没有新的审阅记录则返回 REVIEW_REREVIEW_EVIDENCE_REQUIRED。降为 DISPUTED／INSUFFICIENT 可以保留原记录与新的解释，但不能由此恢复当前支持资格。这仍只证明录入内容变化，不认证它是真的新审阅。
- 从 DISPUTED／INSUFFICIENT 改为 SUPPORTED_WITHIN_SCOPE 时，同样要求该项 REVIEW_RECORD 引用集合相较上一修订发生上述实际变化，并提供新的审阅说明／日期；不能先降级刷新基线、再仅切回支持状态来解除重核要求。
- 重新加入曾存在的checkpoint时，以同一StandardReview中该项最近一次出现的修订、决定及直接来源基线作为重核比较对象；若直接来源已变或该次决定为DISPUTED／INSUFFICIENT，仍须REVIEW_RECORD引用集合实际变化及新的审阅说明／日期。移出范围不清除重核义务；不能通过删除检查项再用原证据加回刷新基线。此前从未记录的检查项按新范围校验。
- 上述新审阅说明要求reviewContext或该项REVIEW_RECORD的provenanceNote实际变化，不能只改changeReason或日期；reviewedOn不得早于该检查项最近一次出现时的声明日期，同日真实重核允许相同日期。引用集合比较实际kind及知识版本／摘录身份／区间／原引文，或外部URL／定位／摘录；新REVIEW_RECORD至少有一处实际定位不在该检查项最近一次出现修订的任何角色证据集合中。只删除旧记录，或把原TECHNICAL_BASIS改成REVIEW_RECORD，不能算新审阅；只更换evidenceId、角色、标题、捕获日期或其他显示说明也不算新审阅记录。比较范围限于该检查项，不因其他检查项曾引用同一位置而阻止真实重核。
- 内容和有效来源基线都相同的保存返回原记录，不增修订、不写空历史；changeReason 单独不同不制造新观察／审阅。直接变更号越过旧基线而缺新审阅证据绝不能按同内容无操作成功。
- 知识仅标题发布可使当前 currentVersionId 改变；generation、正文 fingerprint 和 status 均未变时，不触发重核，不因这一展示元数据变化追加审阅修订或重写旧基线。最新来源事实仍参与预览摘要，因此跨该变化提交旧预览时须重新预览，但不要求补造新审阅证据。
- 意外缺失的已存直接关联返回不可用标记，跨 owner 的输入来源按404处理；数据库／解析器错误照常失败，不能统一 catch 成“没有依据”。附件功能被停用属于依赖不可读，返回明确错误或能力不可用，不能继续报告已完整检查。
- 只检查直接题目、显式知识／摘录、审阅修订、答案及引用。知识从事实／表达／AI 派生的更深依赖、外部网站后续变化尚未闭合，`lineageCheck=PARTIAL` 固定保留；GROW-02 的直接受审能力可以交付，S8 间接更正不能因此关闭。

## 7. HTTP、读写与曝光

建议新接口分在现有 bank／review 模块路径，自动受原资料模块守卫，不新建脱离守卫的标准模块。owner 只取登录上下文。所有写请求带原标准 UUID `Idempotency-Key`；预览不消耗键，`Cache-Control: no-store`。

| 方法／路径 | 请求与响应 | 规则 |
|---|---|---|
| GET `/api/v1/bank/standard-reviews?questionId=&versionId=&status=&cursor=&limit=` | StandardReviewPage | questionId／versionId 成对必填；status可空表示全部；摘要无正文／引文 |
| GET `/api/v1/bank/standard-reviews/{id}?revision=` | StandardReviewDetail | revision可空为当前；只返回摘要与当前资格，不含审核结论或来源摘录 |
| POST `/api/v1/bank/standard-reviews/preview` | StandardReviewDraft → StandardReviewPreview | id／expectedRevision 同空为新建，同非空为编辑；只读，使用本人的确切 REFERENCE_VIEW exposure |
| POST `/api/v1/bank/standard-reviews` | SaveStandardReview → 201 StandardReviewSnapshot | draft.id／expectedRevision 必须 null；重算 hash 后原子保存 |
| PUT `/api/v1/bank/standard-reviews/{id}` | SaveStandardReview → StandardReviewSnapshot | draft.id等于路径；完整替换可变内容，确切问题身份不变，CAS |
| POST `/api/v1/bank/standard-reviews/{id}/withdraw` | WithdrawRecord → StandardRevisionSummary | 只返回修订元数据；同键恢复原回执；已撤回的新键同内容请求在CAS通过后返回当前修订摘要，不再追加 |
| GET `/api/v1/bank/standard-reviews/{id}/history?before=&limit=` | StandardHistoryPage | 只列修订元数据；标准原文和审阅摘录不藏在普通历史 GET 中 |
| POST `/api/v1/bank/standard-reviews/{id}/open` | OpenStandardReview → OpenedStandardReview | 明确 exact revision；同事务记录确切题库版本 REFERENCE_VIEW 曝光，返回该审阅历史快照及修改理由；幂等恢复不重复曝光 |
| GET `/api/v1/review/observations?sessionId=&questionId=&answerId=&status=&cursor=&limit=` | ObservationPage | 三元答案必填，先检查原答案评价访问；无原文列表 |
| GET `/api/v1/review/observations/{id}?revision=` | ObservationDetail | 查询确切修订＋当前资格；每次复核原答案评价访问 |
| POST `/api/v1/review/observations/preview` | ObservationDraft → ObservationPreview | id／expectedRevision 同空或同非空；只读；核精确标准与所有引文 |
| POST `/api/v1/review/observations` | SaveObservation → 201 ReviewedObservation | 新建必须有通过的当前预览 |
| PUT `/api/v1/review/observations/{id}` | SaveObservation → ReviewedObservation | CAS、完整内容、固定 answer／checkpoint；重算当前链 |
| POST `/api/v1/review/observations/{id}/withdraw` | WithdrawRecord → ObservationHistory | 追加终态修订，来源失效不能阻止本人撤回历史记录 |
| GET `/api/v1/review/observations/{id}/history?before=&limit=` | ObservationHistoryPage | 确切历史，先检查答案访问，历史项不附假装当时的“当前资格” |

StandardReviewDraft.referenceExposureId 必须指向本人 exact question/version 的真实 question_exposure、kind=REFERENCE_VIEW；题库编辑器通过原 `/questions/{id}/versions/{versionId}/reference` 入口取得。AUTHORED、客户端布尔“已读”和别题 exposure 不能替代。这个字段只服务访问与预览，历史快照只保留审阅内容／基线，不把 exposureId 误当审阅证据。

两种 draft 新建时 changeReason=null，编辑时为1–2000码点非空文字；WithdrawRecord.expectedRevision 必填且为安全整数，reason 为1–2000码点非空文字。所有输入对象身份／引用身份沿原规则使用标准小写 UUID；所有 expectedRevision、revision 与 before 都核安全整数范围。标准撤回在核 owner、当前资料守卫与 CAS 后复制已存修订，不要求来源当前仍有效；响应不返回正文，避免把撤回入口变成无需曝光的查看入口。观察撤回仍核确切答案访问，但不要求审阅当前有效。

标准的 open 之所以是命令，是因为审核结论／摘录可能泄露参考；它需与曝光一起提交，不能做成普通 GET 后只在前端折叠。该入口不返回完整 referenceAnswer；要看标准原文仍用原题库参考入口。观察复用确切答案已存在的 EvaluationAccess；若尚未取得，提示到原评价访问入口，不能从受审入口暗中授权或跳过 AFTER_SESSION 反馈时机。曝光事实不回溯修改已有答案的当时条件。

GET 查询拒绝未知／重复／空参数，limit默认20最大50；history.before为独占上界安全整数，修订倒序。列表按 `(id ASC)` 键集分页，cursor 为标准小写UUID，绑定当前固定问题或答案筛选由前端查询键保持；服务端每页重新检查 owner／筛选，游标只作位置，不承诺跨请求快照。列表资格在页内一次 REPEATABLE_READ快照计算，不扫描全库补齐所谓有效页。存在但不合格的记录仍显示，不能吞掉形成假空。

复盘观察深链接固定为`/review?sessionId=&questionId=&answerId=&reviewedObservationId=&reviewedRevision=`。观察标识为标准UUID，修订为可空的非负安全整数，提供修订时须同时提供观察标识与确切答案身份。普通页内记录选择可不修改地址；外部回链按确切修订读取。既有AI的observationId和手工反馈的revision继续沿原规则解析，不能共用字段。更换答案、观察或修订及会卸载面板的无效路由，须先处理本页脏稿与未决命令。

## 8. 事务、摘要和错误

两类 preview 在 REPEATABLE_READ 中使用同一 UTC 微秒 now。请求上限256KiB；单条不可变历史／快照256KiB；列表／详情／预览上限1MiB；命令回执沿 IdempotencyService 的2MiB。超限明确失败不截断引文，也不拆命令。请求及输出文本不进入普通日志。

标准 previewHash 的规范内容固定为 `{purpose:"standard-review",draft,existingRevision,questionFacts,evidenceFacts,basis,checkpoints,validationDates,limitations}`；观察为 `{purpose:"reviewed-observation",draft,existingRevision,binding,answerConditions,standardEligibility,citationChecks,validationDates,limitations}`。existingRevision 为本次编辑前快照或null；questionFacts 含确切版本身份、checkpoints／参考结构摘要及当前状态；evidenceFacts 按 evidence输入顺序固定确切引用摘要和当前来源事实；citationChecks 按输入顺序固定匹配身份／字段／区间／原文摘要，不含全量答案副本。

两个摘要分别用 UTF-8 前缀 `standard-review-preview-v1\n`、`reviewed-observation-preview-v1\n` 加规范 JSON，SHA-256输出64位小写。对象属性按名称 ASCII 顺序，null明示，Instant固定六位小数UTC、LocalDate固定yyyy-MM-dd、整数无浮点；数组保留约定顺序。服务端生成的枚举集合按声明顺序输出且不重复；客户端数组先拒绝重复或不合约顺序，不在摘要阶段排序、去重修正请求。directSources按DirectKind声明顺序＋sourceId ASCII升序；validationDates按所用区域ID升序，保存其当次当地日用于未来日期约束。当前读取时钟不入hash；跨日导致合法日期核对日改变时需重做预览。摘要不是签名，客户端不提交服务端资格真值。

写流程为：原 `commands.execute` 取得owner锁 → 当前资料守卫 → 观察命令的确切答案访问守卫 → 原键回执恢复或新业务 → 核路径和draft身份／CAS → 重新读取exact源与当前资格 → 重算预览 → 对比hash → 校验真实变化及重核证据 → 生成一个新修订、当前指针、引用行及历史 → 保存原机制回执。观察创建从请求取得答案三元身份，编辑／撤回从owner限定的已存记录取得固定答案身份；回执恢复前只核确切答案存在、原EvaluationAccess和当前反馈时机，不要求标准当前有效。这样来源更正不阻挡撤回，也不会把含原文的历史回执当作免授权读取。标准命令沿原资料守卫；原execute调用的摘要和回执结构保持不变，新增可选命令守卫只用于需要额外来源访问检查的入口。当前修订、基线、引文、日期、状态任一变化不允许复用旧预览。新写接口只调用一次execute，内部钩子为MANDATORY且检查可写事务。

原键原请求可恢复历史成功回执，当前资格需随后另读；不能把回执中的旧ACTIVE当当前资格。同键异文沿 IDEMPOTENCY_KEY_REUSED，不换键掩盖不确定结果。now早于拟写对象／来源generation行updatedAt返回409 REVIEW_CLOCK_CHANGED。same-content无操作需先通过CAS、来源与访问核对。

| 错误 | 语义 |
|---|---|
| 400 INVALID_REQUEST | 严格形状、数值、日期、身份或封闭联合无效 |
| 404 STANDARD_REVIEW_NOT_FOUND／REVIEWED_OBSERVATION_NOT_FOUND | 本人对象或确切修订不存在；不区分他人对象 |

state／revision在当前行与revision快照的一致性由同事务维护，并在读取时核对；发现不一致作为完整性错误，不能自行用最新值补历史。checkpoint的evidenceIds映射在修订JSON中，保存时与本修订 evidence 行核对；不另建正文标准表。读回历史时保留版本验证，不能接受任意JSON当已核快照。

建议查询索引：standard_review `(owner_id,question_id,question_version_id,status,id)` 与不含status的同前缀目录索引；observation `(owner_id,answer_id,status,id)` 与 `(owner_id,answer_id,id)`；历史主键支持revision倒序；evidence增加 `(owner_id,basis_kind,knowledge_item_id,review_id,revision)` 和 `(owner_id,excerpt_id,review_id,revision)` 追溯索引；observation_revision增加 `(owner_id,standard_review_id,standard_review_revision,observation_id,revision)`。不对审阅者姓名／完整引文建全文搜索索引。

同一题目允许不同审阅记录，同一答案／检查项允许不同实际观察，不用全局唯一约束抹去分歧；网络重复提交由幂等键控制。列表及成长统计须按对象id区分“记录条数”和真实训练提交，不把多个修订／多位记录者变成多个独立答题样本。

只读投影一次最多50条观察，每条最多30个检查项／12条依据，但只为该观察所用checkpoint解析所需直接元数据，按来源去重批量查；不得在成长列表加载全部答案或知识全文。内部投影只读白名单元数据及规范摘要所必需的固定短条件，公开响应仅保留身份／布尔／枚举；原文定位验证由本域预览／单条详情读取所需确切文本。材料读取按既有1–5条边界；不得为了绕过上限静默扩大用户的候选集合。SQL执行计划与数据库事务需服务器验证，本文不承诺性能通过。

第三批新增 V42 的 `review_question_projection_stamp`，按 owner＋questionId＋versionId 保存一次 `sourceContentHash`、原协议 canonical fingerprint 和 createdAt，复合外键指向确切题目版本，不更改V41。sourceContentHash 是三个原UTF-8文本字段 prompt_json／reference_answer／checkpoints_json 各取SHA256后，按此顺序拼接三个64位十六进制串再取SHA256。仅标准 create／save／open 命令在原owner锁与同事务全文核验后，以实际 QUESTION stamp 建立；现有标记只核一致，不更新。撤回及原键回执不补写。旧记录缺标记由内部投影抛503 REVIEW_PROJECTION_UNAVAILABLE；成长目录／概览以ERROR能力和UNAVAILABLE计数表达，确切身份解析映射503 GROWTH_SOURCE_UNAVAILABLE，不报零。用户显式打开或保存核验后建立标记，不从历史基线自动回填，不在GET写库。版本原文或指纹与已有标记不一致按完整性异常失败。

观察窄SQL对原存content_json／snapshot_json的UTF-8字节取SHA256，按原协议重建binding；只返回确切身份、曝光白名单和三个有界短条件。知识／摘录的UTF-16引文匹配在数据库按二字节码元偏移比较，应用层只取得布尔结果和当前正文指纹。材料继续核固定解析执行／片段、定位、原附件摘要及启用状态。每批缓存绑定owner且只在本次投影内使用，按确切答案、标准修订／检查项、引用和直接来源复用已核结果，不进入摘要或跨请求复用。

2026-11-09官方取证：dev.mysql.com直取三页均为Technical Difficulties；Oracle托管的 MySQL 8.4 手册镜像实际HTTP200读取了[utf16](https://docs.oracle.com/cd/E17952_01/mysql-8.4-en/charset-unicode-utf16.html)、[CAST／CONVERT](https://docs.oracle.com/cd/E17952_01/mysql-8.4-en/cast-functions.html)、[SHA2](https://docs.oracle.com/cd/E17952_01/mysql-8.4-en/encryption-functions.html)。文档支持补充字符的代理编码、二进制字节比较与摘要类型；不证明本SQL已执行。SQL与JDBC UTF-8摘要一致性、代理对／尾空格、JSON_TABLE、MySQL执行计划和V42事务均待服务器验证。

## 10. 成长第七种 EvidenceRef 的接入

### 10.1 确切身份、全部修订目录与时间

在[成长证据契约](今日聚合与成长证据契约.md)原六种封闭联合之外增，并与[成长查询精确稿](成长证据查询与复用实施契约.md)共享目录口径：

```text
kind = REVIEWED_OBSERVATION
objectId = ReviewedObservation.id
revision = 确切观察revision（必填安全整数）
versionId = null
partId = null
```

成长目录默认保留每个 ReviewedObservation 的**全部不可变修订**，包括 CREATED、REVISED、WITHDRAWN；七类按各自确切版本／事件身份统一展示。occurredAt 固定取 `reviewed_observation_revision.created_at`，等于该修订快照 revisedAt；observedOn 只表示记录者声明的观察日期，answerCreatedAt 只表示原答时间，都不替代目录发生时间。目录条目数是修订／事件数，不是新增观察数或独立答题数。

沿成长 DateWindow、asOf、`(occurredAt,evidenceKey)` 排序和排他游标筛选，每个 revision 是一个扫描和消费单位，不先按 observationId 合并为最新修订。后续编辑不会使原时间窗内的旧修订消失，也不会把新修订回填到旧发生时间。当前资格按本次 checkedAt 独立计算；旧修订保留 RECORD_REVISED，映射为 recordCurrency=SUPERSEDED 与 REVIEW_REQUIRED，不能用当前正文替换它。未来“仅最新版”筛选若增加，必须单独定义窗口含义。

### 10.2 领域投影与公开元数据

本域提供 `ReviewedObservationProjection.read(owner,List<RevisionRef>)`，每次1–50个不同确切引用，响应保留输入顺序；调用方为growth，只读，不回调growth、不读取目标覆盖表。内部投影使用以下封闭类型，字段均非空，原有 PriorExposure 内部可空成员仍沿原域规则，不增加任意 Map／JsonNode：

| eligibility | 以本域封闭ObservationEligibility映射当前状态、原因、资格及限制；不能把完整StandardReviewSnapshot、EvidenceCheck或来源摘录透传成长 |

第七类公开载荷复用成长 AnswerMeta、QuestionRef 以及本域枚举／RevisionRef／ObservationEligibility，Java／OpenAPI／TypeScript 同步。answerNumber 为1–100；声明日期须在原答时间与该修订保存时间的当地日之间。所引确切题目版本必须等于 AnswerMeta.sourceQuestion，原答只能是 MAIN 或有自身题库来源的 REPLAY。本域不依赖 GrowthDtos，不通过通用 JSON 对象占位。

成长分类复用确切答案的既有窄读取：目标／主题／维度取实际保存快照，不从用户观察结论或检查项文字推断。原域路由使用 observationId＋revision 和确切answer三元身份进入观察详情，再执行原评价访问检查；标准内容仍经本域open曝光入口读取。

### 10.3 当前状态与变更摘要

成长的 assessmentLevel 使用 REVIEWED_OBSERVATION、recordKind 使用 REVIEWED_CHECK，表达对象来源；结合当前 reviewFlags／eligibility显示“当前有限观察”或“历史受审依据，待复核／已撤回”。不把来源失效改造成AI_UNREVIEWED对象，也不抹历史。DISPUTED产生争议标记；RECORD_REVISED、撤回、标准修订或直接链变更产生REVIEW_REQUIRED；不可访问产生SOURCE_UNAVAILABLE。directState及其优先级沿成长规则，lineageCheck始终PARTIAL直到S8有真实完整检查结果。目标覆盖保存仍由growth自己的规则决定，本投影不产生自动SUPPORTS或能力分。

originHash只能来自该确切观察修订、固定答案条件／身份及绑定的确切审阅修订摘要，不能包含当前资格或当前最新审阅；必要正文一致性摘要在本域内部计算，正文不外传。currentHash应结合当前观察／审阅修订与状态、所用checkpoint的直接基线检查结果、答案当前直接依赖及最终EvidenceState，不能只哈希 eligible 布尔值而漏掉失效原因变化。哈希规范与字段类型纳入主会话共享DTO冻结，不以任意JSON载荷跨域返回；原始正文和外部摘录从不进入公开摘要输入对象。

投影内部 originHash 使用 `reviewed-observation-projection-origin-v1\n` 与封闭 `Origin(exactHistory,fixedConditions)`；其中确切历史含旧绑定，fixedConditions 来自原答有界条件。内部 currentHash 使用 `reviewed-observation-projection-current-v1\n` 与 `Current(ref,originHash,observationCurrentRevision,observationCurrentStatus,standardCurrentRevision,standardCurrentStatus,checkpointId,scopedBasis,scopedEvidence,eligibility)`。scopedBasis 按原基线顺序，只含 QUESTION 及所选项实际引用的知识／附件；scopedEvidence 按该修订依据顺序。摘录意外缺失时保留其 UNAVAILABLE/null 检查，不补造附件或引入其他项的附件。

成长 originHash 使用 `GROWTH_REVIEWED_ORIGIN_V1` 与 `{ref,reviewOriginHash,answerOriginHash}`；currentHash 使用 `GROWTH_REVIEWED_CURRENT_V1` 与 `{reviewCurrentHash,answerCurrentHash,state}`。答案摘要由原 TrainingGrowthQuery 实际读取生成，包含其直接依赖；本域不复制其解析器。旧训练 origin 的 Conditions 规范输入固定原七字段（kind及六载荷），公共 Conditions 新增 reviewed:null 不改变旧训练、AI及历史关联摘要；不使用全局忽略null规避显式字段协议。

### 10.4 活动与统计

首次录入观察按 observationId＋revision=0 的真实保存时间，计一次“记录受审观察”；REVISED／WITHDRAWN 按 observationId＋revision 分别计入“受审观察维护”，两者必须分开。维护活动不增加回答数、独立复练数或训练时长。多个受审／自检／AI观察指向同一answer时，答题样本仍按answerId去重；标准审阅记录自身也不算新答案。

活动按原答实际保存的目标归属，跨目标EvidenceUse只改变证据发现，不新增另一目标的实际活动。活动窗口仍取各次保存事件时间，后来的撤回／失效不改写既有活动。ActivityMetric 在原19项末尾依次追加 `REVIEWED_OBSERVATIONS_CREATED`、`REVIEWED_OBSERVATIONS_MAINTAINED`，均 EVENT／additive=true，每桶和totals完整21项。2MiB上限及保守核算见[成长精确稿§5](成长证据查询与复用实施契约.md#5-真实活动序列)。新增两项为独立领域，读取失败只使它们不可用，不将失败计为0。

## 11. 实施接线顺序与审定点

主会话已采纳真实审阅证据双角色、外部摘录仅记录不抓取、直接来源变更号与明确查看曝光四项业务取舍；独立复核发现的检查项移除／重加缺口已补入§6.3及SR-09，不写成用户逐项确认。首批第1–2项及第二批第3项的观察服务／接口／复盘界面已有静态交付记录；第三批落实只读元数据投影、第七类精确DTO、活动口径与共享契约，最终构建和验收状态只以开发记录为准，不代表缩减完整产品范围：

1. 新DTO／严格校验／迁移和只依赖Mapper的直接影响钩子；同时接QuestionService与KnowledgeService全部实际写入口，验证原命令摘要不变。
2. StandardReview预览、保存、查看、撤回、历史与当前资格；按新增源码核对OpenAPI和客户端，不直接扩旧QuestionInput。
3. ReviewedObservation基于原评价访问、确切答案与受审范围，接新页面和资料二次守卫；再提供不含正文的只读投影。
4. 成长接第七证据、当前flags与能力状态。运行响应的capability=READY仅表示该次实际领域查询成功完成；缺标记／数据库／权限／完整性失败返回对应错误或ERROR／UNAVAILABLE。它不是项目验收标签，文档和交付仍标静态检查与待服务器验收，不能仅有代码就报告数据库查询已验证。S8间接更正继续PARTIAL。

前端入口建议：题库确切版本参考页内“审阅记录”，只显示录入来源与范围；答案评价区内“有受审依据的观察”，显示原答与标准条件并选择单个checkpoint。没有合适审阅证据的空态指向原自检／未审反馈，不能引导用户随便填一个审核人就称平台认证。保存前展示引用来源性质、原文命中与未核语义的区别；UI不得提供“全部技术正确”默认选项。
