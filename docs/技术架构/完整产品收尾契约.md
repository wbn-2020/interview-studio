日期：2026-11-13。版本：v1.0。适用范围：当前完整产品的文件交换、概念合并、数据管理、来源与跨域集成。状态：代码收尾、集成与最终静态构建通过，运行、迁移及视觉待服务器验证。完成状态与实际命令只在[开发阶段与进度](../开发记录/开发阶段与进度.md)维护。

本文件补充既有专题契约。本批之前文档中的“后续范围”是当批边界，不是当前产品裁剪；本文所列实现接点取代这些项目的历史下一步说明。暂不做语音、本地不启动服务、不编写单元测试，继续遵守[项目约束](../../AGENTS.md)。

## 1. 入口与业务身份

| 入口 | 业务能力与身份边界 |
|---|---|
| `/knowledge/packages` | 独立知识包预览、方案登记、整包提交与原映射恢复；不冒充完整业务备份恢复 |
| `/knowledge/merge` | 两个重复概念的影响预览、用户最终选择与合并；不改写历史题目、回答或证据 |
| 知识详情／版本历史的资料来源 | 绑定确切知识发布版本，独立修订；不改变正文版本、技术审阅或模型许可 |
| 题库文件导入 | 文件候选逐题预览并创建正式题目；候选参考不自动成为已审标准 |
| 脑图／白板的交换入口 | JSON Canvas、Markdown脑图与站内快照；先填画布草稿，再显式保存 |
| 目标编辑／历史 | 直接复用确切题单／学习路线版本；不复制集合正文或自动展开为AI输入 |
| `/settings` | 主题、字号、内容宽度、动效、时区、保存恢复提醒和空间用量 |
| `/settings/data` | 独立隐私账本、回收站、精确清除预览及完整导出；离线恢复另有受控CLI |

数据管理和授权管理允许进入安全外壳，便于接续原操作。这个路由例外不授予资料访问：私有标题、范围预览、作业和新命令仍受登录、可见性、训练条件及隐私检查。独立训练需要查资料时，保留辅助确认入口；不能因未知命令锁定而把恢复入口一并隐藏。

## 2. 文件交换与概念合并

### 2.1 知识包

服务端入口为 `/api/v1/knowledge/packages`：`POST /preview`、`POST`登记、`GET`分页、`GET /{id}`、`POST /{id}/commit`。机器字段以[累计OpenAPI](openapi-s7.json)为准。

- 每包1–20份文本、至多20项已上传附件映射。原文、目标类型、IMPORT／SKIP、标签、概念别名和主题由用户逐项核对。登记仅保存方案与指纹，完整原文在明确提交时再次提供，不把浏览器内存称为服务器草稿。
- 同一来源包默认恢复原包及映射；只有明确选择副本才创建新的包身份。恢复须核对同一原文件和已登记方案，不能靠同名标题猜测身份。
- 整包提交在同一owner命令事务内先创建全部真实知识及首版，再建立引用索引，支持前向和循环的正文引用。任一身份、附件或引用校验失败，不能留下半包正式对象。
- 包内路径与原文身份映射不同于完整恢复。普通导入创建新业务身份，不恢复旧模型授权、技术审阅或训练完成状态。
- 私有附件先通过现有上传链取得READY身份及原件摘要，再显式映射；不执行文件中的路径、脚本或嵌入代码。正文 `material:<uuid>` 是结构引用，不等于摘录采用或模型外发许可。
- 暂时隐藏、焦点访问核对与实际会话切换分别处理。前两者遮挡内容、使旧请求失效，不得清空尚未提交的文件与处理选择。未知写入保留固定请求和原幂等键。

### 2.2 题目与画布

题目文件导入复用正式题目的版本及保存规则。每项候选成功才刷新正式题库；关闭、切题和换文件先经过保稿检查，未确认请求不得换新键重复创建。

JSON Canvas／Markdown脑图交换支持有界的节点、分组和连线。文件引用由用户映射至当前画布已有真实引用，或明确保留为临时文本／跳过；不自动查找同名对象。导入只替换当前草稿，保存仍沿画布原修订、幂等与冲突路径。导出明确格式遗漏和确切快照，浏览器发出下载请求不等于文件已保存。

普通白板的KNOWLEDGE、QUESTION、ATTACHMENT引用各有来源验证。训练答案目前只接知识引用与文字；带题目／附件引用的普通画布不能未经转换直接成为训练答案，也不能把这些引用自动授予模型。

### 2.3 重复概念合并

`POST /api/v1/knowledge/concept-merges/preview`生成双方当前版本、组织信息、关系、布局和引用影响的摘要。最终命令`POST /api/v1/knowledge/concept-merges`再次核对摘要，明确别名、标签、主题、关联笔记、主笔记、收藏及位置选择。

合并保留目标概念正文与历史，归档源概念并登记解析链。不会重写旧笔记引用或历史训练证据；原身份仍可追踪至目标。主笔记冲突必须明确选择，实际关系冲突不能静默丢弃。已合并源不能通过普通恢复命令重新变成第二个活跃身份。

预览失效与用户选择分开保存：临时访问核对后须刷新摘要，但不能自动以新建议覆盖用户已作出的最终选择。新增候选输入、回忆卡来源或标准审阅依据也属于预览影响，应使旧摘要失效。

## 3. 来源、搜索、设置与目标关联

资料来源采用独立的`expectedRevision` CAS。七个字段为标题、地址、作者、获取时间、适用版本、权利说明和备注；字段均显式提供，仅获取时间可为null。单个确切发布版本最多20项来源。新追加只允许ACTIVE知识的当前发布版本，旧版本来源及其修订继续只读查看。

来源保存不会推进正文、草稿、组织信息、审阅或授权修订。来源未保存或结果未知时，父编辑器阻止发布、归档及采用服务器正文，避免换版本导致来源输入丢失。回执须核对原知识、原版本、下一来源修订及完整规范化内容。

知识搜索增加来源类型和断链整理。USER／AI_ADOPTED／TEXT_IMPORT／PACKAGE_IMPORT表示实际登记来源；“存在AI采用记录”不表示整篇正文作者身份。断链由真实扫描结果或当前不可用目标判断；接入前尚未扫描的旧版本，需要用户显式运行原引用重建命令，不能默认当作没有断链。

个人偏好只控制呈现：关闭保存恢复提醒不解除离开保护，时区不改变数据库UTC时间，动画减少不移除功能。星图仍保留自己的深色画布，不能以站点主题替换知识关系。

PRE-03的`COLLECTION`只增加到准备对象的结构引用。新选择须本人、ACTIVE且为当前题单／路线版本；服务器已登记的旧关联可保留，当前页及历史显示确切快照、改版／归档提示。材料祖先遍历只核登记身份，不展开集合步骤。目标AI仍使用原明确白名单，不把结构关联全量发送。

## 4. 隐私账本、回收站与清除

独立账本目录由`STUDIO_PRIVACY_LEDGER_DIRECTORY`配置，位于业务备份之外。账本只记录无正文身份、动作、清除字段定位、顺序及哈希链；数据库保存应用检查点。两者不一致时封闭普通资料、任务与副本重建，接续原操作或封闭恢复，不以数据库回滚撤销已经持久化的隐私意图。

`/api/v1/data-privacy`提供状态、账本初始化、回收站分页及TRASH／RESTORE／PURGE的预览与命令。类型分为三层：14类可操作根对象`DataPrivacyRootKind`、15类影响对象`DataPrivacyObjectKind`、17类账本身份`PrivacyLedgerKind`。影响对象包含派生模型授权，但授权只能通过原生授权管理撤回，不能作为回收站操作根；账本另含内部`MATERIAL_EXCERPT`和`EXPORT`身份。前后端分别核对对应层级，不混用集合。操作须选择精确类型和UUID，不接受“清空所有数据”式模糊范围。

| 操作 | 明确结果 |
|---|---|
| 初始化 | 明确确认当前基线；没有独立历史账本的旧备份不能被追认成完整可信历史 |
| TRASH | 屏蔽对象及相关版本／摘录的资料访问，保留正文；按业务能力归档或暂停，不自动彻底清除 |
| RESTORE | 解除回收站屏蔽；不自动恢复归档、复习排程或模型授权，回执为`RESTORED_WITHOUT_REACTIVATION` |
| PURGE | 确认最新影响摘要及整份混合派生正文，清除所列业务正文副本、索引、文件及历史导出，保留无正文身份墓碑 |

清除范围沿真实登记的采用和版本身份追踪。普通链接不会把独立笔记变成可任意删除的派生正文；无法安全切分的混合派生正文必须整份列出、整份确认。处理有节点、记录和字节限额；超限拒绝并说明，不能截取一部分却声称全部清除。

业务状态枚举、身份、数值及JSON形状不是正文。按实际表列生成替换值并遵守现有CHECK；不得把事实核实枚举写成中文清除标记，也不得把数组统一写成对象。正文、哈希、字节数和受约束快照须同步保持结构一致。原回执或AI引文同样不能泄回已屏蔽摘录。

磁盘处理只作用于预览登记的业务副本，不删除独立账本、备份或已下载副本。已下载文件无法远程撤回，界面必须明确这一限制。中断留下未对齐意图时保持封闭，原键恢复不得改换目标或扩大清除范围。

## 5. 完整导出与封闭恢复

真实格式及CLI参数以打包资源[完整导出与恢复格式v1](../../backend/src/main/resources/dataarchive/restore-manifest-v1.md)为权威位置。本节规定产品入口与交接边界。

- HTTP `/api/v1/lifecycle/archives`提供状态、作业、明确确认创建、详情与鉴权下载。私有完整包包含对象身份、全部版本、关系、业务记录和可用附件；manifest列出表结构、每载荷摘要、遗漏、转换和独立账本检查点。
- 不包含登录凭据、会话、模型密钥、独立账本原文件、旧索引或可执行worker租约。排队／运行中的模型及解析任务会阻止生成，不能导出一个仍会变化的后台执行环境。
- 默认单包上限1GiB、100万行，保留24小时；均为服务器显式配置。失效是下载资格失效，不冒充物理文件已经删除。
- 离线恢复不启动Spring或HTTP。仅向已完成当前全部迁移的独立空库、新空材料目录及新空索引目录恢复，不覆盖正在使用的库、不关闭外键、不删除失败现场。
- 操作者必须从业务备份之外取得最新独立账本头。包内旧头只能是最新链的已证明前缀；整条账本被旧副本替换时，外部最新头是必须的校验依据。
- 导入绑定操作者确认的整包SHA，后续每次读取仍须校验同一包与载荷摘要。文件存在、自校验通过或owner相同，都不能替代用户已确认的包身份。
- `LedgerArchiveLifecyclePolicy`通过Spring与ServiceLoader复用真实生命周期策略。恢复重放清除、撤权和检查点，排除已清附件，撤销旧AI授权，暂停复习排程；再由生产分析器建立新的Lucene代并逐项核验，才能开放。
- 恢复成功仍关闭模型发送。管理员明确确认当前公开模型配置后才可解除恢复封锁；旧授权不重建，下一用途仍走正常授权。公开配置确认不代表密钥可用或供应商调用已经验证。

恢复CLI涉及数据库和磁盘变更，实际执行仍需用户针对目标、路径、影响和恢复方式的明确授权。本轮不连接服务器、不读取既有凭据、不执行这些命令。

## 6. 材料与派生内容

材料摘录更正、归档和用途变化分别处理，历史原答及采用来源不被改写。真实派生遍历覆盖准备后继、AI正式采用、知识链、题目、训练／答案图、关系和标准审阅；结构链接不伪装成正文采用，缺少历史见证时拒绝新用途，不猜材料祖先。

新增材料依赖影响按PREPARATION／QUESTION／KNOWLEDGE／RELATION／STANDARD_REVIEW展示目标原基线、当前版本及固定来源。处理选择依目标能力限制为保留、已更新、已归档、已撤回或已移除；原因、预期修订／版本与确认在同一命令内核对。

本地训练资格与模型外发资格分开。用户复核派生正文后不因此重新授予原材料外发许可；用途恢复也不重启旧任务、旧授权或旧评分。新任务捕获实际材料祖先及其代次，历史任务保持原冻结点。
