# 表达素材依据复核契约

版本：v1.1 · 2026-11-12。适用：S8 第九批。状态：代码完成待验证；独立静态复核、后端打包及正式业务入口专项类型／构建检查通过，整仓前端构建仍受参考界面缺件阻塞。数据库、HTTP、模型、视觉及交互尚未运行验收。承接[表达素材输入与来源](表达素材输入与来源契约.md)，实际进度以[开发阶段与进度](../开发记录/开发阶段与进度.md)为准。

## 1. 业务与本批范围

表达保存的是用户的叙述，事实核实不是表达正确性的认证。表达新版本必须显式选择当前、已确认、所属项目活跃的 1–50 个确切事实版本。手工新建、保存新版本和 AI 候选显式采用，在原 owner 命令事务中同时保存不可变的 `SAVED_BASIS`：原文顺序、事实与项目身份、事实版本、事实和项目来源代次、表达版本及当时修订。

事实改版、核实决定、归档／恢复或所属项目改版、归档／恢复推进来源代次后，保存基线不再匹配。之后即使来源恢复为当前有效，旧表达仍待复核；收藏和焦点不改变代次。项目概况编辑也要求重新核对表达，但不声称事实正文已改变。表达自身归档不改写依据记录，恢复后仍核对原基线。

用户可编辑并保存一个新表达版本，同时重新建立明确所选事实的基线；保存不改写旧版本或旧复核记录。保留当前正文则须读取最新依据、逐项核对、填写理由并显式确认，追加 `CONFIRMED_BASIS`，不创建正文版本。该确认推进表达元数据修订与来源代次，使之前的 AI 任务／许可继续失效，不因人工复核恢复旧授权。

升级前已有表达没有可证明的历史基线，当前资格按待复核处理。只在显式确认或新版本保存时建立记录，不伪造旧时已核对。不回填更正根事件，也不改写旧正文、关系、manifest、摘要、决定和幂等回执。

本批覆盖“事实／项目 → 表达”的当前可用性与持久复核历史，不是逐根更正事件账本；不声称准备／表达的已采用知识、卡片或审阅已完成更正传播。后续桥接须保留真实准备根及确切采用版本，不能直接冒用知识根身份。

## 2. 当前状态与历史

所有身份为标准小写 UUID，所有代次／修订为 JavaScript 安全整数。依据按表达正文 `factVersionIds` 顺序读取，并与完整 `FACT_BASIS` 关系双向核对，不能用空关系、异常关系或只检查部分来源获得有效资格。

`Basis` 六字段：

| 字段 | 规则 |
|---|---|
| itemId / versionId | 确切 FACT 对象及版本 |
| title / versionNumber | 该固定事实版本的标题与正整数版号 |
| projectId | 事实固定所属项目 |
| check | 原六字段 `PreparationDtos.SourceCheck`；kind=FACT，身份与外层一致 |

`Record` 十字段：`id,itemId,versionId,versionNumber,revision,kind,reason,itemRevision,createdAt,basis`。itemId 为表达，revision 是每表达严格递增的正安全整数，kind 为 `SAVED_BASIS|CONFIRMED_BASIS`。保存基线 reason=null；人工确认 reason 经 Java `String.strip()` 规范化后为 1–1000 个 Unicode 码点，拒绝纯空白、NUL 和孤立代理。前端请求、计数及回执校验使用同一规则；NBSP 和 FEFF 不按 JavaScript `trim()` 擅自剥除。basis 的 1–50 个检查均为捕获当时的 CURRENT，代次非空，历史只读。

`State` 十字段：`itemId,versionId,versionNumber,itemRevision,status,revision,latest,basis,reviewRequired,canConfirm`。revision 为该表达最后记录序号，无记录为 0；latest 为当前表达版本的最后记录，没有则 null。basis 是当前事实检查，来源失效仍保留真实固定身份。reviewRequired 表示缺少基线、基线不匹配或事实当前不可用；canConfirm 仅在表达 ACTIVE、真实依据完整且全部 CURRENT、修订可继续推进时为 true。它不代表已同意或已经核对。

`Page` 三字段：`itemId,items,nextCursor`。历史按每表达 revision 降序，nextCursor 为还有下一页时最后记录的 revision，否则 null；不要求 createdAt 随 revision 单调。历史不是当前资格；旧标题、检查及理由不以当前内容替换。

## 3. API 与命令边界

根路径：`/api/v1/prepare/items/{itemId}`。全部沿现有 owner 与普通资料访问守卫，响应 `Cache-Control:no-store`。

| 方法与后缀 | 输入 | 输出 |
|---|---|---|
| GET `/expression-basis-review` | 无查询参数 | State |
| POST `/expression-basis-review/confirm` | Idempotency-Key、Confirm6；无查询参数 | Record |
| GET `/expression-basis-reviews` | limit 默认20，1–20；before 可选正安全整数；拒绝重复／未知参数 | Page |

Confirm6 为 `expectedItemRevision,expectedVersionId,expectedRevision,basisChecks,reason,confirmed`。confirmed 必须 true；expectedVersionId 与当前表达版一致；expectedItemRevision、expectedRevision 分别匹配当前元数据和最后复核序号；basisChecks 完整等于 State.basis 中的有序 check 列表。请求体最多 64 KiB，拒绝未知／重复字段和类型强制转换。

在既有 owner 锁与幂等事务内重新读取所有依据，检查身份、版本、修订、完整代次列表和 ACTIVE／CURRENT 状态后推进元数据、追加记录并保存回执。任一步失败全部回滚。同键同请求返回原 Record，不根据后来事实重算；正常历史恢复不要求来源再次 CURRENT，但仍遵守当前资料访问权限。不同键的旧基线须冲突。归档、失效或不完整来源不能确认；超出修订上限拒绝，不发生溢出。

## 4. 存储与全部消费者

新 V70 保存复核头与有序事实快照，采用 owner／表达／版本的复合外键、每表达 revision 唯一、事实版本与项目身份约束。旧 V1–V69 不改；不新增依赖，不执行本地 SQL。

表达详情、直接影响目录、面试安排来源状态与 AI 来源读取共享基线核对。沿用原 `SourceCheck`／`ExpressionCheck` 形状；表达自身在当前版本但依据待复核时用已有 `UNVERIFIED` 表示“表达依据待复核”，不把表达当成待核实事实。AI 新预览、授权、发送、接纳、采用及来源问答的现有 CURRENT 守卫必须拒绝该状态。事实自身检查语义保持。

历史任务和旧幂等回执保留原形状，不追加必填字段。旧任务仍按旧 manifest 的全部代次核对；本批确认增加表达代次，不能让已失效的旧任务恢复。数据库错误按错误处理，不能伪装为来源已撤回。

## 5. 界面与恢复

表达“来源与影响”中主动读取当前基线及分页历史，分别显示保存时事实检查与当前事实检查，提供固定事实版本／所属项目入口。缺历史基线明确说明；来源不可用提示先核对或修订事实，再编辑表达或显式确认。

正文脏稿、父保存未决、过期修订、隐藏、对象切换或权限变化使旧核对资格失效；保留理由和未决原请求。只读打开／刷新不自动提交、不调用模型、不改正文。人工确认必须有理由和本次勾选同意；成功回执严格匹配提交的固定身份与基线，再刷新详情。网络中断保留原键／原请求，旧成功回执只证明当时操作成功，不抬升现在资格。交互沿既有保稿导航与资料守卫，支持加载、错误、重试、分页、键盘和窄屏。
