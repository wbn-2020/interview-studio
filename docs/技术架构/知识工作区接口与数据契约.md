## 1. 范围与共同规则

本阶段实现笔记／概念关联、主笔记、别名／标签／收藏、正文引用与反链、已发布内容全文检索、历史对照、星图邻域／路径／布局历史以及脑图／白板。材料和附件在 S3、训练画布快照在 S4、AI 候选在 S5、合并／彻底删除／Obsidian 导入导出在 S8 接入，不能展示为已可用。

所有路径以 `/api/v1` 为前缀。沿用 Session、CSRF、owner 校验、Problem Details、1 MiB JSON 请求上限和 2 MiB 幂等回执上限。所有写入复用 `IdempotencyService`，相同 owner 的事务锁覆盖检查与写入。ID 为小写 UUID；时间 UTC；修订号是非负 JS 安全整数，溢出拒绝。写入失败或结果未知时保留原请求与原幂等键。读取历史不回退当前内容；恢复产生新修订。

S1 表与迁移保持原文，S2 通过追加迁移扩展。MySQL 保存业务事实；Lucene 是可重建投影。所有分页 limit 1–50（默认 20），游标为最后记录 ID，除明确标明的版本或访问排序；不得把已加载窗口当作全量。新查询继承前端 `sessionEpoch` 与 `sessionActive` 边界。

## 2. 知识整理与引用

### 2.1 整理状态

- `GET /knowledge/items/{id}/organization` → `Organization`。
- `PUT /knowledge/items/{id}/organization`：`{expectedRevision,aliases,tags,favorite,noteIds,mainNoteId}` → `Organization`。
- `POST /knowledge/items/{id}/visit`：`{}` → `{visitedAt}`。

`Organization={revision,aliases:string[],tags:string[],favorite:boolean,noteIds:UUID[],mainNoteId:UUID|null,visitedAt:Instant|null}`。初始 revision=0；更新推进独立整理修订，不改变正文、主题或草稿的修订。只允许 ACTIVE 对象修改整理信息；访问记录不推进整理修订。别名只用于概念，最多 20 个，每项 100 字；标签最多 20 个，每项 40 字；trim 后去重，大小写归一用于匹配而保留展示值。概念最多关联 100 篇当前 ACTIVE 笔记；`mainNoteId` 必须属于 noteIds 或为 null。笔记自身的 noteIds 必须为空、mainNoteId 为 null。归档不删除既有关系，读取必须能说明关联对象状态；已有归档关联可保留或移出，不能新加入。概念摘要与笔记正文完全独立。

`GET /knowledge/items/{id}/connections?type=ASSOCIATION|SEMANTIC|OUTGOING|BACKLINK&cursor=&limit=20` → `{items:Connection[],nextCursor}`。

`Connection={id,kind,itemId,title,status,relationType:null|string,direction:null|IN|OUT|BOTH,sourceVersionId:null|UUID,sourceVersionNumber:null|integer,lineStart:null|integer,lineEnd:null|integer,excerpt:null|string}`。ASSOCIATION 返回关联的另一对象；SEMANTIC 按对象查真实边，返回另一端、类型、方向，包含归档状态；OUTGOING 只使用源对象当前发布版本，BACKLINK 默认只查其他对象当前发布版本的引用。每条正文引用保存源对象 ID、**不可变源版本 ID／版本号及 1 起始行区间**，段落摘要最多 300 字。历史版本阅读仍展示该版本内链接，不把历史出处替换为最新正文。

### 2.2 正文链接

统一语法为 Markdown `[显示名](knowledge:目标UUID)`；用户通过显式选择器插入，同名对象显示类型和 ID，不猜目标。渲染器将其转换为站内对象导航；外部链接继续沿用 S1 协议白名单和图片限制。后端使用 CommonMark AST 识别真正链接，排除代码块、行内代码、转义和图片中的伪链接，记录所在段落的源行；最多 200 个知识引用／版本。

创建及发布事务中校验目标 owner／存在并保存引用；目标可以归档但必须显示归档状态，未知或无权目标统一 `REFERENCE_UNAVAILABLE`。标题变更不改变稳定目标 ID。历史版本引用不自动随新发布消失；当前反链仅查当前源版本。S1 既有版本的引用索引通过显式 `POST /knowledge/references/rebuild`（`{}`）分批补齐，返回 `{processedVersions,hasMore,unresolvedReferences}`，每次最多 100 个未处理版本；已处理记录标记防止空引用重复扫描。历史原文不可修改：其中无法解析或无权访问的目标记录为该版本的未解析计数，不建立可导航关系，继续处理其余版本；不返回他人的标题或存在性。这一兼容规则仅用于旧版本补齐，不放宽新发布校验。迁移／恢复后的补齐进度和历史警告作为服务器验收项。

`GET /knowledge/library?collection=ALL|FAVORITES|RECENT|UNCATEGORIZED&kind=&status=ACTIVE&q=&cursor=&limit=20` → S1 `ItemPage`。q 是已发布标题字面筛选；RECENT 使用访问时间降序与 ID 联合游标，其他按 ID。收藏、访问是用户整理状态，不代表掌握程度或模型记忆。断链清理随 S8 生命周期接入，当前发布拒绝悬空目标。

## 3. 全文检索与恢复

- `GET /knowledge/search?q=&kind=&status=ACTIVE&topicId=&tag=&source=USER&limit=20&offset=0` → `{items:SearchHit[],hasMore,syncStatus,scanLimited:boolean}`。
- `SearchHit={id,kind,title,status,versionId,versionNumber,excerpt,matchedFields:string[],topicIds:string[],tags:string[]}`；`syncStatus=READY|BUILDING|DEGRADED|DISABLED`。
- `GET /knowledge/search/status` → `{state,generation,pendingEvents,lastErrorCode}`。
- `POST /knowledge/search/rebuild`：`{}` → `{accepted:boolean,state}`，只登记任务；后台执行，新一代索引完成前保留旧代。

q trim 后 1–100 字，offset 0–1000，表示已通过数据库回验的有效结果偏移；不接受用户 Lucene 语法、正则或任意通配符。索引仅含已发布版本、别名、标签、主题与状态；草稿明确不参与全文检索。中文用 CJK 分词，代码保留完整标识符和拆词字段，单字查询走受限字符字段。source 当前只允许 USER，未来来源随对应阶段扩展。结果文字与摘要只取通过数据库现状校验的内容，避免过期索引泄漏已归档／变更对象。索引版本或整理信息落后时跳过该命中并继续扫描，不因一页含旧结果就误报已到末页。每批最多 100 候选，每请求最多扫描 4096 候选；达到安全边界而未完成收集时 `scanLimited=true`，提示缩小条件或待同步后重试。hasMore 仅根据额外有效命中计算，不作精确总数承诺；前端下一页偏移按实际返回数推进且不超过 1000。

只有一个后台索引写入者，固定小批消费 outbox；Lucene commit 成功后才确认相应事件，崩溃后可重复索引。事件按具体 ID 确认，不用全局最大 ID 吞掉尚未提交事务。创建、发布、归档恢复、主题及整理变更均写 outbox。索引重建采用新目录：记录边界、分页扫描 MySQL、追赶期间事件并在同一 owner 写锁下短暂完成最终追赶／切换；切换标记原子持久化。旧代保留用于诊断，不自动清理目录。新进程启动不得仅凭目录存在认定索引 READY，缺失／损坏时可退化并重建；索引不可用不阻止笔记保存。配置默认关闭索引任务，部署时显式启用并指定可写数据目录；开发机不启动它。

## 4. 星图探索与布局

- `GET /knowledge/graph/neighborhood?centerId=&depth=1&limit=200` → S1 `Graph`；depth 1–2，只扩展 ACTIVE 概念真实关系，节点 200／边 600 上限，超出显式 truncated。保留已存世界坐标。
- `GET /knowledge/graph/path?fromId=&toId=&type=` → `{nodeIds:string[],edges:Relation[],found:boolean,truncated:boolean}`；有向边按方向，对称边双向；只在 ACTIVE 概念的真实语义边上寻最短路径，最多检查 10000 边。无路径不造边。
- `GET /knowledge/graph/state` → `{layoutRevision,viewport:{x,y,zoom}}`；默认视口 x=0,y=0,zoom=1。
- `PUT /knowledge/graph/state`：`{expectedRevision,positions:Position[],viewport:{x,y,zoom}}` → `{layoutRevision}`；positions 0–200 个、坐标范围沿用 S1，视口平移范围 ±1000000，zoom 0.05–10。保存一次布局历史，允许只保存视口。
- `GET /knowledge/graph/history?before=&limit=20` → `{items:[{revision,createdAt,positionCount}],nextCursor}`（修订倒序）。
- `POST /knowledge/graph/history/{revision}/restore`：`{expectedRevision}` → `{layoutRevision}`；恢复该次保存**之前**的受影响坐标／视口，只处理仍 ACTIVE 的概念，产生新历史，不更改正文。CAS 防止覆盖其他标签的布局。历史每次存变化前后数据，而非回滚全库。

S1 `/graph/layout` 保存也必须纳入同一历史机制。新概念／归档恢复引发的全局布局修订保留，历史修订不要求连续。主题筛选、搜索定位、邻域展开只调整可见性与镜头，不自动重排。显式重新布局先在前端预览，用户确认后走布局保存；取消恢复预览前数据。列表提供等价选择、关系和移动操作，减少动效遵循系统设置。

坐标与视口分开读取时必须核对 layoutRevision 一致；若不同，重新读取成对快照。不得用较新视口的修订号替旧坐标升级 CAS 基线。本地已有未保存编辑时保留原基线，不自动合并后台更新。

## 5. 脑图与白板

- `GET /knowledge/boards?cursor=&limit=20` → `{items:BoardSummary[],nextCursor}`。
- `POST /knowledge/boards`：`{kind:MIND_MAP|BOARD,title}` → `BoardDetail`。
- `GET /knowledge/boards/{id}` → `BoardDetail`。
- `PUT /knowledge/boards/{id}`：`{expectedRevision,title,nodes,edges,viewport}` → `BoardDetail`。
- `GET /knowledge/boards/{id}/history?before=&limit=20` → `{items:[{revision,title,createdAt}],nextCursor}`。
- `GET /knowledge/boards/{id}/history/{revision}` → `BoardSnapshot`；历史存引用 ID 与当时的显示快照，不用新原文冒充当时内容。
- `POST /knowledge/boards/{id}/history/{revision}/restore`：`{expectedRevision}` → `BoardDetail`，产生新修订。
- `POST /knowledge/boards/{id}/nodes/{nodeId}/convert`：`{expectedRevision,title}` → `{board:BoardDetail,itemId}`，把临时 TEXT 节点的正文显式转为独立笔记并将该实例改为引用；一个事务＋幂等回执。
- `POST /knowledge/boards/{id}/edges/{edgeId}/convert`：`{expectedRevision,type:RelationType}` → `{relation:Relation}`，仅允许两端为 ACTIVE CONCEPT 引用；复用正式关系的自环／环路／对称去重规则；不把普通连线自动升级。

`BoardSummary={id,kind,title,revision,updatedAt}`；`BoardDetail={id,kind,title,revision,updatedAt,nodes,edges,viewport,references:BoardReference[]}`；`BoardSnapshot` 同样包含上述字段，但 references 是保存时的发布版本快照。`BoardReference={itemId,kind,title,status,versionId,versionNumber,body}`；当前读取使用最新发布内容，历史引用保留当时版本。

`BoardNode={id:UUID,type:REFERENCE|TEXT,itemId:UUID|null,text:string,x:number,y:number,parentId:UUID|null,collapsed:boolean,group:string|null}`。最多 100 节点；临时文本每个最多 5000 字，总计 50000 字；REFERENCE 的 text 为空、itemId 必填，TEXT 的 itemId 为 null；引用对象可以多实例存在。最多 200 条边，`BoardEdge={id:UUID,source:UUID,target:UUID,label:string}`，label≤100 字。父节点属于同画布且无环；MIND_MAP 最多单父层级，父子边仅为排版关系。节点移出画布不删除知识对象；删除节点实例时一并移除相连画布边，子节点提升为根。group≤40 字，只用于画布分组。

标题≤200 字，坐标／视口范围沿用星图。保存服务端验证结构、归属与容量，超限拒绝不截断。引用正文可能过长：画布引用展示和历史快照每项正文最多 2000 字并明确是预览，完整原文从对象版本接口读取；服务端单次返回保持在回执容量内。画布保存与恢复均 CAS；历史恢复遇到不可用引用显示说明并拒绝，不静默丢卡。客户端提供拖动、键盘移动、连线、分组、对齐、折叠、缩放、撤销／重做与 JSON／Markdown 下载；保存后的撤销通过历史恢复产生新修订。训练快照待 S4，不把画布保存当作已提交答案。

## 6. 静态检查与服务器验收

本地仅类型／编译／打包、契约映射与代码审查；不运行应用、数据库、浏览器服务或单元测试。运行验收覆盖 AC-06/07/08/09/11/12/13/14/15/16/43/44 的 S2 子集，详细执行记录放开发记录与审查目录。

必须在服务器验证：关联／主笔记 CAS、正文 AST 引用与历史定位、归档关联可见性、索引落后／损坏／重建中写入／进程中断、中文及 Java 标识符召回、图谱 200／600 上限与键盘等价入口、布局保存后撤销与并发冲突、画布多实例及显式转换幂等、会话过期保留未保存输入。未执行不得标记通过。
