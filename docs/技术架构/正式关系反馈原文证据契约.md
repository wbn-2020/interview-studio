# 正式关系反馈原文证据契约

版本：v1.2 · 2026-11-10。适用 S5 第二十四批，并说明第二十五批 AI 反馈与第二十九批面后回忆证据的独立边界；状态：本批原实现静态检查通过待服务器验收。承接 PRD KNOW-06／07、[正式关系补充契约](正式关系补充理由与来源契约.md)及[资料／训练直接原文证据契约](正式关系直接原文证据契约.md)。实际进度以[开发记录](../开发记录/开发阶段与进度.md)为准，本契约 §10 保留第二十四批最终检查证据；静态检查与构建不表示迁移、接口或视觉验收通过。

## 1. 范围与独立身份

本批允许用户从确切自检 SELF_CHECK 或手工外部反馈 EXTERNAL_FEEDBACK 修订中，选择原文字段片段并说明理由，追加为本人已有正式关系的独立证据。本接口仅支持这两类人工反馈；第二十五批通过[独立 AI 反馈台账](正式关系AI反馈原文证据契约.md)接入成功评价的单条观察，第二十九批通过[独立回忆台账](正式关系面后回忆原文证据契约.md)接入面后回忆，不扩本 DTO、V50、快照或回执。资料／训练生成关系候选另见[第二十六批契约](资料训练来源关系候选契约.md)，各批状态分别以开发记录为准。

每次确认追加一条不可变台账，保存原 relationId、规范化端点／类型、理由、确切反馈修订、当时决定及来源快照。追加不改变关系 ID、端点、类型或 revision，不新增图边、不改变正式路径／计数／布局；不改写原反馈、反馈决定或既有证据，不将已争议／忽略的反馈自动改为接受。

新台账与 V49 的 MATERIAL／TRAINING 直接证据分别保存，不扩展或重写 V49 DTO、快照与回执；也不改变 AI 任务、Manifest、模型用途或外发规则。保存为本地人工操作，不调用模型、不新增费用。复用 ReviewDraftSources 和 ReviewDraftInput 只用于来源校验与固定存储，不构成 AI 预览或外发授权。

反馈的来源、覆盖判断、决定和必要限定都须可回看。保存原文、引用区间匹配或来源为 CURRENT，只表示出处链可按规则核对，不证明反馈正确、原答案正确、技术能力或关系语义成立；用户理由不能覆盖原反馈中的条件、依据和限制。

## 2. 主动选择与窄来源读取

用户主动查询既有 growth MANUAL_FEEDBACK 元数据目录，按确切 feedbackId＋revision 选择一条，再请求本批新增的反馈来源接口。目录摘要用于定位，不作为保存时原文或最新决定的替代证据；目录可能返回旧修订，来源接口只接受仍为 currentRevision 的明确修订。

`GET /api/v1/knowledge/relation-feedback-sources/{feedbackId}?revision=...` 返回[FeedbackText](../../backend/src/main/java/com/wenjie/studio/ai/ReviewDraftDtos.java)，内容为反馈身份／修订、确切答案三元组、提交编号与条件、dimension／coverage、当前决定修订／choice，以及 observation、condition、basis、limitation、suggestion 五个原文字段。不返回题面、原答案正文、反馈 citations、authorLabel、其他反馈或其他修订正文。

[ReviewDraftSources.readFeedbackSource](../../backend/src/main/java/com/wenjie/studio/review/ReviewDraftSources.java)读取指定修订并核验持久元数据、实际当前头及原答查看条件，再检查 revision 等于 currentRevision；旧修订、读取失败或权限不足都不能回落到最新正文。查询失败保留用户已选身份，要求重新核对。反馈修订范围 1–100，决定修订为 0–20；0 表示该反馈修订尚无决定，此时 decisionChoice=null。

来源目录不是额外的原文出口。当前[反馈选择器](../../frontend/src/components/RelationFeedbackPicker.vue)只有在用户提交日期查询后才访问 growth `/evidence?kind=MANUAL_FEEDBACK`，不自动扫完全部记录；选择后由新来源接口读取五字段原文。目录的标题、时间或作者等既有元数据不扩大新来源响应范围。

## 3. 创建选择与固定快照

[共享 DTO](../../backend/src/main/java/com/wenjie/studio/knowledge/RelationFeedbackEvidenceDtos.java)的请求为：

```text
Create = {reason, source, confirmed}
Selection = {kind, feedbackId, feedbackRevision, expectedDecisionRevision, answer, fragments}
answer = {sessionId, questionId, answerId}
fragment = {field, start, end, quote}
```

三个顶层字段及 source 的全部字段必填，confirmed 必须 true。kind 仅 SELF_CHECK／EXTERNAL_FEEDBACK；answer 是所选反馈真正关联的确切提交，不接受跨会话／题目／答案拼接。feedbackRevision 必须仍为当前修订，expectedDecisionRevision 必须与首次写事务内读取的决定修订一致。决定发生变化时整次写入拒绝，不把用户旧确认自动更新为新决定。

reason 原样保存，长度 1–1000 个 UTF-16 码元；拒绝 NUL、孤立代理，以及全部由 `Character.isWhitespace` 或 `Character.isSpaceChar` 组成的内容，不 trim 或覆盖旧理由。

fragments 为同一反馈修订的 1–8 项，按用户选择顺序保存，只允许 OBSERVATION、CONDITION、BASIS、LIMITATION、SUGGESTION。每项 start／end 为整数，`0 <= start < end`，与该原字段的 UTF-16 半开区间逐字对应，不越界、不切断代理对；quote 的 UTF-16 长度等于 end−start，最多 8000，拒绝 NUL／孤立代理并沿 Java `isBlank` 兼容规则。相同 field 的选区不可重叠或重复，相邻选区允许。

反馈完整字段沿原领域码点规则：observation 最多 2000 个码点；condition、basis、limitation、suggestion 分别最多 1000 个码点，condition 可为空，其余按 Java `isBlank` 要求非空白。理由、选区 quote 与完整反馈字段的计长／空白口径不同，不能把新理由规则套到合法历史原文。

服务端保存的 source 是 `ReviewDraftDtos.Input={kind,feedback,recollection:null}`。feedback 固定如下内容：

| 内容 | 固定字段与规则 |
|---|---|
| 来源身份 | feedbackId、feedbackRevision、answer 三元组；不由摘要标题推导。 |
| 当时作答与反馈条件 | answerNumber、answerCondition、dimension、coverage。 |
| 当时决定 | decisionRevision、decisionChoice；保存当时值，不因后来改决定而重写。 |
| 必要限定全文 | condition、basis、limitation；即使未选这些字段的片段也完整保存。 |
| 用户明确选择 | fragments 中五类字段的原文 quote 与原字段绝对 UTF-16 区间，顺序固定。 |

因此快照不只是选中的 quote：来源条件、依据、限制随选区一并固定，避免把脱离条件的反馈当作无条件结论。未选中的 observation／suggestion 全文不额外保存；题面、原答案、citations 和 authorLabel 不进入该快照。服务器从确切反馈源构造必要限定和决定，客户端摘要或旧缓存不能代替持久原文。

首次保存还必须核对确切正式关系存在、两个概念端点均 ACTIVE。PRECEDES／PART_OF／APPLIED_IN 保留方向，RELATED／CONTRASTS 按小写 UUID 字典序归一，自环无效；原 relationId 失效不得自动改绑同元组的新关系。

## 4. 四个操作与三个路径

接口以 `/api/v1` 为前缀，受登录、owner 隔离、独立训练资料守卫及本批确切答案评价权限约束。写命令要求 CSRF 与 Idempotency-Key；owner 从认证上下文取得，ID 为标准小写 UUID。

| 方法与路径 | 输入 | 响应 |
|---|---|---|
| GET `/knowledge/relation-feedback-sources/{feedbackId}` | 必填 revision | FeedbackText；只读用户选中的当前确切反馈修订及五字段原文。 |
| GET `/knowledge/relations/{relationId}/feedback-evidence` | 可选 cursor／limit，limit 默认 20、范围 1–20 | Page，只有记录元数据，不读取或返回 snapshot。 |
| POST `/knowledge/relations/{relationId}/feedback-evidence` | Create | 201 Entry，只返回元数据回执。 |
| GET `/knowledge/relations/{relationId}/feedback-evidence/{evidenceId}` | 原 relationId＋evidenceId | Detail，显式返回该条固定来源快照及 sourceState。 |

| 对象 | 字段 |
|---|---|
| Entry | `id,relationId,sourceId,targetId,type,reason,sourceKind,feedbackId,feedbackRevision,sourceCount,createdAt`。sourceId／targetId 是关系概念端点，sourceCount 为片段数。 |
| Page | `relationId,relationExists,items,nextCursor`；items 为 Entry。 |
| Detail | `entry,relationExists,source,sourceState`；source 为固定 ReviewDraftInput，不是重新拼装的最新反馈。 |

[OpenAPI 规格](openapi-s7.json) v7.18.0 定义 `getKnowledgeRelationFeedbackSource`、`listKnowledgeRelationFeedbackEvidence`、`createKnowledgeRelationFeedbackEvidence`、`getKnowledgeRelationFeedbackEvidence` 四个新 operation，并新增 RelationFeedbackEvidenceSelection、CreateRelationFeedbackEvidence、RelationFeedbackEvidenceEntry、RelationFeedbackEvidencePage、RelationFeedbackEvidenceDetail、RelationFeedbackEvidenceSource 六个具名 schema。[生成类型](../../frontend/src/api/schema.d.ts)已包含对应三路径、四操作及六对象；固定快照在本批 Detail schema 中约束为两种反馈，不改变旧 ReviewDraftInput 或 V49 机器契约。

[前端边界校验](../../frontend/src/api/relationFeedbackEvidence.ts)检查实际响应的精确字段、UUID、关系元组、反馈修订、答案三元、决定组合、计数、时间及选区范围。来源与快照的 dimension、片段的 field 在枚举键查询前显式要求字符串，拒绝以数组／对象转成属性名的异常值。Page 校验 UUID 顺序、同元组及 nextCursor；Detail 对照所选 Entry 完整指纹，并核对来源种类、反馈 ID／修订和片段数量。JSON Schema maxLength 的码点语义、生成类型与运行时 UTF-16／逐字原文检查各有边界，不能互相替代。

POST 原始 JSON 上限 262144 bytes，严格拒绝重复键、未知／缺失字段、尾随 JSON、错误类型、数字枚举、字符串或浮点整数与隐式标量转换。快照按实际 UTF-8 JSON 字节数限制为 1048576 bytes（1 MiB），计入所有字段与转义；超限返回 422 `RELATION_FEEDBACK_EVIDENCE_TOO_LARGE`，不截断原文，不提交台账或回执。该限制是保存快照的大小，不是整个 Detail HTTP 响应大小。

记录列表按 evidence UUID 字典序升序，cursor 为排他 `id > cursor`，nextCursor 只在还有下一页时取本页末项 ID；不按 createdAt 排序，不提供跨请求快照。列表／Entry SQL 不读取 snapshot_json，但理由可能包含反馈内容，仍须核对每条记录对应答案的评价访问条件，包括 limit＋1 的下一页探测行。

| 状况 | 结果 |
|---|---|
| 请求身份、文本、选区、字段、修订范围或确认无效 | 400 INVALID_REQUEST。 |
| 来源修订非当前、首次保存决定修订／答案绑定／片段发生变化 | 409 RELATION_FEEDBACK_SOURCE_CHANGED。 |
| 确切反馈或原答不存在／不可访问 | 沿来源模块 404 AI_REVIEW_SOURCE_NOT_FOUND；不回落其他修订。 |
| 尚未授权原答评价区 | 409 AI_EVALUATION_ACCESS_REQUIRED。 |
| 尚未确认提前查看本场结束后反馈 | 409 AI_EARLY_FEEDBACK_CONFIRMATION_REQUIRED。 |
| 指定关系不可访问，或列表既无本人边又无本人历史 | 404 RELATION_NOT_FOUND。 |
| 首次保存时端点已归档 | 409 RELATION_ENDPOINT_ARCHIVED。 |
| 证据不属于本人或不属于路径中的原 relationId | 404 RELATION_FEEDBACK_EVIDENCE_NOT_FOUND。 |
| 同键改变操作或请求 | 409 IDEMPOTENCY_KEY_REUSED。 |

## 5. 原答权限、读取次序与历史状态

通用资料守卫与确切答案评价守卫分别执行。后者按 sessionId／questionId／answerId 读取权限和反馈时机元数据，不为权限检查加载题面、原答或标准正文。必须存在该提交的评价区授权；若会话尚未结束、约定 AFTER_SESSION 且未确认 earlyFeedback，则拒绝。历史证据、元数据理由或原键回执都不是跳过该条件的通道。

[领域服务](../../backend/src/main/java/com/wenjie/studio/knowledge/RelationFeedbackEvidenceService.java)的历史详情先读取并核验 Entry 元数据，按台账 row.answer 调用 `requireAnswerAccess`，通过后才读取 snapshot_json，严格解析固定字段和来源结构、核对绑定，最后调用 `state`。不能先调用 `current` 将权限拒绝吞成 false，也不能在权限失败时仍返回“来源不可用”的正文。

绑定核对包括 sourceKind、feedbackId／feedbackRevision、sourceCount、answer 三元组以及固定 decisionRevision／choice。列表和详情还校验台账中的非零决定是否确实对应独立决定行；缺失决定、choice 不符、坏 JSON、字段类型／形状损坏或数据库异常均报错，不伪装为空页或正常失效。

sourceState 保留原反馈来源的四种状态，不折叠成可用布尔值：

| sourceState | 含义 |
|---|---|
| CURRENT | 原反馈修订仍当前，按现行规则重建的固定来源及决定与保存快照一致。 |
| SUPERSEDED | 反馈已有较新的当前修订，保存的旧修订与选区继续保留。 |
| REVIEW_REQUIRED | 确切来源仍可定位，但决定或相关来源条件与保存时不同，或出现已识别的正常来源变化；须重新核对。 |
| UNAVAILABLE | 确切反馈来源当前无法取得；不得把原答权限拒绝当作此状态。 |

`state` 只将明确来源缺失转为 UNAVAILABLE，将正常来源变化转为 REVIEW_REQUIRED；评价授权／提前反馈错误继续抛出，决定修订倒退和固定身份损坏属于完整性错误。CURRENT 同样不证明反馈或关系正确。原来源修订、当时决定、必要限定和 quote 不随 sourceState 改写。

## 6. 首次写入、原键恢复与删边历史

创建使用[七参数幂等命令入口](../../backend/src/main/java/com/wenjie/studio/common/IdempotencyService.java)，传入独立 accessGuard。在同一 owner 写锁内，先执行通用资料守卫和 `requireAnswerAccess(owner,request.source.answer)`，再读取已有回执；因此同键回放也必须满足本次原答评价查看条件。

仅首次执行 action 时重核原关系 ACTIVE 端点，再从真实反馈捕获当前修订／原答／决定／片段。实际固定来源的 kind、feedbackId、revision、answer 必须与请求一致，decisionRevision 必须等于 expectedDecisionRevision，fragments 必须保持原选择与顺序。全部核对、台账插入、写后元数据与绑定复读、Entry 回执在同一事务中提交；任一步失败整笔回滚。

同键同请求恢复原 Entry，不重新要求反馈仍当前、决定仍相同或原边仍存在；但当前访问权限继续核对。回执只表示原命令元数据，不代表已重新读取来源正文。不同键为新的追加，台账不自动按理由或反馈选区去重；网络结果未知时保留原键及完整请求恢复，不能自动换键。

正式关系删除后历史记录继续以旧 relationId 保留，relationExists=false；读取权限与固定来源规则照常执行。相同端点／类型重新创建得到新 ID，新边不继承旧证据；原键回放也不重建旧边。边删除与原反馈决定是不同生命周期，不能因删边撤回或改写原决定。

## 7. V50 持久化约束

[V50](../../backend/src/main/resources/db/migration/V50__relation_feedback_evidence.sql)新增 `knowledge_relation_feedback_evidence`，存储 owner、evidenceId、原关系 ID 与规范化元组、理由、反馈种类／ID／修订、片段数量、答案三元、决定修订／choice、snapshot_json 和 created_at。不建立到可删除正式边的外键。

来源外键分别使用 `(owner,feedbackId,sessionId,questionId,answerId)` 绑定真实反馈与其原答，`(owner,feedbackId,feedbackRevision)` 绑定确切反馈修订，`(owner,feedbackId,feedbackRevision,decisionRevision)` 绑定当时决定。接口／快照中的 decisionRevision=0 在数据库列转换为 null，decisionChoice 同为 null；非零决定范围 1–20 且 choice 为 ACCEPTED／DISPUTED／IGNORED，不以伪造的第 0 行占位。

迁移 CHECK 限制两种 sourceKind、反馈修订 1–100、片段数 1–8、决定条件字段、五种关系类型、无自环与对称规范化，以及 JSON 对象和 OCTET_LENGTH≤1048576。数据库 reason 的字符长度 CHECK 不替代 Java UTF-16、Unicode 和空白校验；快照 shape、确切绑定、片段逐字匹配与非重叠由领域层核验。

当前[mapper](../../backend/src/main/resources/mapper/knowledge/RelationFeedbackEvidenceMapper.xml)只提供查询与追加，未提供覆盖或删除台账操作；Entry 查询按固定决定修订连接决定行，不拿后来最新决定替换原 choice。迁移仅完成文本核对，真实 MySQL 约束及历史数据升级尚未执行。

## 8. 已实现界面与恢复边界

当前反馈选择器要求用户主动按日期查询 growth MANUAL_FEEDBACK，默认最近 28 天，可调整为最多 366 天；每页 20 项，沿 growth 水位／游标规则并核对 asOf。上一页使用同次查询已验证的元数据页，空页可继续后续游标；扫描受限／能力不可用不被显示为“无记录”。选择只传 kind、feedbackId／revision 与 answer 三元，正文另行显式读取。

[追加表单](../../frontend/src/components/RelationFeedbackEvidenceCreate.vue)显式读取所选反馈修订，核对返回种类、revision 与原答案三元；展示当时决定、作答条件、维度／覆盖，以及将随证据完整保存的 condition／basis／limitation。用户从五字段只读原文拖选、使用键盘选择或输入原字段 UTF-16 起止位置，逐段加入 1–8 个片段。textarea 的换行归一会映射回原文下标，quote 保持原换行；实际坐标行为仍待浏览器验证。

理由、片段、字段或选区改变时撤销确认；访问代次变化保留理由、确切修订、片段与未加入选区，隐藏原文并要求显式重核。重核比较包含原文、作答条件及决定的来源指纹，差异会保留旧输入并提示用户主动重选，不能自动改用较新修订或决定。重选在用户确认且新来源成功读取后才替换旧片段，读取失败不丢旧稿。

保存明确确认后使用固定请求与幂等键。Entry 回执只核对元数据形状、原 relationId、reason、sourceKind、feedbackId／revision 和 sourceCount；不因保存成功自动读 Detail，也不声称回执已逐项比对 quote 或必要限定。回执不匹配保留原请求／键；未知结果用原请求恢复。会话或访问条件变化后到达的合法回执暂缓接收，恢复访问后提供接收入口；新追加不可用时仍保留原键恢复能力。

[历史面板](../../frontend/src/components/RelationFeedbackEvidencePanel.vue)按用户展开读取每页 20 条元数据，明确展开单条才请求其固定快照，并用 Entry 指纹确认详情仍属于所选记录。只有有效分页响应才推进游标；失败重试保持原目标页，创建表单不随列表载入而卸载。详情展示当时反馈修订、原答与条件、决定、必要限定全文、选区及四态来源说明，并链接确切反馈修订；刷新记录或访问变化会清除已读详情，迟到响应受会话、访问代次和请求序号约束。

详情若已合法确认 `relationExists=false`，面板记录该原关系已移除并禁止新追加；收起详情、清空详情或请求失败不会解除这个状态，只有新的有效 Page 响应可重新判定。已有表单保稿且可恢复原请求。`removedConfirmed` 不用于改绑同元组新关系，服务端首次写入仍核原 ID。

[关系列表](../../frontend/src/components/ConnectionsPanel.vue)为知识补充、资料／训练证据与反馈证据使用各自状态键，汇总 dirty／locked 后保护离开、分页、删除和后台数据刷新。关闭面板／表单先检查未保存输入，访问受限时隐藏内容并保留表单状态。上述行为已有源码及独立静态复核证据；真实选区、换行、重试、跨标签权限、键盘与窄屏交互仍待服务器验收。
