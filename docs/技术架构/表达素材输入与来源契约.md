# 表达素材输入与来源契约

版本：v1.2 · 2026-11-12。适用：S5 第十四批表达来源、S8 第九批依据复核及第十批知识传播接入。S5 原范围静态检查通过待服务器验收；S8 接入代码及专项检查完成，整仓前端构建受参考界面缺件阻塞，数据库、模型和界面尚未运行验收。承接[准备版本生成候选](准备版本生成候选契约.md)、[附件摘录生成候选](附件摘录生成候选契约.md)及 PRD MAT-03–05、AI-02–06；实际进度仅见[开发记录](../开发记录/开发阶段与进度.md)。

## 1. 用户流程与事实边界

用户明确选择已有表达的当前版本，可与知识、目标、项目、已确认事实和已保存摘录混选 → 核对外发文本与费用 → 本次授权 → 阅读知识／题目候选与引用 → 编辑后显式采用或忽略。表达属于用户写作素材；有事实依据、曾由 AI 生成或被用户采用，都不证明表达的每句话真实、技术正确或已经掌握。

表达自身必须 ACTIVE 且为当前版本，正文非空白。其保存的 1–50 个事实依据必须仍为确切当前、已确认、所属项目 ACTIVE 的版本。沿用现有准备域的事实核实与职责约束；不把表达的修辞、假设、参与或仅了解改成新增经历或本人负责。

知识／准备／摘录合计 1–5 个明确外发来源；表达的事实依据仅用于本地检查，不占外发来源名额，不自动追加到模型输入。需要把关联事实作为独立来源外发时，用户须另行选择该 FACT，并计入五项上限；已写入表达正文或要求中的文字仍会发送。新批不改事实生成表达的 EXPRESSION_DRAFT 用途，不扩大训练背景、评价、追问或准备建议的输入范围。

## 2. 固定投影与授权检查

外层沿用 `Source={itemId,versionId,number,kind,title,body}`，kind 新允许 EXPRESSION。表达 body 为按 `type,body` 顺序序列化的紧凑 JSON，保留原值；type 为已有五种表达类型。正文不截断；空白、NUL、孤立代理或超出既有存储上限的无效表达不能作为新输入。外发清单完整展示固定投影，不带标签、factVersionIds、事实／项目正文、核实理由、附件、来源地址或采用历史。用户手工写进允许字段的文字仍会发送。

Manifest 尾新增可缺省、可空 `expressionChecks`，元素为 `PreparationDtos.ExpressionCheck={expression,factChecks}`。二者复用 SourceCheck 的身份、状态与代次结构：expression 为该 EXPRESSION 的自身检查，projectGeneration=null；factChecks 按表达原 factVersionIds 顺序保存 1–50 个 FACT 的 sourceGeneration 和 projectGeneration。每项在授权时均须 CURRENT，代次为安全非负整数。表达项与 sources 中的表达逐一对应，其自身检查还须与 preparationChecks 中的同项完全相等；不接受缺项、额外项、重复身份或空列表。

检查时双向核对表达正文的 factVersionIds 和保存的关系：owner、目标对象／版本、FACT_BASIS 用途、FACT 类型、事实对象／版本、数量与集合必须一致；不依赖 `reviewRequired=false` 证明依据完整。正常来源不可用与数据库／数据结构故障分别处理，故障不得伪装成已撤回来源。原准备 `read/check` 保留边界，表达走专用入口，读取加入调用方事务。

检查快照参与授权摘要，只用于本地核对，不外发模型。表达改版、归档后恢复、事实撤回后确认、事实归档后恢复或父项目改版／归档恢复，都会使原授权失效；收藏不影响来源代次。S8 第九批按[表达素材依据复核契约](表达素材依据复核契约.md)增加持久保存基线，缺基线或代次不匹配的当前表达返回 UNVERIFIED，不能创建新预览；用户显式确认或保存新版本后方可按新基线预览。确认推进表达自身代次，旧授权不恢复。创建、重试、排队恢复、领取、发送、接纳和采用继续比较自身及全部依据快照；旧清单形状与摘要不改。

外发字节和费用覆盖与网关相同的 `{purpose,instruction,sources}`，有摘录时另带 materialDraftSources，沿用 32 KiB 限额及已有输出／预算限制；本地 expressionChecks 不计为外发正文。引用仍针对 Source.body 的整个 JSON 文本使用绝对 UTF-16 半开区间，逐字、代理对和去重规则沿用现有候选；不得引用未单独选择的事实正文。

## 3. 接口、版本与存储

复用 `/api/v1/ai/preparation-drafts/preview|tasks` 和 `/api/v1/ai/material-drafts/preview|tasks`；PreparationLink.kind 扩展 EXPRESSION，请求字段和用途 KNOWLEDGE_DRAFT／QUESTION_DRAFT 不变。纯知识、旧准备来源与旧资料混选保持原提示版本。清单中只要包含表达来源，就使用下表版本：

| 内容 | 知识整理 | 出题 |
|---|---|---|
| 无摘录的表达混选 | expression-source-knowledge-draft-1 | expression-source-question-draft-1 |
| 有摘录的表达混选 | expression-source-material-knowledge-draft-1 | expression-source-material-question-draft-1 |

无表达时 expressionChecks 必须 null；其他专用用途拒绝非空值，训练整理也不得混入。旧清单／回执缺此字段按 null 读取，不重写历史 JSON 或摘要；升级前未提交的预览若摘要不匹配须重新预览。固定输出、采用请求及幂等 operation 复用既有语义。

V26 仅扩展 ai_preparation_source 的来源类型 CHECK，表达关系继续使用 owner 复合外键及确切版本。V20 原文不改；不新增表或依赖。任务／关系／费用／回执的创建事务、知识版本／题目版本的显式采用和一次决定均沿用现有流程；依据失效保留用户改写，忽略不要求来源当前，关闭模型后仍可采用有效候选。

采用来源以原清单为历史依据，核对持久关系的身份、顺序、数量与当时元数据；表达自身为 `UNVERIFIED` 时，采用来源显示 `REVIEW_REQUIRED`，表示表达依据待复核；其他非 CURRENT 状态按原状态显示。自身 CURRENT 而依据失效或任何授权代次变化时同样显示 `REVIEW_REQUIRED`。只检查该条表达及其依据，不因同任务另一条独立来源变化而误标所有表达。原标题、版本、候选及引用保留，入口回到确切表达版本。S8 第九批只接入表达自身依据复核；准备来源到已采用知识的更正传播由[第十批契约](准备来源知识更正传播契约.md)接入，实施状态见开发记录；完整删除传播仍未覆盖。

## 4. 界面与恢复

现有来源选择器增加“表达素材”；只读详情确认当前版本、非空正文及动态依据状态，服务器预览再执行完整核对。事实生成表达和准备建议选择器继续限定原有类型。选中表达显示它是用户表达；清单显示完整 type/body，并说明关联事实只做本地检查、未选中时不外发正文。

预览及创建回执核对表达来源、检查快照和提示版本，输入变化撤销预览和同意。原键恢复、会话代次、迟到响应、未决请求和离开保护沿用现有流程。知识／题目引用与采用历史按 EXPRESSION 跳转准备工作区确切版本，不能落入知识对象路由。来源变化只改变可用性提示，不覆盖正在编辑的最终内容。
