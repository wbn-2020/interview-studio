# 跨模块统一检索契约

版本：v1.2 · 2026-11-11。状态：三批静态检查通过待服务器验收，未作运行或视觉验收。本文主体记录第一批统一只读检索、确切来源查看及回链；训练／人工反馈／面后回忆见[第二批契约](训练复盘与回忆检索契约.md)，AI评价固定观察及有界报告扫描见[第三批契约](AI评价观察检索契约.md)。完整产品范围见[产品需求](../需求文档/产品需求文档.md)，进度以[开发阶段与进度](../开发记录/开发阶段与进度.md)为准。

## 1. 范围与读取条件

第一批覆盖 KNOWLEDGE（已发布笔记／概念）、PREPARATION（目标／项目／事实／表达）、MATERIAL_EXCERPT（已保存资料摘录）和 QUESTION（题面）。提供统一入口，按单域查询及分页，不混合排序，也不提供精确总数。

默认 ACTIVE；可明确查看 ARCHIVED。资料没有归档状态，ARCHIVED 查询返回 applicable=false 的空页。资料模块关闭时沿用 MATERIALS_DISABLED，不通过直接 SQL 绕过配置。知识草稿、非摘录解析全文、题目参考／检查项、未揭示卡片答案、训练回答、反馈报告和面后回忆不在本批搜索范围。后续各域接入须单独补齐访问条件；本批不代表全部跨域检索完成。

所有出口按 owner 读取，并纳入普通训练资料守卫；请求入口和 GET 序列化前均检查。独立训练未确认资料查阅时不得搜索或查看来源；前端响应代次变化拒绝迟到正文，遮挡期间停止查询并清除展示。路由不加入授权元数据或追问通知的豁免集合。

检索只用于发现和导航，不调用模型、不自动选入上下文，也不形成 AI 外发许可。后续跨域问答的显式来源选择、完整清单预览与授权另批接入，不扩展既有仅接受摘录的资料问答契约。

## 2. 查询与分页

`GET /api/v1/search?domain=KNOWLEDGE&q=缓存&status=ACTIVE&offset=0&limit=20`

- domain 必填且只接受本批四值；q strip 后 1–100 个 UTF-16 单位，不接受不完整代理对；status 为 ACTIVE／ARCHIVED，默认 ACTIVE。
- limit 为 1–50，默认 20；offset 为 0–1000，默认 0。offset 按最终可见匹配计数；额外一条有效命中才 hasMore，到分页上限返回 scanLimited。翻页不是数据库快照会话，内容变化后可能重复或漏项，刷新从首页重新查询。
- KNOWLEDGE 复用既有 Lucene 候选、最多 4096 条和数据库当前版本／组织修订回验，matchMode=ANALYZED。保留 READY／BUILDING／DEGRADED／DISABLED 状态，不把空结果或失效索引说成全库无资料，不自动启用 SQL 全文退路。
- 其余域 matchMode=LITERAL、indexStatus=null。仅在白名单文本上做有界候选查询，对 `!`、`%`、`_` 转义，最终按原文字面忽略大小写匹配。候选按固定 id 降序分批读取，每批最多 100、累计最多 4096；上限造成不完整时 scanLimited=true。候选 SQL 可放宽，但不得用未展示的 JSON 键／身份／参考产生最终命中。全部来源 SELECT 设置 5 秒语句超时，编排只读事务总上限 20 秒；超时作为错误返回。4096 限制 Java 接收候选数，不代表 MySQL 实际扫描行数上限；SQL 执行计划、超时和字符排序规则仍待服务器验证。
- Page 返回 domain/query/status/matchMode/applicable/indexStatus/items/limit/offset/hasMore/scanLimited。各域独立展示范围及状态，不能假设相关度一致。

## 3. 白名单与版本身份

| 域 | 原文白名单 | 确切身份与状态 |
|---|---|---|
| KNOWLEDGE | title、body | itemId＋已发布 versionId；列表只匹配当前发布版本，详情可读历史版本；别名／标签可能参与分词匹配，但属于当前组织元数据，不伪造为该版本的固定正文 |
| PREPARATION/TARGET | title、company、jd、requirements[].text | itemId＋versionId；不搜 URL、要求 ID、链接身份、周预算等结构字段 |
| PREPARATION/PROJECT | title、overview、technology | itemId＋versionId；不搜来源 URL 或来源备注 |
| PREPARATION/FACT | title、scenario、problem、action、result、technology、tags[] | itemId＋versionId；分别呈现对象状态、当前 verification 与所属项目当前状态 |
| PREPARATION/EXPRESSION | title、body、tags[] | itemId＋versionId；不返回事实版本 ID，不把可读表达当作事实依据已复核 |
| MATERIAL_EXCERPT | locator、text；附件名只作展示标题 | excerptId 即固定摘录身份；统一接口约定 versionId=excerptId、versionNumber=null，不创建伪造数据库版本；保留 attachmentId／runId |
| QUESTION | title、prompt、conditions、technology、scenario、tags[] | questionId＋versionId；不读 reference_answer／checkpoints_json，不返回含它们的输入 DTO |

搜索匹配与来源详情使用同一白名单投影。数组拆成固定字段键，例如 requirements.0.text、tags.0；不把 JSON 序列化字符串当正文。题目类型、技术字段及准备类型不改变原对象身份；题目参考仍需原模块显式打开并记录曝光。

Hit 返回 domain/id/versionId/versionNumber/kind/title/status/currentVersion/verification/projectStatus/attachmentId/runId/fragments。可空字段显式为 null；准备核实及父项目状态反映读取时的当前元数据，不认证旧版本事实。currentVersion 仅表示当前版本指针匹配，ACTIVE 仅表示对象未归档。固定摘录使用 READY、kind=EXCERPT；父项目不存在显示 UNAVAILABLE。表达须提示事实依据未在搜索中复核。

## 4. 命中片段与确切原文

`GET /api/v1/search/sources/{domain}/{id}?versionId=...&q=缓存`

domain/id/versionId 必须有效且身份、owner、版本对应；q 与搜索一致，必填。返回 Source={item,fields}；fields 为完整白名单 TextField={id,label,text}，item 的状态和当前性在本次读取重新核对。当前列表与历史详情分开，详情允许读取确切历史或归档版本，不用最新版本静默替换。资料须满足固定摘录与 READY 附件、SHA、既有解析执行／片段／选区的一致性；不读取磁盘原件，不替换成最新解析结果。

每项列表最多三个 Fragment，按白名单字段顺序选择首个完整检索词命中。text 是原字段的连续子串，最长约 300 UTF-16 单位，代理对完整；startOffset/endOffset 为片段在字段中的半开区间，matchStart/matchEnd 为命中在同一字段原文中的半开区间；不在片段中添加省略号。lineStart/lineEnd 为命中所在的 1 起始行号，按 CRLF／CR／LF 分行，与知识版本查看器一致；CRLF 只计一次换行，原文和 UTF-16 偏移不被规范化。匹配定位直接在原文计算，不复用转小写后字符串的下标。

分词、别名或标签命中可能没有完整检索词原文定位，此时 fragments=[]，页面说明原因，不伪造命中行或把旧知识 excerpt 当证据选区。片段只是检索展示，后续引用仍需显式选择完整字段和确切范围，不能自动授权。

前端以文本插值和可信区间切分高亮，不使用 v-html。选结果后显式读取确切来源、显示字段和命中位置，再可跳原模块：知识 item/version（正文命中可加 lineStart/lineEnd），准备 kind/item/version，题库 item/version，材料 attachment/excerpt（可带固定 run）。其他模块现无通用 offset 高亮，不宣称跳转后自动高亮。

## 5. 查询生命周期与错误

全局搜索为独立路由和工具入口，保留原知识专用搜索与重建操作。采用既有工作台组件、色彩和保稿路由守卫，按来源切换；检索词、状态或来源变化重新从首页开始。提交后的查询与编辑输入分离，旧结果不会被标成新查询。

会话、资料权限、请求代次、条件或选中身份变化均使旧响应失效；同一来源的详情不跨查询复用。权限检查中、独立训练受限或会话失效时隐藏并清除列表及确切正文。错误明确提示，可在当前权限下重试，不把连接失败显示成无命中。切换查询不发写命令、不改资料；前往编辑页继续经过既有保稿守卫。

无权属或确切身份／版本不对应返回 404 SEARCH_SOURCE_NOT_FOUND；固定摘录若不满足 SQL 中的 READY／SHA／原执行及片段关联条件，同样不可读取并返回 404，不读取关联范围外正文。已找到来源但白名单结构损坏，或 Java 复核定位／UTF-16 选区／原片段正文失配，返回 409 SEARCH_SOURCE_INVALID，不悄悄跳过 SQL 批次中的无效来源而提前结束一页。资料模块关闭返回 503 MATERIALS_DISABLED；独立训练受限继续使用 409 ASSISTANCE_CONFIRMATION_REQUIRED。错误不包含原文或私有 JSON。

## 7. 官方语法核对

访问日期：2026-11-11。以下为 MySQL 8.4 官方页面实际可读正文的静态依据，不证明本项目 SQL 已在服务器执行。

- [JSON Data Type](https://dev.mysql.com/doc/refman/8.4/en/json.html)：JSON 转换字符串使用 utf8mb4／utf8mb4_bin，默认大小写敏感；本批候选明确指定比较规则。
- [String Comparison Functions](https://dev.mysql.com/doc/refman/8.4/en/string-comparison-functions.html)：LIKE 的 `%`／`_` 通配、ESCAPE 单字符及比较规则说明；本批使用绑定参数、显式 `ESCAPE '!'` 和字面转义。
- [JSON Table Functions](https://dev.mysql.com/doc/refman/8.4/en/json-table-functions.html)：确认 JSON_TABLE 的 PATH、标量列、ON EMPTY／ON ERROR 顺序和数组展开语法；本项目字符比较、异常与查询计划仍按 UNI 场景待验。
