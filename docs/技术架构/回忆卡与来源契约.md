## 1. 卡片与复习的边界

从独立知识库的已发布笔记或概念创建 QA 问答卡／CLOZE 填空卡。CLOZE 由用户在题面手写可见空位，例如 `HashMap 的默认负载因子为 ____`，参考独立填写；本批不解释挖空语法、不自动遮蔽文本、不拆成多张子卡。两类使用相同保存与来源规则，类型可通过新版本修改。

本批提供创建、编辑、版本、来源状态、显式浏览参考和归档／恢复。保存卡片、打开参考、归档、恢复均不产生复习、揭示或评分事件，不建立到期时间，不改变复练动作、能力观察或今日队列。ACTIVE 只表示卡片在正常管理列表可用，不表示已启用排程。AI 制卡候选、正式作答／揭示／自评、FSRS 与人工排程由上列后续专项契约补充；完整 MEM-01、MEM-02–07 不因首批交付而标为完成。

## 2. 对象与版本

稳定 Card 保存 owner、UUID、ACTIVE／ARCHIVED、从 0 开始的 revision、当前 versionId／versionNumber 和创建／更新时间。Version 保存独立 UUID、从 1 开始的 number、完整内容及创建时间；题面、参考、来源版本、相关概念一起不可变。对象 revision 上限 1000、内容版本最多 1000；到上限拒绝需要递增的操作。

POST 创建 ACTIVE 对象和第 1 版；PUT 仅允许 ACTIVE，校验 expectedRevision 后完整保存并追加版本，revision 加 1。历史内容不覆盖，不能只保存题面而隐式取当前参考。归档／恢复只改状态与 revision，不产生内容版；同状态新命令仍校验 revision，匹配时返回原对象。历史及归档对象可读参考；编辑归档对象须先恢复。没有物理删除入口。

| Content 字段 | 本批规则 |
|---|---|
| kind | 必填字符串枚举 QA／CLOZE |
| title | 1–200 Unicode 码点，非空白 |
| prompt | 1–10000 码点，非空白；仅展示 Markdown／代码，不执行 |
| reference | 1–20000 码点，非空白；由用户填写的参考，不标成审核通过 |
| sources | 1–10 个 `{itemId,versionId}`，均为本人 NOTE／CONCEPT 的确切发布版本；同一二元组不得重复，保留用户顺序 |
| relatedConceptIds | 0–20 个不同的本人 CONCEPT UUID，保留用户顺序；结构关联独立于来源依据 |

所有数组和字段必填；没有内容的集合传 `[]`，不得用 null 或遗漏代替。文本保留原字面值，不静默修剪、换行归一化或截断；禁止 NUL 和孤立 UTF-16 代理。UUID 使用标准小写形式，修订和分页参数必须是整数，拒绝数值枚举、浮点转整数、未知字段和重复 JSON 键。

单版本完整 Content JSON（含参考及两类链接）的实际 UTF-8 上限为 **192 KiB**；单次写入请求编码后不超过 **224 KiB**。历史读取以保存时的内容计量，不因 DTO 后续新增可空字段而重算旧内容大小或摘要。复用既有 2 MiB 幂等回执上限；超限事务回滚，不截断。字符数和序列化后字节数分别校验，控制字符转义也计入字节上限。

普通读模型使用 `Prompt`，没有 reference 属性。`Card.currentVersion`／`VersionDetail.version` 只含不可变题面与确切链接；`sourceReferences`、`relatedConcepts` 是当前读取投影。列表只给 Summary，版本列表只给 VersionSummary。来源正文、当前知识草稿和参考不夹带在这些响应中。共享 DTO 见 [MemoryDtos.java](../../backend/src/main/java/com/wenjie/studio/memory/MemoryDtos.java)。

存储定义见 [V34__memory_cards.sql](../../backend/src/main/resources/db/migration/V34__memory_cards.sql)，读写映射见 [MemoryMapper.xml](../../backend/src/main/resources/mapper/memory/MemoryMapper.xml)。仅为部署准备迁移文件，不自动执行。

| 表 | 保存内容与约束 |
|---|---|
| memory_card | 稳定对象、状态、CAS revision 和当前版本指针；owner／status／id 支持游标列表 |
| memory_card_version | 不可变题面 JSON、独立参考列、创建时完整内容字节数及来源／概念数量；card 内版本号唯一；普通查询不读取参考列 |
| memory_card_source | 确切知识版本及顺序；owner／card／version 和 owner／knowledge item／knowledge version 分别使用复合外键；来源二元组与位置各自唯一 |
| memory_card_concept | 概念结构关联及顺序；owner 复合外键约束知识归属，CONCEPT 类型由命令事务校验；概念与位置各自唯一 |

当前版本指针由创建／保存命令事务维护，避免与首版插入形成循环外键。卡片归档不删除历史关系；本批表没有复习事件、待复核状态或排程列。

## 3. 来源保留与变化

来源通过 `KnowledgeService.detail(owner,itemId)` 和 `version(owner,itemId,versionId)` 核对所属对象与版本。对当前已发布内容使用 `detail.published`／`currentVersionId`；现有 `detail.title` 来自草稿，不能拿它表示确切发布版本。来源标签取被引用版本的 title／number，种类取知识对象 Kind。

- 创建时所有 sources 必须 ACTIVE 且指向当前已发布版本。编辑新增／替换的二元组执行同一规则；只可保留**本次编辑前当前卡版本**已存在的旧二元组，包括已被新版本替代或归档的来源，并显示动态状态。不能用卡片任意历史中出现过的引用绕过新增校验。移除后再次加入视为新增。
- relatedConceptIds 只用于分类、发现与星图导航，不自动成为制卡证据。新增关联必须为 ACTIVE CONCEPT；编辑可以保留当前卡版本已有的归档概念，读取显示其状态。标签使用概念当前已发布标题，不展开正文、不自动复制概念版本、不传播内容错误。它可以与某个来源概念同 ID，但两种关系分别保存。
- 同一卡片可以有多个来源；任何一条新增来源无效都拒绝整个写入，不悄悄删去失效项。跨 owner、版本不属于对象、NOTE 冒充相关概念均拒绝。事务内完成来源核对，不能只相信前端读到的状态。

| SourceReference 字段 | 精确定义 |
|---|---|
| itemId／versionId／kind／title／number | 确切被引用知识版本的身份、类型及标签；不自动换成当前版本 |
| state | ARCHIVED 优先；否则 versionId 等于 currentVersionId 为 CURRENT，其余为 SUPERSEDED |
| bodyChanged | 被引用版本 body 与当前**已发布**版本 body 按原字符串比较，不同为 true；不比较标题、主题、标签、布局或未发布草稿 |

state 和 bodyChanged 在同一一致读取中计算。只改标题并发布：SUPERSEDED、bodyChanged=false；发布正文变化：SUPERSEDED、true；归档且正文未变：ARCHIVED、false。bodyChanged 表示文本差异，包含 Markdown 排版变化，**不能据此证明实质更正或错误**；SUPERSEDED 也只表示存在较新版本。来源正文更正后又改回，bodyChanged 可能为 false，不能用该值消除后续持久化的待复核记录。

本批按读时状态提示“正文有变化，请核对”／“来源已有新版本”／“来源已归档”，不自动改卡片、不自动迁移引用，也不声称已自动暂停复习。MEM-06 的实质更正识别、待复核、来源归档及恢复代次、确认新版本后的显式重新启用由第二批另立契约；仅保存或恢复卡片不能代替确认。未来启用排程前须把这些边界接到每次开始／揭示／评分的校验。

已读代码表明 `KnowledgeService` 发布与归档／恢复会写 `knowledge_outbox`，其 `processed_at` 目前由搜索投影消费。本批不新增触发器、不修改该消费位，也不把搜索已处理视为记忆影响已处理。第二批需明确独立消费检查点与来源可用性代次，防止归档再恢复、正文改后改回抹去中间变化；这不等于本批已有传播能力。

## 4. API、权限与事务

前缀 `/api/v1/memory`。写接口及参考浏览均带 `Idempotency-Key`、`Content-Type: application/json`，请求体按固定 DTO 严格解码。先校验原始请求字节上限，再解析 JSON 并拒绝重复键、尾随 JSON、过深嵌套和字段强制转换；HTTP 通用 1 MiB 限额仍在更外层生效。

| 方法及路径 | 请求与响应 |
|---|---|
| GET `/cards` | status 默认 ACTIVE；可选 kind、query（标题字面包含，0–100 码点）、sourceItemId、relatedConceptId；过滤条件取交集；cursor 小写 UUID，按 id 升序排他，limit 1–50 默认 20；返回 Page |
| POST `/cards` | `{content}`；201 返回不含参考的 Card |
| GET `/cards/{id}` | 当前 Card，含当前版本和动态来源检查 |
| PUT `/cards/{id}` | `{expectedRevision,content}`；返回 Card |
| GET `/cards/{id}/versions` | number 倒序，before 为排他整数 1–1001，limit 1–20 默认 10；返回 VersionPage |
| GET `/cards/{id}/versions/{versionId}` | VersionDetail，含确切版本及该版本的动态来源检查 |
| POST `/cards/{id}/versions/{versionId}/reference` | `{}`；返回 `{cardId,versionId,versionNumber,reference}`，200；编辑／浏览参考入口 |
| POST `/cards/{id}/archive`、`/restore` | `{expectedRevision}`；返回 Card |

参考读取绑定路径中的确切版本。允许浏览历史／归档版本，不能用“当前版本”隐式替换。它复用 owner 锁和命令回执，但不修改卡片 revision，不写正式复习 revealed、评分或 FSRS 日志；本批不新增参考曝光统计。以后正式揭示必须经独立复习会话命令，不能拿这份 Reference 回执充当已揭示证明。

实现时将 `memory` 加入 `TrainingAccessGuard` 资料模块：列表、题面、历史、参考以及写命令都受既有独立训练守卫保护。命令在读取旧幂等回执**之前**校验当前资料权限，GET 序列化前沿用动态再次检查。仅在前端隐藏参考不满足权限边界；不能通过历史参考／响应丢失后的原键恢复绕过当前独立作答条件。登录、owner 隔离和 CSRF 沿用现有入口规则；本批 memory 响应要求 `Cache-Control: no-store`。

创建／编辑、版本、源链接、相关概念、对象修订和回执必须在既有 owner 命令事务中一起提交；新增引用核对与对象 CAS 同事务。只读列表、详情和历史使用 REPEATABLE_READ 一致快照，详情内的来源核对加入同一事务。所有持久关联包括 owner，版本 FK 指向所属 card，知识来源 FK 指向确切 knowledge item/version。

响应未知保留原 request 与 key，同键同内容恢复原回执；同键不同请求返回 IDEMPOTENCY_KEY_REUSED。原回执中的来源检查是该命令当时的结果，恢复后另取详情刷新状态，不改写回执。对象 revision 冲突保留输入并返回 currentRevision；不能自动重试成覆盖写。未来扩展不能给旧写 DTO 增加参与摘要的默认字段或重算旧请求 hash。

错误沿用 INVALID_REQUEST、REVISION_CONFLICT、REVISION_LIMIT、ITEM_ARCHIVED、SOURCE_CHANGED、SOURCE_UNAVAILABLE、RECEIPT_TOO_LARGE 和资料守卫错误。新增 `MEMORY_CARD_NOT_FOUND`（404，卡或所属版本不存在／不可访问）及 `MEMORY_LIMIT`（422，版本内容／本批大小上限）。知识来源与关联的无效身份统一返回 SOURCE_UNAVAILABLE，不泄露其他 owner 内容。

## 5. 前端入口与后续排程

知识区域增加“回忆卡”管理入口，知识笔记／概念的已发布版本提供“创建回忆卡”；该入口仅预选确切 source，不把完整知识正文自动塞进参考。无岗位、无训练、无 AI 都能制卡。新建表单支持 QA／CLOZE；CLOZE 提供手工空位示例，不预览“自动遮蔽成功”。

默认详情展示题面、版本、来源与关联概念；用户明确点“查看参考”或“编辑”才 POST 确切版本参考。编辑必须等待参考读取成功，将其与同一版本题面组合，再以所读取对象 revision 保存；不能用空字符串代替读取失败的参考。编辑中卡片或来源变化显示冲突／状态，保留表单；历史浏览不替换草稿。reference 缓存按登录代次＋cardId＋versionId 隔离，辅助遮挡／登出清空可见正文；明确浏览只标“查看参考”，本批无“揭示成功／复习完成”按钮或到期计数。

第二批依[Java-FSRS 接入核验](../调研/Java-FSRS接入核验.md)继续设计原始复习事件、固定 CardVersion、正式揭示／评分幂等、时间单位和排程版本。该资料目前是固定源码与制品证据，未完成算法运行验收；本批 DTO 不包含 FSRS 库类型、due／稳定性／难度／记忆概率。卡片版本、复习事件、排程状态各自保存，编辑不回写旧自评，恢复不立即塞入今日，卡片完成也不关闭独立复练动作。
