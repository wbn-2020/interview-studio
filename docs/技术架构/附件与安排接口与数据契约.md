# 附件与安排接口与数据契约

日期／版本：2026-11-07 · v0.3。状态：S3 第二批实现契约；S5 第八批补充确切摘录检索与 AI 来源边界。容量为实施默认值，运行表现待服务器验证。承接[准备内容契约](准备与资料接口与数据契约.md)和[完整产品需求](../需求文档/产品需求文档.md)的 MAT、EVENT、AC-35／47，不表示已完成运行验收。进度以[开发记录](../开发记录/开发阶段与进度.md)为准。

## 1. 附件、传输与存储

原附件、上传尝试、解析执行和来源摘录分别拥有稳定 ID。原附件 READY 后不可替换字节；重新上传不同文件创建新附件。文件名仅供展示，私有路径由内部 UUID 派生。上传／解析不确认项目事实、不授予模型外发权限、不抓取 URL。

- 格式白名单：PDF、DOCX、PNG、JPEG；原名≤200 字符且无控制字符／路径分隔符，声明格式与实际文件格式必须匹配。文件 1 字节–20 MiB，大小和 SHA-256 在创建意图时固定；摘要为 64 位小写十六进制。原名后缀与声明格式不匹配时拒绝，MIME 请求头不能代替实际检查。
- 单 owner 保留容量默认 1 GiB。所有上传尝试按声明大小预留，失败／中断也继续计入；不能因为数据库状态变为 FAILED 就当成文件已被清除。每附件最多 3 次上传尝试。解析 PDF／DOCX 每次预留 2 MiB，图片每次预留 24 MiB，每附件最多 10 次解析，待执行队列最多 20 项。配额是对保留文件上限的保守计数，详情显示已预留容量和用途；本批不自动删除原件、部分文件或旧结果。
- 附件状态 RESERVED／READY；上传状态 RESERVED／RECEIVING／SUCCEEDED／FAILED／INTERRUPTED；失败代码说明长度、摘要、格式、I/O 或中断，错误不回显服务器路径。附件未 READY 时仅能查看意图／尝试状态和显式创建新尝试。
- 创建意图及新尝试使用现有 Idempotency-Key、owner 锁和短事务。二进制 PUT 以稳定 uploadId 定位唯一尝试，要求 Session／CSRF、application/octet-stream 和 X-Content-SHA256；同尝试不会开启第二个写者。成功重读／重传返回既有附件，不替换原字节。未知响应先 GET 状态，不能直接创建第二份附件。
- PUT 在短事务认领后，以有界缓冲、CREATE_NEW 写独立文件，核对实际字节数、SHA-256 和格式；文件 I/O 不持有 owner 锁。最后短事务确认同一尝试仍有完成资格，再使附件 READY。文件完成但数据库确认失败时保留原尝试和预留额度，重启／超时把未完成认领标记 INTERRUPTED，不能仅凭文件存在升级 READY。
- 私有根目录必须由服务器显式配置为已存在的绝对目录，并由运行账号独占写入。拒绝根和各路径段符号链接、非普通文件、路径越界；应用不拼接原文件名，不自动清理目录。文件系统与数据库不是跨资源原子事务，状态与容量账本覆盖中断窗口。上传读超时由容器／反向代理共同限制，客户端二进制请求超时 120 秒。

`Attachment={id,fileName,kind,byteSize,sha256,description,status,revision,createdAt,updatedAt,uploads,latestRun}`；`Upload={id,attachmentId,status,reservedBytes,receivedBytes,errorCode,createdAt,startedAt,finishedAt}`。description≤5000，可单独 CAS 修改；不替换文件或解析版本。`MaterialStatus={enabled,usedBytes,quotaBytes,maxFileBytes,parserEnabled}`，usedBytes 是保守预留值。ID／时间／修订沿用小写 UUID、UTC 微秒及 JS 安全整数规则。

| 方法／路径（前缀 /api/v1/materials） | 请求／返回 |
|---|---|
| GET `/status` | MaterialStatus；关闭时可读状态，资料操作返回 MATERIALS_DISABLED |
| GET `/attachments?cursor=&limit=20&q=` | ID 正序标题筛选，返回 `{items:AttachmentSummary[],nextCursor}` |
| POST `/attachments` | `{fileName,kind,byteSize,sha256,description}`，创建意图和首个尝试，201 Attachment |
| GET `/attachments/{id}` | Attachment，含所有上传尝试和最近解析摘要 |
| PUT `/attachments/{id}/description` | `{expectedRevision,description}` → Attachment |
| POST `/attachments/{id}/uploads` | `{expectedRevision}` → 新 Upload，201；仅未 READY 且没有 RESERVED／RECEIVING 尝试 |
| GET `/uploads/{uploadId}` | Upload |
| PUT `/uploads/{uploadId}/content` | 原始字节；成功返回 Attachment，重复读取完成结果；并发传输返回 UPLOAD_IN_PROGRESS |
| GET `/attachments/{id}/content` | 鉴权下载原件，attachment／nosniff／no-store；PDF／DOCX 不通过 iframe 内联 |

## 2. 解析执行与安全预览

解析由用户显式触发；图片操作在界面称“生成图片预览”，不声称执行 OCR。每次重试生成新的 runId，旧片段不改写。`QUEUED → RUNNING → SUCCEEDED|FAILED|UNSUPPORTED|INTERRUPTED`；最多一个解析子进程，任务在数据库持久保存。中断后显式重试，不沿用旧结果版本。

运行方式为同一应用 JAR 内的独立 ParserMain，使用 Boot PropertiesLauncher 选择入口，**不启动 Spring 容器或 Web 服务**。子进程限制堆 256 MiB、元空间 128 MiB、运行 45 秒；父进程确认退出后才释放执行槽。子进程自身以 JVM uptime 和单调时钟限制寿命，父进程持有 stdin 写端，EOF／断管触发子进程退出；JVM 无法调度或 OS 挂起时不承诺精确准点。清空继承的业务环境变量，只保留启动 JVM 必需的系统项。结果是≤2 MiB 的 JSON 文件，公开日志只记错误类别。它提供内存／时间边界，不是操作系统沙箱；打包入口和强制终止仍须服务器验证。

- PDFBox 3.0.8：只提取文字层，最多 200 页、累计 250000 字符、最多 1000 片段，每片段≤10000 字符，固定页码和片内偏移；加密或禁止提取的文档拒绝。空文字层提示可能是扫描件且未执行 OCR。到上限保留截断标记，不伪装完整文档。
- POI XWPF 6.0.0：最多 2000 ZIP 条目、单条目 16 MiB、总解压 64 MiB、压缩比最低 1%；拒绝宏、OLE／嵌入包／ActiveX、加密、外部关系和不支持格式，不访问远程对象。活动内容同时检查部件路径、关系 Type 和 Content_Types 的 Default／Override，改名不绕过拒绝规则。保留正文段落、表格行／列／段落位置；不生成虚假的 DOCX 页码。字符／片段上限同 PDF，复杂布局、页眉脚等未支持内容明确提示。
- PNG／JPEG：尺寸上限每边 4096、总像素≤8000000；在受限子进程解码并重新编码 PNG，预览文件≤20 MiB。只内联已生成的 PNG 派生文件，原件按附件下载；不接受 SVG／HTML，不自动读取远程图片。
- 每次执行记录附件摘要、解析器和版本、状态、限制说明、是否截断、失败代码和时间。运行前复核原文件摘要；结果文件和片段只有全部校验后在短事务中提交。无法提交的文件仍占预留额度。

`ParseRun={id,attachmentId,status,parserVersion,truncated,warnings,errorCode,segmentCount,createdAt,startedAt,finishedAt,hasPreview}`；`Segment={id,attachmentId,runId,ordinal,locator,text}`，locator 表示 PDF 页和偏移或 DOCX 结构位置。所有已成功片段不可修改。

| 方法／路径（前缀 /api/v1/materials） | 请求／返回 |
|---|---|
| POST `/attachments/{id}/runs` | `{}`＋Idempotency-Key → ParseRun，202；同附件最多一个 QUEUED／RUNNING |
| GET `/attachments/{id}/runs?before=&limit=20` | 创建时间＋ID 倒序的执行历史 |
| GET `/runs/{runId}` | ParseRun |
| GET `/runs/{runId}/segments?after=0&limit=20` | 按 ordinal 正序，`{items:Segment[],nextCursor}`，仅成功执行 |
| GET `/runs/{runId}/preview` | 仅成功图片执行的私有 PNG 派生文件，inline／nosniff／no-store |

## 3. 不可变摘录与准备内容来源

采用解析片段前，用户可选中 UTF-16 字符范围；前端将 textarea 规范化换行后的选区映射回已保存原文的码元位置，CRLF 不造成偏移。服务器验证段落、执行、附件和 owner 归属，按保存的片段原文截取，不能信任客户端提交的“原文”。另可对 READY 附件手工摘录，必须填写定位说明，明确标记 MANUAL，不冒充机器解析。

`Excerpt={id,attachmentId,runId,segmentId,origin:PARSED|MANUAL,locator,text,startOffset,endOffset,createdAt}`。手工摘录的 runId／segmentId／偏移为空；定位说明 1–500 字符，摘录原文 1–10000 字符。解析摘录固定附件 SHA-256、runId、segmentId 和范围；同一源片段可产生不同摘录，但保存后不改写。

| 方法／路径（前缀 /api/v1/materials） | 请求／返回 |
|---|---|
| POST `/attachments/{id}/excerpts` | `{segmentId,startOffset,endOffset,locator,text}`；解析方式只填前三项，其余为 null；手工方式前三项为 null，填 locator/text；幂等创建 Excerpt，201 |
| GET `/attachments/{id}/excerpts?cursor=&limit=20&q=` | ID 正序摘录页；可选 q 去除首尾空白后≤100，按已保存正文或定位说明做转义子串筛选，空值列出全部，禁止 NUL |
| GET `/excerpts/{id}` | Excerpt，返回确切来源信息 |

准备域 Source 增加可选 `excerptIds:string[]`，最多 20 个，不传时按空数组处理；既有历史版本保持原 JSON。PROJECT／FACT 保存时在 owner 锁内验证摘录可读且附件 READY，并把确切 preparation_version 与 excerpt 的关系同事务保存。事实正文可自行组织，引用的原摘录不随之改写。前端提供摘录选择／移出和原文查看，保存事实仍为待核实。附件单独可用；知识笔记采用和训练引用在对应阶段补关系，不能提前宣称已覆盖所有来源传播。

S5 第八批[资料摘录问答](资料摘录问答契约.md)只读取用户明确选择的 1–5 条确切摘录；检索不扫描原件、不自动解析或外发。AI 来源查询是加入外层事务的无副作用读取，按 owner／附件 READY／SHA／摘录及解析身份核验，不能调用会执行恢复写入的附件详情入口。说明修改、重解析不替换旧摘录；资料域归档／删除及其传播仍待后续生命周期实现。

## 4. 私人面试安排

持久状态只有 PLANNED／COMPLETED／CANCELLED。到期／已过时间是按服务端 asOf 计算的提示，不是实际参加结果；界面用“已过计划时间，尚未标记结果”。取消、完成不覆盖历史，终态不再编辑。准备任务、题单和面后回忆依 S4／S6／S7 接入，本批改期只改变安排和其提醒，不移动其他任务。

`EventInput={title,targetId,round,location,meetingUrl,notes,time,remindBeforeMinutes,materials}`：标题 1–200，round≤100、location≤500、notes≤10000、meetingUrl 空或 http(s)≤2000；targetId 可空；提醒提前量 0–10080 分钟；materials≤50，为 `kind:PROJECT|FACT|EXPRESSION|KNOWLEDGE,itemId,versionId` 的确切版本引用。新增材料须当前活跃有效；保留原有旧引用时显示状态，不替换依据。目标第一次关联／改变时固定服务端 targetVersionId；目标未改变时保留原版本。

`TimeInput={localStart,zoneId,offset,durationMinutes}`：localStart 严格到分钟，zoneId 是 IANA 区域 ID 或 UTC，durationMinutes 为 1–1440 的整数。`ZoneRules.getValidOffsets` 无合法偏移时拒绝不存在的本地时间；两种偏移时用户必须选定；唯一偏移可由服务器推导。客户端不得自行把浏览器本地时区当作填写时区。保存 `ResolvedTime={localStart,zoneId,offset,startAt,endAt,durationMinutes}`；后续时区规则更新不改已存 Instant。

`InterviewEvent={id,targetId,targetVersionId,targetState,title,round,location,meetingUrl,notes,time,materials,materialReferences,remindBeforeMinutes,remindAt,reminderAcknowledgedAt,status,timing,revision,createdAt,updatedAt}`。timing 为 UPCOMING／DUE／IN_PROGRESS／PAST／CLOSED。targetState 为 null／CURRENT／SUPERSEDED／ARCHIVED；材料引用除准备域状态外增加 REVIEW_REQUIRED，表示表达依据需复核。列表和日历共用同一事件；日历按页面选定 IANA 时区分组，打开详情保留事件原时区。列表／提醒页返回 asOf，活动页面每分钟刷新；详情刷新不覆盖本地脏输入。提醒在站内查询，浏览器关闭不保证推送。

| 方法／路径（前缀 /api/v1/schedule） | 请求／返回 |
|---|---|
| POST `/time/resolve` | 只读 `{localStart,zoneId}` → `{state:UNIQUE|OVERLAP|GAP,options:[{offset,startAt}]}`，仍需 CSRF |
| GET `/interviews?from=&to=&targetId=&status=&cursor=&limit=20` | UTC 区间≤366 天，取与区间重叠事件，startAt／ID 正序联合游标；`{items,nextCursor,asOf}` |
| POST `/interviews` | EventInput → InterviewEvent，201，Idempotency-Key |
| GET `/interviews/{id}` | InterviewEvent |
| PUT `/interviews/{id}` | `{expectedRevision,...EventInput}` → InterviewEvent；普通编辑禁止改变 time，改期必须先预览再使用改期命令 |
| POST `/interviews/{id}/reschedule-preview` | 只读 `{expectedRevision,time,remindBeforeMinutes}` → `{from,to,remindAt,relatedTaskChangesAvailable:false}`，仍需 CSRF |
| POST `/interviews/{id}/reschedule` | 同预览输入＋reason（1–2000）→ 新修订；重验 CAS 和时间 |
| POST `/interviews/{id}/cancel`、`/complete` | `{expectedRevision,reason}` → 新修订；cancel 原因非空，complete 在计划开始前拒绝 |
| POST `/interviews/{id}/acknowledge` | `{expectedRevision}` → 仅确认已看提醒，不把面试标为完成 |
| GET `/interviews/{id}/history?before=&limit=20` | 修订倒序摘要页；包含 revision/action/title/startAt/status/reason/createdAt |
| GET `/interviews/{id}/history/{revision}` | 当时事件完整快照，只读 |
| GET `/reminders?cursor=&limit=20` | 未完成／未取消、未确认且 remindAt≤asOf，按 remindAt／ID 正序；页面重进仍保留未处理项 |

改期／改变提前量清除旧提醒确认，只改备注不重新提醒。全部写入使用原请求幂等键、owner 锁、JS 安全 revision 和 CAS；事件、历史、材料关系、提醒状态和回执同事务。404 不区分无权和不存在，未知写入保留原请求与表单。非法时区／DST、状态、来源和修订冲突都有明确错误代码。

## 5. 存储与集成

追加 V7（attachment、upload、parse run、segment、excerpt、准备版本来源关系）与 V8（interview event、history、确切材料关系），保留 V1–V6。使用复合 owner 外键和版本匹配约束，跨类型合法性再由服务校验；不依赖 JSON 搜索实现权限或生命周期影响查询。

新增 `studio.material.enabled`／`directory`／`parser-enabled`／`quota-bytes` 配置，默认关闭附件域，服务器显式启用并提供私有目录；未配置不能偷偷写到当前目录。二进制上传保持 multipart 关闭，不改变现有 JSON 限额。前端沿用现有依赖，准备入口增加“附件资料”和“面试安排”子页；同源读取和全局草稿／未知请求守卫继续生效。

后端使用 PDFBox 3.0.8、POI OOXML 6.0.0，版本在 2026-11-05 从 Apache 发布页及 Maven Central 元数据核验（HTTP 200）：[PDFBox 下载](https://pdfbox.apache.org/download.html)、[PDFBox 元数据](https://repo.maven.apache.org/maven2/org/apache/pdfbox/pdfbox/maven-metadata.xml)、[POI 下载](https://poi.apache.org/download.html)、[POI 元数据](https://repo.maven.apache.org/maven2/org/apache/poi/poi-ooxml/maven-metadata.xml)。网页和元数据不代替本工程编译、恶意文件处理或复杂文档的运行验收。

## 6. 验证边界

本地仅类型／编译／构建、DTO 与 OpenAPI／Mapper／DDL 对照和独立静态审查。不启动服务或解析子进程，不运行单元测试，不读取用户附件或凭据。服务器必须覆盖上传中断／并发／DB 确认失败、重启恢复、配额不被失败重试绕过、符号链接／跨 owner／伪造类型、ZIP 炸弹／扫描件／加密损坏文件、worker 超时与真实退出、来源错配、DST 重复／不存在时刻、改期／提醒／历史，以及列表日历、草稿和会话恢复。
