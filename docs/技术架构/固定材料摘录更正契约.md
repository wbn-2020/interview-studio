# 固定材料摘录更正契约

版本：v1.1 · 2026-11-12。状态：S8第二十六批静态检查通过待服务器验收；第二十七批的知识链准入与影响扩展见[材料更正知识影响契约](材料更正知识影响契约.md)。本文件保留原文声明与历史规则，下述准入已注明后续扩展；实现、机器契约与实际检查见[开发记录](../开发记录/开发阶段与进度.md)，下列服务器场景全部未执行。

## 1. 更正声明与原文

材料摘录保存后正文不可变。用户先通过现有手工／解析摘录功能保存新原文，再明确声明“旧摘录 → 新固定摘录”，提供理由并确认。声明表达用户的内容更正判断，不认证新内容客观正确；两份原件、来源、定位、正文及所有历史引用保持各自原身份。

允许同本人跨附件更正，例如修正版文件另存为新附件。旧新须为不同摘录、正文确有差异、来源可完整核对、附件READY、生命周期ACTIVE，且均未成为既有更正声明的旧端。替代摘录可以已撤回AI用途；正文更正不授予外发许可。

每个旧摘录只能有一个不可撤销的更正声明。`A→B`后可显式声明`B→C`，原A仍准确指向B，不自动展开或重定向到C。新声明禁止选择已经被更正的替代摘录，结合本人写锁、旧端唯一及非自身约束防止循环。不提供删除声明、撤销或原地改正文。

## 2. 准入及事务

第二十六批原范围只支持无正式采用及其他本地绑定的旧摘录，当时在原owner命令锁内调用`hasUnsupportedReferences(owner, oldId, false)`。第二十七批将参数改为`true`，仅对完整核验的知识ADOPTED及受支持出口增加例外；合法未采用AI登记和IGNORED沿原规则。准备／关系／审阅直接材料绑定、其他域ADOPTED、未知决定、不支持身份及未承接的知识出口仍以`MATERIAL_HAS_REFERENCES`拒绝；准确范围与预算以[知识影响契约](材料更正知识影响契约.md)为准。

原范围门禁不等于完整核验所有旧Manifest／hash，也不是完整删除影响清单。第二十七批新增的知识链例外必须核验完整实际采用闭包和原清单摘要，在同一真实声明下记录V75影响，并调用Memory／Reviewed钩子；不能仅凭原门禁放行已有采用。其他域的更正传播仍未覆盖。

V74仅创建真实更正声明表，不回填过去声明。记录旧新ID、声明时两端生命周期revision、规范化理由及时间；旧端唯一，两端外键限定本人摘录，保留非自身、安全修订、理由和时间约束。声明与幂等回执同事务提交，失败不留下半条关系。

生命周期revision及V73事件只表示原四类状态／用途动作，本批不推进或伪造这两端的生命周期事件。更正事实独立参与当前资格，不能仅凭旧revision未变就认为来源仍有效。

## 3. 接口与历史

- `GET /api/v1/materials/excerpts/{id}/correction`：本人确切摘录的State4，只读事务、`no-store`；无声明时`correction`明确为null，存在时为Statement7。查询参数不接受，声明的身份、理由、修订及时间须与两端原始记录核对；替代后续归档或再次更正不抹除原声明。
- `POST`同路径：Create5为`expectedRevision`、`replacementExcerptId`、`expectedReplacementRevision`、`reason`及`confirmed=true`。严格拒绝未知／重复JSON字段、错误类型和查询参数；沿现有CSRF、本人、资料启用及独立训练访问守卫。成功返回200及原State4回执。

State4为`excerptId / attachmentId / lifecycleRevision / correction`；Statement7为`id / excerptId / replacementExcerptId / sourceRevision / replacementRevision / reason / createdAt`。返回不包含正文，用户通过既有确切读取主动核对原文。

命令在owner锁内重新校验两端修订、来源和准入，不能信任先前GET、选择器或hasReferences。不同键再次更正旧端返回`MATERIAL_CONTENT_CORRECTED`；修订冲突沿`MATERIAL_REVISION_CONFLICT`。同键同请求仍返回原声明回执，即使替代摘录后来归档或再次更正；同键异请求仍为`IDEMPOTENCY_KEY_REUSED`。资料模块及独立训练访问规则在回执前仍须检查；两端当前可用性核验在首次业务动作中进行，不阻断已成立事实的原键恢复。

## 4. 新选用与AI

已更正旧端退出ACTIVE选择列表及统一新搜索；ALL范围和确切历史读取保留，不能把旧生命周期ACTIVE误当作仍可新选用。新本地依据、直接及间接AI的`requireActive / aiAllowed / captureAiChecks / currentAiChecks`同时排除已更正旧端；直接资格错误为`MATERIAL_CONTENT_CORRECTED`，既有间接来源失效沿原用途规则。

旧端的四类生命周期变更也拒绝，避免以恢复状态或重新允许用途覆盖内容更正事实。生命周期历史、旧任务Manifest／hash／scope及旧回执不改写。旧任务即使保存相同许可revision也不能通过当前资格；新摘录须作为独立来源重新预览授权，不继承旧许可。

已有实际采用内容仅在第二十七批明确支持的知识链及出口内接通下游复核；其他本地使用仍阻塞，不承诺全域传播。处理单条知识影响不恢复旧材料祖先的AI资格，也不自动替换来源。已取得发送许可的请求仍可能到达供应商，费用及未知状态保留，不承诺取消已处理正文。

## 5. 界面与恢复

材料详情提供主动展开的更正面板，展示确切旧原文，复用现有摘录选择器选择新原文，读取两端当前修订并填写理由、明确确认。保存后展示原声明和主动查看替代原文入口，不自动跳转、替换历史引用或连续追到最终替代。

更正与生命周期／资料编辑命令互斥，未保存输入及未决原请求进入既有离开守卫。隐藏、会话或训练访问变化清除可见正文、换代并拒绝迟到结果；重新可读后由用户重读或恢复原请求，不能自动重发外部任务。
