# 正式关系直接原文证据契约

版本：v1.4 · 2026-11-10。适用 S5 第二十二批，并说明后续人工／AI反馈、面后回忆证据及AI生成的独立边界；状态：本批原实现静态检查通过待服务器验收。承接 PRD KNOW-06／07、[正式关系规则](首阶段接口与数据契约.md)与[补充理由及知识来源契约](正式关系补充理由与来源契约.md)。实际进度以[开发记录](../开发记录/开发阶段与进度.md)为准，本契约 §9 保留第二十二批检查证据；静态检查与构建不表示迁移、接口或视觉验收通过。

## 1. 独立证据台账与范围

用户可向本人已有正式关系手工追加理由，并选择完整资料摘录，或同一次确切训练提交中的答案片段。每次确认写入一条不可变证据记录及当时原文快照，按原 relationId 聚合；不覆盖此前记录，不更新关系身份、规范化端点或类型，不新增关系边或 revision，不改变星图路径、关系计数和布局。

直接原文证据使用独立台账，与第二十一批的 RelationSupplement 知识来源记录分别保存。一次记录只能是 MATERIAL 或 TRAINING，不混合两种来源，不借用旧补充接口携带附件／答案正文。现有 AI 候选、逐项决定、任务与 Manifest 的用途、字段、hash 和外发规则不因此改变；本命令不创建 AI 任务、不调用模型，也不增加模型费用。内部复用来源校验代码不构成 AI 预览或外发授权。

保存原文及其出处只建立可追溯的引用关系。手工摘录不等于原附件逐字认证，训练提交可能包含假设、自述或辅助条件；即使详情返回 `sourceAvailable=true`，也只表示当前能够按既定规则核对来源，不证明原文真实性、作者经历、技术结论或关系语义正确。

第二十二批接入[产品需求](../需求文档/产品需求文档.md)中已有关系的资料／训练直接依据分支；第二十三批接入[候选星图层](知识关系候选星图契约.md)，第二十四批以[独立人工反馈台账](正式关系反馈原文证据契约.md)接入自检／外部意见的确切修订选区，第二十五批以[独立 AI 反馈台账](正式关系AI反馈原文证据契约.md)接入成功评价的单条观察选区，第二十九批另以[独立回忆台账](正式关系面后回忆原文证据契约.md)接入面后回忆，均不修改本接口或 V49 快照与回执。第二十六批通过[独立预览授权入口](资料训练来源关系候选契约.md)接入资料／训练生成 AI 关系候选，V52 与任务固定来源单独保存，不自动外发这里的手工证据记录；人工反馈／回忆和AI反馈生成候选分别见第二十七／二十八批契约。各批状态以开发记录为准，完整更正传播仍待S8，不能据此关闭 KNOW-06／07 全量需求。

## 2. 请求、文本与来源规则

### 2.1 共用规则

请求为 `Create={reason,source,confirmed}`，三个字段均必填且 `confirmed=true`。reason 原样保存，不 trim、不覆盖其他理由；长度为 1–1000 个 UTF-16 码元，拒绝 NUL、孤立代理以及完全由 `Character.isWhitespace`／`Character.isSpaceChar` 构成的内容。

首次写入必须定位用户指定的确切 relationId，且该边两个 CONCEPT 端点均 ACTIVE。PRECEDES、PART_OF、APPLIED_IN 保留方向；RELATED、CONTRASTS 按小写 UUID 字典序归一；禁止自环。补充时没有“匹配同元组即可替代原 ID”的分支，原边失效不得自动新建或改绑。

原文按来源域既有规则读取并保存，不套用理由的新空白规则重判历史。材料 fileName／locator／text 分别按 200／500／10000 个 UTF-16 码元限长，答案片段 quote 按 8000 个 UTF-16 码元限长，均沿 Java `isBlank` 空白语义并检查 NUL／孤立代理。内部核对的训练题面，以及选择器读取的整答／图原文字段，沿既有训练域的码点上限；此口径不改变最终所选片段的 UTF-16 上限。答案选区和解析摘录的定位始终按 UTF-16，合法代理对不能被切开。不得通过 trim、换行改写、截断、较新标题／正文或另一提交修补保存的证据。

### 2.2 MATERIAL：完整摘录

`source={kind:"MATERIAL",excerptIds:[...],training:null}`。excerptIds 为 1–5 个不重复的本人摘录 ID，顺序按用户确认保存。客户端只指定摘录身份，完整内容和出处由服务端读取；本接口不接受客户端另传资料正文，也不把摘录之外的附件、其他解析片段或全文加入快照。

每项固定 `excerptId,attachmentId,fileName,sha256,origin,runId,segmentId,locator,text,startOffset,endOffset`。附件须处于 READY，附件 hash 必须与摘录绑定一致。MANUAL 的解析执行、片段及偏移均为空，保留用户原手工摘录与定位说明；PARSED 必须属于该附件的确切成功解析执行和片段，hash、locator、UTF-16 半开区间与逐字 text 均对应原片段。后续重新解析不替换已选 runId／segmentId。

### 2.3 TRAINING：确切提交中的答案选区

`source={kind:"TRAINING",excerptIds:[],training:{sessionId,questionId,answerId,fragments}}`。三个 ID 必须共同定位本人的同一次确切提交。fragments 为 1–8 项，按用户选择顺序保存，不允许将多个提交的片段混入一条证据。

每个片段为 `{field,elementId,start,end,quote}`；只接受以下答案字段：

| field | elementId | 原文字段 |
|---|---|---|
| ANSWER_TEXT | 必须为 null | 已提交答案正文。 |
| ANSWER_NODE_LABEL | 该提交中的图节点 UUID | 节点标签。 |
| ANSWER_NODE_DESCRIPTION | 该提交中的图节点 UUID | 节点描述。 |
| ANSWER_EDGE_LABEL | 该提交中的图边 UUID | 边标签。 |

start／end 为整数，满足 `0 <= start < end`，区间不越过原字段、不切断代理对；quote 必须与原字段 `[start,end)` 逐字一致，长度差等于 quote 的 UTF-16 长度。同一 field＋elementId 的选区不能重叠或重复，相邻片段可分别保存。单段 quote 沿已有训练选区的 8000 UTF-16 上限和 Java `isBlank` 兼容规则。

服务端额外固定 answerNumber 与 answerCondition；条件为 LEARNING、BEFORE_ASSISTANCE 或 ASSISTED，不因后来训练状态、提交或辅助访问变化而改写。内部来源适配器为选区校验会读取确切原答和题目 snapshot，并核对原题身份及结构。本台账只保存和返回所选答案片段及提交身份／条件，不保存或返回题面、题目条件、标准答案、参考材料、反馈或未选答案正文；不得把窄快照规则误写为内部从未读取原答或题目。

## 3. HTTP 与响应对象

接口位于 `/api/v1/knowledge/relations/{relationId}/evidence`，沿用会话、owner 隔离、资料访问守卫；写命令要求 CSRF 与 `Idempotency-Key`。owner 从认证上下文取得，UUID 使用标准小写形式。

| 方法与路径 | 输入 | 响应 |
|---|---|---|
| GET 基础路径 | 可选 cursor、limit；limit 默认 20，范围 1–20 | `Page`，只返回证据记录元数据，不返回原文快照。 |
| GET `/{evidenceId}` | 原 relationId 与 evidenceId | `Detail`，显式读取这一条固定原文及当前来源可核对状态。 |
| POST 基础路径 | `Create` | 201 `Entry`，创建回执只有记录元数据，不自动返回原文快照。 |

[共享 DTO](../../backend/src/main/java/com/wenjie/studio/knowledge/RelationEvidenceDtos.java)定义如下：

| 对象 | 字段与边界 |
|---|---|
| Selection | `kind,excerptIds,training`；MATERIAL 必须 training=null，TRAINING 必须 excerptIds=[]。 |
| Entry | `id,relationId,sourceId,targetId,type,reason,sourceKind,sourceCount,createdAt`。sourceId／targetId 是关系概念端点；sourceCount 在 MATERIAL 表示摘录数，在 TRAINING 表示选区数。 |
| Page | `relationId,relationExists,items,nextCursor`；items 为 Entry，不携带 snapshot、材料正文或答案片段。 |
| Snapshot | `kind,materials,training`；MATERIAL 的 training=null，TRAINING 的 materials=[]。 |
| TrainingInput | `sessionId,questionId,answerId,answerNumber,answerCondition,fragments`。 |
| Detail | `entry,relationExists,source,sourceAvailable`；source 是保存时 Snapshot，不是当前来源自动替换出的新正文。 |

[OpenAPI 规格](openapi-s7.json) v7.16.0 为本批三个操作定义 `listKnowledgeRelationEvidence`、`createKnowledgeRelationEvidence`、`getKnowledgeRelationEvidence`，并增加上述 8 个具名请求／响应 schema；[生成类型](../../frontend/src/api/schema.d.ts)已包含对应路径、操作与对象。当前规格结构为 291 paths、342 operations、961 schemas；这些是机器契约结构，不能代替接口运行验收。

[前端边界校验](../../frontend/src/api/relationEvidence.ts)复用生成类型，但另行严格检查响应实际字段、UUID、时间、关系规范化元组、来源分支及数量。Page 检查 UUID 顺序、同一关系元组和 nextCursor；Detail 检查路径身份、快照及 Entry 的来源种类／数量，可与所选列表 Entry 完整指纹逐项比较。JSON Schema 的 maxLength 按码点计数，不能替代运行时 UTF-16、代理对、逐字原文或非重叠选区检查；静态类型也不能保证服务端实际返回值正确。

POST 从原始字节严格解析，原始请求不超过 262144 bytes；拒绝重复 JSON 键、额外／缺失字段、尾随 JSON、无效分支组合和标量强制转换。每层字段集合固定；nullable 字段仍须显式出现，start／end 不能使用浮点数或字符串。

快照以紧凑 JSON 的实际 UTF-8 字节数限制为最多 1048576 bytes（1 MiB），包含字段、转义及所有完整原文；不能只按原文字符数、HTTP 长度声明或数据库字符数推算。超限返回 422 `RELATION_EVIDENCE_TOO_LARGE`，整次追加不提交。1 MiB 是保存快照上限，不表示整个 Detail HTTP 响应恰有相同上限。

分页按 evidence UUID 字典序升序，条件为 `id > cursor`，没有下一页时 nextCursor=null。该顺序不等于 createdAt 时间顺序，也不提供跨请求快照；并发追加落入已读 UUID 区间时，重新加载可取得当前记录。列表在不读取 snapshot_json 的前提下检查 owner、原 relationId、规范化元组、理由、来源分支／计数及顺序。

| 情况 | 处理 |
|---|---|
| 请求字段、理由、选择、确认或 UUID 不合法 | 400 `INVALID_REQUEST`。 |
| 首次追加指定关系不存在，或列表既无本人边又无本人历史 | 404 `RELATION_NOT_FOUND`。 |
| evidenceId 不存在、非本人或不属于路径中的 relationId | 404 `RELATION_EVIDENCE_NOT_FOUND`。 |
| 首次追加时原关系任一端点归档 | 409 `RELATION_ENDPOINT_ARCHIVED`。 |
| 资料／训练选择失效 | 沿原来源模块错误拒绝，例如 MATERIAL_NOT_FOUND、AI_TRAINING_SOURCE_NOT_FOUND、AI_SOURCE_CHANGED；不写入缺来源记录。 |
| 同键改变操作或请求 | 409 `IDEMPOTENCY_KEY_REUSED`。 |
| 当前独立训练尚未允许资料访问 | 409 `ASSISTANCE_CONFIRMATION_REQUIRED`，不通过元数据列表或历史回执绕过。 |

## 4. 原文读取、可核对性与访问控制

详情先核对证据元数据与当前边的固定身份，再严格解析 snapshot_json，校验来源分支／数量、训练三元身份，或材料绑定数量／ordinal／excerptId 顺序。快照字段、JSON 类型或绑定损坏属于完整性错误；数据库异常和反序列化异常继续抛出，不统一变成 `sourceAvailable=false`，也不把错误页当作“暂无证据”。

通过固定结构检查后，MATERIAL 按既有 MaterialSources.current 规则重新读取原摘录并比较完整保存快照；模块关闭、读取不到符合现行条件的摘录或快照不一致时返回 false，数据库异常继续抛出。本批不扩展材料域的所有语义损坏分类，不能据此宣称材料原域所有坏结构都会单独报错。

TRAINING 重新核对原三元身份、提交条件及原选区的窄投影。来源不存在、会话状态不可用或选区不匹配仍按既有来源错误处理，已知错误可使 sourceAvailable=false。题目 kind／固定源 ID 绑定错误、题目或答案容器／snapshot 绑定损坏，以及最终固定 input 校验失败则抛出 `IllegalStateException`；JSON 反序列化和数据库异常亦继续抛出，不能被 current 降为普通失效。本次调整改变错误分类，未改变原文本接受规则。sourceAvailable 不是“最新版本”标记，也不表示用户已核实原文或关系。

后续新解析、其他提交、会话推进和不属于本快照的内容不应替换原证据。已保存训练片段不扩展到完整答案，已保存材料摘录不扩展到完整附件。列表本身包含用户理由，亦属于受保护出口；不能因为不含源正文就绕过资料访问限制。

新接口复用[训练资料访问守卫](../../backend/src/main/java/com/wenjie/studio/training/TrainingAccessGuard.java)，GET 在序列化前由[读取响应守卫](../../backend/src/main/java/com/wenjie/studio/training/TrainingReadAdvice.java)再次核对当前条件；写命令在 owner 锁内、读取回执之前检查。会话变化、跨 owner、训练条件变化或访问被限制时，客户端不得继续展示迟到原文。

## 5. 写入事务、幂等及删边历史

首次追加在同一 owner 写锁与[幂等命令事务](../../backend/src/main/java/com/wenjie/studio/common/IdempotencyService.java)中核对确切边和 ACTIVE 端点、捕获当前可取得的来源、校验快照及大小，写台账／材料绑定，再保存 Entry 回执。任一步失败均回滚，不留下只有元数据、只有部分来源或没有回执的追加。并发请求按既有 owner 命令锁串行处理，不为关系引入 revision。

同键同操作同请求恢复原 Entry 回执，不再次要求边仍存在或来源仍可用，也不重新捕获较新的来源。会话、owner 与当前资料访问守卫继续生效。回执中的 reason／来源种类与数量是原命令元数据；当前边存在性和来源可核对性应显式查询，不能从回执推断。

不同幂等键代表独立追加，本台账不以理由或 source 内容自动去重。未知网络结果必须保存原键及原请求恢复，不能盲目换键。删除正式边后，按旧 relationId 仍可读取本人证据历史，relationExists=false；原键回放不重建边。相同端点／类型重新建边得到新 ID，新边不继承旧关系证据。

## 6. V49 持久化边界

[V49](../../backend/src/main/resources/db/migration/V49__relation_evidence.sql)新增 `knowledge_relation_evidence` 与 `knowledge_relation_evidence_material`。台账保存 owner、evidenceId、原 relationId、规范化端点／类型、reason、source_kind／source_count、可空训练三元身份、snapshot_json 和 created_at；材料绑定保存 owner、evidenceId、source_kind、excerptId、ordinal。

台账不建立到可物理删除正式边的外键。TRAINING 使用完整 `(owner_id,session_id,question_id,answer_id)` 复合外键指向确切 training_answer；MATERIAL 以 owner＋excerptId 指向 material_excerpt，由摘录沿原关系约束其附件／解析执行／片段。材料绑定到台账的外键包含 source_kind，禁止给 TRAINING 记录塞入材料绑定；同台账 excerptId 和 ordinal 分别唯一，ordinal 范围 1–5。

迁移文本以 CHECK 限制五种关系类型、自环／对称归一、分支数量与 nullable 训练字段、JSON 对象及 OCTET_LENGTH≤1048576。数据库 reason 字符长度约束不能替代 Java UTF-16、NUL、代理与空白校验；snapshot 的字段形状、逐字选区、连续顺序及数量与绑定一致性由领域层核对。迁移未在本地执行，外键、CHECK、历史数据兼容和事务效果均待服务器验证。

## 7. 界面与恢复边界

当前[知识关系列表](../../frontend/src/components/ConnectionsPanel.vue)已接入[直接证据面板](../../frontend/src/components/RelationEvidencePanel.vue)。面板展开后分页读取 Entry；只在用户展开一条记录时读取该 evidenceId 的 Detail，并逐字段核对详情 Entry 与所选列表项，不能预取全部原文。列表刷新、翻页、收起或访问代次变化会清除已读详情；删除边后只展示历史，禁止追加。

详情展示保存时资料文件名、摘录类型、定位、hash、确切解析身份／区间及全文，或训练三元身份、提交版本／条件、答案字段／元素、区间与选中原文。sourceAvailable 的界面文案限定为“本次读取可核对出处”，并保留不证明内容／关系正确的说明。详情提供确切来源入口，但不得用较新来源替换固定显示内容。

[追加表单](../../frontend/src/components/RelationEvidenceCreate.vue)固定挂载时 relationId，提供材料和训练两种互斥来源方式。材料方式先核对模块状态，再经[摘录选择器](../../frontend/src/components/material/MaterialExcerptPicker.vue)选择；取得确切摘录与附件后核对 READY、身份及完整原文元数据，展示整段摘录并保持选择顺序。访问条件变化后保留选择，但撤销已核对状态；重新核对只接受与原选择完全相同的快照，差异要求用户主动移出后重选，不能悄然更新。

训练方式通过[提交选择器](../../frontend/src/components/TrainingAnswerPicker.vue)选择一份确切回答，再读取并校验该提交身份、版本、条件及整答／图原文字段。用户从正文、节点或边字段拖选文字，或输入原字段 UTF-16 起止坐标，逐段加入 1–8 个不重叠片段。textarea 的换行归一由选区捕获转换回原始 UTF-16 下标，保存的 quote 不改写换行。换来源种类、移出提交或改选另一提交时，对已有选择作显式确认；切换种类保留理由，另一提交读取成功后才清除旧片段，读取失败保留原草稿。

理由、来源、原文字段、选区或访问条件变化会撤销确认。访问代次变化使已核对来源失效并隐藏原文，保留理由、确切来源和未加入的选区；恢复后需重新核对。表单与关系面板把 dirty／locked 接入离开保护，父关系列表不会用后台重读卸载含草稿或未决命令的行；取消填写经过未保存检查。

保存前明确勾选确认，发送固定 Create 与幂等键。成功 Entry 回执只核对元数据形状、原 relationId、reason、sourceKind 和 sourceCount；由于响应没有原文，不能据回执声称已逐项比对保存的来源正文。通过元数据核对后结束表单并刷新列表，仍由用户显式展开 Detail 查阅快照。回执不匹配时保留原请求／键；网络未知结果用原请求恢复。会话或访问条件变化后到达的已保存回执暂缓接收，提供恢复访问后的接收入口，不自动换键或改绑关系。

上述为当前实现的源码行为。选区与 CRLF 偏移、迟到响应、跨标签守卫、键盘、窄屏和完整业务交互尚未在浏览器中验证，继续列入服务器场景。
