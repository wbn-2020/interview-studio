# 训练改写参考与并排展示契约

日期／版本：2026-11-09 · v1.0。适用 S5 第二十批。状态：独立静态复核及前后端构建通过，待服务器验收。进度与实际检查见[开发记录](../开发记录/开发阶段与进度.md)。关联 [PRD](../需求文档/产品需求文档.md) TRN-03／06／08、REV-03、RET-02 和 AI-02–06；访问规则复用[训练评价契约](训练评价与证据报告契约.md)，任务、费用及协议规则复用[AI 任务契约](AI任务与外发契约.md)。

## 1. 业务位置与结果身份

每个 `ANSWER_REWRITE` 任务绑定用户明确选中的一次不可变提交，以 AI 未审改写参考帮助用户观察表达组织方式。原答、当时个人参考与 AI 改写候选并排展示，三个区域分别标明身份。主问、追问和同题复练按该次真实题实例取原文，不自动换为最新提交或当前题库版本。

改写候选是只读参考，不采用为正式答案、不写回训练草稿或提交、不生成新的独立尝试。重新生成形成另一任务及候选，旧任务保留。生成和查看不完成复练、不关闭改进动作、不产生能力结论。用户需要验证改进时，沿既有空白复练流程独立作答。

提示词要求根据原答已说出的内容整理表达；没有说出的职责、结果、生产经历、性能数据或技术步骤不能冒充用户原意。需补充或核实的问题进入独立 `questions` 区域。引用和结构校验不能证明模型完全遵守这些语义要求，真实候选质量须由用户及服务器验收分别审阅。

## 2. 访问确认、辅助与曝光

本批复用按确切答案保存的 `evaluations/access`，在现有评价区中主动生成和打开改写参考。访问确认与第三方外发授权仍是两个动作：前者允许进入参考区，后者才创建获准模型请求。未开启 AI 也可以读取已有合法候选。

- `AFTER_ANSWER` 在已提交后允许确认访问；`AFTER_SESSION` 在结束前必须单独确认提前反馈。
- 专项／模拟尚未结束且未获辅助授权时，确认访问在同一 owner 事务记录 `MATERIAL_ACCESS`，之后提交按 `ASSISTED` 保存。此前提交的文字、图、条件及截止事件均保持原样。
- 访问确认继续保存原 `EVALUATION_ACCESS` 曝光语义：请求打开评价区，不证明实际阅读，更不证明看过某份改写。已有历史记录、曝光枚举及成长计数字段不改写。同答案已有访问记录时不重复追加曝光。
- 用户在已获准区域仍须主动选择生成，外发授权明确说明将生成并展示改写参考；任务完成、后台读取和状态通知不新增阅读事件。
- 暂停／结束不改变已提交输入的身份；另一场独立训练、当前未获辅助授权的训练、旧任务入口、历史回执及浏览器缓存均继续执行资料守卫。复练默认隐藏旧答、参考和改写。

新接口统一在 `/api/v1/ai/answer-rewrites` 下，继承 `/ai` 入站和序列化前资料守卫，不增加训练安全路径例外。创建、读取、重试及原键恢复均核对该答案访问资格。一般来源不可用、权限拒绝、持久数据损坏和数据库故障不得混为一种正常失效。

## 3. 固定输入与唯一外发投影

Manifest 不增加字段，复用 `evaluation` 的完整 `EvaluationInput`，`purpose=ANSWER_REWRITE`、`promptVersion=answer-rewrite-1`。输入包括：

| 内容 | 固定边界 |
|---|---|
| 身份与条件 | sessionId、questionId、answerId、answerNumber、mode、feedbackTiming、原答提交时的 answerCondition |
| 题面 | 该题实例固定的 title、prompt、conditions、technology、scenario、type |
| 原答 | 已提交 text，图节点 id／label／description，边 id／source／target／label |
| 个人参考 | 该题实例确切题库版本的 referenceAnswer 与 checkpoints；无题库来源时为 null |

没有题库来源的追问或 REPLAY 不借用根主问参考。输入不包含未提交稿、评价报告或决定、训练背景正文、附件、知识正文、准备事实、图坐标、节点外链或其他答案。以上全部输入在外发前完整展示，不用摘要代替原文预览。

两种兼容协议、输入限额和费用预算使用同一业务投影 `{purpose,evaluation}`。按 UTF-8 序列化后的完整投影执行 32 KiB 上限；超限直接拒绝，不截断原答、图字段或个人参考，不自动拆分请求。供应商、模型、配置及价格继续显示在授权清单中，变化后须重新预览。

创建时在 owner 锁内重读确切输入并核对 `expectedManifestHash`。同一次提交的后续新答案、暂停／恢复和结束不自动替换原输入；真实固定原文、访问资格或配置发生变化时，不能沿旧授权继续发送。旧 Manifest 的字段顺序、空值省略规则及存储摘要不因本用途而改写。

读取历史题面、原答和个人参考沿原码点长度及 Java `isBlank` 规则。包含 NUL、孤立代理等不支持外发的字符或结构时，预览返回 `422 AI_SOURCE_UNAVAILABLE` 并提示更正来源后选择新的确切提交，不把既有合法保存内容直接称为数据库损坏。该错误不加入正常来源失效白名单；固定清单、绑定或持久 JSON 损坏仍作为完整性错误，数据库故障继续传播。

## 4. 候选结构与引用

候选结构为 `Candidate{level,summary,answer,changes,questions,limitations,validationNote}`。`level` 固定 `AI_UNREVIEWED`；下列文字上限均以 UTF-16 码元计数，引用坐标同样为 UTF-16：

| 字段 | 约束与展示用途 |
|---|---|
| summary | 非空，最多 2000；说明本次组织思路 |
| answer | 非空，最多 20000；AI 改写参考正文，单独标识，不冒充原答 |
| changes | 1–12 项；每项 explanation 非空且最多 1000，citations 为 1–6 条确切原文引用 |
| questions | 0–8 条，每条非空且最多 1000；需用户补充或核实的问题，不混进已知经历 |
| limitations | 非空，最多 2000；说明材料、参考与改写的限制 |
| validationNote | 服务端固定说明，不由模型自由改写 |

文字总量含引用 `quote` 不超过 32000 UTF-16 码元。新候选正文和引用不能全由 `Character.isWhitespace` 或 `Character.isSpaceChar` 定义的空白组成，包括纯 NBSP。拒绝 NUL、孤立代理、非法枚举、未知／缺失字段、重复 JSON 键、类型强转及尾随内容；保留原文字，不通过截断或宽松解析修补模型结果。原始模型 JSON 和成功结果持久读回都执行结构与引用校验。

固定说明为：

> AI 改写仅供参考，不代表原答、真实经历或已验证能力；新增内容请先核实，再独立作答。

引用复用 `EvaluationCitation{kind,elementId,start,end,quote}`，`quote` 非空且不超过 500 UTF-16 码元。允许定位本次完整输入中的原答文字、原答图节点／边字段、固定题干／条件、个人参考或检查点。普通字段 `elementId=null`；图元素与检查点须为输入内存在的确切 ID。

`start/end` 为原字段左闭右开的绝对区间，必须在范围内、不能拆开代理对，原文字串须与 `quote` 逐字一致。同一改动说明内相同 kind／elementId／start／end 不得重复。不存在的标准、未授权输入、其他提交或图坐标不可作为引用。各条改写说明必须有引用，引用只证明定位来源；不能据此宣称改写语义正确、个人参考已经审核或新增内容属于真实经历。

## 5. API、任务与存储

所有接口要求登录与 owner；POST 要求 CSRF，创建任务还要求 `Idempotency-Key`。预览无持久副作用、不发送模型、不产生费用或曝光。

| 方法／路径 | 请求与响应 |
|---|---|
| POST `/api/v1/ai/answer-rewrites/preview` | `{sessionId,questionId,answerId}` → Preview |
| POST `/api/v1/ai/answer-rewrites/tasks` | 同上，增加 expectedManifestHash、consentConfirmed=true → Task |
| GET `/api/v1/ai/answer-rewrites/tasks?sessionId=&questionId=&answerId=&cursor=&limit=` | sessionId 必需，questionId 可选；指定 answerId 时必须同时指定 questionId；返回 EvaluationPage 形状的摘要，不返回清单、原答、参考或候选正文 |

两个 POST 从最多 262144 字节的原始 JSON 严格读取，拒绝重复键、未知／缺失字段、null 身份、非字符串 UUID、非 Boolean 授权及尾随内容。创建成功返回201。列表 limit 为1–20、默认20；cursor 是排他任务 UUID，按任务ID升序查询。指定 answerId 时核确切访问记录。

详情、取消、显式重试和费用核对复用 `/api/v1/ai/tasks/{id}` 系列接口。Task 在尾部追加可空 `rewrite:EvaluationLink` 与 `rewriteCandidate`；旧回执缺省按 null 兼容。新用途不能混入评价报告或其他用途候选，旧用途也不能带入改写分支。改写没有采用／忽略命令，不借用知识、题目、事实或评价决定。

V47 在 V46 后扩展 AI 任务用途 CHECK，增加独立 `ai_answer_rewrite` 表。绑定使用同 owner 的 task 及已确认访问的确切 session／question／answer 复合外键；每任务一条固定绑定。创建、恢复、领取、发送、结果接纳、重试、详情和回执恢复都核对用途、清单与绑定，坏绑定不能冒充正常来源变化。

每答案最多 3 个改写任务，同答案最多 1 个未决改写任务；配额独立于评价任务，不写入 `ai_evaluation`，不计入评价覆盖。每任务最多 3 次尝试及工作区总未决上限沿 AI 底座。任务、初次尝试、费用预留、绑定、通知及回执同 owner 事务保存。未知费用、取消后迟到结果、进程恢复和明确重试沿现有状态机；生成失败不阻止保存回答或结束训练。

## 6. 并排阅读与恢复

原答、个人未审参考、AI 改写参考使用明确标题分栏；窄屏依次排列且保留身份。原答和参考均来自固定清单，图节点、边的文字内容完整展示；节点或边没有文字时如实显示，不以图美观程度作质量结论。无个人参考时显示该次输入没有参考，不补读其他题的标准。

改写说明可以定位到确切原文／图字段；待核实问题和局限独立展示。重新生成只创建新任务，任务历史能够区分同题不同提交。列表只含摘要，选择任务后读取正文，不用最新提交覆盖历史任务身份。

来源、配置、登录或资料访问条件变化使旧预览同意失效；未知创建结果保留原请求与幂等键。迟到响应按任务／答案身份、登录和访问代次检查，旧回执不得回退较新状态或把另一答案候选展示到当前页。重新取得访问资格后显式恢复原请求或读取已有任务，不自动再次付费生成。
