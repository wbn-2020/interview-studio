# 首阶段接口与数据契约

版本：v1.0 · 2026-11-05。状态：S1 实施契约；运行与服务器验收待执行。

范围：账号会话、笔记／概念、草稿与不可变发布版本、主题与语义关系、稳定星图位置。全文搜索、正文引用、概念笔记关联、布局历史、永久删除与 AI 属后续阶段。完整规则仍以[产品需求](../需求文档/产品需求文档.md)为准，实际进度见[开发记录](../开发记录/开发阶段与进度.md)。

## 1. 通用约定

- 根路径 `/api/v1`，同源 JSON。ID 为标准小写 UUID 字符串；服务端生成对象 ID；`ownerId` 从认证上下文取得，客户端不得指定。
- 所有时间以 UTC 存储和 ISO-8601 `Z` 返回；MySQL `DATETIME(6)` 配套 UTC JDBC 会话。修订号为非负整数，本阶段不跨 JavaScript 安全整数范围。
- 用户手写来源记为 `USER`。笔记 NOTE 与概念 CONCEPT 共用版本存储结构但身份种类不可改变；只有概念参与语义边与默认星图。
- 单用户部署的 owner UUID、登录名、BCrypt 密码哈希由服务器环境配置；无默认密码、无公开注册。此轮不创建、读取实际凭据。owner UUID 是持久数据归属，部署后不得随意更换。
- 使用 Spring Security 服务端 Session，Cookie 名 `STUDIO_SESSION`，HttpOnly、SameSite=Lax、默认 Secure。所有写请求（含登录／退出）检查 CSRF。登录／退出后重新获取 CSRF；匿名可读取会话状态及 CSRF token，其他 API 均需登录。
- `/auth/csrf` GET 返回 `{headerName,token}`；`/auth/session` GET 返回 `{authenticated,username,ownerId}`，匿名后二者 null。`/auth/login` POST 为表单 `username/password`，成功 204；`/auth/logout` POST 成功 204。
- 业务写请求必须带 `Idempotency-Key`（UUID 格式）。作用域 owner＋key，摘要覆盖 HTTP 操作与规范化请求。同键同请求返回原结果，同键不同请求 409 `IDEMPOTENCY_KEY_REUSED`。网络结果不明时保留原键和请求重试，禁止盲目换键重复创建。
- 同一 owner 的写事务通过 `INSERT ... ON DUPLICATE KEY UPDATE` 建立／取得工作区写锁，再 `SELECT ... FOR UPDATE` 读取 `owner_workspace`；避免并发首次操作中的共享锁升级。业务写与回执同事务提交，异常均回滚；回执 JSON 上限 2 MiB，覆盖合法长正文的草稿／发布双份内容及 JSON 转义。个人单实例采用该粗粒度写锁防止双向边／循环竞态，后续基于证据再细化。只读不取此锁。
- Problem Details 包含 `type,title,status,detail,instance,code,traceId,retryable,currentRevision`。参数错误 400，未登录 401，CSRF 403，不存在或非本人 404，修订冲突 409，容量限制 422。业务 JSON 请求体最多 1 MiB（按实际字节有界读取，不能只信 Content-Length），超限 413 `REQUEST_TOO_LARGE`。错误不含 SQL、堆栈、密码、笔记全文。
- 标题 1–200 字符，正文至多 100000 字符；主题名称 1–64 字符／颜色 `#RRGGBB`，单知识最多 20 个主题；拒绝重复 ID、非法枚举和未知主题。正文按原文保存，不通过 trim 改写证据源。

## 2. 对象与数据表

| 表 | 关键字段与规则 |
|---|---|
| owner_workspace | owner_id PK、layout_revision；首次业务命令建立；写入时锁行 |
| command_receipt | owner_id＋idempotency_key PK，operation、request_hash、response_json、created_at；本阶段不自动过期／清理；S8 删除与导出必须覆盖回执中的正文 |
| knowledge_item | id PK、owner_id、kind、status ACTIVE/ARCHIVED、metadata_revision、current_version_id、version_number、created_at、updated_at；id＋owner 索引与所有权查询；current_version_id 只允许创建事务中间态为 NULL，事务提交前必须指向第 1 版本 |
| knowledge_draft | item_id PK、title、body、revision、saved_at；草稿可改，已发布版本不变 |
| knowledge_version | id PK、item_id、owner_id、version_number、title、body、source_type USER、created_at；UNIQUE(item_id,version_number) |
| knowledge_topic | id、owner_id、name、normalized_name、color、created_at；UNIQUE(owner_id,normalized_name)；本阶段最多 200 个主题 |
| knowledge_item_topic | item_id＋topic_id PK；关联写入前重核 owner；不表示语义前置 |
| knowledge_relation | id、owner_id、source_id、target_id、relation_type、created_at；同类型同端点唯一；只关联 ACTIVE 概念 |
| knowledge_position | item_id PK、owner_id、x、y；世界坐标，与主题归属无关 |
| knowledge_outbox | 自增 id、owner_id、item_id、version_id、event_type、created_at、processed_at；发布／归档／恢复与此记录同事务，为 S2 索引消费保留；本阶段无索引消费者 |

各表使用 InnoDB、utf8mb4；UUID 列 ASCII，FK／唯一键保护实体引用；索引支持 owner／状态／kind 与稳定 ID 游标。迁移以 `V1__knowledge_foundation.sql` 提供，**不在应用启动时自动迁移**。发布步骤显式执行 Flyway；此轮不连接数据库。

元数据 revision、草稿 revision、发布 versionNumber 和全局 layoutRevision 分开。创建同时写第 1 个不可变版本和 revision=0 草稿，方便概念立即成为星图实体；后续保存只改草稿，发布才生成新版本。初次发布的空正文允许，空标题不允许。

## 3. 响应形状

`ItemSummary`：`id,kind,title,status,revision,versionNumber,updatedAt,topicIds`。title 为当前草稿标题，星图 title 为已发布标题，界面必须明确未发布草稿。

`ItemDetail`：上述字段＋`currentVersionId,draft,published`。`draft={title,body,revision,savedAt}`；`published={id,number,title,body,createdAt}`。

`Topic`：`id,name,color`。`Relation`：`id,sourceId,targetId,type`。

## 4. 知识与版本 API

| 方法／路径（均在 /api/v1 下） | 请求 | 返回／行为 |
|---|---|---|
| GET /knowledge/items | kind 可选；status 默认 ACTIVE；q 标题子串（非全文检索，至多 100 字符）；cursor 可选 UUID；limit 默认 40、最大 100 | `{items:ItemSummary[],nextCursor}`，按 id 升序，用 limit+1 判断下一页；q 的 `%/_` 按字面量匹配 |
| POST /knowledge/items | `{kind,title,body,topicIds}` | 201 ItemDetail；同时创建第 1 版本、草稿、主题关联、outbox；概念还写初始位置并增加 layoutRevision |
| GET /knowledge/items/{id} | — | ItemDetail；含归档对象，只能查看本人 |
| PUT /knowledge/items/{id}/draft | `{expectedRevision,title,body}` | ItemDetail；检查草稿 revision 和 ACTIVE，成功 revision+1；冲突 409 `REVISION_CONFLICT` |
| POST /knowledge/items/{id}/publish | `{expectedRevision,expectedVersionNumber}` | ItemDetail；固定当前草稿为新版本、草稿 revision+1、元数据 revision+1、outbox；版本变化拒绝，重复点击靠原幂等键重放 |
| PUT /knowledge/items/{id}/topics | `{expectedRevision,topicIds}` | ItemDetail；检查元数据 revision、ACTIVE，revision+1 |
| POST /knowledge/items/{id}/archive | `{expectedRevision}` | ItemDetail；有未发布草稿时拒绝 `DRAFT_UNPUBLISHED`；保留版本／边／位置，退出默认选择与星图 |
| POST /knowledge/items/{id}/restore | `{expectedRevision}` | ItemDetail；显式恢复 ACTIVE，元数据 revision+1；归档／恢复均写 outbox |
| GET /knowledge/items/{id}/versions | before 可选正整数；limit 默认 20、最大 50 | `{items:[{id,number,title,createdAt}],nextCursor}`；版本号降序 |
| GET /knowledge/items/{id}/versions/{versionId} | — | `{id,number,title,body,createdAt}`；双重校验 item 与 owner，原文只读 |

归档／恢复不改草稿和历史正文；概念归档／恢复同时推进 layoutRevision，防止旧星图覆盖变化后的窗口。状态相同的新命令返回当前对象（仍校验 expectedRevision）；修订冲突绝不覆盖输入。前端收到冲突保留本地内容，允许加载服务端副本或将本地内容另存新笔记；不自动合并／强制覆盖。

## 5. 主题、关系和星图 API

| 方法／路径 | 请求 | 返回／行为 |
|---|---|---|
| GET /knowledge/topics | — | `{items:Topic[]}`，name/id 稳定排序 |
| POST /knowledge/topics | `{name,color}` | 201 Topic；trim 后名称大小写归一判重，重复 409 `TOPIC_EXISTS` |
| POST /knowledge/relations | `{sourceId,targetId,type}` | 201 Relation；拒绝自环，校验概念与状态，已有同边返回原 Relation |
| POST /knowledge/relations/{id}/remove | `{}` | `{removed:true}`；本人已无该边时同样成功，不泄漏别人对象 |
| GET /knowledge/graph | limit 默认 200、最大 200 | `{nodes:[{id,title,topicIds,x,y}],edges:Relation[],topics:Topic[],layoutRevision,truncated}`；ACTIVE 概念按 id 取 limit+1；最多 600 条真实边；超出窗口明确 truncated |
| PUT /knowledge/graph/layout | `{expectedRevision,positions:[{id,x,y}]}` | `{layoutRevision}`；有限数值、绝对值≤1000000、1–200 个且 ID 不重复；全体校验后原子更新指定节点，revision+1 |

关系类型为 `PRECEDES/PART_OF/APPLIED_IN/RELATED/CONTRASTS`；前 3 有向，后 2 对称且按端点 UUID 排序去重。PRECEDES 与 PART_OF 分别检查全量本人该类型关系的闭环（含归档端点，恢复不能引入潜在循环）；遍历有界，超过安全边界拒绝而非跳过检查。每人本阶段最多 10000 条语义关系。

每个概念创建时持久化初始坐标；主题切换只淡化／筛选，不重排。节点拖动产生待保存布局，显式保存且有冲突提示；图谱刷新前保留未保存状态。图与列表读取同一实体，侧栏可打开同一正文。初始没有合成知识或伪造连线。空知识库要引导创建概念。

## 6. 前端与验证

- 页面使用 Vue Router；Pinia 仅维护必要的 UI 状态；Vue Query 管服务器查询、写后失效；登录身份变化清空缓存。
- 创建、保存和发布分别有进行中／成功／失败状态；只有服务器回执才显示成功。请求失败保留表单与重试键，离开脏草稿提示；浏览器刷新前提示，默认不将正文写 localStorage。正文和主题各自保留开始编辑时的服务端基线：保存其中一项时，响应中的另一项即使更新，也不能在保留其本地修改的同时悄悄提升该项 CAS 修订号。
- Markdown 用 CodeMirror 编辑，markdown-it 禁用原始 HTML，DOMPurify 净化；远程图片不自动加载，外链限制协议。未接入的模块以清楚的阶段说明呈现，不摆可点击的假操作。
- 不启动本地服务、不写单元测试。允许检查已读脚本后执行 `vue-tsc`、Vite build、Maven compile/package（明确跳过测试）；运行、SQL、Session/CSRF、并发与视觉均待服务器。
- 静态 OpenAPI 与 SQL 跟随本契约；前端通过 openapi-typescript 离线生成类型。暂不接入用不到的 AI、解析器、FSRS、Lucene 运行依赖。
