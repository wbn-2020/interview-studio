## 1. 代码依据与本批决策

本次已读 `MemoryDtos`、正在实施的 `MemoryService/MemorySources/MemoryMapper`、`KnowledgeService`、`IdempotencyService`、`PlanningRules` 及搜索 Mapper。卡片版本和参考已分开读取，sources 有独立关系表；MemorySources 依赖 KnowledgeService。知识发布有手工 `publish` 和 AI 采用 `publishWithinCommand` 两个入口；归档／恢复在 `changeStatus`。这些变更均处于同一 owner 命令事务。`IdempotencyService` 在业务动作前取得 owner 锁、检查资料守卫及旧回执，动作与回执同事务。搜索独占使用 `knowledge_outbox.processed_at`，不能兼作记忆消费者进度。

| 决策 | 采用规则及原因 |

## 3. 先回忆、揭示与评分

正式尝试只从当前 ACTIVE 卡版本开始。REGULAR 的 countRegular 固定 true；CRAM 必须显式传布尔值，界面缺省 false。计入标记、卡版本、算法参数、排程修订与冲刺归属在 START 固定，之后不可切换。

`THINKING → REVEALED → RATED`；THINKING／REVEALED 可显式 SKIPPED，也可因卡、依据或排程变化 INVALIDATED。RATED／SKIPPED／INVALIDATED 均为终态，释放一卡一个未决占位。关闭页面不自动跳过、评分或释放占位；重入读取同一 attempt，用户可以继续或跳过。重复新建返回 `MEMORY_ATTEMPT_OPEN` 和本人的未决 attemptId，不偷偷复用新请求的新条件。

- THINKING 可以只想，或保存文字草稿。`responseMode=THOUGHT|WRITTEN`；THOUGHT 的文字为空，WRITTEN 为非空、最多10000 Unicode码点，均沿用首批 Unicode／字节上限规则。保存草稿需 attempt CAS，服务器成功后才显示已保存。
- REVEAL 是显式写命令，原子固定 responseMode／最终 response、revealedAt 与 REVEAL 事件，随后才返回确切版本 reference。`thoughtConfirmed=true` 表示用户选择揭示，不证明系统观察到其思考。revealedAt 采用服务器 UTC 微秒时间。
- 普通 attempt 读取始终没有参考字段；揭示命令返回同版参考，刷新后通过受 revealedAt 约束的显式参考恢复接口读取。失效前未揭示的尝试不能借历史查询取得参考，仍可走首批明确“浏览参考”入口。
- 评分只接受 AGAIN／HARD／GOOD／EASY。必须已揭示，并重新校验所有权、当前卡版本／修订、gate、来源与所需排程修订；不能靠前端按钮状态授权。
- SKIP 不调用算法，不改变 due、难度、稳定性、预算消耗或复练动作；保留此前是否已揭示的事实。
- 首批 reference 浏览没有正式 attempt、揭示或评分；浏览历史和未计入 CRAM 都不改变常规排程。自评从不成为技术审核结论、能力总分或项目复练动作完成条件。

thinkingElapsedMs=揭示时间−开始时间，totalElapsedMs=评分时间−开始时间；保存为有单位的 long 和原始时间。它们是墙钟间隔，可能包含离开页面／离线，不能称“有效专注时间”。客户端时钟不决定 due 或事件顺序；服务器时间倒退则拒绝评分并保留已揭示尝试，不能写负耗时。

## 4. 来源影响、卡片保存及显式复核

### 4.1 同步影响入口

新增 `MemoryInvalidation`，只依赖记忆／知识 Mapper 和纯规则，不依赖 MemoryService、MemorySources、KnowledgeService 或 PlanningService。内部入口要求 MANDATORY 写事务且调用者已取得 owner 锁。调用方向为 MemoryService→MemorySources→KnowledgeService→MemoryInvalidation→Mapper，没有返回上层 Service 的依赖环。

KnowledgeService 的两种发布入口都在版本写入同一事务调用该组件，传入先前已发布版本、新版本和同一 now；按 body 原字符串比较。saveDraft、改主题、收藏、布局不调用正文失效逻辑。changeStatus 仅在实际状态迁移时记录影响，恢复只追加状态事实，不清除旧待复核。首次创建知识没有旧依赖，无须制造更正事件。

影响查询沿**当前卡版本的 sources**，不沿 relatedConceptIds、主题、双链、普通结构边或任意历史版本。已有源关系按 owner＋source item 与当前 cardVersion 连接，记录当前受影响对象／版本。正文变化的门禁更新、暂停排程、关闭未决尝试、影响记录和知识新版本一起提交；任一失败回滚全部。不得先发布再后台补暂停，也不能复用搜索 processed_at。

建议以按索引限定的集合 SQL 处理直接依赖，避免每张卡调用服务；实际扇出耗时仍待服务器测量。若超出既有事务超时，整体失败并报告，不截断传播名单。间接“事实→表达／AI 笔记→卡片”不是这次直接源钩子的已实现能力，后续 S8 必须接到同一影响入口。

### 4.2 影响规则

| 变化 | 待复核／排程／尝试规则 |
|---|---|
| 来源只改标题并发布 | 维持旧引用标签；动态 state 可为 SUPERSEDED，bodyChanged=false；不增加 gate，不暂停或使 attempt 失效 |
| 来源已发布正文改变 | 记录 SOURCE_BODY_CHANGED，gate 增加且 reviewRequired=true；排程暂停，未决尝试 INVALIDATED。提示“正文变化需核对”，不标为已确认错误 |
| 正文改后改回 | 再记录变化；即使当前 bodyChanged=false，旧 reviewRequired 仍保留 |
| NOTE 来源归档 | SOURCE_ARCHIVED；暂停依赖卡排程并保留显式复核要求，未决尝试失效；恢复不自动启用 |
| CONCEPT 来源归档 | 按 PRD §7：若仍有其他有效依据来源，保留排程并警告；若无其他有效依据则暂停并要求复核。两种情况都推进 gate 并使旧 attempt 失效，避免旧来源快照被评分接受 |
| 来源恢复 | 追加 SOURCE_RESTORED、推进 gate；不清除原待复核或暂停。以前只是非阻断概念警告的卡保持其原状态 |
| Card 改 kind／prompt／reference 或 sources 集合 | 记录 CARD_BASIS_CHANGED、要求复核、暂停已有排程、使未决尝试失效；用户刚编辑不等于确认沿用旧间隔 |
| Card 仅改 title、relatedConceptIds 或 sources 顺序 | 不新建待复核或暂停；新 CardVersion 仍使旧 attempt 失效，旧固定题面与新版本不混用；不得清除原待复核 |
| Card 归档／恢复 | 归档暂停已有排程并关闭未决尝试；恢复只恢复管理状态，必须另外显式恢复排程 |

“其他有效依据”指同一当前卡版本的其他 sources：本人可访问、ACTIVE、bodyChanged=false，且卡没有未处理正文影响。此规则只将 CONCEPT 归档的 PRD 多来源例外保留下来，不把额外相关概念当成有效依据；未来如要让 NOTE 来源也可替代，需另作产品决定。

新增卡在同一命令创建 gate；当前来源验证成功可以先为无需复核，仍不自动创建排程。保存新版本必须保留既有 pending 状态；移除／替换来源虽然停止该来源对未来当前卡的传播，**不能自动抹去已经影响卡正文的记录**。移除来源属于 CARD_BASIS_CHANGED，用户确认改写或取消依赖后再复核；至少一个 sources 的首批规则保持。

### 4.3 复核与部署基线

用户通过首批显式参考接口读取确切当前卡／参考，核对来源状态后，单独提交 source-review，携带 expectedCardRevision、expectedGateRevision、confirmed=true 和 reason。请求、响应及确认快照都不复制题面、参考或来源正文；reason 为用户本次填写的确认说明。前端须等待同版参考读取成功才允许确认，confirmed 表达用户已核对的声明，不宣称服务器观察了阅读行为。服务端重新校验同一版本及当前依据：正文仍不同的旧来源必须先改绑当前版本或从卡内容撤销；归档 NOTE／全部失效概念不能通过复核。只改标题而 body 相同的旧版本可保留。确认记录保存所核对的 gateRevision、来源身份／版本／状态及结果修订；gate 加1并解除当前 reviewRequired，历史影响不删除，旧确认不能覆盖之后新增的影响。

source-review 本身不启用／恢复排程，也不替用户选择沿用间隔。提交时有未决尝试则关闭为 INVALIDATED，之后按新基线重新开始；不能把揭示过的旧尝试迁移到新基线评分。

第二批迁移时，既存首批卡没有可证明完整的来源变更观察期，统一初始化 `BASELINE_REVIEW_REQUIRED`，首次启用前由用户复核；不从当前 bodyChanged=false 推断过去没有改后改回。迁移后新建卡使用同步钩子建立观察基线。

GET 只计算状态，不修复数据库。若读到缺失 gate／来源或未覆盖的异常变化，返回不可开始／需重新核对，不能在随后抛异常的评分事务中“先标失效再回滚”并声称标记已保存。维护性修复需独立命令与明确成功回执。

## 5. 排程算法、手工调整与恢复

使用经核验的 `io.github.open-spaced-repetition:fsrs:1.0.0`，实现标识含固定提交；默认21权重、retention=0.9、学习步骤60/600秒、重学步骤仅600秒、maximumInterval=36500天、fuzzing=false。参数保存为不可变配置 `fsrs-java-1.0.0-default-unfuzzed-1`，含实际数值；事件引用版本并保存必要前后状态。不开放多步重新学习配置，规避已核验上游分支缺陷。

领域状态自行保存 state／step／stability／difficulty／due／lastReview；不序列化库对象，不暴露库概率。评分时间显式传 Instant，reviewDuration 向库传 null，产品另存 elapsedMs。输入／输出校验有限数值、时间有序及合法状态；算法或依赖失败时整次评分回滚，attempt 保持 REVEALED，允许原请求恢复。不得悄悄改成固定间隔并仍称 FSRS。

| 操作 | 行为 |
|---|---|
| 首次 enable | 卡 ACTIVE、gate 已核对、来源有效；新建排程和 cycle，初始库态 LEARNING／step=0／稳定性难度null／lastReview=null；按 timeMode／at 解析生效时间 effectiveAt，设 suggestedDueAt=effectiveAt，无评分事件 |
| 常规评分 | 以真实 ratedAt、当前周期前态及固定参数调用算法，保存算法返回 suggestedDueAt；清除已消费的 deferUntil，一次推进 schedule revision |
| defer | 保存未来 deferUntil 和理由；不改算法 suggestedDueAt／稳定性／lastReview，不伪造学习；effectiveDueAt=max(suggestedDueAt,deferUntil) |
| pause | status=PAUSED，保留原 due 及 FSRS 状态；关闭该卡可推进排程的未决尝试。单纯手工暂停不禁止来源有效的 CRAM、不产生待复核 |
| resume KEEP | 重新核对卡、gate、来源；保留算法状态，将 timeMode／at 解析的 effectiveAt 设为新的 deferUntil，不把过去 due 重写成已完成 |
| resume RESET_AS_NEW | 明确确认后建立新 cycle、清空当前周期算法前态，以 effectiveAt 设置新 suggestedDueAt；旧事件／周期保持。用户界面说明将重新作为新卡 |

首次 enable 与 resume 都要求显式 `timeMode=NOW|AT` 和必填可空 `at`。NOW 必须 at=null，使用取得 owner 锁、通过旧回执检查后，在本次业务动作内取得并统一使用的服务器 UTC 微秒 now 作为 effectiveAt；客户端不发送一个模拟“现在”的时间戳。AT 必须给出符合持久化范围及微秒精度的 UTC Instant，且严格晚于该 now，否则保留输入并返回时间冲突；不静默转成 NOW。非法组合整体拒绝。同一 now 用于校验、生效时间、状态及历史时间；原键重试先恢复旧回执，不重新计算 NOW 或用新的时钟否定已成功的 AT。

恢复还必须显式选择 KEEP 或 RESET_AS_NEW，并确认“立即”或指定未来时间。尚在未来的 suggestedDueAt 在 KEEP 下不会被提前；需要提前练习可使用不计入 CRAM。defer 的 deferUntil 则必须晚于当前 effectiveDueAt 和 now，不提供“立即延期”；没有隐式延期、批量改过期事件或定时伪造完成。

已有排程的参数／算法不随部署默认值静默切换。本批固定一种配置；以后迁移需要可追溯的 ScheduleChange，原评分事件保持原版本。

## 6. 常规、冲刺与每日预算

REGULAR 和 `CRAM + countRegular=true` 共用 eligible 判定：卡 ACTIVE、gate 无待复核、依据有效、已有 ACTIVE 排程、effectiveDueAt≤服务器 now、无其他未决 attempt、匹配 card/gate/schedule CAS。来源有效性、due 与 CAS 在开始、揭示、评分三处重核；自动失效和人工排程变更会同步关闭相关未决尝试，不能把已过时的评分套在新状态上。

`CRAM + countRegular=false` 可以在无排程、未到期或手工 PAUSED 时进行，仍要求卡及依据可用、gate 通过、无其他未决尝试；不依赖 schedule CAS、不调用 FSRS、不消费常规预算。已有排程可作为当时上下文记录，但不能把它当更新前态。不能在评分请求中把 false 改为 true；若用户改变决定，应跳过旧尝试并按常规条件重新开始。

CramBatch 由用户显式选择1–200张 ACTIVE 卡，startDate/endDate 为包含首尾1–90天，zoneId 使用 IANA／UTC。日期是计划区间，不是自动失效时间；过期显示实际日期，不自动顺延或冒充完成。固定 cardIds 只表达范围，开始尝试时固定所选卡的当前版本；变化卡逐项提示。首批卡筛选可用于选择来源／概念范围，但创建时展开为明确 cardIds，不存会悄悄扩大的动态集合。本批不为冲刺批次创建普通准备任务或训练会话。

ReviewSettings 采用每日新卡10张、复习50张作为建议初值，范围0–1000；这是本方案审定的可编辑界面默认值，不是算法参数或用户已经保存的设置。0表示默认队列不推荐该类，用户仍可明确“继续超出今日预算”。zoneId 必须由设置明确提供，复用 PlanningRules.zone 的校验语义；不从服务器 OS 或浏览器固定偏移猜测。未保存设置时 GET 返回 configured=false 与建议值，不能假装已有 revision；首次启用排程和常规计入前须显式创建设置。未计入 CRAM 使用批次自己的明确时区。

- “今日”以当前设置 zoneId 的本地日期计算 `[当地零点,下一当地零点)` 后转换为 UTC；不以24小时代替 DST 日长度。队列只纳入实际到期且可用的卡，排序建议先到期学习／重学，再按 effectiveDueAt、cardId；返回固定 asOf，分页用完整排序键，不因读取推进状态。asOf 只固定到期上界，不宣称跨请求数据库快照；卡片可用性／due 在分页间变化时界面按 cardId 去重，已知写入后重读首页，开始时仍执行事务内校验。
- 每日预算消耗只统计该 UTC 区间内成功的 countRegular=true 评分，每张卡计一次，按当天第一条计入事件的周期前态分 NEW／REVIEW。同一张新卡当天分钟级再次评分不重复占额度；原始评分次数另外显示，不混为卡片数。
- 已在当日额度中计过的卡继续到期学习步骤，不被预算截断。未决尝试可单独显示，不冒充已完成；预算为软约束，无需占用或回收硬额度。
- 开始时若新增一张卡会超过建议预算，要求 continueBeyondBudget=true。进入尝试后设置变化、跨午夜或其他卡先评分，不得因此拒绝已揭示后的合法评分；实际评分归属按 ratedAt 与当时设置记录。
- 更改 zoneId 不移动 UTC due 或改写事件。今日统计依据新时区重新查询真实时间区间，明确提示统计区间发生变化；事件保留评分时的 zoneId／localDate／settingsRevision，历史原标签不重写，不将切换时区宣称为“额度清零”。
- 今日后续聚合使用 `sourceType=MEMORY_CARD,sourceId=cardId` 引用本域结果，不复制第二份可勾选完成状态。普通准备任务和复练动作仍由各自原域完成条件决定。

## 7. API 契约

## 8. 事务与并发推导

所有命令首先通过 IdempotencyService 的当前资料守卫；旧回执返回原结果，不重新执行算法或来源影响。原回执中的来源状态是当时事实，恢复后另读 recall-state 更新当前提示。普通 GET 不偷偷启动、揭示、消耗预算或推进排程。

评分事务顺序：取得 owner锁 → 找旧回执 → 校验 attempt状态／修订与未决占位 → 校验固定card/gate及计入时schedule修订 → 验证来源和时间 → 纯函数计算 → 写RATE事件、排程前后快照及当前排程CAS → 关闭attempt并释放占位 → 写回执。预算与日期标签在同一评分时间基线上生成。任何异常连同回执整体回滚；不在提交前发外部通知或调用模型。

| 竞态 | 确定行为 |
|---|---|
| 同键重复评分 | 返回原RATE结果，只有一次事件／排程变化 |
| 不同键重复评分 | 首次提交后attempt终态；后者拒绝，不再次调用算法 |
| 两个标签开始同一卡 | owner锁与唯一未决占位保证只保留一个THINKING／REVEALED |
| 更正先提交、评分后取得锁 | 影响与失效已提交；评分拒绝，原揭示／回答可读 |
| 评分先提交、更正后取得锁 | 评分是变更前的真实记录；后续影响暂停下一次排程，不倒改评分 |
| 更正后改回、归档后恢复 | 影响记录和gate保留，旧attempt不复活；源当前性不能替代gate |
| 卡新版本或source-review并发 | 固定card/gate修订失配，关闭旧attempt；不能给旧已揭示回答套新卡 |
| 暂停／延期与评分并发 | 可推进排程的attempt在变更事务中失效，或先完成评分后再基于新schedule CAS操作 |
| 设置跨午夜／时区变化 | 不改固定评分条件与UTC排程；成功评分按真实ratedAt及当次设置记账，不能以预算变化丢弃评分 |

## 9. 持久化与验收边界

## A. 第二批 A 的共享字段与管理接口

本节是 A 批的精确机器字段依据；类型定义为 [MemoryReviewDtos.java](../../backend/src/main/java/com/wenjie/studio/memory/MemoryReviewDtos.java)。不更改首批 MemoryDtos 写字段或摘要，不依赖 attempt、评分、队列或冲刺表。下面的响应都是管理状态或不可变操作摘要，没有卡题面、参考、知识正文或用户回忆回答。

### A.1 基础类型、上限与可空规则

- ID 均为标准小写 UUID。Card 修订仍为整数 0–1000；gate／schedule／settings 修订为整数 0–9007199254740991。创建修订为0，需要递增且已到上限时整体拒绝。序号独立于修订：每张卡的来源历史和排程历史各自从1连续递增，上限9007199254740991；无历史时 lastHistorySequence=0。达到序号上限不得截断历史或跳过记录。
- 所有声明的请求字段必填；只允许本节标明的字段为 null。confirmed 必须是 JSON 布尔 true，不能省略、传字符串或用默认值。未知字段、重复 JSON 键、尾随 JSON、非整数修订／预算及数值枚举整体拒绝。
- reason 为1–1000 Unicode码点的非空白原文，保留字面值；沿用首批的 NUL／孤立代理禁用规则。首次 enable 的已审定请求没有 reason；其历史 reason 保存空串，不编造用户解释。系统影响历史由 kind／impactId 表达原因，自动排程变更的 reason 也保存空串。
- 时间传 UTC `Z` 结尾的字符串，持久化范围为1000-01-01T00:00:00Z至9999-12-31T23:59:59.999999Z；值必须可精确表示为微秒，不能截断。NOW 的 at 必须为 null；AT 的 at 必须非空且严格晚于命令取得锁后统一取值的 now。deferUntil 同时严格晚于 now 与当前 effectiveDueAt。
- 单次 A 写请求原始 UTF-8 不超过16 KiB；普通状态／命令响应不超过64 KiB；单条不可变历史摘要不超过16 KiB，历史页不超过1 MiB。仍受既有2 MiB幂等回执上限约束。上限检查在提交前完成，超限返回 MEMORY_LIMIT，不截断理由、来源或历史。GET 超限不写入任何状态。
- 所有列表均非空值，空集合用 `[]`。响应里的可空字段仍输出为 null；前端不得把缺失／null 修订当0。未来 B 可增加可空读取字段，但旧 A 请求、摘要及已存历史语义保持；旧回执缺少新读字段时按未知处理，不补造尝试／评分事实。

### A.2 写请求与对应响应

前缀 `/api/v1/memory`。所有 POST／PUT 使用 `Content-Type: application/json`、Idempotency-Key、现有 Session／CSRF 和 memory 资料守卫；原键回执读取前仍检查当前权限。所有响应使用 no-store。

| 方法／路径 | 精确请求 DTO 与字段 | 成功响应 |
|---|---|---|
| POST `/cards/{id}/source-review` | `SourceReview(expectedCardRevision,expectedGateRevision,confirmed,reason)` | 200 RecallState；gate.lastReviewDecisionId 指向本次不可变决定 |
| POST `/cards/{id}/schedule` | `EnableSchedule(expectedCardRevision,expectedGateRevision,timeMode,at,confirmed)` | 201 Schedule；只有首次启用可创建 |
| POST `/cards/{id}/schedule/defer` | `DeferSchedule(expectedScheduleRevision,deferUntil,reason)` | 200 Schedule |
| POST `/cards/{id}/schedule/pause` | `PauseSchedule(expectedScheduleRevision,reason)` | 200 Schedule |
| POST `/cards/{id}/schedule/resume` | `ResumeSchedule(expectedCardRevision,expectedGateRevision,expectedScheduleRevision,policy,timeMode,at,confirmed,reason)` | 200 Schedule |
| POST `/review-settings` | `CreateSettings(zoneId,dailyNewBudget,dailyReviewBudget)` | 201 Settings；显式初始化一次 |
| PUT `/review-settings` | `SaveSettings(expectedRevision,zoneId,dailyNewBudget,dailyReviewBudget)` | 200 Settings |

`TimeMode=NOW|AT`；`ResumePolicy=KEEP|RESET_AS_NEW`。请求中的 Card、Gate、Schedule 修订分别对应当前对象，先核对全部预期值再执行业务变化。source-review 和 resume 要求当前 ACTIVE 卡及存在 gate；source-review 允许尚无排程，成功只推进 gate，不代替启用或恢复。暂停可作用于已有排程，不要求卡仍 ACTIVE；恢复仅接受 PAUSED。defer 仅接受 ACTIVE 排程，PAUSED 必须走显式恢复。

pause 对已经 PAUSED 且 expectedScheduleRevision 匹配的排程返回原对象，不修改原暂停原因、修订或历史；不匹配仍冲突。enable 对已有排程的新 key 返回冲突，不能变成隐式恢复。每次成功 source-review 都追加决定并推进 gate，包括对已无待复核状态的再次明确核对；该行为不能当作评分。

### A.3 recall-state、来源与门禁

| DTO | 精确字段与含义 |
|---|---|
| RecallState | `cardId,cardRevision,cardVersionId,cardStatus,gate,sources,schedule,eligibility,asOf`；cardStatus 使用首批 ACTIVE／ARCHIVED。asOf 是本次一致读取的服务器时间；gate、schedule 可空，其余必填 |
| Gate | `cardId,revision,reviewRequired,lastReviewDecisionId,lastHistorySequence,updatedAt`；lastReviewDecisionId 首次确认前为 null。reviewRequired 是持久事实，不从当前 bodyChanged 反推 |
| SourceSnapshot | `itemId,versionId,kind,versionNumber,state,currentVersionId,bodyChanged`；顺序对应当前卡版1–10条 sources。kind 为 NOTE／CONCEPT，state 为 CURRENT／SUPERSEDED／ARCHIVED／UNAVAILABLE；不复制标签或正文 |
| Eligibility | `sourceReviewAllowed,basisReady,blockers,warnings`；只表示当前卡、来源和 gate 的管理条件，不判断到期、预算或未决尝试，也不产生“可评分”承诺 |

来源存在且可访问时，SourceSnapshot 的 kind／versionNumber／currentVersionId／bodyChanged 均非空；bodyChanged 只按确切来源与当前发布正文比较。不存在、版本错配或不能确认时 state=UNAVAILABLE，以上四字段全为 null，保留卡中已存 itemId／versionId 供定位，不泄漏外部对象。其他可读取来源仍返回；遇到不可用来源不能跳过后把整卡视为有效。归档优先于新旧版本状态。

`BlockReason=CARD_ARCHIVED|GATE_MISSING|REVIEW_REQUIRED|SOURCE_UNAVAILABLE|SOURCE_BODY_CHANGED|ARCHIVED_NOTE_SOURCE|NO_VALID_SOURCE`；列表不重复，按此顺序输出当前成立项。basisReady 要求没有阻断项。sourceReviewAllowed 要求卡 ACTIVE、gate 存在且当前来源满足 §4.3 的确认条件，REVIEW_REQUIRED 本身不妨碍用户复核。缺失 gate 的 GET 返回 gate=null、basisReady=false、sourceReviewAllowed=false，不偷偷插入修复行。

`Warning=ARCHIVED_CONCEPT_WITH_OTHER_SOURCE`，最多返回一次；确切归档概念可由 sources 定位。只对 §4.2 的多有效来源 CONCEPT 例外给出此警告；relatedConceptIds 不参与判定。已有持久正文待复核仍保持，不能因另有来源或 bodyChanged=false 自动清除。启用／恢复还须另外检查 Settings 已配置和 Schedule 状态；客户端提示不能替代命令内校验。

新卡 gate 初始 revision=0、reviewRequired=false、lastReviewDecisionId=null、lastHistorySequence=0；既存首批卡初始 revision=0、reviewRequired=true，并追加序号1的 BASELINE_REVIEW_REQUIRED。迁移没有来源正文观察记录，不得把旧卡初始化成已复核。卡内容或来源新影响推进 gate 时保留先前决定 ID，便于查看曾确认到哪里；该 ID 不表示后来影响已经确认。

### A.4 不可变来源历史与操作者

GET `/cards/{id}/impacts` 返回 ImpactPage，合并 IMPACT 与 SOURCE_REVIEW；不能只返回当前未处理项而丢掉更正后改回的过程。

| DTO | 精确字段与含义 |
|---|---|
| Actor | `kind,ownerId`；kind=OWNER 时 ownerId 为当前工作区 owner，服务端从身份取得；kind=SYSTEM 时 ownerId=null，用于部署基线等维护事实。写请求不能指定操作者 |
| SourceChange | `itemId,kind,referencedVersionIds,previousVersionId,currentVersionId,previousStatus,currentStatus`；所有字段非空，referencedVersionIds 为当前卡版对本知识对象的1–10个不同确切版本，按卡中顺序；状态使用知识 ACTIVE／ARCHIVED |
| Impact | `id,cardId,cardVersionId,gateRevision,reason,source,reviewRequired,actor,createdAt`；gateRevision／reviewRequired 是本次影响后的门禁值；source 在来源变更时非空，在基线／卡片影响时为 null |
| SourceReviewDecision | `id,cardId,cardVersionId,cardRevision,reviewedGateRevision,resultingGateRevision,sources,reason,actor,createdAt`；sources 固定确认时1–10条 SourceSnapshot；resultingGateRevision=reviewedGateRevision+1，actor.kind=OWNER |
| SourceHistoryEntry | `sequence,kind,impact,decision`；kind=IMPACT 时仅 impact 非空，kind=SOURCE_REVIEW 时仅 decision 非空，另一个显式 null |

`ImpactReason=BASELINE_REVIEW_REQUIRED|SOURCE_BODY_CHANGED|SOURCE_ARCHIVED|SOURCE_RESTORED|CARD_BASIS_CHANGED|CARD_ARCHIVED|CARD_RESTORED`。同一次知识变更对同一卡只推进一次 gate，SourceChange.referencedVersionIds 同时记录该卡对同一知识对象的全部当前引用，避免同 item 的多版本引用重复制造一次影响。只改标题／relatedConceptIds／sources 顺序不新增来源影响；完整 CardVersion 仍由首批保存，B 必须在该事务使旧尝试失效。

来源恢复记录当前事实并推进 gate，不清除 reviewRequired。卡归档／恢复也记录相应影响；归档不凭空制造正文待复核，恢复不清既有 pending、不恢复排程。源历史与 Gate 的 lastHistorySequence 同事务推进；源事件序号和 gate revision 含义不同，不可互相替代。后续读取不重新计算历史 SourceSnapshot，也不把当前状态覆盖到旧决定。

### A.5 排程状态与不可变调整历史

| DTO | 精确字段与含义 |
|---|---|
| FsrsState | `phase,step,stability,difficulty,dueAt,lastReviewAt`；phase=LEARNING／REVIEW／RELEARNING；step、stability、difficulty、lastReviewAt 可空，其余非空 |
| Schedule | `cardId,revision,cycleId,status,pauseReason,algorithmVersion,parameterVersion,state,suggestedDueAt,deferUntil,effectiveDueAt,lastRatedEventId,lastHistorySequence,createdAt,updatedAt` |
| ScheduleChange | `id,sequence,cardId,cardVersionId,cardRevision,gateRevision,kind,before,after,impactId,actor,reason,createdAt`；固定操作当时版本和门禁；before 仅 ENABLE 时为 null，after 始终非空 |
| ScheduleHistoryPage | `items,nextBefore`；items 为 ScheduleChange 列表，nextBefore 为可空整数 |

`ScheduleStatus=ACTIVE|PAUSED`。ACTIVE 的 pauseReason=null；PAUSED 的 `PauseReason=MANUAL|SOURCE_REVIEW|CARD_ARCHIVED`。pauseReason 表示导致当前暂停的记录，source-review 清除门禁后仍须另行 resume 才能清除暂停原因。deferUntil、lastRatedEventId 可空，其余 Schedule 字段必填。A 的 lastRatedEventId 恒为 null；这是领域状态中的空身份字段，不查询或建立 B 的事件表。

固定 algorithmVersion 为 `java-fsrs:1.0.0@c561ee6c56239b621a0a45b16a6c2e688441eae5`，parameterVersion 为 `fsrs-java-1.0.0-default-unfuzzed-1`，均至多128个 ASCII 字符。它们标记将采用的不可变实现与参数配置，不表示 A 已执行 FSRS。A 首次 enable／RESET 的 FsrsState 只写 `LEARNING,step=0,stability=null,difficulty=null,dueAt=effectiveAt,lastReviewAt=null`。A 不生成评分、稳定性或难度。

Schedule.suggestedDueAt 必须等于 state.dueAt；effectiveDueAt 为 suggestedDueAt 与非空 deferUntil 的较晚者。defer／KEEP 只改 deferUntil；pause 保留三个到期字段和完整算法状态。RESET 生成新 cycle，state 和 suggestedDueAt 重设为初态、deferUntil=null、lastRatedEventId=null，保留初次建立的 createdAt。首次 enable 的 revision=0、lastHistorySequence=1；其后每次实际排程变化各加1。已存在且内容不变的暂停不写新历史；自动暂停只有当前状态或暂停原因实际变化时才记录排程变化，来源影响仍完整记录。

`ScheduleChangeKind=ENABLE|DEFER|PAUSE|RESUME|RESET|SOURCE_PAUSE|CARD_PAUSE`。resume KEEP 记录 RESUME，RESET_AS_NEW 记录 RESET；SOURCE_PAUSE／CARD_PAUSE 必须引用本事务实际 Impact 的 impactId，其余 impactId=null。来源钩子操作者为触发变更的 OWNER，不能伪装系统自动发现。历史 before／after 保存完整 Schedule，不在读取时重算到期或版本；A 无 RATE 类事件。

### A.6 设置与分页

Settings 精确字段为 `configured,revision,zoneId,dailyNewBudget,dailyReviewBudget,createdAt,updatedAt`。GET `/review-settings` 未配置时返回 configured=false、revision/zoneId/createdAt/updatedAt=null、dailyNewBudget=10、dailyReviewBudget=50；不会插入设置行。显式 POST 必须提供 IANA／UTC 时区和0–1000的整数预算，保存后 configured=true、revision=0，两个时间非空。PUT 需实际 expectedRevision，成功修订加1，不把时区变化理解为修改 UTC due 或清空历史。

两个历史 GET 的分页参数统一为 `before`（可省略，给出则为1–9007199254740991的整数、排他）与 `limit`（默认20，范围1–50）。按对应卡的 sequence 倒序，额外读取一条判断后续；有后续时 nextBefore 为本页最后一条 sequence，否则 null。来源和排程分别使用自己的序号，不用 UUID 或毫秒拼接代替序号，也不把 source-history cursor 用于 schedule-history。历史查询、recall-state 使用一致只读事务，不推进 gate、修订或序号。

### A.7 错误定位与待验证边界

继续使用现有 ApiProblem 的 `code/currentRevision`，以错误码明确修订对象，避免改造公共错误 DTO：card 冲突用 REVISION_CONFLICT；gate 用 MEMORY_GATE_CONFLICT；schedule 用 MEMORY_SCHEDULE_CONFLICT；settings 用 MEMORY_SETTINGS_CONFLICT。currentRevision 只代表对应对象实际当前值；缺失对象没有修订时不填造0。多个修订同时不匹配时按 card→gate→schedule 检查并只报告先遇到项，客户端保留输入后重新读取。

MEMORY_CARD_NOT_FOUND 保持404；不存在排程返回 MEMORY_SCHEDULE_NOT_FOUND（404）；缺失 gate 返回 MEMORY_GATE_UNAVAILABLE（409）；设置未配置返回 MEMORY_SETTINGS_REQUIRED（409）；待复核返回 MEMORY_REVIEW_REQUIRED（409）；PAUSED 上直接 defer 返回 MEMORY_SCHEDULE_PAUSED（409）；AT／deferUntil 已不满足未来条件返回 MEMORY_TIME_CONFLICT（409）。字段组合／类型错误仍为 INVALID_REQUEST，非法或不可访问来源复用 SOURCE_UNAVAILABLE／SOURCE_CHANGED；容量和修订上限分别为 MEMORY_LIMIT／REVISION_LIMIT。错误必须保持事务回滚，不夹带正文。

A 的服务、同步来源钩子、V35 和 HTTP 处理已通过静态检查及构建。服务器待验证项目沿用 MRR-04／05／06／08，并补查：既存卡初始待复核、重复 JSON 键／字节边界、两个独立历史序号、无配置 GET 的 null 修订、同 item 多来源版本只产生一次影响、原键 NOW 回放、不可变摘要与操作者／理由，以及源归档多依据例外。B 接入后另核对同事务 attempt 失效；DTO、契约或编译一致不能替代这些运行证据。

### B.3 尝试快照、草稿与状态

| DTO | 精确字段与含义 |
|---|---|
| StartSnapshot | `cardVersionId,cardVersionNumber,cardRevision,gateRevision,mode,countRegular,cramBatchId,zoneId,schedule,sources,admission`；固定 START 时事实，后续读取不重算 sources 或 admission |
| Attempt | `id,cardId,sequence,start,revision,state,responseMode,response,responseSavedAt,startedAt,updatedAt,revealedAt,ratedAt,closedAt,thinkingElapsedMs,totalElapsedMs,rating,skipReason,invalidation,lastEventSequence` |

| RatedAttempt | `attempt,event`；event 为本次不可变 RATE，attempt 已进入 RATED |

StartSnapshot.schedule 在 countRegular=true 时保存完整 A Schedule，因此 schedule.revision／cycleId／algorithmVersion／parameterVersion 和算法前态一起冻结；false 时 schedule=null，不记录一个能误用为更新前态的排程。admission 同样只对 true 非空。zoneId 为开始时用于说明的设置时区或批次时区，不决定未来常规评分的归属日。sources 为已验证的 A SourceSnapshot 列表，包含已允许的归档概念警告条件；其当前性只代表开始时事实。

| 状态 | 时间、内容与终态约束 |
|---|---|
| THINKING | revealedAt/ratedAt/closedAt、两个耗时、rating/skipReason/invalidation 均 null；初始 responseMode=THOUGHT、response=""、responseSavedAt=null，尚无用户已思考声明 |
| REVEALED | revealedAt、thinkingElapsedMs 非空；responseSavedAt=revealedAt，回答固定；ratedAt/closedAt/totalElapsedMs/rating/skipReason/invalidation 仍 null |
| RATED | revealedAt/ratedAt 非空，closedAt=ratedAt；两个耗时和 rating 非空；skipReason/invalidation=null |
| SKIPPED | closedAt、skipReason 非空；ratedAt/totalElapsedMs/rating/invalidation=null；保留原 revealedAt／thinkingElapsedMs，有则仍可恢复原参考 |

THINKING 的成功草稿保存只更新 responseMode/response/responseSavedAt/updatedAt 并推进 attempt revision，不新增学习事件。CAS匹配且原文与模式完全相同可返回原 Attempt，不刷新保存时间或修订；即使相同内容，旧 expectedRevision 仍冲突。WRITTEN 的空编辑缓冲不能被显示为服务器已保存；明确改选“只想”并提交空串才清除服务器文字草稿，不能因自动保存失败丢掉本地输入。

REVEAL 同事务保存请求中的最终原文、同一 now、事件和修订，不要求先另存草稿。thoughtConfirmed 对两种模式都是用户揭示声明，不是观察到思考的证据。揭示后回答不可再编辑；要另答须先跳过并开启新尝试，不能覆盖既有揭示事件。

thinkingElapsedMs=floor((revealedAt−startedAt)/1ms)，totalElapsedMs=floor((ratedAt−startedAt)/1ms)，原时间保留微秒。它们是墙钟经过时间，包含后台／离线，不是专注时长。所有尝试命令使用 owner 锁内的一个 now；不得早于本尝试最后 updatedAt。START 还不得早于该卡上一尝试最后 updatedAt；同步失效也遵守时间顺序。发生时钟倒退则整次命令失败，不写负数、不把时间强行抬到前次时间；同一微秒可有不同序号事件。

### B.4 不可变事件与排程关联

每个 START 新增每卡连续 attempt sequence（1起）；草稿修订不消耗此序号。每个 attempt 的事件从1开始：START为1，后续每条真实事件加1，本版最多3条（START、REVEAL、一个终结事件），事件号与 attempt revision 不等同。两种历史都按各自序号倒序、before 排他，nextBefore 为本页最后序号或 null。可在 owner 锁内根据该卡最后 attempt sequence 分配下一号，配合唯一约束，不从毫秒生成序号；本批不删除终态尝试或事件。

AttemptEvent 精确字段：`id,attemptId,sequence,attemptRevision,kind,fromState,toState,actor,occurredAt,started,revealed,rated,skipped,invalidated`。attemptRevision 是该事件生效后的修订；START为0。actor 复用 A Actor，所有用户命令以及被用户知识操作触发的失效均为 OWNER。仅 kind 对应的一个载荷非空，其余四个显式 null。

| kind | 状态迁移与载荷 |
|---|---|
| START | fromState=null、toState=THINKING；Started(snapshot)，等于 Attempt.start；occurredAt=startedAt |
| REVEAL | THINKING→REVEALED；Revealed(responseMode,response,thinkingElapsedMs)，固定最终回答；occurredAt=revealedAt |
| RATE | REVEALED→RATED；Rated(rating,thinkingElapsedMs,totalElapsedMs,day,budget,schedule)；occurredAt=ratedAt |
| SKIP | THINKING或REVEALED→SKIPPED；Skipped(reason)，等于 Attempt.skipReason；occurredAt=closedAt |
| INVALIDATE | THINKING或REVEALED→INVALIDATED；Invalidated(cause)，等于 Attempt.invalidation；occurredAt=closedAt |

Rating 为 AGAIN／HARD／GOOD／EASY，对应“忘记／困难／记得／熟悉”，只有用户显式自评，不由回答长度或 AI 代填。事件与 Attempt 最终字段必须一致，事件不含 reference；REVEAL 的原回答即使后来卡内容改变也保持。

| Rated 子对象 | 精确字段与可空规则 |
|---|---|
| RatingDay | `zoneId,localDate,windowStart,windowEnd,settingsRevision`；以 occurredAt 落入的当地日构造实际 UTC窗口。计入时取评分当次设置，settingsRevision非空；未计入时取固定批次时区，settingsRevision=null |
| BudgetUse | `kind,firstForCardToday,firstCountedEventId`；只对计入事件非空。第一条计入时 firstCountedEventId 指向自身，否则指向当前日区间内该卡首条已计入事件 |
| ScheduledRating | `changeId,sequence,before,after`；只对计入事件非空，before/after 复用 A Schedule；sequence 为本次排程历史序号 |

计入评分须使 before 与被冻结的排程修订、cycle、算法／参数及前态一致；after.revision=before.revision+1、after.lastHistorySequence=before.lastHistorySequence+1、cycle/createdAt不变、status=ACTIVE、pauseReason=null、deferUntil=null。after.state 使用适配器输出，suggestedDueAt=state.dueAt=effectiveDueAt，lastRatedEventId=本RATE事件ID，updatedAt=occurredAt。新增 A 的 RATE ScheduleChange：impactId=null、reason=""，before/after 与本 ScheduledRating 相同，changeId 为该历史ID。无需为 A 增加一个可与 lastRatedEventId 矛盾的 eventId 字段。

未计入评分的 Rated.budget/schedule 均为 null，不推进排程历史、revision、cycle、算法参数或每日预算；仍保存真实自评、版本、揭示、时间与批次归属。EventPage(items,nextBefore) 最多返回该尝试已有3条事件，不通过历史接口推导或补造曾经的揭示。

### B.5 占位、CAS、幂等与恢复

active-attempt-slot 的唯一键为 owner＋cardId，值为 attemptId；只允许指向同一 owner/card 的 THINKING或REVEALED。一卡所有模式共用一个占位；START与占位同事务创建，RATED／SKIPPED／INVALIDATED与占位删除同事务提交。不能仅查询“当前没有”后在锁外插入；除了 owner 锁，还需唯一约束和所属关系约束。读取发现占位缺失／错配不自动修复，返回状态不可用并保留原记录。

写命令的固定顺序：当前权限／资料守卫 → owner锁与同 key／摘要回执查询 → 取单一 now → 所属对象和请求修订 → 状态与占位 → 当前业务条件 → 容量／时间／算法校验 → 数据、历史和回执一起提交。IdempotencyService 已负责锁与旧回执顺序，B 不在动作外预先运行算法或重新取 NOW。业务冲突检查顺序如下：

- START：当前 card修订→gate修订→计入时schedule修订→无未决占位→卡及依据→设置／排程状态／到期→批次成员→软预算。依赖对象不存在时直接使用其缺失错误，不伪造修订0。
- SaveResponse／Reveal／Rate／Skip：先核对 attempt revision，再核对状态和占位。Reveal／Rate 随后按 card→gate→计入时schedule 与固定 START 比较，再查当前来源／到期／时间；不让客户端提交新修订替换原 START。
- SaveResponse／Skip 不因 gate 或排程异常而自动改写基线。正常变化早已同步失效；对遗漏钩子的异常旧记录，草稿只保存在原尝试，Skip允许用户终结占位且不改变排程。Reveal／Rate 仍拒绝过时基线。
- RATE 不重新要求预算确认，也不对 Settings revision 做开始时CAS；设置只用于本次真实日标签。算法异常、校验失败、响应过大或事务失败均回滚，REVEALED与占位保留；没有“先失效再抛异常”这种会一起回滚的假修复。

收到网络未知结果时保存原 Idempotency-Key、原请求体及路径；重放同一请求先取得原回执，绝不因未知就换键。旧 START／草稿回执是当时事实，恢复后再 GET当前 Attempt／active-attempt及A recall-state；旧 THINKING回执不能覆盖后来RATED或INVALIDATED的当前状态。若服务端确未提交，原键重试会重新验证当前条件并可能冲突，此时保留用户输入，不把冲突当成数据已保存。

浏览器同一尝试的草稿、揭示、评分命令串行发送；揭示前等待在途草稿结果，使用最终 expectedRevision，防止晚到草稿覆盖揭示。多标签冲突显示当前修订并保留本地输入，由用户明确取舍，不自动拿最新修订强行覆盖。关闭页面或超时不释放占位；ActiveAttempt／OpenAttemptPage 只提供恢复入口，不因读取自动开始或跳过。

### B.6 同步失效原因

Invalidation 精确字段为 `reason,currentCardVersionId,currentCardRevision,currentGateRevision,currentScheduleRevision,sourceHistoryKind,sourceHistoryId,scheduleChangeId`，表示失效事务生效后的定位条件。currentScheduleRevision 在无排程时null；两个sourceHistory字段同为空或同非空。kind=IMPACT 指向A影响，kind=SOURCE_REVIEW指向A确认决定；scheduleChangeId 只有该事务实际新增排程历史才非空，不能引用想象中的暂停记录。

| 触发 | reason／关联 | 关闭范围 |
|---|---|---|
| 卡产生任意新版本，包括仅标题 | CARD_VERSION_CHANGED；依据改变时关联实际IMPACT，只改标题等无该关联；定位新卡版本 | 全部未决 |
| 卡实际归档／恢复 | CARD_ARCHIVED／CARD_RESTORED，关联实际IMPACT | 全部未决；恢复不复活旧尝试 |
| 来源正文改变／归档／恢复 | SOURCE_BODY_CHANGED／SOURCE_ARCHIVED／SOURCE_RESTORED，关联实际IMPACT | 全部未决，包括CONCEPT保留排程的多依据例外 |
| 显式source-review | SOURCE_REVIEWED，关联SOURCE_REVIEW决定 | 全部未决，不把旧揭示套到新gate |
| 延期／实际暂停／KEEP恢复／RESET | SCHEDULE_DEFERRED／SCHEDULE_PAUSED／SCHEDULE_RESUMED／SCHEDULE_RESET，关联实际排程历史 | 仅countRegular=true |

一次知识影响可能同时暂停排程，但只写一个 INVALIDATE，主原因保留来源或卡变化，并可关联同事务实际排程变更；不能先写笼统SCHEDULE_PAUSED丢掉来源原因。同一owner事务内先形成新门禁／排程事实，再以一个终结事件关闭占位；失败回滚知识操作、门禁、排程和尝试全部变化。

来源仅标题发布、草稿、主题／收藏／布局、预算／时区设置或冲刺计划跨日期都不自动终结尝试；首次建立排程及纯手工排程变化不干扰未计入CRAM。A中对已暂停排程的无变化pause也不生成伪失效。仅对THINKING／REVEALED处理，既有终态保持原事件和原因。间接派生传播仍待S8接入，B不能把只覆盖直接sources的钩子表述为全库传播完成。

### B.7 每日预算的精确计数

DailyBudget 精确字段为 `settingsRevision,zoneId,localDate,windowStart,windowEnd,newLimit,reviewLimit,newCards,reviewCards,ratedEvents`。budget revision来自当前配置，window为当前时区该日真实的半开UTC区间，按时区规则处理23／25小时日及其他偏移变化，不用固定24小时。newLimit/reviewLimit为0–1000；所有计数只读真实RATE事件，含跨REGULAR和计入CRAM，不以队列项、START或打开参考计数。

先筛选 `countRegular=true AND windowStart≤ratedAt<windowEnd`，按 cardId 分组；每卡以最早成功的计入事件为该日分类依据。因一卡只有一个未决尝试，使用该卡 attempt sequence 确定成功先后，同微秒仍稳定；不依赖全局UUID排序。首事件 before.state.lastReviewAt=null 则NEW，否则REVIEW。该卡之后同日的计入事件，包括重学／作为新卡重置后再次评分，都沿用该日首事件类别；newCards／reviewCards各计不同卡数，ratedEvents统计全部筛中事件条数。未计入CRAM、自评前揭示、SKIP／INVALIDATE均不消耗。

BudgetAdmission 精确字段为 `budget,kind,countedToday,overBudget,continueBeyondBudget`，保存START锁内快照。若卡当天已计入，kind取首事件，countedToday=true、overBudget=false；未计入则kind取当前排程前态，当前该类已用数量≥limit时overBudget=true，此时必须明确continueBeyondBudget=true才可开始。预算不预留：同时开启不同卡不预占、不释放、不声称已消耗；允许之后评分的真实结果超过建议数量。

RATE时重新按当次设置和ratedAt构造RatingDay/BudgetUse；跨午夜、改时区、降低预算或其他卡先提交均不能否定本来合法的已揭示评分。若此时是当日该卡首条，firstForCardToday=true并关联自身；否则关联已存在首条，不能人为加第二个名额。更换时区后当前统计重新按新UTC区间查询，可能纳入带旧时区标签的事件；历史RatingDay/BudgetUse保持原标签，当前查询不能直接累加旧firstForCardToday标记或改写其值。

例如：同一天新卡依次AGAIN、GOOD、GOOD，预算为新卡1张、原始评分3次；当天RESET后再评仍占这1张。晚上开始、次日评分按次日实际窗口计数；这不是移动先前完成事件，也不是超时自动评分。

### B.8 到期队列与游标

QueueItem 精确字段为 `cardId,kind,title,cardVersionId,cardVersionNumber,cardRevision,gateRevision,scheduleRevision,cycleId,phase,effectiveDueAt,budgetKind,countedToday,recommended,requiresBudgetConfirmation,warnings`，全部非空；kind/title为当前卡版，warnings复用A警告。列表无题面／回答／参考，也没有可单独勾选的完成状态。

ReviewQueue 精确字段为 `items,budget,asOf,serverTime,eligibleDueCards,recommendedCards,openAttempts,nextDueAt,includeOverBudget,nextCursor`。budget 必须是已配置 Settings；asOf 固定首请求的真实到期上界，serverTime 为本次一致读取的时间。nextDueAt为当前符合卡／依据／排程／无占位条件且effectiveDueAt>asOf的最早时间，无则null。openAttempts计本人所有未决占位，独立于推荐数和完成数；恢复目录另读 `/attempts/open`。

先形成卡ACTIVE、gate／来源有效、排程ACTIVE、无占位、effectiveDueAt≤asOf的完整可用集合。排序键为 `(phaseRank,effectiveDueAt,cardId)` 升序：LEARNING／RELEARNING的phaseRank=0，REVIEW为1；不能只按本地日期纳入尚未真正到期的卡。eligibleDueCards为此集合的不同卡数。队列读和聚合使用同一只读事务，避免同一响应内部数字彼此不符。

推荐集合包含当天已计入且再次到期的卡；另外对NEW、REVIEW各自未计入的卡，沿完整排序键选取 `max(limit−used,0)` 张。这个类别名额筛选在分页游标之前执行，不能每页重新得到一份名额。recommendedCards为完整推荐集合大小；includeOverBudget=false只分页推荐集合，true分页全部可用集合。QueueItem.recommended表示该次推荐集合成员；requiresBudgetConfirmation仅表示此时START新增该卡是否超预算，不因卡排在第11个就伪称已经消耗前10个名额。每日预算为0时，已计入的到期步骤仍推荐。

游标编码固定版本、用途、asOf、settingsRevision、zoneId、localDate、includeOverBudget以及最后完整排序键；仅作为有限查询条件，不授予访问权限，所有查询仍限定owner。首请求由服务器产生asOf，不接受客户端自选未来上界。后续请求的时区／日期／设置修订／includeOverBudget必须与游标一致，否则MEMORY_QUEUE_CHANGED并从首页重读；篡改、非法时间／排序键或未来asOf按INVALID_REQUEST。limit只控制本页大小，可在1–50内改变。

asOf不冻结跨请求数据库快照：其他评分、资料变更或占位变化可能使成员消失／重排。同一页计数只代表当次一致读取；界面按cardId去重，已知写入、跨午夜／时区变更后丢弃旧游标重读首页，START始终再校验。不能靠先跳过旧排序范围来承诺绝不遗漏。OpenAttemptPage及CramBatchPage按 `(startedAt,id)`／`(createdAt,id)` 倒序keyset读取，游标绑定用途；OpenAttemptPage.asOf为当次读取时间，不宣称跨页固定快照。

### B.9 冲刺批次与成员读取

批次是用户选定范围和计划日期的不可变快照；调整范围／日期时新建批次，原批次与尝试关联保留。CreateCramBatch的cardIds为1–200个不同标准UUID，保留输入顺序，owner锁内逐一确认本人ACTIVE卡，不静默跳过归档／不可访问卡。选区可包含尚需复核或尚无排程的卡，成员读取说明各自条件，START仍执行准入检查。批次创建不触发尝试、排程或预算。

startDate/endDate为严格ISO本地日期，范围1000-01-01至9999-12-31，包含首尾1–90天；zoneId按A的IANA／UTC规则。允许过去、现在或未来的计划区间，UI按批次时区显示实际日期；日期既不自动开始，也不自动终止已打开尝试，过期不顺延。countRegular是每次尝试的明确选择，不在批次创建时固定为全部计入。

| DTO | 精确字段与空值 |
|---|---|
| CramSelection | `cardId,cardVersionId,cardVersionNumber,cardRevision`，保存选入时版本；不把它当成正式尝试基线 |
| CramBatch | `id,title,startDate,endDate,zoneId,cards,createdAt`；cards为固定顺序CramSelection，始终1–200条 |
| CramSummary | `id,title,startDate,endDate,zoneId,cardCount,createdAt` |
| CramBatchPage | `items,nextCursor`，nextCursor可空 |
| CramSchedule | `revision,status,pauseReason,phase,effectiveDueAt`，复用A状态；pauseReason仅ACTIVE时null |
| CramMember | `position,selection,currentCard,gateRevision,eligibility,schedule,openAttempt`；position从1开始，selection为固定成员；currentCard复用首批Summary |
| CramMemberPage | `items,nextAfter,asOf`，nextAfter可空，为本页最后position且仅有后续时返回 |

`/cards`成员页按固定position升序，after可省略或0–200整数、排他；limit默认20、1–50。成员卡缺失／当前不可访问时仍保留原selection定位，但currentCard/gateRevision/eligibility/schedule/openAttempt均null，不补造“ACTIVE”；存在时eligibility必填、gateRevision可因缺失gate而null、schedule可因未启用而null、openAttempt可因无占位而null。源可读但不满足条件时复用A blockers／warnings，不复制来源正文。

selection与currentCard.versionId不同显示版本已变，开始需使用当前卡／gate／必要排程修订，不能沿用选入时旧revision。批次不可变，因此没有批次CAS；成员归属每次START仍查本人批次与确切cardId，若将来允许编辑批次，必须先新增批次版本与CAS契约，不能让既有请求语义悄悄变化。CRAM与REGULAR仍争用同一个卡占位；批次本身没有从“看完列表”推导的完成状态。

### B.10 FSRS适配输入与官方制品复核

纯适配器边界建议为 `FsrsState next(FsrsState before, Rating rating, Instant ratedAt)`，输入／输出复用A领域FsrsState；不接收owner、数据库、时区、预算、提示词或知识正文。服务负责核对固定算法／参数标识、排程CAS和事务，适配器只做已锁定配置的确定性转换。countRegular=false根本不调用此适配器。

- 新卡输入只能为LEARNING、step=0、stability/difficulty/lastReviewAt=null；dueAt为原算法建议时间，不能把deferUntil当作算法due。
- 已评输入要求stability有限且≥0.001、difficulty有限且位于[1,10]、lastReviewAt非空且≤ratedAt、dueAt>lastReviewAt；LEARNING的step为0或1、RELEARNING为0、REVIEW为null。缺失一半数值、未知状态、时间越界、参数版本不符均拒绝，不猜初态。
- 显式构建库Card的cardId=0和全部领域字段，传 `reviewCard(card,rating,ratedAt,null)`；业务UUID仅由本域管理，库int标识不进入业务关系。reviewDuration单位在锁版源码中无明确约定，传null，产品自行记录有单位的elapsedMs。
- 固定21权重为 `[0.2172,1.1771,3.2602,16.1507,7.0114,0.57,2.0966,0.0069,1.5261,0.112,1.0178,1.849,0.1133,0.3127,2.2934,0.2191,3.0004,0.7536,0.3332,0.1437,0.2]`；retention=0.9、learningSteps=60/600秒、relearningSteps仅600秒、maximumInterval=36500天、enableFuzzing=false。参数数组在适配器内新建并私有持有，不对外暴露库的可变数组或Random。
- 输出要求有限数值和合法phase/step、lastReviewAt=ratedAt、dueAt>ratedAt且为有效UTC微秒；REVIEW间隔为1–36500个完整24小时。36500限制的是长期间隔，不能用它截断stability。学习／重学分钟间隔保留，不强行拉到次日。算法时间加法超出存储范围时拒绝，不静默钳制。
