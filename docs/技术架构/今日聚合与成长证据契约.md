## 2. 来源身份与聚合规则

`SourceRef={kind,id}` 是当前安排的身份，owner 来自会话，不允许客户端传 owner。`kind` 固定为 `KNOWLEDGE_DRAFT|TRAINING_SESSION|PREPARATION_TASK|MEMORY_CARD|REVIEW_ACTION|INTERVIEW_EVENT`。同一来源在今日、日历、来源工作区中始终使用同一个 SourceRef；标题、日期、版本变化不换安排身份。版本／修订只用于核对和历史，不能拼入去重键导致每次编辑生成新待办。

| 来源 | 纳入依据及实际入口 | 完成／推进的唯一来源 |
|---|---|---|
| KNOWLEDGE_DRAFT | ACTIVE 知识的服务端 draft.title／body 与 published 不同；返回草稿修订、savedAt、当前发布版身份，不返回正文 | 原知识保存／发布；仅发布或处理草稿才能使待发布项退出，今日不能勾完成 |
| TRAINING_SESSION | DRAFT、RUNNING、PAUSED 会话；标明服务器保存的草稿题数。ENDED 中留存的草稿只在历史报告查看，不提示可继续写原场 | 原训练 start／resume／draft／submit／end；既有结束守卫不放宽 |
| PREPARATION_TASK | IN_PROGRESS 优先继续；TODO 按原 plannedDate／zoneId，未安排者进待安排；PAUSED、DONE、CANCELLED 单列筛选 | 原 `/prepare/tasks/{id}/status`；不据日期过去推成失败或完成 |
| MEMORY_CARD | B 返回的真实到期／未决 attempt；A 的归档／待复核可作为管理提醒，但不算可复习 | 原揭示与 RATE、延期／暂停／恢复命令；移出今日不修改 due，不伪造 RATE |
| REVIEW_ACTION | OPEN 中仍 TRACKING 的来源；需要处理的来源为 latest 为空、applicable=false，或 latest.outcome 不为 HANDLED。无待处理来源不作为待复练推荐 | 原复练创建、新提交、确切对照和逐 sourceId 判断；DROPPED 不算已处理 |
| INTERVIEW_EVENT | 原站内未确认提醒、当前时段及最近未来安排；保留 PLANNED／COMPLETED／CANCELLED 与动态 Timing 两种口径 | 原 acknowledge／complete／cancel／reschedule；PAST 不等于已发生，确认提醒不等于完成面试 |

动作 pending 数必须复用 `RepracticeService.progress` 的适用条件，包括验证条件是否仍相同、当前跟踪状态、回忆来源当前性。不能只统计 HANDLED 字面值，也不能只读取 ActionSummary.trackingCount 就称其为待复练数量。按页批量读取所需来源和最新判断，领域规则由 review 提供查询服务；今日模块不直接修改其 Mapper。

前端每个 SourceRef 只呈现一行，优先区段为 `CONTINUE → ATTENTION → TODAY → BACKLOG`；`HIDDEN` 为用户主动查看的筛选。行内 `reasons[]` 可同时包含进行中、到期、未确认提醒、显式加入等原因，不能为每个原因复制一行。同一卡存在未决 attempt 又到期，展示“继续本次回忆”，不再生成第二个开始入口；复练创建的训练会话使用 TRAINING_SESSION 身份并附 repracticeId，不另建复练会话待办。

动作合并后，原 MERGED 动作不再纳入有效待办，来源判断仍按稳定 sourceId 跟随当前 OPEN 动作；旧安排偏好留作可查询记录，显示合并去向，不静默覆盖目标动作的日期、暂停或优先级。当前合并目标只出现一次。旧日期不会自动搬到新动作；用户从合并提示显式安排目标动作。同一题目的不同动作来源不能仅凭题号或相似标题合并。

每条当前行附 `SourceStamp`，为下列封闭联合类型，未知字段拒绝：

| kind | 核对字段 |
|---|---|
| KNOWLEDGE_DRAFT | draftRevision、currentVersionId |
| TRAINING_SESSION／PREPARATION_TASK／INTERVIEW_EVENT | revision |
| MEMORY_CARD | cardRevision、cardVersionId、gateRevision；scheduleRevision、attemptId、attemptRevision 可空，后两项必须同时为空或同时有效 |
| REVIEW_ACTION | revision、progressHash；hash 固定当前 sourceId／跟踪／验证条件／最新判断身份及修订／适用状态，不能只依赖动作 revision |

SourceStamp 不是权限凭据。任何写入都重读来源并比较；读取后的归档、合并、评分、改判或来源变化均可能让操作失效。

## 3. 今日 DTO、读取与依赖状态

本节字段为建议精确契约，后续生成 OpenAPI 时不得将下列新增类型混入旧命令摘要。

- `DayContext={zoneId,localDate,startAt,endAt,asOf}`：同一请求固定一个服务器 UTC 微秒 asOf，localDate 按明确区域计算；起止为当地零点到下一当地零点的 UTC 半开区间。
- `Availability=READY|DEPENDENCY_PENDING|NOT_CONFIGURED|ERROR`。`Count={value,mode}`，mode 为 `EXACT|LOWER_BOUND|UNAVAILABLE`；UNAVAILABLE 的 value 必须 null，其余为非负安全整数。错误／未接依赖不能用 0 代替。
- `SourceCapability={kind,status,reasonCode,count,scanLimited}`；READY 只表示本次投影可读，不表示功能已服务器验收。动态来源过滤达到扫描上限时，count 只能为 LOWER_BOUND，保留后续游标。
- `SourceTime={kind,instant,localDate,zoneId}`：kind=`NONE|INSTANT|LOCAL_DATE`；NONE 其余为空；INSTANT 有 instant／zoneId、localDate=null；LOCAL_DATE 有 localDate／zoneId、instant=null。不把日期级任务伪装成午夜时间点。
- `Estimate={minutes,basis}`：minutes 可空；basis=`SOURCE|USER|UNKNOWN`，UNKNOWN 必须为空。普通任务使用原 minutes；动作、卡片和草稿没有真实预计值时显示“未估时”，不按平均值伪造。
- `TodayItem={source,stamp,title,section,sourceStatus,reasons,targetRefs,time,eventWindow,estimate,placement,continuation,pendingCount,availableActions,warnings}`。sourceStatus 保留领域原枚举及类型；targetRefs 指向确切目标版本，无目标为 []；continuation 为受支持的 routeName 与白名单参数，不返回任意可执行 URL。pendingCount 仅动作使用，其余为 null。eventWindow 仅面试有值，固定 `{startAt,endAt,zoneId,remindAt}`，日历按完整起止区间绘制；提醒与开始原因仍属于同一行。摘要不含知识／答案／反馈／参考正文。
- `TodayOverview={context,capabilities,sections,reminderState}`；每区最多先给 5 行及本区分页入口，不计算跨区可被重复相加的总完成率。
- `TodayPage={context,sourceKind,section,items,nextCursor,scanLimited,count}`；每页只查一种 sourceKind 与一个 section。统一 UI 合并小页，后端不加载整个用户库再排序。首次后续 cursor 绑定 sourceKind、section、过滤条件、zoneId、asOf、完整排序键；不接收独立客户端 asOf 来回拨“现在”。

默认排序为用户 orderValue、区段内业务时间、稳定 sourceId：无 Placement 的 orderValue 按500000处理；继续项用最近成功保存时间倒序；到期项用实际 due／计划日期；提醒用 remindAt；待安排用原 updatedAt 倒序。null 业务时间固定排末尾；同微秒用 sourceId 打破平局。动态过滤也须按完整排序键扫描候选，不能先截取按ID排序的一页再宣称全局时间有序；游标记录最后消费候选的位置。页面已经识别的 sourceId 去重，发生本页写入后重新读取首页。asOf 固定时间分类上界，**不承诺多个 HTTP 请求共享数据库快照**；后续页的实时来源变化可能造成漏项，刷新首页重新核对，开始时始终重验。

| 新方法／路径（前缀 `/api/v1`） | 请求与响应 |
|---|---|
| GET `/today/overview?zoneId=` | zoneId 必填、明确选择的 IANA／UTC；TodayOverview。未保存个人时区不读服务器 OS 来猜 |
| GET `/today/items?zoneId=&kind=&section=&cursor=&limit=` | kind／section 必填，limit 默认20、1–50；可选 targetId，必须与 cursor 绑定；TodayPage |
| GET `/today/calendar?from=&to=&zoneId=&kind=&cursor=&limit=` | 日期成对、包含首尾最多31天；按 kind 分页，返回 CalendarPage。UTC 事件按区间相交；日期项规则见 §4 |
| GET `/today/sources/{kind}/{id}?zoneId=` | 当前 TodayItem 或不可安排的来源状态；zoneId必填。已归属他人／不存在统一404，不返回标题。用于页面重入与未知写结果后的当前性刷新 |

CalendarPage 固定 `{from,to,zoneId,asOf,kind,items,nextCursor,scanLimited,count,capability}`；items 使用相同 SourceRef、SourceStamp 和 SourceTime，不保存第二份日历事件。未来回忆只显示已经存在的 effectiveDueAt，不演算尚未发生评分后的未来队列。

**B 接口依赖：**memory 需提供受控的队列／未决尝试查询投影，至少包含 cardId、确切卡版本、card／gate／schedule 修订、有效 due、来源阻断原因、未决 attempt 身份／状态／修订、预算分类及可开始条件；正式评分统计至少提供不可变 RATE 身份、attempt／card／version／cycle、ratedAt、countRegular、rating、评分时 zoneId／localDate／settingsRevision。具体 B 类型、表名和排序以后续冻结的机器契约为准，本文不预造它们。B 未接入时 MEMORY_CARD 队列 capability=DEPENDENCY_PENDING、value=null，说明“正式队列尚未接入”，不能从卡片总数或 A 的 ACTIVE 排程数假装得到到期可复习数。

## 4. 时间、预算与提醒

今日查询、成长统计采用显式 zoneId；首次可向用户建议已有 ReviewSettings.zoneId，但须明确这是显示时区。今日时间预算与 memory 的张数预算、AI 的费用预算分别处理。本文不新增第二份全局用户时区配置：显示时区先作为页面显式条件；S8 个人偏好接入后由同一偏好来源提供默认值，旧事件时区不重写。

- **即时事项**：回忆 effectiveDueAt、面试 startAt／remindAt 按 Instant 比较服务器 asOf；显示同时保留原区域。跨午夜和 DST 不使用固定24小时近似一天。
- **日期事项**：普通任务 plannedDate 仍是原 zoneId 下的日期。今日“到期／过往”用 `asOf` 在**该任务原时区**的本地日期比较，并展示 sourceLocalDate；不能因为查看者已跨午夜就把另一时区尚未到日的任务标成逾期。日历按原日期标签摆放，标明原时区，不把它转成午夜 UTC 后漂移到前一天。跨时区精确日程仍用面试等有 Instant 的对象。
- **移出今日**：只抑制某个 `{localDate,zoneId}` 的安排推荐；回忆 due、动作跟踪和原任务日期不改变。换显示时区可能改变当天归属，界面说明，不将其解释为学习额度清零。
- **暂停**：普通任务和常规回忆使用源域 PAUSED；动作／草稿仅可“暂停此安排”，不停止动作跟踪、不结束训练。当前进行中的训练／回忆继续入口和未确认面试提醒保留可达，即使用户移出推荐清单也不能伪装已处理。
- **提醒**：复用 `/schedule/reminders` 的真实查询语义和 acknowledge。超过面试结束仍 PLANNED 且未确认者显示“时间已过，待确认”，不标“未参加”。关闭浏览器不保证推送；重进重算，不依赖本机定时器、消息发送或外部日历。确认提醒后不增加成长完成记录；改期或变更提前量沿用原模块清除确认的规则。

学习时间预算用每日显式保存的 `DayBudget={localDate,zoneId,revision,availableMinutes,createdAt,updatedAt}`；0–1440 名义分钟，不表示 DST 当天实际长度或空闲日程。没有保存时返回 null，不假装默认预算已经确认。预计时间未知者单列，不按0分钟塞入预算；面试时长只展示占用，不擅自从用户填写的学习可用时间再扣一遍。

## 5. 同源安排、建议与快速记录

增加轻量 `Placement` 只保存显示／安排偏好：`{id,source,revision,plannedDate,planZoneId,estimatedMinutes,priority,orderValue,dateLocked,visibility,suppressedOn,createdAt,updatedAt}`。priority 为1–5；orderValue 为0–1000000整数，重复时按 sourceId 稳定排序；visibility=`VISIBLE|PAUSED`。suppressedOn 为空或 `{localDate,zoneId}`。

`PlacementContent={plannedDate,planZoneId,estimatedMinutes,priority,orderValue,dateLocked,visibility,suppressedOn}` 是写请求的完整可编辑字段；不接受 id、source、revision 或时间戳混入 content。历史 change 由服务端固定为 `CREATED|UPDATED|ORDERED|SUGGESTION_APPLIED|INTERVIEW_RESCHEDULED`；普通安排写入的 reason 可空，存在时保留用户原文，不能从生成标题捏造理由。

- plannedDate／planZoneId 只允许 KNOWLEDGE_DRAFT、TRAINING_SESSION、REVIEW_ACTION 使用，均空或均非空；其余必须为空，日期／due 留在源域。estimatedMinutes 仅允许这些类型和 MEMORY_CARD，1–1440或null；普通任务读取自身 minutes，面试不使用学习估时覆盖。
- visibility=PAUSED 仅用于没有独立安排暂停状态的上述三类；其他来源固定 VISIBLE，暂停转源域。dateLocked 只阻止建议重排，用户显式手工修改日期仍可执行；已有开始记录也禁止自动重排。
- Placement 不含 title、正文、sourceStatus、done、completedAt 或掌握字段。无 Placement 的来源也可进入自动聚合；GET 不为每个来源创建行。重复加入按 owner＋kind＋sourceId 唯一，不按标题去重。

SuggestionPreview 固定 `{context,budget,items,selectedKnownMinutes,unknownEstimateCount,remaining,previewHash,limitations}`。items 为 `{source,sourceStamp,placementRevision,estimatedMinutes,recommended,reasonCodes,proposedContent}`；remaining 为本次明确候选中未推荐来源及其确切数量，不杜撰全库数量。items 已限定最多100项，无需另造有服务器状态的候选分页令牌。算法是可解释的规则排序：继续事项、已到期／明确日期、用户优先级；按已知分钟选择，超出预算列余项，不无限补满。未知估时只可预览待估时，不能自动入选。预算未保存时 expectedBudgetRevision=null，预览只列候选且 recommended=false；采用前须先保存预算并重做预览。用户修改本次估时／候选选择，或在源页修改顺序、日期、优先级／预算后重新预览，再明确采用。

普通任务只从已经进行中或源日期已经到日的事项纳入当天建议；未安排／未来日期者列 `SOURCE_DATE_REQUIRED|SOURCE_DATE_IN_FUTURE`，提供原任务日期编辑入口，保存后再预览。卡片需由B确认当前可继续／可开始；未到期卡不借建议清单绕过正式队列，仍可去冲刺入口。建议采用只保存本次显示、顺序及可用的Placement字段，不能为普通任务／卡片偷偷补一份“今日日期”；日期改变始终进入源域修订。锁定日期或已经开始的来源，proposedContent不得修改其现有日期。

预览不调用 AI。previewHash 是规范化请求、预算修订、候选完整 SourceStamp／Placement 修订及提议内容的 SHA-256；apply 在 owner 锁内重新读取、重算并匹配，校验所选已知分钟和预算，变化返回 `PLAN_PREVIEW_CHANGED`。不能把客户端提供的摘要当作签名或读取权限。新进入队列但不在该次明确清单内的来源不自动追加；跨日使“移入今日”日期条件不再成立时重新预览。一次确认涉及超过50项须拆成独立明确批次，不能暗中分事务部分成功。

**快速记录**复用 `POST /api/v1/knowledge/items`：`{kind:NOTE,title,body,topicIds:[]}`。用户明确保存后才显示成功，首个版本行为与知识域一致；再编辑沿用草稿／发布流程。收件箱是 `kind=NOTE,collection=UNCATEGORIZED` 的现有知识集合，不另存正文。未请求／未同步的输入只在当前页面保留并显示状态；未知响应保留原键，不能重复创建。今日“手工待办”同样复用原普通任务 POST，target 可以 null，不能创建另一套 todo 表。

## 6. 面试关联与联动改期

既有 materials 继续使用面试模块的材料版本关系。补充 `InterviewPreparationLink` 关联 `PREPARATION_TASK|REVIEW_ACTION|COLLECTION`：任务／动作引用稳定身份，题单引用确切 collectionVersionId，仅作准备入口；不能将题单顺序视为实际训练或为其自动生成任务。用户可以关联无目标事项，界面显示与面试目标的差异，不能按相同 targetId 自动绑定所有事项。

Link 为 `{id,eventId,revision,kind,sourceId,sourceVersionId,status,createdAt,updatedAt}`；status=`ACTIVE|REMOVED`，仅 COLLECTION 的 sourceVersionId 非空。每种来源可关联多个面试；唯一键 owner＋eventId＋kind＋sourceId，移除只改状态及历史。新建／恢复须核对当前事件 PLANNED、来源存在且可用；关联任务不修改源目标。相同已有效关联返回冲突，不能以再次添加覆写原来源版本。

|---|---|
| GET `/preparation-links?cursor=&limit=` | LinkPage，含当前源状态与题单确切版本；最多50条一页 |
| POST `/preparation-links` | `{expectedEventRevision,kind,sourceId,sourceVersionId,expectedSource}` → 201 Link；COLLECTION 的 expectedSource 为当前对象 revision／versionId，其余沿用 SourceStamp |

ReschedulePlanPreview 为 `{from,to,remindAt,linkChecks,changes,previewHash,limitations}`。每项 linkCheck 固定 link 身份／修订、SourceStamp、Placement 修订及 `MOVABLE|STARTED|DATE_LOCKED|NO_DATE|PAUSED|TERMINAL|SOURCE_CHANGED|REFERENCE_ONLY|MULTIPLE_EVENTS` 原因。移动条件：

1. 普通任务为 TODO 且 startedAt=null；动作需为 OPEN、仍有待处理来源，并且这些 sourceId 尚未关联到任何已经 STARTED 的复练会话；草稿／回忆卡不在该关联改期类型中。已有开始历史即使当前暂停也不得自动移动。
2. 需要原日期，未锁定、未暂停；同一任务／动作还关联其他有效 PLANNED 面试时不自动移动，列 MULTIPLE_EVENTS，用户去源页明确处理。题单只作引用，列 REFERENCE_ONLY。
3. 默认日期增量按各事项的原 zoneId，计算原面试 startAt 与新 startAt 所在本地日期差，再移动其原 plannedDate；不把 UTC 小时差除24当作天数。新日期仍保留原 zoneId。用户可修改提议日期并重新预览；排到面试后给明确警告，不静默挪回。

previewHash 覆盖所选 link 集合、当前全部有效关联集合摘要、所选来源关联的其他面试状态／修订、事件修订、时间解析结果、来源／进度／Placement 修订和最终提议日期；新增关联、开始任务、锁定日期、改判或面试变动后均须重新预览。apply 取得同一 owner 锁，重核全部条件后，通过 schedule／planning／today 的 MANDATORY 内部命令一同保存事件、任务或 Placement 修订、各自历史和一个回执；不能循环调用带独立回执的公开 HTTP 命令并宣称原子。任一项冲突整体不提交，不移动已完成历史、不重写面后回忆所指的旧面试版本。

## 7. 成长证据与层级

成长是查询视图。每条证据使用不可变 `EvidenceRef={kind,objectId,versionId,revision,partId}` 封闭联合身份，字段均显式存在，不适用字段为 null。禁止把当前正文或最新答案悄悄替换历史：

| kind | 身份字段与来源 | 允许的说明 |
|---|---|---|
| TRAINING_ANSWER | objectId=answerId，其余null；回查确切 session／question、题面和当时模式／辅助／曝光 | 实际提交；独立条件、学习练习、已用辅助分别统计，不据“独立”推断首次见题 |
| MANUAL_FEEDBACK | objectId=feedbackId、revision=确切修订，其余null | SELF_CHECK／EXTERNAL_FEEDBACK 与记录者说明；接受决定不认证技术正确 |
| AI_OBSERVATION | objectId=taskId、partId=observationId，其余null；任务需有成功固定报告 | AI 未审建议；用户决定和争议另呈现，不升成已审结论 |
| RECOLLECTION | objectId=recollectionId、versionId=确切版本，其余null | 面后回忆／无旧答及不确定性；不能作为正式旧答提升基线 |
| REPLAY_JUDGMENT | objectId=judgmentId，其余null；关联 sourceId、comparisonId、新answerId和验证条件 | 用户逐来源判断，保留 HANDLED／PARTIAL／UNHANDLED／UNCERTAIN 及当前适用性；不是平台判定能力 |
| MEMORY_RATING | objectId=不可变 RATE eventId，其余null；依赖 B | 对确切卡版本的一次自评，区分常规／冲刺／是否计入；不等于项目实践或独立面试表达 |

`EvidenceSummary={ref,occurredAt,title,recordKind,assessmentLevel,reviewFlags,conditions,facets,sourceStatus,route}`。conditions 只用来源实际字段，缺失用 UNKNOWN：回答模式／辅助条件、历史曝光、SAME／VARIANT、正式／回忆／无旧答基线、技术与场景、参考标准身份、回忆 selfRating／countRegular 等。列表不含原答、参考或反馈原文；用户从原域受控入口打开细节，原域访问确认仍执行。

assessmentLevel 至少区分 `SELF_RECORDED|AI_UNREVIEWED|REVIEWED_OBSERVATION`，recordKind 区分 ANSWER／RECOLLECTION／MEMORY_SELF_RATING 等事实类别；`reviewFlags` 可包含 DISPUTED、REVIEW_REQUIRED、SOURCE_UNAVAILABLE。一个分组可以同时拥有多类证据和争议，不能用一个互斥“掌握状态”覆盖。`NO_RECORD`／`RECOLLECTION_ONLY` 是查询范围的派生空态，不写为人的永久属性。处于筛选之外、读取失败或依赖未接时也不能判 NO_RECORD。

**受审观察依赖：**PRD §8.2要求确切题目／标准版本、审核人说明、日期和审阅依据。PERSONAL_UNREVIEWED／AI_UNREVIEWED、接受／采用、人工HANDLED或自选标签均不能替代标准审阅。C3-R以真实审阅记录、确切答案观察及当前直接来源核对接第七类，目录仅元数据，标准正文经显式open记录曝光；缺投影标记或依赖失败不报“已审0条”。平台不认证技术真伪，S8间接来源继续PARTIAL，运行验收仍待服务器。精确条件见受审契约，不提供“标为已审”开关。

更正／争议对当前适用性的处理：读取时复用来源当前状态、动作 applicability 和 memory gate；待复核证据保留历史，退出当前确定覆盖计数。S8 尚未提供间接派生完整状态时，涉及“事实→表达／知识→后续证据”的结果标 `lineageCheck=PARTIAL`，不能宣称全部依赖已核对。历史事件及当时判断不改写；来源恢复不能自动清除已有待复核决定。

**主题和考察项**必须说明关联依据。训练使用固定 QuestionSnapshot 中的 topicIds／dimensions；反馈使用当时 dimension；目标来自当时 ContextSnapshot、任务目标或面试历史。回忆卡只有确切知识来源／relatedConceptIds，当前主题查询可用于发现，但须标 `CURRENT_CLASSIFICATION`，不能伪造评分时的主题快照。没有记录考察项的卡不能靠关键词自动分配维度。facets 每条保存／返回 `basis=RECORDED|CURRENT_CLASSIFICATION|USER_LINK` 和确切来源，无法确定者放未分类。

## 8. 成长查询、跨目标复用与下一步

成长时间查询默认28天，明确 from／to／zoneId，最大366天；按本地区间转 UTC 读取实际发生时间，事件原记录的时区标签同时可查。主题／考察项／目标筛选按 §7 的明确关系；目标筛选含确切 targetVersionId，不能仅凭同名公司或题目猜测复用。

EvidenceUse 固定 `{id,revision,target,requirementId,evidence,coverage,comparability,reason,status,createdAt,updatedAt}`。coverage=`SUPPORTS|PARTIAL|CONTEXT_ONLY|INSUFFICIENT`，状态=`ACTIVE|WITHDRAWN`；是本人对该要求的标注，不叫“平台已覆盖”。comparability 精确包含 `dimension,scenario,technology,assistance,date` 五项，每项 `{state: MATCH|DIFFERENT|UNKNOWN,reason}`。日期只列出证据与目标时间，不设未经验证的自动有效期；未知不默认匹配。创建只接受本人当前 ACTIVE TARGET 的确切版本及确切 requirementId；同 owner＋目标版本＋requirementId＋EvidenceRef 唯一，重复返回已有身份冲突。旧目标改版后关联保留在旧版本，不迁移为新要求覆盖。

EvidenceUsePreview 为 `{target,requirement,evidenceSummary,comparability,sourceStamp,previewHash,limitations}`；只按可直接比较字段给出一致／不同／未知的**初始提示**，技术文本含义和场景是否适用由用户填写理由，不能以字符串相等认证语义等价。提交时按原范围再次核对；证据待复核或引用不可用仍可保存 CONTEXT_ONLY／INSUFFICIENT 说明，但不能新增 SUPPORTS，界面保留现有判断并显示影响。旧已保存 SUPPORTS 不删除，当前覆盖汇总须排除来源已不可用／待复核项。

实际活动趋势采用独立计数，不混成总分：

- 回答数按唯一 answerId；已作答题实例数按 sessionId＋questionId；独立、学习和辅助条件分列。复练新答也是一份回答，汇总回答数不能再加一次“复练数”。
- 复练尝试数按真实 repracticeId；处理情况按稳定 sourceId 的**当前最新适用判断**，另列停止跟踪、条件变化与无法判断。不用旧 HANDLED 覆盖新改判，合并不重复计数。时间段内“作出判断次数”与当前待处理存量分列。
- 回忆自评次数按真实 RATE eventId；成功评分卡片数按卡身份去重。常规预算消耗严格使用 B 的按日首条计入事件及 NEW／REVIEW 口径；成长页面换显示时区不重算或覆写 B 的已保存预算记录。冲刺不计常规者仍可算活动，必须独立标识。
- 普通任务 DONE、面试 COMPLETED 仅记实际显式状态历史，不表示能力或面试成功；提醒确认、查看参考、排程建立／延期和卡片保存不计复习或完成活动。
- 缺少可靠单题耗时不输出单题学习时长；训练的 observed／unobserved／paused 只能按整场分列。没有 B elapsed 记录时不从“打开到关闭”猜回忆耗时。

下一步来自实际 pending source、到期或待复核卡、本人标注的未覆盖要求、未安排普通任务；每条返回原身份和原因。`NextStep={subject,reasonCodes,continuation}`，subject 是封闭联合：`{kind:SOURCE,source,stamp}` 或 `{kind:TARGET_REQUIREMENT,target:{itemId,versionId},requirementId,targetRevision}`。目标要求不是 SourceRef，不能伪造安排 ID；用户可从该要求显式建立原普通任务，再用其真实 ID 安排。来源项调整走 Placement 或源域；忽略成长建议按下一段保存，不以“缺陷已解决”代替。

为满足 GROW-05 的持续忽略，使用轻量 `NextStepPreference={id,revision,subject,visibility,updatedAt}`；visibility=`VISIBLE|HIDDEN`。新增 `POST /growth/next-step-preferences` 请求 `{subject,visibility}`、`PUT /growth/next-step-preferences/{id}` 请求 `{expectedRevision,expectedSubject,visibility}`、`GET /growth/next-step-preferences?visibility=&cursor=&limit=` 和 `GET /growth/next-step-preferences/{id}/history?before=&limit=`，均带 `/api/v1` 前缀；默认20最多50条。subject 的唯一身份只含 SourceRef，或确切目标版本＋requirementId，不含动态 stamp；expectedSubject与创建请求使用同一联合结构，身份不可改绑，写请求按其stamp／targetRevision核对当前性，偏好只存稳定身份。存储与读取前重新核对归属，历史追加且不含源正文。该偏好只隐藏成长建议，不隐藏今日到期记录，也不改变历史表现；若再次显示，按真实来源重新生成。无依据时可返回空列表，保留写笔记、练一题、建目标三个通用入口。已争议的 AI 观察不自动作为已确认缺陷，用户仍可选择按其来源创建动作。

领域投影通过各模块只读 QueryService 批量读取，返回允许字段及状态；聚合层不在浏览器串联整库HTTP请求、不通过抓取正文构造“证据数据库”。训练／动作／知识当前表可加有证据必要的复合索引：

- 普通任务候选按 `(owner,status,planned_date,id)`；现有 status／date索引是否足够须服务器 EXPLAIN 后决定，不能未测就全部重建。
- 面试按 `(owner,status,remind_at,id)` 与 `(owner,status,start_at,id)`，延用源域提醒过滤；按页核对材料／目标，不加载附件原文。
- 草稿按 owner／状态／保存时间定位；正文是否等于发布版在知识服务内判断，最多扫描500条每页，不把扫描截断当没有草稿。后续如需要 has_unpublished 索引字段，必须由原保存／发布事务维护并核对旧数据。
- 动作按 owner／status；页内最多50个动作，每动作最多原契约20个来源，批量取当前来源和每source最新判断。sourceId归属、verification及回忆状态仍走领域规则，不只用SQL计数字段冒充判断。
- 训练回答和评分／判断事件按 `(owner,occurred_at,id)` 及确切所属外键分页；B 评分实际表与索引由其契约定义。memory_schedule 当前已有 suggested_due_at 索引，effectiveDueAt含defer，不可误把 suggestedDueAt 过滤结果直接当真实队列。

成长首先按来源种类分页查询，不提前建设常驻 evidence 内容副本。需要统一时间线时，各种类分别取有界排序窗口后合并，游标保存每类已消费的排序位置；后续页仍核对权限和当前来源，不以计算失败回填零。若未来因容量增加索引投影，必须有独立检查点、重建代次和覆盖时间，不复用知识搜索 outbox 的 processed_at；任何未完整重建区间标为不完整。

下面是普通任务 BACKLOG 的候选 SQL 设计，字段取自当前 preparation_task；不是已执行迁移或性能结论。候选进入投影后仍须做统一资料守卫、来源当前性和响应上限检查。candidateLimitPlusOne 最多501，额外一条只判是否还有候选，不提前消费。

```sql
SELECT t.id, t.revision, t.title, t.updated_at,
       COALESCE(p.order_value, 500000) AS order_value
FROM preparation_task t
LEFT JOIN today_placement p
  ON p.owner_id = t.owner_id AND p.source_kind = 'PREPARATION_TASK' AND p.source_id = t.id
WHERE t.owner_id = #{owner} AND t.status = 'TODO' AND t.planned_date IS NULL
  AND (p.suppressed_date IS NULL OR p.suppressed_date <> #{localDate}
       OR p.suppressed_zone_id <> #{zoneId})
  AND (#{cursorId} IS NULL OR COALESCE(p.order_value, 500000) > #{cursorOrder}
       OR (COALESCE(p.order_value, 500000) = #{cursorOrder} AND t.updated_at < #{cursorTime})
       OR (COALESCE(p.order_value, 500000) = #{cursorOrder}
           AND t.updated_at = #{cursorTime} AND t.id > #{cursorId}))
ORDER BY COALESCE(p.order_value, 500000), t.updated_at DESC, t.id
LIMIT #{candidateLimitPlusOne}
```

targetId过滤存在时须在SQL中加入 `t.target_item_id = #{targetId}`，并进入游标过滤摘要；不得取一页后仅在前端筛选。来源日期时区由服务器Java区域规则计算，不能假定MySQL已装时区表。有日期的任务须按来源区域分别给出当天比较值，复用同样的稳定分页原则。新表写入使用 `WHERE owner_id = #{owner} AND id = #{id} AND revision = #{expectedRevision}` 的CAS且断言影响一行；预算以owner＋日期＋区域为CAS键。历史、当前行和回执必须同事务提交，不把SELECT后无条件UPDATE当作并发控制。

## 10. 权限、幂等、并发与前端恢复

所有新路径私有，`today`、`growth` 必须加入 TrainingAccessGuard 的资料模块及前端 `carriesReference`／资料遮挡列表。标题、日期和统计也属于私有数据。独立训练限制期间，只用现有 `/training/active` 显示继续该场的入口；今日和成长完整响应拒绝，不能先把资料返回再由CSS隐藏。跨 owner／来源错配统一404或既有来源不可用错误，不回传他人数量。

所有 GET no-store，并在序列化前动态复核资料访问。新 POST 预览同样无写入却有正文／来源摘要，必须扩展当前 TrainingReadAdvice 的预览识别；该 Advice 目前仅特殊处理 AiDtos.Preview，不能假定它自动覆盖本文 SuggestionPreview／EvidenceUsePreview／ReschedulePlanPreview。所有写命令先做当前资料守卫，再查询原幂等回执；身份／CSRF／owner锁沿用现有机制。

普通读取采用一致只读事务；来源检查加入同一快照。原子多域命令须在外层 IdempotencyService owner事务内调用 MANDATORY 领域入口，源对象、Placement、各自历史与回执一起提交。预览后状态变化返回明确409，原输入保留；不自动重试成覆盖写。原键回放恢复当时结果，再单独GET当前状态，回执不随源更正重写。

前端查询键包含会话代次、资料访问代次、显示时区／日期、kind／section／过滤条件及游标；可见区域失活、登出、重新登录或资料权限变化使旧请求失效。列表的旧同修订响应也不能覆盖较新的动态来源状态；同一 SourceRef 使用统一查询入口，写成功或条件改变后统一重新取数。读取失败保留编辑／预览输入，但不能继续显示陈旧成功统计为当前值。参考和回答正文始终通过其原详情入口读取，不放入今日／成长缓存。

新增错误建议：400 INVALID_REQUEST／CURSOR_MISMATCH；404 TODAY_SOURCE_NOT_FOUND／EVIDENCE_NOT_FOUND；409 PLACEMENT_EXISTS／PLACEMENT_REVISION_CONFLICT／PLAN_PREVIEW_CHANGED／PLAN_SOURCE_CHANGED／EVIDENCE_USE_EXISTS／EVIDENCE_USE_REVISION_CONFLICT；422 TODAY_LIMIT／GROWTH_LIMIT。依赖缺失在读取 capability 体现；需要该依赖的命令返回409 DEPENDENCY_NOT_READY，不向客户端伪造可执行操作。错误应指出对象类型与允许公开的当前revision，不能混用card／gate／schedule／Placement修订。

## C1. 四个读取入口的精确契约草案

本附录与 TodayDtos.java 已经主会话审定；DTO 字段保持冻结。后端 [TodayController](../../backend/src/main/java/com/wenjie/studio/today/TodayController.java)、[TodayService](../../backend/src/main/java/com/wenjie/studio/today/TodayService.java)、[TodayRules](../../backend/src/main/java/com/wenjie/studio/today/TodayRules.java)、[TodayRows](../../backend/src/main/java/com/wenjie/studio/today/TodayRows.java)、[TodayMapper](../../backend/src/main/resources/mapper/today/TodayMapper.xml) 实现四个 GET 的只读聚合；快速记录继续复用原域。此次后端范围不含 UI、共享资料守卫或机器契约的集成交付，TodayDtos 的初稿类注释只记录其最初落盘时点。C1 不创建 Placement、预算或面试准备关联，不实现成长查询；§5–9 的写接口与表属于 C2／C3，不能因为 C1 后端代码存在而标记完成。

### C1.1 请求、响应和版本边界

| 方法／路径（前缀 `/api/v1`） | 请求及精确响应 |
|---|---|
| GET `/today/overview` | `zoneId` 必填；可选 `targetId`、`includeOverBudget`，返回 TodayOverview。固定四个 SectionPreview 和24个 SourceSectionCapability，每种来源×区段恰好一次；memoryQueue 可空 |
| GET `/today/items` | `zoneId,kind,section` 必填；可选 `targetId,includeOverBudget,cursor,limit`，返回 TodayPage。只读一个来源和一个区段，不能传多个 kind 后服务端任意截断 |
| GET `/today/calendar` | `from,to,zoneId,kind` 必填；可选 `targetId,cursor,limit`，返回 CalendarPage。from／to 为包含首尾的日期，最多31天；不支持 includeOverBudget |
| GET `/today/sources/{kind}/{id}` | `zoneId` 必填，返回 SourceDetail。先按实际 owner 核对源身份，不存在或跨 owner 统一404；该条退出今日仍返回当前状态与 exclusionReason，不伪造删除 |

查询参数拒绝未知键和同名重复值。limit 缺省20、范围1–50；includeOverBudget 缺省false，仅影响 overview 和 MEMORY_CARD／TODAY，其他 items 组合传true返回400。targetId 是标准小写 UUID，过滤所有**实际记录**的该目标版本；C1 不提供“当前目标版本覆盖率”。知识／回忆卡没有目标关系，选择 targetId 后这两类可由明确空关系得到 READY／EXACT 0，不能以标题或相关知识猜目标。targetRefs 每项保留确切版本，按 itemId／versionId 去重；动作从来源的固定训练背景或回忆面试快照提取，不能改读当前面试目标。

DayContext 的 `asOf` 是首页由服务器固定的 UTC 微秒时刻；`serverTime` 是本次请求时间。localDate／startAt／endAt 由 asOf 和显示 zoneId 计算，使用当地零点到下一当地零点的半开区间，不能假设24小时。calendar 的 window 另存 from／to 及相应 UTC 半开区间，不改变今日归属日期。仅接受服务器支持的 IANA／UTC，日期和所有转换后的时间须落在1000–9999年可持久化范围，边界溢出返回400。

SourceDetail 在 capability=READY 时 item 非空；item.section 非空代表按缺省推荐条件属于今日，exclusionReason=null。退出聚合时 section=null、exclusionReason为确切原因，保留可访问的源工作区入口；如已结束训练不能标“继续训练”。其余 capability 返回 item=null、exclusionReason=null，不把查询失败包装成某种终态。不存在对象仍是404，不用 ERROR 隐藏身份检查。

### C1.2 载荷、状态和 null 的唯一含义

SourceRef、SourceStamp.kind、SourceStatus.kind 必须相同。两个联合对象都输出固定七字段：`kind,knowledge,training,task,memory,action,interview`，与kind对应的一项非空，其他显式null；未知字段非法。此处是强类型载荷的封闭联合，不接受开放字典，也不通过类型名反射读取客户端对象。

| 来源 | stamp 载荷 | sourceStatus 载荷及约束 |
|---|---|---|
| KNOWLEDGE_DRAFT | `{itemRevision,draftRevision,currentVersionId}`；分别对应 metadataRevision、实际草稿修订、发布版 | `{itemKind,status,unpublishedDraft,draftSavedAt}`；kind=NOTE／CONCEPT，status=ACTIVE／ARCHIVED；unpublishedDraft仅比较服务器草稿title/body与当前发布版，draftSavedAt来自真实草稿 |
| TRAINING_SESSION | `{revision,generation,questionsHash}` | `{mode,status,savedDraftCount,lastDraftSavedAt,lastActivityAt,repracticeId}`；复用Training枚举，savedDraftCount为0–60；无草稿时lastDraftSavedAt=null，repracticeId仅真实复练绑定非空 |
| PREPARATION_TASK | `{revision}` | `{status,startedAt,completedAt}`；复用Planning五态和原时间，不能由过去日期生成completedAt |
| MEMORY_CARD | `{cardRevision,cardVersionId,gateRevision,scheduleRevision,attemptId,attemptRevision,settingsRevision}` | `{cardStatus,scheduleStatus,pauseReason,phase,eligibility,openAttempt,recommendation}`；复用Memory枚举与实际Eligibility；后四类管理条件不能替代开始／评分命令校验 |
| REVIEW_ACTION | `{revision,progressHash}` | `{status,mergedInto,sourceCount,trackingCount}`；OPEN的mergedInto=null，MERGED有确切目标；两个数量0–20，pendingCount另按逐来源判断计算 |
| INTERVIEW_EVENT | `{revision}` | `{status,timing,reminderPending}`；复用Schedule枚举和timing规则；reminderPending仅PLANNED、未确认且remindAt≤asOf为true |

训练草稿保存只推进题目修订，证据是 [TrainingMapper](../../backend/src/main/resources/mapper/training/TrainingMapper.xml) 的saveDraft与 [TrainingService](../../backend/src/main/java/com/wenjie/studio/training/TrainingService.java) 的draft流程。因此 questionsHash 是最多60题按 positionIndex／id 排序后，将 `[id,revision,status,hasDraft,draftSavedAt,latestAnswerId,answerCount,positionIndex]` 固定顺序JSON编码后的SHA-256小写十六进制；时间规范化为六位小数UTC，null原样保留，不含正文。lastActivityAt取会话updatedAt和仍存在的草稿savedAt之最大值，不读取浏览器文字。generation使用会话实际值，不能替代questionsHash。

progressHash固定动作当前修订和按sourceId排序的 `[sourceId,actionId,tracking,verificationHash,latestJudgmentId,latestJudgmentRevision,latestOutcome,applicable,recollectionState]`；verificationHash对原验证条件UTF-8原文求SHA-256，不把验证正文返回今日。无判断时相关三字段null，DROPPED不当作HANDLED；同一批次的待处理数与hash由同一份领域投影产生。任何hash都不是权限凭据或技术正确性证明。

MemoryStamp的gateRevision仅在实际gate缺失时null；scheduleRevision仅无排程时null；attemptId／attemptRevision成对为空或有效。settingsRevision只在本次读到实际已配置设置时非空，不能补0。MemoryState中无排程则scheduleStatus／pauseReason／phase均null；ACTIVE排程pauseReason=null，PAUSED必须有原原因。openAttempt只允许THINKING／REVEALED，并与stamp的attempt身份／修订一致；其mode、countRegular和开始／更新时间来自B记录。recommendation仅来自B的真实QueueItem，包含budgetKind、countedToday、recommended、requiresBudgetConfirmation；null表示没有该队列投影，不能显示“无需确认”或“可开始”。

TodayItem各字段完整输出。pendingCount仅动作非空，范围0–trackingCount；eventWindow仅面试非空且startAt<endAt，保留原zoneId和remindAt。placement在C1恒为null，Java以Void表示，其JSON模式只能是null；不创建C2空对象。estimate仅普通任务取原minutes及SOURCE，其余 `{minutes:null,basis:UNKNOWN}`；训练配置的总时限不是预计剩余耗时。标题保持来源原文、不截断；列表禁止题面、知识body、参考、回答、反馈或验证条件正文。

SourceTime固定 `{kind,instant,localDate,zoneId,zoneBasis}`：NONE其余全null；INSTANT必须instant／zoneId／zoneBasis非空且localDate=null；LOCAL_DATE必须localDate／zoneId非空、instant=null且zoneBasis=SOURCE。普通任务使用原日期／时区，面试使用开始Instant／原时区，回忆使用实际effectiveDueAt／本次显示时区且zoneBasis=DISPLAY；后者不声称是评分当时或原排程时区。无日期来源为NONE。UUID、长整型和修订沿用源域边界；Card修订0–1000，其余JS安全整数，hash为64位小写hex；任何浮点修订或字符串强制转换非法。

### C1.3 续作入口只导航，不隐式执行命令

Continuation固定 `{route,item,action,attempt}`。route为TodayDtos.Route枚举，客户端只通过下面白名单映射；item为 `{item:UUID}`、action为 `{action:UUID}`、attempt为 `{attempt:UUID}`，非对应参数载荷显式null，禁止URL或额外query键。

| route | 前端固定路由名／参数 |
|---|---|
| KNOWLEDGE | `knowledge`，item非空 |
| TRAINING | `training`，item非空；DRAFT只是进入开始前核对，不能通过GET启动 |
| PREPARATION_TASKS | `preparation-tasks`，item非空 |
| MEMORY_CARDS | `memory-cards`，item非空，来源复核或排程管理从该卡进入 |
| MEMORY_RECALL | `memory-recall`；未决时attempt非空，否则三个参数均null进入原队列。当前前端只接受attempt参数，不能另造card查询键 |
| REVIEW | `review`，action非空，合并后的旧动作仍可打开原身份查看去向 |
| SCHEDULE | `schedule`，item非空 |

AvailableAction也只包含动作种类与Continuation，不传HTTP方法或命令正文。继续训练、继续未决回忆分别限实际非终态；待开始卡只提供OPEN_MEMORY_QUEUE，在源页重新核对预算／来源并明确开始。C1没有直接完成、评分、延期、暂停、排序或移出今日按钮。快速记录沿用§5的NOTE创建和原幂等恢复；手工任务走原planning创建。无数据入口由前端固定为写笔记／练一题／建目标，不为这三个入口创建今日写API。

### C1.4 区段分类、时间和排序

同一SourceRef只出现于最高优先级区段 `CONTINUE → ATTENTION → TODAY → BACKLOG`，reasons可并存。下表没有的来源／区段组合是该范围内的确定空集合，可返回READY／EXACT 0；HIDDEN需要C2偏好，C1不接受该枚举。

| 来源 | 入选规则 | 来源页完整排序（最终身份用于打破平局） |
|---|---|---|
| 知识草稿 | ACTIVE且unpublishedDraft→CONTINUE | draftSavedAt DESC，itemId ASC |
| 训练 | DRAFT／RUNNING／PAUSED→CONTINUE，ENDED退出 | lastActivityAt DESC，sessionId ASC |
| 普通任务 | IN_PROGRESS→CONTINUE；TODO的plannedDate小于／等于该任务zoneId的当前本地日期→ATTENTION／TODAY；TODO且无日期→BACKLOG；未来日期或PAUSED／DONE／CANCELLED不进今日 | CONTINUE／BACKLOG为updatedAt DESC、id ASC；ATTENTION／TODAY为plannedDate ASC、id ASC。来源日期按各自zoneId比较，不能按显示时区偷换到期 |
| 回忆卡 | B未决→CONTINUE；ACTIVE且无未决、Eligibility含阻断→ATTENTION；其余仅B队列实际返回者→TODAY，includeOverBudget=false只纳入recommended。手工暂停、未到期或无排程卡不冒充到期；未决优先于常规卡 | CONTINUE沿B：startedAt DESC、attemptId DESC；TODAY沿B：phaseRank ASC、effectiveDueAt ASC、cardId ASC；ATTENTION按card／gate／schedule的最大updatedAt DESC、cardId ASC |
| 改进动作 | OPEN且pendingCount>0→ATTENTION；MERGED、无跟踪或最新适用判断全部HANDLED退出 | action.updatedAt DESC、actionId ASC；判断变化由progressHash体现，不伪造动作更新时间 |
| 面试 | PLANNED且提醒未确认或timing=PAST→ATTENTION；否则与本显示日UTC区间相交→TODAY；未来开始在后7个显示本地日内→BACKLOG；COMPLETED／CANCELLED退出 | ATTENTION用remindAt ASC、id ASC；TODAY／BACKLOG用startAt ASC、id ASC。PAST只表示时间已过，仍需本人决定结果 |

未接C2时所有来源排序的orderValue等价500000，不读不存在的today_placement表。上面的来源业务排序仍有效；不能在任意ID页上本地排序后声称全局有序。reasons按Reason枚举顺序去重，warnings按Warning枚举顺序去重；源时区与显示时区不同时标SOURCE_ZONE_DIFFERS，不改原日期。

overview每区最多5行，先取该区各来源最多5个有界候选，再按固定来源顺序轮流取一条直到5条：CONTINUE为训练／回忆／普通任务／知识，ATTENTION为面试／回忆／任务／动作，TODAY为面试／任务／回忆，BACKLOG为面试／任务。该预览不宣称跨日期与Instant的统一优先级排名。只提供来源页入口并从该来源首页重新读取，不使用已消费但未显示的候选游标，避免丢项。overview每来源最多扫描100候选、总计最多600，不能为了填满预览扫描全库；被扫描预算截断的区段显示scanLimited。只凭动态过滤已读项计数时必须为LOWER_BOUND；原领域独立全量COUNT已经得到的真实EXACT不因摘要扫描限额失效。

calendar支持有真实时间的来源：普通任务按原plannedDate标签筛from/to，含其五种实际状态；面试按`startAt<window.endAt && endAt>window.startAt`，含三种实际状态。知识草稿／训练／动作在C1没有安排日期，返回READY／EXACT 0而不是用updatedAt塞进日历。回忆日历已接下述真实排程窄投影；不能使用B的nextDueAt推演整个区间。其区间／计数仅由实际schedule决定，页内卡ID再调用sources获取真实队列成员资格，用于TodayItem.section及续作入口，未配置预算仍能返回实际日历。日历项依然使用TodayItem，若不满足今日条件section=null；日历仅展示实际记录，不把日期内状态当作完成活动。排序：任务plannedDate ASC/id ASC，面试startAt ASC/id ASC，回忆effectiveDueAt ASC/cardId ASC。

### C1.5 游标、计数与错误

每个列表游标为有版本的规范编码，最多4096个ASCII字符。逻辑字段固定：`v,purpose,ownerId,kind,section,targetId,includeOverBudget,zoneId,localDate,asOf,from,to,sort,afterInstant,afterDate,afterRank,afterId,delegateCursor,memorySettingsRevision,memoryZoneId,memoryLocalDate`；不适用字段显式null，拒绝未知／重复／缺失字段。purpose只允许today-items／today-calendar；不接收独立asOf查询参数。游标不是权限凭据，ownerId必须等于当前会话，客户端更换kind、section、时区、日期、目标或推荐范围须从首页读。

sort对应C1.4的固定来源排序，实际封闭值为`KNOWLEDGE_SAVED_DESC|TRAINING_ACTIVITY_DESC|TASK_ACTIVITY_DESC|TASK_DATE_ASC|MEMORY_OPEN_DESC|MEMORY_DUE_ASC|MEMORY_ATTENTION_DESC|ACTION_UPDATED_DESC|INTERVIEW_REMINDER_ASC|INTERVIEW_START_ASC|MEMORY_CALENDAR_ASC`。非memory仅启用afterInstant或afterDate其中之一和afterId；TASK_DATE_ASC使用日期，其余使用Instant。memory外层三个after字段和afterRank均null，完整排序位置保存在原delegateCursor内；未决的原游标最终身份为attemptId，其他为cardId，不重造“等价”顺序。普通候选页记录最后**实际消费**的候选，不是最后输出行；达到limit时剩余候选留给下页，发现还有后续用一条lookahead但不提前消费。原域分别核对delegateCursor的用途、asOf及日期区间，外层核对owner、筛选、设置与复习日。

首次请求在同一只读快照内固定asOf，后续请求读取当前数据库状态，**不宣称跨请求快照**。游标最长15分钟且不能来自未来；跨显示本地日、memory设置修订／复习日变化或排序版本变化返回409 TODAY_CURSOR_CHANGED，保留客户端选择并提示回首页。页内SourceRef唯一，前端跨页去重，主动写入或来源变动后重新取首页，不将旧同修订响应覆盖较新动态状态。

items／calendar每次最多扫描500候选、返回最多50项；scanLimited=true表示扫描额度耗尽且尚有候选，不是普通分页的hasMore，也不否定独立全量COUNT的EXACT。nextCursor非空也可能是正常limit截断；扫描500却无匹配时允许空items和非空nextCursor。每批动作候选最多50个以便复用逐来源规则，跨批累计扫描仍受500约束。

Count始终描述**当前整个来源＋区段＋筛选范围**，不描述累计浏览或当前页余量。简单来源可由同快照的真实COUNT得到EXACT；动态扫描只有从首页完整走完匹配集合才能升级为EXACT，否则返回LOWER_BOUND（至少本次已核对并输出的不同来源数）。后续页走到末尾不能把“本页0条”变成整个范围EXACT 0，也不能把前几次响应的数量相加当精确计数。memory队列的eligibleDueCards／recommendedCards只复制B真实总数；今日items.count按includeOverBudget选择对应总数，未决另列且不相加为“完成数”。MemoryQueueInfo只在该次memory队列投影成功且未被目标筛选排除时非空。

| capability | reason及响应含义 |
|---|---|
| READY | reason=NONE；计数为EXACT或LOWER_BOUND，允许scanLimited。只说明本次读取可用，不表示服务器验收通过 |
| DEPENDENCY_PENDING | reason=QUERY_NOT_INTEGRATED；所需窄查询适配尚未接入，count={value:null,mode:UNAVAILABLE}、items=[]、nextCursor=null、scanLimited=false |
| NOT_CONFIGURED | reason=MEMORY_SETTINGS_REQUIRED；已接B队列但本人尚未保存设置，同样UNAVAILABLE。只影响需要该设置的队列，不阻断独立未决目录或日历的实际UTC排程 |
| ERROR | reason=SOURCE_READ_FAILED／SOURCE_INTEGRITY_FAILED；本次来源投影失败或身份／占位不一致，不能降为NOT_CONFIGURED或返回0，不能继续使用旧成功页；输出与依赖未接相同的空载荷边界 |

缺少数据表、SQL异常、数据库连接失败不是“尚未配置”。资料权限／会话／owner错误始终按原HTTP错误返回；共享数据库故障或只读事务已标回滚时整次失败，不捕获后伪造部分成功。ERROR只用于仍可安全返回的明确来源投影失败；内部日志保留原因，对客户端只给上述封闭错误原因，不返回SQL／正文。整体响应上限1MiB、单TodayItem最多32KiB，超限以422 TODAY_RESPONSE_LIMIT拒绝该次读取，不截断标题或引用。筛选与游标不匹配为400 INVALID_REQUEST，过期／跨日／复习设置变化为409 TODAY_CURSOR_CHANGED。C1仅GET，继续沿用no-store及序列化前资料守卫。

### C1.6 必要的窄查询入口及实际 SQL 所需摘要

已核对 [MemoryQueueService](../../backend/src/main/java/com/wenjie/studio/memory/MemoryQueueService.java)、[MemoryAttemptService](../../backend/src/main/java/com/wenjie/studio/memory/MemoryAttemptService.java)、[MemoryTodayQuery](../../backend/src/main/java/com/wenjie/studio/memory/MemoryTodayQuery.java)、[MemoryTodayDtos](../../backend/src/main/java/com/wenjie/studio/memory/MemoryTodayDtos.java) 和 [RepracticeService](../../backend/src/main/java/com/wenjie/studio/review/RepracticeService.java) 的当前源码；下列窄入口已落盘，今日只读层已接入并通过集成编译。原queue／openAttempts公开HTTP的路径和命令不变；实现是否运行正确仍待服务器核验。

| 内部签名 | 契约与复用要求 |

MemoryTodayDtos包含三个内部摘要：`CardProjection={card:MemoryDtos.Summary,gate:MemoryReviewDtos.Gate|null,schedule:MemoryReviewDtos.Schedule|null,eligibility:MemoryReviewDtos.Eligibility,openAttempt:MemoryAttemptDtos.AttemptSummary|null,queueItem:MemoryAttemptDtos.QueueItem|null}`；`SourceProjection={items:List<CardProjection>,settings:MemoryReviewDtos.Settings,asOf}`；`ProjectionPage={items:List<CardProjection>,nextCursor,scanLimited,scannedCount,exactTotal:Long|null,asOf}`。settings未配置沿A的configured=false表达，exactTotal=null不表示0。原calendarWindow／attention窄查询的queueItem恒null，只承诺管理／日历事实；今日源详情和日历页内补充分类使用sources的真实队列成员摘要。CardProjection不可含Reference、AttemptDetail、回答、知识正文或卡题面。

memory新增SQL需要的列和条件限定如下，不请求全量日历表或新派生表：

1. 主查询从 `memory_schedule s` 以owner关联 `memory_card c` 及其当前 `memory_card_version v`；calendar只取c.status=ACTIVE、s.status=ACTIVE／PAUSED，计算`effectiveDueAt=max(s.suggested_due_at,coalesce(s.defer_until,s.suggested_due_at))`，并使用fromInclusive≤due<toExclusive。SELECT只需卡身份／标题／种类／当前版本号／修订／更新时间和现有Schedule字段，不取prompt／reference。
2. 按 `(effectiveDueAt,cardId)` 升序键集分页，最多limit+1（≤51）；cursor绑定owner、from、to、asOf和最后due／cardId，区间不变才可继续。额外一行只决定后续，查询的是实际保存的当前due，不是“每天会复习这些卡”。同快照可选COUNT；不做COUNT则exactTotal=null，只报告已读取下界。

目录按 `updatedAt DESC,id ASC`，源标题、状态、stamp 和 continuation 在同一快照中投影；Placement source、currentSource.kind、sourceStatus.kind 必须一致。源已归档／终态仍可展示当前状态并打开原详情，但不能给“继续”入口。持有偏好不授予源权限；意外缺失或跨 owner 的关联按完整性／权限错误处理，不泄漏旧标题。目录是恢复安排偏好的必要入口，不把 C1 已退出的事项重新算入今日。

`asOf/serverTime` 是服务端读取前取得的分类时刻，不是数据库快照所包含修改的时间上界。首次一致性读取前并发提交的当前修改可以出现在响应里；客户端及目录游标不得据 `updatedAt > serverTime/asOf` 拒绝该合法记录。仍校验每条记录自身的时间格式、createdAt≤updatedAt、游标有效期与日期，以及真实 due／未决 startedAt 的业务筛选。前端时区检查只作浏览器可识别名称的预检查；后端按实际 Java 时区库精确判定。原名称原样发送和保存，服务器拒绝时展示明确错误，不擅自规范化别名而改变预算或抑制记录的身份。

写入先在 owner 锁内核对当前源身份和可安排性，再比完整来源 stamp、偏好修订／预算修订；来源不存在或跨 owner 返回404 TODAY_SOURCE_NOT_FOUND。新建／普通保存／order 拒绝已归档、已终态、合并动作及无待处理工作；源暂停或未来日期允许保存合法显示偏好，但不因此进入今日或绕过源状态。已有偏好读取与历史不受“当前仍可安排”的写条件限制。

- 已有同源偏好新建返回409 PLACEMENT_EXISTS，currentRevision 为该偏好当前修订；用 by-source 查询身份，不向既有 ApiProblem 追加字段。偏好不存在返回404 PLACEMENT_NOT_FOUND；版本冲突409 PLACEMENT_REVISION_CONFLICT。
- 预算已存在返回409 DAY_BUDGET_EXISTS；修改未创建预算返回404 DAY_BUDGET_NOT_FOUND；版本冲突409 DAY_BUDGET_REVISION_CONFLICT。上述 currentRevision 只指预算，不混用来源或偏好修订。
- 来源 stamp 变化／当前不再能安排返回409 PLAN_SOURCE_CHANGED，currentRevision=null，因为复合 stamp 不能压成一个修订。预览／采用期间的候选、预算或提议变化统一409 PLAN_PREVIEW_CHANGED；依赖尚未接入为409 DEPENDENCY_NOT_READY，实际读取错误仍失败，不变成“没有候选”。
- 同内容保存或 orderValue 未变时，在 CAS 与来源核对通过后返回当前快照，不产生空历史或递增修订。含多项的 order／apply 只为真实变化项追加历史，响应仍含全部明确所选项。
- 新命令摘要包含规范请求和全部路径定位字段；同键异文拒绝，同键恢复原回执。当前资料守卫先于旧回执读取；旧回执恢复后另读当前来源，不将历史成功快照当作当前状态。单条历史32KiB、请求256KiB、读取页1MiB和原2MiB回执限制沿 §11；超限整体回滚。

### C2a.3 偏好必须真正进入 C1 聚合

源域事实先于偏好：归档／终态／已合并／无待处理等原排除条件先判断，Placement 不能使它们重新可做。偏好为当前投影增补，不复制 title、完成状态、卡片知识或训练答案。

1. **必须保留的入口**：RUNNING／PAUSED 训练、IN_PROGRESS 任务、B 的未决回忆，以及未确认／已过时或正在进行的 PLANNED 面试仍按 C1 来源规则展示。PAUSED 安排、当天 suppressedOn 或未来安排日期不能藏掉这些入口；本行带 `PLACEMENT_CONTINUATION_RETAINED` warning。推荐建议仍可以尊重其暂停／抑制，不把“入口保留”解释为用户已同意再次安排。
2. **可改安排日的三类**：其余知识未发布稿、DRAFT 训练、OPEN 且仍有 pending 的动作，若有 Placement 日期，按该 planZoneId 下的当前日期比较：过往→ATTENTION，当日→TODAY，未来→退出今日。若没有日期，沿 C1 原区段。VISIBLE 且没有匹配 suppressedOn 才推荐；PAUSED、当日抑制分别退出今日。只设优先级／顺序／估时不改变原区段。
3. **源日期不可覆盖的三类**：任务、回忆、面试仍由原来源决定区段和日期。手工顺序只改变同区段的展示先后；卡片 eligibility、完整队列推荐、预算确认及未决优先级继续由 B 决定，不能由 Placement orderValue 重新计算谁占张数额度。
4. **估时与时间字段**：任务保留 `{minutes:源minutes,basis:SOURCE}`；其余支持用户估时的类型有值时为 USER，否则 UNKNOWN／null。三类 Placement 日期在 SourceTime 中使用 LOCAL_DATE 和 `zoneBasis=PLACEMENT`，保留 planZoneId；无日期仍 NONE。源时间原规则不变。
5. **日历**：三类有 Placement 日期的来源按该日期标签进入日历，显示当前源状态和偏好；暂停／抑制不抹掉已经保存的安排事实，也不生成完成事件。原任务、真实回忆 due、面试区间保持 C1 读取。calendar 首先按日期／Instant 升序，其次 orderValue、最后稳定身份；拖动展示次序不改变时间位置。

`TodayItem.placement` 返回完整当前 Placement 或 null，身份必须与 item.source 相同；普通详情中的 sourceStatus 仍是源状态。SourceDetail 保留原源排除原因的优先级；只有源本可进入今日而被偏好排除时，才返回 `PLACEMENT_PAUSED|PLACEMENT_SUPPRESSED_TODAY|PLACEMENT_FUTURE`。偏好日期形成的当日／过往原因分别增加 `PLACEMENT_TODAY|PLACEMENT_OVERDUE`，原原因可保留，不能把偏好日期叫作算法到期。

**排序必须在取候选页之前生效。** 原 C1 组合的 items 完整键为 `(coalesce(orderValue,500000) ASC, C1该来源区段业务键, 最终稳定身份)`；orderValue 相同沿用原微秒、日期、phaseRank和身份方向。知识／训练新增的 ATTENTION、TODAY，以及动作的 ATTENTION、TODAY，固定使用 `(orderValue ASC, plannedDate ASC且null排后, 该来源活动时间 DESC, sourceId ASC)`；活动时间分别为 draftSavedAt、lastActivityAt、action.updatedAt。因此未设日期的动作在相同顺序值下仍按原 updatedAt 排序；不同来源时区的日期保留原标签。priority 不暗中再次改变列表次序，只参与下述建议算法；用户显式 order 是列表顺序依据。日历的时间主键顺序另依上段。

overview 每来源先按上述完整键拿本区至多5个候选，再按 orderValue 从小到大合并。相同 orderValue 内按固定来源轮询，各来源仍保持自身业务排序，取前5：CONTINUE 和 BACKLOG 沿 C1；ATTENTION 为面试／回忆／任务／动作／训练／知识；TODAY 为面试／任务／回忆／训练／动作／知识。新增组合随真实偏好投影计数，不能沿用 C1 的“该组合确定为空”。无偏好时新增组合为空，因而保持 C1 原预览方式，显式跨来源顺序也能影响概览。仍从各来源首页进入完整列表，不把未展示候选的游标给客户端。

memory 不能先读原 B 队列一页再重排：C2a 需补充**内部**安排排序投影，在 B 的完整合格集合／完整推荐排名已经计算后，才关联当前 owner 的 Placement、应用排除与完整排序，并做键集分页；未决和来源提醒同样在取页前关联。继续复用 B 的实际 source flags、Eligibility、占位和推荐表达式，不复制一套“尚有额度所以推荐”的判定。原 B HTTP、队列排序与命令保持原样，今日的次序仅是今日展示次序；回到原队列仍按其原规则开始。

**游标与扫描：** 增加 owner 级 `placementGeneration`，缺省0且 GET 不落库；一次实际改变偏好的原子命令只递增一次，所有偏好、历史及该值一起提交。仅改预算不改变 C1 列表排序，不必推进该值。items／calendar 游标升级 v2，逻辑字段保留 C1 全部键并增加 `placementGeneration,afterOrderValue`；delegateCursor 在 v2 恒 null，全部来源使用本次完整排序键。新增 sort=`PLACEMENT_DATE_ACTIVITY_DESC|PLACEMENT_CALENDAR_ASC`：前者同时使用 afterDate（可空，null日期排后）、afterInstant、afterId；后者用 afterDate、afterId。原排序仍使用各自既有时间／身份字段，memory TODAY 额外使用 afterRank=0或1，其余 afterRank=null；memory CONTINUE 的最终 afterId 仍为原 attemptId 且倒序，不能换成cardId。所有有效位置的 afterOrderValue 必填；calendar 以时间主键在先、orderValue在后。v1、代次变化、15分钟过期、显示跨日、memory设置／复习日变化返回 TODAY_CURSOR_CHANGED，从首页重新读；源本身变化仍不承诺跨 HTTP 数据库快照。目录游标另固定 `{v,purpose,ownerId,zoneId,localDate,asOf,kind,visibility,placementGeneration,afterUpdatedAt,afterId}`，purpose=today-placements，其余规范编码和过期规则沿 C1。

排序后的完整候选流仍受每页扫描500／overview每来源100、合计600上限；lookahead 不提前消费，达到 limit 的未消费候选留给下页。动态排除使500项均不输出时仍允许空 items＋非空 nextCursor。scanLimited 与普通分页 hasMore 分开；精确 count 必须包含偏好过滤，否则降为 LOWER_BOUND。B 的 MemoryQueueInfo 仍报告原真实 eligible／recommended 数；今日 items.count 是考虑偏好后的展示数量，二者不能直接互换或相加。不能循环拉完整 B 队列绕过500上限，也不能只重排当前页后声称所有数据已按手工顺序排列。

### C2a.4 预览算法、日界与原子采用

本轮建议的业务边界是**当前显示日、显式候选集合、显式学习分钟**。DayBudget 可保存任一合法日期；preview／apply 的 request.localDate 必须等于服务器在 request.zoneId 下的当前日，跨日返回409 PLAN_DAY_CHANGED。DayContext 按该次服务器时刻产生；日界使用 IANA 当地零点，不以24小时近似 DST。日期／区域组成预算身份，切换显示区域不会修改旧预算，也不清空 memory 张数或 AI 费用预算。

预览 items 为1–100个不同 SourceRef，输入数组顺序属于请求且不自动去重。expectedPlacementRevision=null 的唯一含义是该源尚无 Placement；若已经存在即冲突，不把 null 当任意版本或0。expectedBudgetRevision=null 同样要求当前不存在预算；存在则须精确相等。完整 expectedSource 必须在同一快照中逐字段相等；来源不存在、跨 owner 或来源查询失败不能伪造为普通落选项。

估时选择顺序为：允许估时的四类用本次 candidate.estimatedMinutes（非空时）→已有 Placement.estimatedMinutes→未知；任务必须传 null，取原任务 minutes；面试必须传 null，保留为 INTERVIEW_REFERENCE_ONLY 且不推荐。显式本次估时仅在采用后写入允许的 Placement 字段；预览不会先保存。unknownEstimateCount 只计“其他业务条件可推荐、但仍无估时”的候选，不把终态或仅引用面试算入待估时学习项。

候选业务资格先判定，再排序和装入分钟：

- 草稿须 ACTIVE 且存在真实未发布内容；训练须非 ENDED；动作须 OPEN 且 pending>0。普通任务仅 IN_PROGRESS 或 TODO 且原日期已到日；无原日期／未来日期分别给 SOURCE_DATE_REQUIRED／SOURCE_DATE_IN_FUTURE，改日走原任务命令。
- 回忆未决可推荐继续原尝试；否则必须来自 B 当前实际队列、recommended=true、requiresBudgetConfirmation=false。未配置、阻断、未到期、未推荐和超张数待确认分别列封闭原因。C2a 不提供继续超张数的授权字段；去原回忆队列完成明确确认，不能借建议采用代替。
- 终态、归档、没有待处理、源暂停、安排暂停及当日抑制均列具体落选原因，proposedContent=null。训练源 PAUSED 仍可继续，和普通任务／常规回忆源 PAUSED 的不可开始语义不同。
- 日期锁定和“曾经开始”只禁止自动改变日期。已有日期若因此不能移到本次日且并非受保护继续项，候选落选；保留原日期或无日期也能继续的事项仍可推荐，附 DATE_LOCKED／ALREADY_STARTED 说明。知识草稿保存不是“曾经开始”；训练读真实 startedAt，任务读 startedAt；动作须窄查询其跟踪来源是否曾绑定实际 STARTED／后续终态的复练会话，不能仅靠动作 revision 或 pendingCount 猜。该布尔值和相关原因进入预览重算，C1 SourceStamp 本身不扩展为伪造的开始历史。

可推荐集合按 `(继续事项优先、已到日其次、其余可安排事项最后)` 排序：第一组仅实际 RUNNING／PAUSED 训练、IN_PROGRESS 任务和 B 未决回忆，第二组为其余源日期／due或已有偏好日期已到日的事项，第三组为其余允许明确安排的草稿／DRAFT训练／动作。组内依次 priority DESC、有效 orderValue ASC、SourceKind声明顺序、该来源 C1业务键及身份；新增日期排序沿 C2a.3，无偏好 priority=3、orderValue=500000。这一可解释规则只处理请求给出的最多100项，不自动扩展库中候选。逐项检查已知分钟，能放入剩余名义分钟则 recommended=true，放不下则 OVER_MINUTES；继续扫描明确清单中的后项，不创造新候选补满。未知估时永不按0分钟入选。未保存预算时全部 recommended=false，业务合格项另列 DAY_BUDGET_REQUIRED。

items 按以上确定顺序返回；recommended=true 必须有已知分钟与非空 proposedContent。其 proposedContent 以现有偏好或显式默认值为底：保留 priority／锁定／visibility，允许改日的三类在未锁定且未开始时改为 request.localDate／zoneId，锁定或开始则保留原日期；其他类型日期恒 null。拟采用的 orderValue 固定为该排序位置的 `1000 × (index+1)`，最多100000，保留选择子集的原位置，不临时重排所选子集。只影响所选偏好，不修改未选项的值，也不承诺插到所有已有 orderValue=0 项之前。符合业务条件但因未知估时、缺预算或超分钟未入选的项仍可显示提议内容；无法安排的项为 null。

selectedKnownMinutes 为 recommended 集合估时之和；unknownEstimateCount 如上；remaining.sources 恰为全部未推荐项、按 items 顺序，remaining.count 等于该数组长度。每项 reasonCodes 按枚举顺序去重，limitations 固定输出五项。availableMinutes 是此次明确候选选择的名义上限，**不是已预留分钟账本**：不把此前另批采用的安排视作自动扣费，不报告“全日已占用／还剩”完整统计。界面须显示“本次候选”和该限制；若后续要求全日已安排容量核算，须另定全日扫描、未知估时和去重口径，不能在本批默认实现。

previewHash 使用小写64位 SHA-256，规范串为 `today-plan-v1` 加固定字段规范 JSON。hash 覆盖：完整 request（含候选原顺序）、当天身份及真实起止日界、当前预算完整快照或 null、每个候选当前完整 SourceStamp／Placement快照或 null、当前业务分类／可用性／开始与锁定判定、排序后的提议内容及原因／推荐结果、分钟合计和 remaining。所有对象字段按固定名称排序，null 明示，时间统一六位小数 UTC，数组保留规定顺序；不做语言相关排序，不含正文。context.asOf／serverTime 不入 hash，否则两次合法计算会仅因时钟前进而不同；影响资格的跨日／到期／状态必须作为上述派生事实重算。hash 不作为权限或签名，也没有客户端自报“已检查”作用。

apply 要求 selectedSources 是当前重新计算预览中 recommended=true 项的1–50个不同来源，并保持预览顺序；仅允许缩小推荐集合。要改估时、候选范围或换选原超分钟项，先修改 request 重做预览。owner 锁内按当前服务器时间重读全部明确候选、预算和偏好并重算 hash，任一不一致返回 PLAN_PREVIEW_CHANGED；再次核对本次所选分钟≤当前预算。确认全部成功后才创建／修改所选 Placement、追加 SUGGESTION_APPLIED 历史、递增一次 placementGeneration、保存一个 AppliedSuggestion 回执，提交在同一事务；不修改源对象、预算值、B排程或任何完成证据。任一 CAS、范围、序列或回执超限失败整批回滚，禁止循环调用公开 PUT 后宣称原子。

### C2b.2 关联命令、状态、历史与分页

所有路径前缀为 `/api/v1/schedule/interviews/{id}`。写命令要求 `Idempotency-Key`；各 operation 使用完整方法与实际路径，摘要包含该命令的完整规范请求。预览不消费幂等键。以下是新契约；原 schedule 写请求和摘要保持原样。

| 方法／路径 | 请求 → 响应 | 精确行为 |
|---|---|---|
| GET `/preparation-links?status=&cursor=&limit=` | 无 body → LinkPage | status 可为 ACTIVE／REMOVED；省略时含两种状态，不设隐含只看有效的默认过滤 |
| POST `/preparation-links` | CreatePreparationLink → 201 PreparationLink | 创建新身份；重复身份不覆盖版本，也不隐式恢复 |
| POST `/preparation-links/{linkId}/status` | ChangePreparationLinkStatus → 200 PreparationLink | 显式移除或恢复；同状态经 CAS 后返回当前快照，不增加修订 |
| PUT `/preparation-links/{linkId}/collection-version` | ChangeCollectionVersion → 200 PreparationLink | 仅 ACTIVE COLLECTION；保留 linkId／sourceId，显式采用当前题单版本，追加 VERSION_CHANGED 历史 |
| GET `/preparation-links/{linkId}/history?before=&limit=` | 无 body → LinkHistoryPage | 包含创建、移除、恢复和换版历史，旧快照不改写 |
| POST `/reschedule-plan-preview` | ReschedulePlanRequest → ReschedulePlanPreview | 完整只读预览；已选不可移动项返回明确原因，不提前落库 |
| POST `/reschedule-plan` | ApplyReschedulePlan → 200 AppliedReschedulePlan | confirmed 必须 true；一次 owner 命令事务保存所有真实变化与一个回执 |

关联唯一身份为 owner＋eventId＋kind＋sourceId，不含题单版本。所有写命令先核对本人事件及 expectedEventRevision，定位 link 时同时核对 owner／eventId／linkId，不能只凭 linkId 操作其他面试的关联。关联变更不递增事件 revision、不重置提醒、不改旧面试历史；其自己的历史保存当时已核对的 eventRevision。Link 初始 revision=0，真实修改加1，上限1000；CAS 断言影响一行。事件、任务、Placement、题单和动作的修订仍分别使用原领域上限，不把它们统一压成 Link 修订。

- **新建：**事件必须 PLANNED。任务允许 TODO／IN_PROGRESS／PAUSED，拒绝 DONE／CANCELLED；动作须 OPEN 且 pendingCount>0；集合须 ACTIVE，sourceVersionId 必须等于当前版本。任务／动作 sourceVersionId 必须 null，集合必须非空且属于 sourceId。expectedSource 必须与同一事务读取的完整 PreparationSourceStamp 相等。已有同源关联无论 ACTIVE 还是 REMOVED 均返回冲突，客户端读取原身份后选择恢复或显式换版。
- **移除：**核对事件 revision 和 Link revision 后只改 Link 状态，可对已关闭事件移除；不要求来源仍可安排，也不修改任务、动作、Placement 或题单。REMOVED 历史的 sourceStamp 固定 null，表达没有重新授权或确认来源；其他历史类型 sourceStamp 非空。
- **恢复：**事件须 PLANNED；任务／动作重新核对上述可用性。集合须 ACTIVE 且关联确切版本仍存在；允许恢复一个已经被新版替代的旧版本入口，返回 SUPERSEDED，不换成 currentVersionId。用户如需新版，再走明确换版命令。恢复不自动改日期。
- **换版：**事件 PLANNED、Link ACTIVE、kind=COLLECTION；sourceId 不可改变。新 sourceVersionId 必须是同一 ACTIVE 集合当前版本，expectedSource 为该集合当前完整 stamp。选中原已关联的同一当前版本时，经全部 CAS／来源核对后原样返回，不增加空历史。REMOVED 关联先明确恢复再换版。

LinkHistory.snapshot 是变更后完整 Link；eventRevision 为该命令核对的事件修订；sourceStamp 为操作时当前来源 stamp，可能与恢复时保留的旧 sourceVersionId 不同，不能借此替换快照中的确切版本。历史 createdAt 与 snapshot.updatedAt 相等；创建记录 revision=0 且 change=CREATED，其他真实变更 revision>0。每条历史 UTF-8 最大32KiB，超限整条命令回滚。列表的 currentSource／sourceStatus 是当前查询值，历史中的 sourceStamp 是当时值，两者不能互作当前 CAS。

关联目录使用 `id ASC` 键集分页，默认20、最多50，读取 limit+1 判定 nextCursor。游标是 UTF-8 规范 JSON 的无填充 Base64url，解码最大4096字节，字段固定 `{v:1,purpose:"interview-preparation-links",ownerId,eventId,eventRevision,status,asOf,afterId}`；status 省略过滤时编码 null。校验 UUID、事件归属、过滤一致、规范编码与字段完整性，asOf 不得晚于本次服务器时间且有效期15分钟。过滤／owner／路径不匹配为400 CURSOR_MISMATCH，版本不支持／过期／事件修订变化为409 PREPARATION_LINK_CURSOR_CHANGED，从首页重读。nextCursor.afterId 是最后实际返回的 Link.id；未返回的 lookahead 不提前消费。

LinkPage.asOf 固定首页游标时刻，serverTime 为本次读取时刻；**这不是跨 HTTP 的数据库快照**。其间其他命令修改 Link 状态或新建关联，可能改变过滤成员，客户端在本页已知写入后清游标重读；来源状态也逐页读取当前值。目录不为分页引入业务行或另一套 event 修订，不声称冻结来源。历史分页按 Link revision 倒序，before 排他、默认20／最多50；nextBefore 非空时等于最后返回快照的 revision 且服务端确有后续。Link 目录及历史读取允许事件关闭，不因关联 REMOVED 隐去恢复或审计入口。

### C2b.3 联动预览、完整关系集合与可移动性

selectedLinkIds 必须存在、为0–50个不同标准小写 UUID，保留请求顺序；所有选中 Link 必须属于当前本人事件且 ACTIVE。跨 owner／错事件／不存在返回404，已移除返回409，不把它们降级为空检查项。dateOverrides 为0–50项、linkId 唯一，只能引用 selectedLinkIds，顺序是该选择列表的子序列；plannedDate 必须是非空合法日期，不允许使用 override 给 NO_DATE 来源新建日期或绕过开始／锁定限制。修改选择或 override 后必须重新预览。

每次预览在同一只读快照中取得下列**去重后的完整关联元数据集合，最多500行**：①当前事件的全部 ACTIVE Link，包含未选中的集合引用；②选中任务／动作在其他事件上的全部 ACTIVE Link，包含其事件已经 COMPLETED／CANCELLED 的记录。每行含 Link 完整快照及所属事件当前 revision／status；按 Link.id 的 ASCII 升序排列。对同一 linkId 去重，两个不同关联即使指同一来源也分别计数。查询最多取得501行，出现第501行即422 PREPARATION_LINK_LIMIT，拒绝本次预览／采用；不得先截断再计算摘要，也不得只检查当前目录页或仅查询仍 PLANNED 的其他事件。此上限仅限制一次联动检查，不删除旧关联、不限制目录继续分页；用户仍可使用原只改面试的命令。

linkChecks 恰好覆盖 selectedLinkIds，按请求顺序；没有选中项时为空。每项读取当前来源 stamp、源状态、pendingCount、完整 Placement 或 null、真实开始事实，以及其他有效 PLANNED 面试。otherInterviews 只列与该源同 kind／sourceId 的其他 ACTIVE Link 所属 PLANNED 事件，按 eventId ASCII 升序；每项保留 link／event 修订、标题、真实 startAt 与事件 zoneId。完整关系摘要仍包含上述其他已关闭事件的元数据。相同目标、标题相似或当前显示日期都不能自动产生关联。

| 来源／条件 | reasons 与日期处理 |
|---|---|
| 普通任务 | 只有 TODO、startedAt=null、有原 plannedDate 才可能 MOVABLE；IN_PROGRESS 或有 startedAt 列 STARTED；PAUSED 列 PAUSED；DONE／CANCELLED 列 TERMINAL。任务日期及区域取原 content，不从 Placement 复制日期 |
| 动作 | 须 OPEN 且 pendingCount>0；MERGED 列 SOURCE_CHANGED，不跟随 mergedInto 偷换身份；无待处理来源列 NO_PENDING_WORK。日期／区域取已有 Placement，缺失则 NO_DATE；Placement.visibility=PAUSED 列 PAUSED |
| 真实开始 | 任务直接读 startedAt；动作复用 C2a 的 startedFacts 窄查询：当前仍 TRACKING 的来源，沿稳定 sourceId 连接任一复练绑定及 training_session.started_at。任一非空即 STARTED；仅创建 DRAFT 不算，暂停／结束不清除此事实。不能仅看 action.revision、updatedAt 或 pendingCount |
| 日期锁定 | 有 Placement 且 dateLocked=true 即 DATE_LOCKED；任务的锁定作用于其源日期。清空源日期后仍残留的锁定偏好不制造日期；可同时列 NO_DATE／DATE_LOCKED |
| 多面试 | 其他有效 PLANNED 面试非空即 MULTIPLE_EVENTS，不因其已过计划时间而忽略；用户到来源页明确处理，不提供“强制联动”字段 |
| 集合 | 始终 REFERENCE_ONLY，from／proposed／placement 为 null、started=false；来源归档或确切版本已被替代可另列 SOURCE_CHANGED，保持确切版本入口，不遍历步骤创建任务 |

reasons 按 MoveReason 声明顺序去重；无阻断理由时仅 `[MOVABLE]`，MOVABLE 不与其他理由共存。warnings 按枚举顺序去重。任务／动作只有 MOVABLE 时 proposed 非空；无日期的 from=null，已有日期则保留真实原日期。非 MOVABLE 的 selected 项仍在预览显示，proposed=null；其 override 不会生效，也不允许 apply 静默跳过它。来源意外缺失／跨 owner 或读取失败直接失败，不伪造 SOURCE_CHANGED 或“没有事项”。

日期增量为 `ChronoUnit.DAYS.between(from.startAt.atZone(sourceZone).toLocalDate(), to.startAt.atZone(sourceZone).toLocalDate())`，将该整数天数加到各事项原 plannedDate。旧面试的 from 使用持久化原 Instant，不用当前 tzdb 重新解释旧 localStart；新 to 严格复用 Schedule TimeInput 的 IANA／UTC、GAP 拒绝、OVERLAP 显式 offset、持续分钟和提醒规则。每项保留自己的 sourceZone；不是按事件 zoneId 一刀切，也不是按 Instant 差除24。显式 override 只替换可移动项的提议日期，不更改区域。

原日期、计算后的日期和各项区域转换结果均须处于1000–9999年范围，越界返回400 INVALID_REQUEST，不能截断。提议日期晚于新 startAt 在该事项区域中的当地日期时附 AFTER_INTERVIEW_DATE；同日事项无精确时段，不判断具体先后，不自动挪回前一天。limitations 按声明顺序固定输出四项。changes 只包含 MOVABLE 且最终日期与原日期不同的项，顺序沿 selectedLinkIds；同日无变化的选择仍保留检查记录，但不新增任务／Placement 空修订。

PLANNED 面试即使已过计划时间，仍沿现有语义允许改期；不能仅凭时钟推断已参加、已完成或实际开始。真实开始保护针对有业务开始记录的准备事项。联动不修改已完成任务历史、复练答案、卡片 due、已保存面后回忆所引用的旧面试修订，也不把题单引用当作已进行训练。

### C2b.4 摘要、原子采用与内部接口

previewHash 为小写64位 SHA-256；输入为 UTF-8 字面前缀 `interview-reschedule-plan-v1`、一个 LF，再接规范 JSON。对象属性固定按名称排序、null 显式，Instant 统一六位小数 UTC；selectedLinkIds／dateOverrides 保留已规定请求顺序，关系元数据和 otherInterviews 使用上节规定排序。不得用语言环境相关排序或浏览器自己重算的值替代服务端预览。

规范 JSON 的顶层字段固定为 `{eventId,request,event,from,to,remindAt,activeLinks,linkChecks,changes,limitations}`：event 为 EventReference；activeLinks 为上述完整集合，每项固定 `{link,eventRevision,eventStatus}`；其余为本附录同名响应／请求字段。它覆盖所有选中 Link 修订、未选中有效关联集合、其他关联事件状态／修订、完整来源 stamp、实际开始、完整偏好、最终日期、原因与警告。eventId 是路径身份，不能省略；不包含当前读取时钟、材料／回答／题单步骤正文。现有动作 progressHash 的格式保持；动作真实开始必须通过 linkChecks.started 独立进入新摘要。

新增关联、移除／恢复／换版、另一个关联面试的状态或修订、任务开始、动作来源／判断变化、动作首次真实开始、日期／锁定／暂停／Placement 修订变化都触发重算。摘要不是签名或读取权限，没有客户端自报“已检查”的作用。reason 不影响预览日期，放在 ApplyReschedulePlan 的幂等请求摘要中；新增 reason 为1–2000 Unicode码点，非空白、拒绝 NUL 和孤立代理，保留用户原字面值，不沿旧接口 strip 后的值冒充新接口原文。

采用流程固定：外层 `IdempotencyService.execute` 取得同 owner 锁并执行当前资料守卫 → 若原键回执存在按原机制恢复 → 否则以本次服务器时间重新读取完整关系集合和全部选中来源／偏好、重算预览 → 比较 expectedPreviewHash → 检查所有 selected 项均 MOVABLE → 调用内部领域命令 → 保存一个 AppliedReschedulePlan 回执。比较失败为409 RESCHEDULE_PLAN_CHANGED；当前请求本身存在不可移动选项且摘要仍相同时为409 PREPARATION_LINK_NOT_MOVABLE。任一 CAS、上限、权限、时间或历史／回执大小失败整体回滚，不能部分保存面试后再返回准备事项失败。

外层统一取得 UTC 微秒 now。三个内部命令均使用该值保存本次变化；若它早于任何拟写对象的 updatedAt，409 RESCHEDULE_CLOCK_CHANGED，全部不提交，不写倒退时间。原事件仍按既有 reschedule 语义保存一次 RESCHEDULED 修订，即使只改变提醒或时间实质未变；只有实际时间／提醒提前量改变才清 reminderAcknowledgedAt。任务／偏好只为真实改日写历史，Placement generation 在存在真实偏好变化时递增一次。任务改日不写另一份今日日期、不推进偏好 generation，客户端主动清相关来源游标。

AppliedReschedulePlan.changedTasks／changedPlacements 只含真实改日的对象，分别按 selectedLinkIds 中相应类型的相对顺序；linkChecks 为采用时写入前已通过的检查快照，不伪装成写入后的当前 stamp。空选择允许只改事件，返回两个空变化数组。回执丢失使用原请求和原键恢复；回执恢复后另读当前事件、关联、任务和偏好，不重写历史成功结果。

### C2b.5 持久化、兼容接线与服务器验收边界

沿 §9 新建 interview_preparation_link／interview_preparation_link_history；迁移编号由主会话分配。本附录的 Link revision 上限1000，历史 source_stamp 仅 REMOVED 可 null；历史须有 change_kind，并以 `(owner_id,event_id,event_revision)` 关联原 interview_event_history 的确切修订。当前 Link 唯一 `(owner_id,event_id,source_kind,source_id)`；反向查询索引 `(owner_id,source_kind,source_id,status,event_id,id)` 服务完整关系检查，目录索引 `(owner_id,event_id,status,id)`／`(owner_id,event_id,id)` 与实际查询对应，性能须服务器 EXPLAIN。source_version_id 仅 COLLECTION 非空，多态来源仍在 owner 事务中逐类型核对，不伪造通用外键。

任务 RESCHEDULE 通过新迁移扩展已有历史 CHECK；无需改变历史快照的 PreparationTask 结构。原面试历史保持 RESCHEDULED 和 InterviewEvent 结构，不把新 Link 塞入旧快照；新关联自身历史保存增删／恢复／换版。Placement 已预留 INTERVIEW_RESCHEDULED，但启用时必须同时扩展严格前端历史校验，不能仅增加显示标签。链接、预览及采用请求限256KiB，列表／历史／预览响应限1MiB，写回执继续限2MiB；任何超限整体拒绝，不截断字段或秘密分事务。

新增错误固定：404 PREPARATION_LINK_NOT_FOUND；409 PREPARATION_LINK_EXISTS（currentRevision 指已有 Link，可从目录查身份）、PREPARATION_LINK_REVISION_CONFLICT（当前 Link 修订）、PREPARATION_LINK_SOURCE_CHANGED（currentRevision=null）、PREPARATION_LINK_NOT_ACTIVE、PREPARATION_LINK_NOT_MOVABLE、PREPARATION_LINK_CURSOR_CHANGED、RESCHEDULE_PLAN_CHANGED、RESCHEDULE_CLOCK_CHANGED；422 PREPARATION_LINK_LIMIT。事件修订冲突、已关闭事件、无效时间等沿原领域错误；复合来源或预览冲突不把其中某个数字冒充 currentRevision。未知服务依赖／实际读取错误不能降为普通落选理由。
