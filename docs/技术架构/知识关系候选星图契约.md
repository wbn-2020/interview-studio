# 知识关系候选星图契约

版本：v1.3 · 2026-11-10。适用 S5 第二十三批及第二十六至二十八批直接、复盘和AI反馈来源候选接入；实际状态以[开发记录](../开发记录/开发阶段与进度.md)为准。承接 PRD KNOW-06／07、[星图交互规格](../交互设计/知识星图与工作台.md)及[关系候选与逐项采用契约](知识关系候选与逐项采用契约.md)。本契约 §8 保留第二十三批检查证据；静态检查与构建不表示接口或视觉验收通过。

## 1. 主动启用与产品边界

用户在知识星图主动开启候选层，从本人已成功的 RELATION_DRAFT 任务目录选择一个任务，查看其尚未决定的关系建议。一个候选层只绑定一个确切 taskId；不自动汇集全部历史任务、不默认选择最新任务、不为图形连通而生成新建议，也不把主题共属／词频共现当成关系。

当前图窗中两个概念端点都已存在的候选以虚线边叠加；有端点位于图窗外的候选保留在列表并计入范围外数量，不为显示它自动扩图、增加节点或切换视口。虚线与“待确认”文字共同区分候选和正式边，不能仅靠颜色。候选方向沿原类型：PRECEDES、PART_OF、APPLIED_IN 有向；RELATED、CONTRASTS 无向且端点已规范化。

本层提供只读发现和审阅入口。采用、补充到已有关系或忽略仍回原 AI 任务执行独立确认，沿用原修订、权限、来源当前性和幂等规则；点击虚线或列表不直接形成任何决定。未决定候选即使与正式关系同元组也保持候选身份，原 `/adopt` 重复冲突及[独立补充流程](正式关系补充理由与来源契约.md)不变。

第二十三批候选层本身不增加 AI purpose、模型调用、外发授权、费用、数据库迁移或依赖。[手工直接原文证据](正式关系直接原文证据契约.md)的保存不授权外发。第二十六批通过[独立来源候选入口](资料训练来源关系候选契约.md)接入知识加资料／训练的RELATION_DRAFT，第二十七批通过[复盘来源候选入口](人工反馈与面后回忆关系候选契约.md)接入知识加人工反馈／面后回忆，第二十八批通过[AI反馈候选入口](AI反馈生成关系候选契约.md)接入知识加成功评价的未审反馈；四种模式共用本目录、窄投影和画布。相应完整输入、V52／V43／V53及生成授权由专项契约规定。回忆手工关系证据、持续授权及其他余项保留，不据候选层关闭 KNOW-06／07 全量需求。

## 2. 两个只读入口

两个 GET 接口沿用会话、owner 隔离及独立训练资料守卫；不写任务、候选、决定、正式关系、布局或命令回执。原 POST `/api/v1/ai/relation-drafts/tasks` 仍创建任务，新增同路径 GET 只提供成功任务目录，不能混用其请求／响应。

| 方法与路径 | 输入 | 响应与边界 |
|---|---|---|
| `GET /api/v1/ai/relation-drafts/tasks` | 可选 cursor、limit；limit 默认 20，范围 1–20，cursor 为小写 UUID | `AiDtos.TaskPage={items,nextCursor}`；items 仅本 owner、purpose=RELATION_DRAFT、status=SUCCEEDED 的 Summary。 |
| `GET /api/v1/ai/tasks/{id}/relation-graph` | 用户选中的确切任务 UUID | `RelationGraphDtos.Projection`；核验后返回该任务的未决定候选及固定来源元数据。 |

目录查询只选择摘要列，不读取 manifest_json、candidate_json 或 attempt 行。Summary 沿用 `id,purpose,status,revision,title,provider,model,currency,attemptCount,createdAt,updatedAt,errorCode`；attemptCount 是任务摘要中的次数，不包含 attempts 明细。目录按 task UUID 字典序升序、`id > cursor` 排他翻页，不按创建时间排序；没有下一页则 nextCursor=null，不提供跨请求快照。

目录中可能包含零候选、全部已决定或来源后来变化的成功任务。目录只说明任务满足选择条件，不证明其完整持久内容已读过，也不保证有可显示虚线；用户显式选中后才读取并核验投影。不存在或非本人任务沿原 404；非成功 RELATION_DRAFT 任务返回既有状态冲突，不能当作合法空投影。非法 UUID、cursor 或 limit 按参数错误拒绝。

[OpenAPI 规格](openapi-s7.json) v7.17.0 在第二十三批新增 `aiListRelationGraphTasks`、`aiGetRelationGraph` 两个 GET operation；目录复用 AiTaskPage／AiSummary，投影新增 RelationGraphEdge、RelationGraphProjection 两个具名 schema。新增一个路径，已有 relation-drafts/tasks 路径增加 GET；不能把“两个接口”误写为两个新增路径。该批规格为 292 paths、344 operations、963 schemas；后续累计版本见开发记录，结构说明不替代运行验收。

## 3. 窄投影与来源说明

[投影 DTO](../../backend/src/main/java/com/wenjie/studio/ai/RelationGraphDtos.java)独立于完整 Task：

| 对象 | 字段 |
|---|---|
| Projection | `task,sourcesCurrent,sources,summary,limitations,validationNote,totalCandidates,decidedCount,relations`。task 是上述 Summary。 |
| Edge | `id,sourceItemId,targetItemId,type,reason,citationCount`。id 为原 r1–r10；citationCount 为知识、材料、训练及复盘四类引用数组数量之和，AI反馈复用reviewCitations并按Snapshot专用校验；各模式只计其允许的数组，旧模式只有知识引用。 |
| OriginSource | `itemId,versionId,number,title,state,kind`；kind 为 NOTE／CONCEPT，保留原来源顺序与当时元数据。 |

`totalCandidates` 为完整原候选数量，范围 0–10；`decidedCount` 为已存在终态决定的候选数量；`relations` 仅未决定项，满足 `totalCandidates = decidedCount + relations.length`。过滤后保留原 rN 及原顺序，可以出现编号空缺，不能把 r3 重新编号为 r1。每条候选 citationCount 为 1–6，规范化端点＋类型不重复。

响应不返回 Manifest、完整 Source.body、Citation.quote／坐标、attempt 明细或原始 candidate_json，也不借只读 GET 加入外发清单。服务端为校验会读取原 Manifest 正文与完整候选；这是内部完整性核验，不等于将原文返回星图。用户需回原 AI 任务查看完整引用并另行确认操作。

来源标题、对象／版本 ID、版本号及 kind 来自原固定 Manifest，并与 `ai_relation_source` 台账逐项核对，不能用知识当前草稿标题、较新发布版本或图窗标签代替。state 由当前来源状态给出：

| state | 含义 |
|---|---|
| CURRENT | 原确切版本仍是 ACTIVE 知识的当前发布版本。 |
| SUPERSEDED | 知识仍 ACTIVE，但已有其他当前发布版本。 |
| ARCHIVED | 原来源知识当前归档。 |
| UNAVAILABLE | 按现有来源读取规则无法核对该来源身份／版本状态。 |

`sourcesCurrent` 核对全部知识来源的当前性及确切内容；第二十六至二十八批还须核各自完整直接、复盘或AI反馈输入，不能仅凭知识state推断。复盘及AI反馈模式先核固定绑定与当前访问，再求当前性；知识先失效不旁路权限。它为 true 时全部知识来源 state 必须为 CURRENT；反向不成立，即使全部 state 为 CURRENT，也不能仅据此推断完整来源核对通过。它为 false 时，合法历史投影仍可查看；显示变化提示并回原任务核对，不能自动采用或换成最新来源。来源状态、hash 匹配、引用逐字命中或可见虚线均不构成技术认证，也不证明原文充分支持关系。

validationNote 必须按任务模式匹配固定说明，不能由客户端或持久 JSON 自行替换。旧纯知识模式为：

> AI 未审关系候选，结构、所选概念端点与引用原文区间已核对；不证明关系语义正确或原文充分支持。候选需逐项审阅，不会自动进入正式星图。

这里“不会自动进入正式星图”指不会自动成为正式关系；本批主动开启的虚线展示仍为待确认候选，不改变原说明的语义。

第二十六批新模式使用[资料／训练来源候选契约](资料训练来源关系候选契约.md)中独立的固定说明，持久读取核三类引用及V52绑定，再返回同一窄投影；投影不带新输入正文。新模式文本沿其Unicode空白规则，旧模式仍沿历史规则，不能通过替换说明把一种模式解释成另一种。

第二十七批使用复盘专项固定说明，核全部知识来源、V43与完整候选，reviewCitations计入总数；投影仍不含 reviewDraft、quote、原答或复盘原文。新 summary／reason／limitations 与知识引文沿严格Unicode空白规则，复盘选区引文沿 Java isBlank；客户端只验证投影已有文字，不借窄投影重构正文。来源失效时回原任务核对，不能以可见虚线跳过重新授权或用户决定。

第二十八批使用AI反馈专项固定说明，核全部知识台账、V53及完整Snapshot绑定，再以专用校验器检查reviewCitations；原报告保持AI_UNREVIEWED。投影不含relationAiFeedback、成功报告正文、原报告引文或选区quote，计数仍使用原四类数组。来源决定变化可使sourcesCurrent=false，报告／尝试／历史决定损坏必须报错；前台固定答案访问须先独立核验，不能用UNAVAILABLE状态放行。

## 4. 持久完整性先于投影

[AI 服务](../../backend/src/main/java/com/wenjie/studio/ai/AiService.java)在只读、REPEATABLE_READ 事务中完成以下核对，全部通过后才投影未决定项：

1. 确认任务属于当前 owner／taskId、purpose=RELATION_DRAFT、status=SUCCEEDED；固定清单须符合原 RELATION_DRAFT 输入，配置存在，重新计算的兼容 Manifest hash 与 task.manifestHash 一致。
2. 核对任务 Summary 的身份、状态、修订及必要元数据；任务 title 对应第一项固定来源标题，provider／model／currency 与 Manifest.configuration 一致。
3. 核对全部 `ai_relation_source` 与原清单的数量、连续 ordinal、taskId、itemId、versionId、版本号、标题、kind；只从这一固定关系输出来源元数据。
4. 使用[ModelGateway 统一持久候选读取器](../../backend/src/main/java/com/wenjie/studio/ai/ModelGateway.java)核验完整原候选，包括已采用或忽略的项。
5. 读取全部逐项决定，拒绝重复 candidateId 或重复 supplementId；复用原决定校验，包括任务／候选归属、ADOPTED 最终内容、IGNORED 空字段及补充台账绑定。
6. 用已核对的决定集合过滤原候选，再返回计数与窄 Edge。决定过滤不得先发生，以免隐藏已决定项中的坏存储。

统一读取器严格解析保存 JSON，拒绝重复键、尾随 JSON、未知／缺失字段和错误类型；顶层字段固定为 summary、limitations、relations、validationNote。以下逐项字段与引用规则适用于旧纯知识分支，三个新模式按§3及专项契约分别核对直接引用数组或相应reviewCitations。旧模式每项固定含 id、端点、类型、reason、citations，新尾数组只兼容缺省／null。四种模式均须顺序编号 r1–rN，N 为 0–10；对称端点须已归一，不能读取时重排修补身份。

旧分支读取器复用原关系结果解析规则：summary 最多 1000、limitations 最多 2000、reason 最多 1000 个 UTF-16 码元，沿既有 Java `isBlank`，拒绝 NUL／孤立代理；端点须是固定清单中两个不同 CONCEPT，类型限五种，规范化元组去重。旧模式每项 1–6 条知识引用，属于确切 itemId＋versionId，start／end 为整数且在原 Source.body 的 UTF-16 半开区间内，不切断代理对，quote 与原区间逐字一致、引用位置不重复；引用文本继续沿既有网关的长度／Unicode 规则，不从窄投影另造限制。

AiService 原有 relationCandidate 读取路径也委托该统一读取器；历史任务详情、决定和星图投影使用同一完整候选校验。解析、固定说明、hash、来源绑定、候选或决定损坏均抛出完整性错误，不能降级为“没有候选”或 sourcesCurrent=false。合法来源改版／归档与持久结构损坏分别处理。

## 5. 前端接口与画布隔离

[前端边界校验](../../frontend/src/api/relationGraph.ts)使用生成类型并对实际返回值作严格检查：目录的摘要类型、UUID 顺序／游标；投影的精确字段、taskId、来源 2–5 项及身份唯一性、至少两个 CONCEPT、第一来源标题、计数等式、固定 validationNote；每条 Edge 的原 rN 顺序、规范化端点、理由和 citationCount。sourcesCurrent=true 却含非 CURRENT 来源时拒绝，sourcesCurrent=false 且全部 CURRENT 不因此判错。来源标题及旧候选保持 Java `isBlank`／UTF-16 兼容，新模式候选按其固定说明使用Unicode空白规则，不能重判合法历史。

[候选面板](../../frontend/src/components/RelationGraphCandidates.vue)位于知识星图，初始收起；用户点击“读取候选任务”才请求成功任务目录，之后显式选择一条“查看候选”。目录支持上一页／下一页、刷新当前页、回第一页及失败原页重试；只有读取成功才推进翻页历史。任何目录刷新或翻页都会清除已选任务和旧投影，避免把旧候选留在新目录下。

选择任务后清除旧投影，再请求该 taskId；除完整边界校验外，面板要求投影 revision 不低于所选摘要，createdAt 与原任务一致。面板分别展示原始候选、已决定、待审、当前图内及范围外五个数量；显示模型原摘要、限制及固定说明，区分“成功返回零条”和“全部已有决定”。每条未决定项保留原 rN、类型／方向及固定版本标题；点击列表或图中虚线可查看原理由、引用数量和回原任务入口，范围外项不产生画布高亮但仍可阅读理由。来源列表保持原顺序，UNAVAILABLE 只显示文字，其余可进入确切知识版本。

“刷新本任务候选”先撤下旧投影再读取，不把加载失败显示成合法零候选。关闭候选面板重置目录、任务、投影、游标和选中；当前图窗节点集合变化清除旧选中，并重新计算图内／范围外数量。列表按钮提供展开、选中、载入和错误状态，作为画布的键盘入口；窄屏样式与实际焦点行为仍须服务器验收。回任务链接只携带原 taskId，提示用户审阅对应 rN，不在星图执行决定命令。

当前[星图组件](../../frontend/src/components/KnowledgeGraph.vue)以独立 candidateEdges 保存窄身份，图中 ID 使用 `candidate:{taskId}:{candidateId}`，与正式关系 UUID 分离；只接收单一任务、最多 10 条有效候选。两端都属于当前 displayed.nodes 的候选才加入 Cytoscape，类名 candidate-edge，显示虚线和“待确认 · rN · 类型”。点击候选边只选择该 taskId／candidateId；列表选择和画布高亮通过同一身份联动。

候选更新仅移除／添加候选边，不重建节点，不设置坐标、运行自动布局或修改 viewport。正式 displayed.edges、connectedEdges、路径请求／结果及关系计数保持正式数据来源；适应画布范围时排除候选边。候选开关、选中和刷新不写 positions、layoutRevision 或视口变更集合。正式边与同元组候选可同时存在，候选不冒充正式边、不参与正式路径高亮。

会话或资料访问条件变化、组件停用时立即清除画布候选，并重置面板目录／投影；恢复后需要再次主动开启和选择任务，不直接复活旧投影。请求以会话、访问代次、独立目录／投影序号及所选 taskId 限定，过期返回不写入面板。父画布只接受当前实际可见候选的选择身份，候选被移除时同步清除选中，避免旧高亮残留。

## 6. 历史与权限边界

两个 GET 均受原 AI／知识资料出口的动态训练守卫约束；跨 owner、未登录或尚未确认辅助访问时不能通过窄投影旁路。GET 返回前沿既有读取响应守卫再核对当前访问条件。前端必须按会话代次、访问代次、taskId 和请求序号丢弃迟到结果，不能将先前任务或先前会话的候选显示到新图窗。

候选投影不要求来源仍当前，因此仍可在受许可访问下查看旧任务；它不解除原新建采用／补充的来源当前性要求，忽略仍沿原决定规则。AI 当前关闭不妨碍只读历史。后续任务修订／决定更新后，重新读取投影应排除已决定项；正式边删除或重建不撤销既有候选决定，也不把已决定项变回未决定候选。

本批无迁移，不补写旧 Manifest、候选、来源台账或命令回执；完整性错误须定位其原证据，不以重新编号、填默认说明、修补标题或静默略过引用来让历史读取成功。
