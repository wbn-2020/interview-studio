# 复盘与面后片段沉淀知识契约

日期／版本：2026-11-10 · v1.2。状态：**静态检查通过待服务器验收。**适用：S5 第十六批及第二十七／二十八批共享来源兼容边界，从 S6 自检、外部反馈或面后回忆的明确片段生成待审知识候选，补齐 REV-06 的相关来源。知识整理沿用 `KNOWLEDGE_DRAFT`，不增加 AI purpose。本文规定该用途实施边界，编译通过不代表功能验收通过；完成项、构建证据和剩余事项以[开发阶段与进度](../开发记录/开发阶段与进度.md)为准。

共享 DTO 以 [ReviewDraftDtos.java](../../backend/src/main/java/com/wenjie/studio/ai/ReviewDraftDtos.java) 为字段基线。相关契约：[训练片段沉淀](训练片段沉淀知识契约.md)、[自检反馈](自检反馈与改进动作契约.md)、[面后回忆](面后回忆记录与题目来源契约.md)、[候选采用](AI候选采用与来源契约.md)、[AI 任务与外发](AI任务与外发契约.md)。

第二十七批[人工反馈／面后回忆关系候选](人工反馈与面后回忆关系候选契约.md)复用本 Input、选区规则、来源适配器和 V43，但属于独立 RELATION_DRAFT 模式，必须另选知识概念端点并单独授权。本文知识整理的 sources=[]、旧 prompt、模型解析及采用路径保持；不能只凭 reviewDraft 非空进入知识采用。后文20字段为第十六批基线，第二十七批未扩字段；第二十八批[AI反馈生成关系候选](AI反馈生成关系候选契约.md)另增第24尾relationAiFeedback，本知识整理必须缺省／null，新空尾从hash投影省略，不改原固定内容。来源原文、片段、review 引文沿 Java isBlank，前端保持同口径，不用 JS trim 重判合法历史；新关系 summary／reason／limitations 的更严规则另见专项契约。本文原静态检查记录保留原适用批次。

## 1. 来源身份与选择

一次任务只选一种来源：一条人工反馈的当前修订，或一条 ACTIVE 面后回忆的当前内容版本及对象修订。来源类型为 `SELF_CHECK/EXTERNAL_FEEDBACK/RECOLLECTION`；人工反馈类型必须与所指不可变修订的 `FeedbackContent.kind` 一致。三类身份贯穿预览、固定清单、任务详情、引用和采用历史。

人工反馈是用户保存的自检或转录意见；回忆是用户面后记录。接受反馈不是技术认证，回忆不是训练 Answer、录音转写或面试实录。生成结果为待审候选，逐字引文校验只证明出处；采用知识不代表经历真实、外部作者已确认或用户能力已经提高。

每次明确选择 **1–8 个片段**，不跨反馈或回忆混选，不默认勾选。片段统一为 `{field,start,end,quote}`：

- `start/end` 为所指原字段的绝对 UTF-16 半开区间，必须满足 `0 ≤ start < end`，且 `quote.length=end-start`。
- `quote` 非空白，每段最多 8000 UTF-16 码元；逐字匹配原字段，不 trim、正规化、折叠大小写或静默改写。
- 拒绝 NUL、孤立代理及拆开代理对的区间边界；同字段区间不可重复或重叠，允许相邻区间。保留客户端片段顺序，使预览、同意和幂等摘要对应同一选择。

| 来源 | 可选 field | 必要背景与固定元数据 |
|---|---|---|
| SELF_CHECK／EXTERNAL_FEEDBACK | OBSERVATION、CONDITION、BASIS、LIMITATION、SUGGESTION | 完整 condition、basis、limitation；dimension、coverage；该修订最新决定的 decisionRevision／decisionChoice；确切反馈修订、AnswerLink、answerNumber、提交时 answerCondition |
| RECOLLECTION | QUESTION、CONDITIONS、ANSWER_FRAGMENT、FEEDBACK、UNCERTAINTY、GAP | 完整 uncertainty；title、type、baselineKind；确切回忆身份、versionId／versionNumber、sourceRevision |

必要背景是此次授权的明确外发内容，预览须完整展示；它不占 1–8 个选区名额。即使选中了其中部分文字，固定输入仍保留完整必要背景。用户不接受外发这些背景时可放弃生成。模型引用仍必须落在实际选区内，不能因完整背景已发送而引用选区以外的文字。

人工反馈不发送 `authorLabel`、决定原因、原 `citations`、完整原答、题面、个人参考或相邻反馈。没有决定时 `decisionRevision=0,decisionChoice=null`；有决定时为该反馈修订的最新决定，修订范围 1–20，choice 为 `ACCEPTED/DISPUTED/IGNORED`。本入口不要求先 ACCEPTED。决定变化使本批旧固定输入失效，详见 §6。

回忆 `baselineKind=NONE` 禁止选择或引用 ANSWER_FRAGMENT，包括伪造的空占位。完整 uncertainty 作为必要背景发送，选区本身无需包含 UNCERTAINTY。回忆关联的 interview／安排快照、公司、时间、目标及其他未选内容不外发；不由这些资料补造旧答。

## 2. 接口及严格请求

打开来源和表单不调用模型。新入口沿用原 AI 任务、费用、状态通知与采用流程：

| 操作 | 路径 | 请求／结果 |
|---|---|---|
| 外发预览 | POST `/api/v1/ai/review-drafts/preview` | `PreviewRequest` → 200 既有 Preview |
| 创建任务 | POST `/api/v1/ai/review-drafts/tasks` | `CreateRequest` → 201 既有 Task；沿用 Idempotency-Key／CSRF |
| 采用／忽略、取消／重试、费用核对、状态通知 | 既有 AI 任务接口 | 沿用原请求与状态机 |
| 采用历史 | 既有 `/knowledge/{itemId}/versions/{versionId}/origins` | Origin 的可空 reviewSource 分支 |

`instruction` 必须显式提供，保留原文，0–1000 UTF-16 码元，禁止 NUL 和孤立代理。新请求拒绝未知、缺失、重复字段，拒绝数字枚举、字符串／浮点修订以及宽松类型转换。可空分支也须显式提供。UUID 使用标准小写格式，不接受客户端替代来源快照。

| DTO | 精确字段及约束 |
|---|---|
| SourceSelection | `kind,feedback,recollection`；SELF_CHECK／EXTERNAL_FEEDBACK 仅 feedback 非空，RECOLLECTION 仅 recollection 非空 |
| FeedbackSelection | `feedbackId,feedbackRevision,fragments`；feedbackRevision 为 1–100，必须等于当前反馈 head |
| RecollectionSelection | `recollectionId,versionId,expectedRevision,fragments`；expectedRevision 为 0–1000，必须等于当前对象修订；versionId 必须等于当前版本 |
| PreviewRequest | `instruction,source` |
| CreateRequest | `instruction,source,expectedManifestHash,consentConfirmed`；创建必须 consentConfirmed=true，且重新读取所得清单摘要相同 |

人工反馈须属于 owner，并核对反馈、不可变修订与确切训练提交的关联。回忆须属于 owner、ACTIVE，核对 currentVersionId、对象修订、版本归属及版本号。历史来源可作为历史出处读取，新预览、执行和采用要求当前性，不自动换成最新来源或新选区。

来源、片段、instruction、固定决定或配置变化都使旧预览及同意失效。创建时发现清单变化应保留表单并重新预览，不能自动接受新清单。

## 3. 固定 Input、Manifest 与互斥

`ReviewDraftDtos.Input` 为 `{kind,feedback,recollection}`，与选择类型一致且只有一个内容分支非空。服务器只从确切来源生成以下完整结构：

| DTO | 字段顺序 |
|---|---|
| FeedbackInput | `feedbackId,feedbackRevision,answer,answerNumber,answerCondition,dimension,coverage,decisionRevision,decisionChoice,condition,basis,limitation,fragments` |
| RecollectionInput | `recollectionId,versionId,versionNumber,sourceRevision,title,type,baselineKind,uncertainty,fragments` |
| Fragment | `field,start,end,quote` |
| Citation | `field,start,end,quote` |

`answer` 为既有 `AnswerLink(sessionId,questionId,answerId)`；answerNumber／answerCondition 来自该不可变提交，不取最新答案或当前辅助条件。sourceRevision 固定预览时回忆对象修订，不冒充内容版本号。dimension／coverage 保留原人工记录；decisionRevision／decisionChoice 表示当时用户决定，不提升为正确性认证。

[Manifest](../../backend/src/main/java/com/wenjie/studio/ai/AiDtos.java) 在现有 19 字段末尾追加第 **20** 项 `reviewDraft: Input|null`：

| 序号 | 字段 |
|---|---|
| 1–7 | purpose、instruction、sources、configuration、inputTokenAllowance、reservedMicros、promptVersion |
| 8–13 | training、evaluation、contextChecks、materialQa、preparationChecks、materialDraftSources |
| 14–19 | expressionType、preparationPlan、trainingDraft、expressionChecks、comparisonInput、comparisonChecks |
| 20 | reviewDraft |

本分支 purpose=KNOWLEDGE_DRAFT、sources=[]、reviewDraft 非空，第 8–19 项全部 null，promptVersion=`review-knowledge-draft-1`。其他知识候选来源必须 reviewDraft=null；其他用途只允许第二十七批明确规定的 RELATION_DRAFT 专用模式使用该字段。本分支和训练、评价、资料、准备、表达、原知识关系、比较等旧分支不能混装；服务端来源校验、网关、结果解析、任务读取、前端接纳与 OpenAPI 均按用途和固定模式检查。

Section 尾部追加可空 `reviewCitations`，Origin 尾部追加可空 `reviewSource`。本批响应中 Section 的普通 citations=[]、materialCitations=null、trainingCitations=null；其他来源的 reviewCitations=null。不得将反馈／回忆身份塞入知识版本引用或旧 trainingCitations。

## 4. 唯一实际外发投影及摘要兼容

两种已支持协议共用唯一业务投影：

`{purpose:"KNOWLEDGE_DRAFT",instruction,reviewDraft:Input}`

**整个 Input 原样外发**，包括 sourceRevision、decisionRevision、decisionChoice、固定身份和必要背景；空分支显式 null。清单中的 configuration、checks、预算值不作为资料正文发送。预览展示、32 KiB 输入限制、输入 allowance／费用预留与网关发送共用此投影定义，不能各自删除字段或缩减元数据。

超过 32 KiB 或当前配置更严格的输入上限时原样拒绝，请用户缩小选区；不截断、摘要改写、缩短必要背景或遗漏授权元数据后继续发送。沿用现有费用估算与协议余量，不引入新 tokenizer、SDK、工具调用、搜索或长期模型上下文。

兼容要求如下：

1. **旧请求不变。**旧请求 DTO、字段顺序、数组顺序、路径操作字符串及幂等序列化保持不变；本批使用独立 PreviewRequest／CreateRequest。不能给旧 CreateTask、CreateTrainingDraft 或 AdoptCandidate 增加 reviewDraft 字段。相同旧请求和原键仍恢复旧回执，异正文同键仍拒绝。
2. **旧实时清单摘要不变。**`AiSources.hash` 仅在 reviewDraft==null 时，从当前序列化对象移除新增的 `reviewDraft` 一项，再按现有规范 JSON 求 SHA-256；其余 19 字段全部保留，包括所有既有 null 字段及 comparisonInput／comparisonChecks。不能删除任意 null、退回 17 字段或尝试多个宽松摘要。其他资料和配置均未变时，升级前的当前 19 字段预览仍与创建一致。
3. **新分支完整摘要。**reviewDraft 非空时对包含全部 20 字段的当前清单求摘要；Input 中任何选区、背景、决定、版本或对象修订变化都会改变授权内容。
4. **历史不可变。**旧 Manifest 缺少 reviewDraft 按 null 读取；更早历史的既有缺省处理沿用。旧 Section／Origin 缺少新可空分支仍可读。已经保存的 manifest_json／manifest_hash、候选、采用历史和幂等回执不重算、不重写；不把补出 null 的对象重新存回历史。
5. **旧训练入口语义不变。**TrainingDraft 的 AI 评价反馈决定和原因仍不参与其固定正文授权，决定变化不使该旧来源失效。本批人工反馈固定最新决定是独立来源规则，不能反向改变旧 TrainingDraft。

## 5. 模型结果与逐字引用

复用 `Candidate(title,sections,validationNote)`。本分支模型输出严格为：

`{title,sections:[{heading,body,reviewCitations:[{field,start,end,quote}]}]}`

只接受上述字段。title／heading 各 1–200 Unicode 码点，1–12 节；每节 body 1–3000 码点，总 body 最多 24000 码点。每节必须有 1–10 条有效且不重复的引用，quote 非空白、最多 1000 UTF-16 码元；其余限制沿[训练片段契约](训练片段沉淀知识契约.md)。

引用 field 使用同一 Field 枚举，必须属于固定来源的允许集合。start/end 为原字段绝对 UTF-16 区间，必须完全落在一个实际选中片段内；以 `fragment.quote` 和偏移差逐字校验。拒绝跨选区拼接、未选背景、错误分支字段、重复 `(field,start,end)`、越界、NUL、孤立代理及拆开代理对的边界。

本批没有 citationIndex、elementId 或原反馈引文链。完整 condition／basis／limitation／uncertainty 虽作为必要背景发送，只有显式选中的区间可成为结果引用。NONE 的 ANSWER_FRAGMENT 在网关输入、结果解析和前端展示接纳中均拒绝。author、reason、ID、标题、分类、版本号和决定元数据不作为可引用正文。

validationNote 由服务器回填，说明只完成结构和出处检查，候选仍需人工核对。来源内容和整理指令均按资料处理，不作为执行命令。

## 6. 当前性、任务阶段与历史状态

创建、领取、发送前、结果接纳、恢复／重试和采用均执行 **task-aware** 核对：同时检查任务身份、Manifest 分支、V43 绑定、owner、确切来源及当前性。仅凭 Input 内容合法不能替代绑定核验；本批任务必须恰有其绑定，普通任务不得带孤立的本批绑定。

| 变化 | 对本批待执行／未采用候选的影响 |
|---|---|
| 人工反馈 head 增加，文字后来改回也一样 | 所选 feedbackRevision 已非当前；旧授权失效，历史保留原修订 |
| 同一反馈修订最新决定增加，包括改回原 choice 或仅理由变化形成新决定 | decisionRevision 不同即失效；固定 choice 同时核对。不修改原候选、原决定或已采用知识 |
| 人工反馈尚无决定、DISPUTED 或 IGNORED | 可以明确选区并预览；不要求先 ACCEPTED，仍固定当前决定状态 |
| 原训练新增答案、暂停／恢复／结束 | 不替换确切 AnswerLink、answerNumber／answerCondition；不靠最新答案或 session.generation 否定不可变提交，当前访问与反馈时机另行检查 |
| 回忆产生新内容版本或对象 head 变化 | versionId、versionNumber 或 sourceRevision 与固定输入不符即失效，不自动换版本 |
| 回忆归档后恢复相同版本 | 归档期间失效；恢复后的 sourceRevision 已增加，旧授权仍失效，需重新预览 |
| 关联面试安排改期、取消或目标变化 | 不自动展开安排，回忆自身未变时不据当前安排推断片段失效 |
| 回忆被整理成题目、建立动作或用于复练 | 不改写本批固定来源，也不据此提升来源可信度 |
| 取消或忽略候选 | 沿用既有状态／费用规则；不改反馈决定，不撤回源记录，不删除历史，不承诺收回已外发资料 |

本批来源历史复用 OriginState，先核验关系及确切历史，再按以下优先级计算：

| 来源 | 状态优先级 |
|---|---|
| 人工反馈 | 确切来源正常不可访问 → UNAVAILABLE；反馈 head 不同 → SUPERSEDED；同修订的最新 decisionRevision／choice 不同 → REVIEW_REQUIRED；完全一致 → CURRENT |
| 回忆 | 确切来源正常不可访问 → UNAVAILABLE；当前 ARCHIVED → ARCHIVED；当前版本不同 → SUPERSEDED；同版本但 sourceRevision 不同 → REVIEW_REQUIRED；完全一致 → CURRENT |

数据库故障、反序列化失败或任务／绑定／Manifest 矛盾是错误，不能伪装成 UNAVAILABLE、sourcesCurrent=false 或空来源。只将有明确错误码的正常来源失效转为不可用。资料守卫与确切反馈访问失败仍按权限规则处理，来源状态不能代替授权。

成功候选在来源变化后仍保留历史内容并提示复核，禁止直接采用。已经采用的知识版本、原候选、固定清单和来源绑定不倒改；后续人工改写的知识不宣称每句话仍由这些引文支持。

## 7. V43 绑定与采用出处

V43 只增加一个本批来源绑定表，按 `(owner,task)` 唯一约束关联 AI 任务。分支字段记录反馈种类、确切反馈修订和原 AnswerLink，或确切回忆／内容版本及 sourceRevision；采用 owner 复合外键和分支互斥 CHECK。固定片段、必要背景及决定快照保存在不可变 Manifest；关系行和 Manifest 的身份、类型及版本必须相符，不用单个反馈或版本 ID 替代完整关联。

任务、首次尝试、费用预留、来源绑定、修订／通知及命令回执在原 owner 锁事务中一致保存；中途失败整体回滚。不修改已有业务表或重写旧任务。多个明确任务可以选择相同来源，沿原容量和预算限制；一次采用继续由任务终态决定的唯一约束保证。

`Origin.reviewSource` 的精确结构：

| DTO | 字段 |
|---|---|
| Origin | `kind,feedback,recollection,state`；仅对应内容分支非空 |
| FeedbackOrigin | `feedbackId,feedbackRevision,answer,answerNumber,decisionRevision,decisionChoice` |
| RecollectionOrigin | `recollectionId,versionId,versionNumber,sourceRevision,title,baselineKind` |

来源目录展示固定身份、当时回忆标题和当前状态，不展开正文；导航明确指向原反馈 revision 或原回忆 versionId，不默默跳到当前版本。保留原 Origin 的 direct、目标版本及更早采用分页语义。旧来源 reviewSource=null。

采用复用现有 NOTE／CONCEPT 新建或追加版本流程：编辑最终标题／正文后显式确认；已有目标须通过当前版本与草稿修订双基线、ACTIVE 和无未发布草稿检查。来源核验、知识版本／索引 outbox、一次终态决定、通知和回执同事务完成；换键不能重复采用。忽略不要求来源当前；关闭 AI 后仍可采用本地有效候选。采用不改反馈决定、原答、回忆、项目事实、关系或复习排程。

## 8. 权限、错误和界面恢复

新路径在 `/ai`，沿现有独立训练资料守卫，包括另一场进行中的独立训练。人工反馈另须核对确切 AnswerLink 的评价区访问，以及该会话实际反馈时机、提前反馈许可和访问记录；不能仅凭曾经存在访问行放行，也不能后台调用 grantAccess。预览、任务正文、采用来源历史、写响应和原键回执恢复前均覆盖相应访问守卫。

来源服务直接依赖 review 包 Mapper、TrainingMapper／TrainingEvaluations 及必要只读规则，不通过 ReviewService 或 AiService。已有 ReviewService 依赖 AiService，新增读取不得形成 `AiSources → ReviewService → AiService` 循环。

读取在同一可重复读快照中核对关系和历史；写命令沿 owner 锁，并在读取幂等回执前执行确切来源的访问守卫。恢复原回执不重新创建任务或外发，也不把来源已经更新误当成访问授权。

前端明确展示固定元数据、选区、必要背景、决定状态、供应商／模型、费用与实际投影；修改输入清空旧预览和同意。保留表单、未决原请求和原键，轮询或迟到响应不能覆盖新选区／编辑稿。会话切换、权限遮挡、请求代次及页面离开守卫沿用原流程；缺少模型配置时仍能保留手工整理路径。

字段／类型／片段错误沿 400 INVALID_REQUEST；不存在或跨 owner 来源沿 404 来源错误；当前性变化沿 409 AI_SOURCE_CHANGED，预览摘要不同沿 409 AI_MANIFEST_CHANGED；容量和模型引用错误沿既有 AI_LIMIT／AI_OUTPUT_LIMIT／AI_CITATION_INVALID。最终错误码以累计 OpenAPI 和实现一致核对，不能吞掉数据库或完整性故障。
