# AI 任务状态推送与恢复契约

日期／版本：2026-11-06 · v1.0。适用 S5 第六批。状态：静态检查与前后端构建通过，待服务器验收。关联 [AI 任务契约](AI任务与外发契约.md)、[评价契约](训练评价与证据报告契约.md)及 [PRD](../需求文档/产品需求文档.md) AI-03／04／06、AC-43／44／45。进度仅维护在[开发记录](../开发记录/开发阶段与进度.md)。

## 1. 同步范围

- 浏览器通过一个同源 SSE 连接接收“任务记录已变化”的通知，再从既有 GET 接口读取任务列表、详情、费用和训练覆盖摘要。结果正文只在原接口的权限与引用校验后提供；通知不携带题目、答案、标题、反馈、费用金额、模型文本或 owner 标识。
- 创建、尝试状态、取消、重试、费用补记／核对、候选采用／忽略、评价决定在原业务事务内更新通知游标。事务回滚不发布变化；幂等回放不额外更新游标。通知合并短时间内多次变化，不能当作业务事件历史。
- 本批实现已持久化任务状态的同步。供应商请求仍使用既有非流式协议；模型暂态正文的接收与展示另有后续范围，不把状态通知显示为逐字生成或完成百分比。

## 2. 游标与接口

`ai_event_cursor` 每个 owner 一行：owner_id、cursor_id。cursor_id 是不透明 UUID，只用于判断变化，不是单调序号、任务 ID、授权或模型结果；无记录返回全零 UUID。游标与对应业务变更同事务保存。

`GET /api/v1/ai/events`，已登录，同源 cookie；不在 URL 中携带身份凭据，不创建任务、不触发模型、不记费用。可带 `after` 查询参数或 `Last-Event-ID` 请求头，均须为标准小写 UUID。它们只是客户端上次观察位置；服务端始终发送当前快照，不重放中间状态。

| 事件 | SSE id／data | 客户端行为 |
|---|---|---|
| snapshot | 当前 cursor；`{"cursor":"…"}` | 每次连接先同步当前已持久化状态，即使游标相同或来自恢复后的数据库 |
| changed | 新 cursor；`{"cursor":"…"}` | 合并刷新当前可读的任务／费用／训练查询，不写入编辑草稿 |
| heartbeat | 无 id；`{}` | 更新连接存活时间，不代表业务进度 |
| reconnect | 无 id；`{}` | 连接轮换，随后重连并重新同步 |

响应为 `text/event-stream`、`Cache-Control: no-store, no-transform`、`X-Accel-Buffering: no`。建立前错误沿用 problem JSON：401 未登录、400 游标错误、429 `AI_STREAM_LIMIT`、503 存储暂不可用。连接建立后故障结束该连接，客户端从现状恢复，不能拼接 JSON 错误正文冒充结果。

## 3. 权限、资源与恢复

- 通知仅含游标，允许当前独立训练接收；通用 AI 内容与其他场训练的既有资料守卫继续执行。后续若在事件中增加任何业务字段，须重新审查权限规则，不能沿用本例外。
- 服务端每轮读取前核对创建连接时的 HTTP session、会话 ID 和认证主体；失效或变化结束连接。每条连接最多约 90 秒后轮换，约每 2 秒读取单行游标，空闲每 10 秒心跳。发送不持有 owner 写锁或数据库事务。
- 单实例最多 4 个连接，使用 Java 21 虚拟线程且先限制连接数；慢连接占用自己的额度，使用与模型调度器分开的执行器。握手失败释放额度；建立后由工作线程退出时统一释放，完成／超时／错误回调只标记关闭。95 秒 emitter 超时不等于任意网络条件下强制终止阻塞写入，容器慢读与断开释放须服务器验证；超额浏览器继续查询恢复。
- 每个可见标签在 AI／训练页面最多 1 条连接；隐藏、离开页面或登录代次改变时关闭。旧连接的事件与异步会话检查不能更新新登录状态。
- 出错后按 2／4／8／16／30 秒上限退避重连，正常轮换等待 1 秒；35 秒没有有效事件时视为失联，前端显示连接、实时同步、定时查询或离线状态。失败或连接期间每 5 秒查询；正常连接仍每 30 秒补读，原训练会话每 3 秒查询保持不变。
- 快照／变化触发合并刷新，只重读当前登录代次、当前页面、当前训练的已启用查询；资料守卫检查或确认期间延后。刷新复用在途 GET，不取消原读取，通知前发起的 GET 可能先返回旧快照，由后续事件和定时查询继续补读；收到通知不代表业务结果已成功同步。
- 通知不重发创建／重试命令、不替代原幂等键，也不自动授权。恢复期间保留候选改写、评价决定和费用输入；服务器新修订使旧确认失效，由用户再次核对。
