# 知识采用多跳传播契约

版本：v1.1 · 2026-11-11。状态：S8 第八批代码完成待验证。独立静态复核、后端打包与正式业务入口专项检查通过；整仓前端构建仍有本批之外的缺失组件，集成、运行与视觉尚未验收，具体证据见开发记录。

业务依据：[产品需求 §7](../需求文档/产品需求文档.md)。本契约扩展[知识采用来源更正与复核](知识采用来源更正与复核契约.md)的传播范围；原根事件、人工处理、时间守卫及历史资格规则保持。实施状态与检查证据只维护在[开发阶段与进度](../开发记录/开发阶段与进度.md)。

## 1. 实际采用链与版本范围

本批接通知识 A → AI 整理采用的 B → 再整理采用的 C，以及更长的已登记知识采用链。只沿 `ai_knowledge_source` 与已采用的 `KNOWLEDGE_DRAFT` 决定传播，使用真实 owner、来源版本和目标采用版本；主题、正文双链、普通关系及未采用候选不作为传播路径。

A 实质发布正文或归档仍只产生一个根事件。根的第一次展开核对全部已登记知识来源版本。若其中一条路径采用为 B@b3，则继续展开实际引用 B@b3 及以后版本的已采用任务；只引用 B@b1／b2 的 C 不受这条影响。比较依据来自真实 `knowledge_version`，不拿今天的发布版或冗余版本号替代。

每条影响分别保留根事件、本跳直接来源、本跳实际输入版、任务、原目标采用版、父影响及跳数。后续人工版保守待复核，保留用户扩写。处理 B 不处理 C，也不替 C 建立新的来源资格；B 后续正文更新产生另一个独立根事件。根恢复或改回、来源影响已处理均不抹去历史失效依据。

本批覆盖接入后的新根事件。旧一跳记录保留真实身份和决定，补齐“本跳来源＝根、父影响为空、跳数＝1”的窄元数据，不为旧根事件追加未曾登记的间接影响。准备／事实／表达、摘录生命周期及其他来源更正、接入前历史核对、清除与独立最新账本继续开发。

## 2. 去重、循环和事务

同一根事件内以 `(event_id, task_id, source_item_id, source_version_id)` 识别一条实际采用边。菱形、循环和自来源采用允许存在；每条边只生成一次影响并调用一次下游失效钩子。不能按知识对象去重：先到 B@b5、后到 B@b2 时，仍需发现引用 b2–b4 的下游边。

多条链到达同一实际边时，保留一个最短的真实父路径作为查看依据。同跳数按任务与来源身份稳定展开；不枚举全部等价路径，也不把这一条查看路径当作全部依赖清单。父影响与子影响属于同一 owner、同一根事件，父目标就是本跳来源，本跳实际来源版本不得早于父目标采用版，跳数严格加一。

遍历在原知识命令持有的 owner 写锁与事务内完成。影响表中的私有展开标志充当事务内待处理集合，每次最多读取 100 项；分页限制内存，不能截断实际传播总量。父行先登记，逐层展开；所有标志归零后才允许根命令提交。不存在独立后台任务或新的业务处理状态。遇到超时、身份不一致、写入失败或跳数无法保存时整笔回滚，不能只提交前半条链。

根事件继续使用严格晚于四类冻结点的时间守卫；全部后代沿用同一根时间，不伪造中间知识正文事件。新采用边仍在采用发布完成之后才登记，建立该边的同一次发布不追溯影响自身。

## 3. 回执与逐跳查看

原目录、处理请求与成功回执保持形状：Page 5 字段、Impact 16 字段、Resolve 6 字段、Resolution 5 字段。`sourceVersionId` 表示本跳实际输入版；多跳时它可以属于中间知识，不能再与 `rootItemId` 拼成来源链接。`SOURCE` 仍表示根变更源头，目录包含该根事件的后代；`TARGET` 表示本跳采用目标。

新增只读接口：

`GET /api/v1/lifecycle/knowledge/{itemId}/revalidation-impacts/{impactId}/lineage`

不接受查询参数。仅当本人可访问的影响以该知识作为根或本跳目标时返回；继续应用资料访问守卫与 `Cache-Control: no-store`。它只读取固定版本的窄元数据，不读取正文、AI 清单、模型响应、费用或授权。

回执 `KnowledgeRevalidationLineage` 有六个必填字段：

| 字段 | 规则 |
|---|---|
| `impact` | 原 16 字段影响回执；决定可以随人工处理变化，固定采用身份不变。 |
| `sourceItemId` | 本跳实际来源知识 ID。 |
| `sourceTitle` | 本跳实际输入版本的标题，作为纯文本展示。 |
| `sourceVersionNumber` | 真实输入版的正整数版本号。 |
| `depth` | 从根开始的跳数，1 至 2147483647。 |
| `parentImpactId` | 第一跳为 null 且来源必须为根；其余为同事件父影响 ID。 |

前端从目录主动查看一跳，再主动请求上一跳；每次只读取一个固定影响。上一跳入口使用本跳 `sourceItemId` 与 `parentImpactId`，重新核对根事件、时间、父目标、跳数及版本范围。对象可以重复出现，但不能接受重复的影响 ID。来源版本链接只在本跳身份核对成功后生成。列表刷新、筛选、翻页、对象切换、隐藏或权限变化清除旧路径显示，未决人工处理请求和理由仍按原规则保留。

路径查看不替代当前目录和目标基线核对，不产生处理决定或学习记录。处理仍需原六字段明确确认，旧成功回执不扩字段、不改摘要、不改写，不能因为增加路径查看而拒绝历史原键恢复。

## 4. 数据与下游边界

新增 V69 迁移，为影响增加本跳来源、父影响、跳数与私有展开标志。根事件外键和目标采用决定外键保持；来源路径／版本外键改绑本跳来源。父外键同时限定 owner、根事件和父目标。唯一边约束与待展开索引配套；旧 V1–V68 原文不改。V69 共五条语句，删除旧外键／调整列与索引、新增外键分为不同 ALTER，保持外键检查开启；自引用目标唯一索引先建立。MySQL DDL 部分提交与恢复仍须服务器核验。

迁移限制依据：2026-11-11实际读取MySQL 8.4官方[Online DDL Operations](https://docs.oracle.com/cd/E17952_01/mysql-8.4-en/innodb-online-ddl-operations.html)与[FOREIGN KEY Constraints](https://docs.oracle.com/cd/E17952_01/mysql-8.4-en/create-table-foreign-keys.html)，两页HTTP 200。外键检查开启时新增外键使用COPY，同条ALTER删旧并新增外键不支持该算法；静态改句不替代实际迁移证据。

每条新影响继续调用现有回忆和审阅上游钩子。卡片保存真实 `upstreamImpactId`、暂停排程并终结开放尝试；审阅按目标原采用版及以后的确切证据判断。AI 当前来源与旧任务冻结基线、旧评分依据继续查询所有适用影响，历史查询包含已处理记录。

处理影响不清卡片 gate、不恢复排程、旧评分、旧审阅或旧 AI 任务。当前来源布尔标志与历史未知字段的兼容规则保持，固定历史快照、原文及摘要不重写。前后端、新接口规格及 V69 须配套部署；迁移执行与查询计划待服务器核验。
