# 准备版本生成候选契约

日期／版本：2026-11-07 · v1.3。适用 S5 第九批，第十批补充混选入口，第十四批补充表达来源；第九批状态为静态检查通过待服务器验收。承接 [PRD](../需求文档/产品需求文档.md) MAT-03、KNOW-07、AI-02–06，以及[外发](AI任务与外发契约.md)、[知识采用](AI候选采用与来源契约.md)、[题库采用](AI出题候选与题库采用契约.md)和[准备来源代次](训练背景更正与AI使用契约.md)。实际进度与验证证据仅维护在[开发记录](../开发记录/开发阶段与进度.md)。

## 1. 用户流程与范围

用户选择目标／JD、项目概况或已确认事实的确切当前版本，可同时选择已发布知识 → 选择知识整理或出题用途 → 核对完整外发文本、供应商及费用 → 本次授权 → 查看候选与确切来源引用 → 编辑并显式采用或忽略。采用只写知识／题库，不改变准备内容或事实核实结论。

本批支持 TARGET、PROJECT、FACT；总计 1–5 个来源。事实必须当前 CONFIRMED，且所属项目 ACTIVE。目标与项目概况是用户提供的背景，不能因进入清单被称作已核实事实。保留 FACT 的责任边界，不把“参与／仅了解”改成“本人负责”。

第十批[附件摘录生成候选契约](附件摘录生成候选契约.md)补充资料与准备混选，使用独立请求和资料引用，保留本篇准备投影及代次守卫。第十一批[事实生成表达候选契约](事实生成表达候选契约.md)将确切事实用于 EXPRESSION_DRAFT，并显式保存表达版本。第十三批[训练片段沉淀知识](训练片段沉淀知识契约.md)另用确切提交来源。第十四批[表达素材输入与来源](表达素材输入与来源契约.md)在本篇两种用途增加 EXPRESSION：下述第九批三类准备投影及旧提示版本保持，表达的白名单、依据代次、提示版本和来源待复核规则由该专项契约补充。用户必须分别选择来源和用途；事实确认、保存、收藏都不是外发授权，自动关系建议仍属后续范围。

## 2. 固定来源与当前性

复用 `Source={itemId,versionId,number,kind,title,body}`；kind 为 NOTE、CONCEPT、TARGET、PROJECT、FACT。itemId／versionId 始终是对应领域的真实对象／版本身份，不将准备版本伪装为知识对象。合并顺序为知识来源在前、准备来源在后；任务内不允许重复 itemId，避免没有 kind 字段的 Citation 出现身份歧义。

准备来源只通过加入外层事务的只读入口读取。按 owner、类型、确切版本和当前可用性核验，不展开关联材料；固定标题和版本号来自所选版本。body 是按以下字段顺序生成的紧凑 JSON 字符串，保留字段值和数组顺序，作为授权及引用区间的确切文本：

| 类型 | body 的字段白名单及顺序 |
|---|---|
| TARGET | company、jd、requirements；每条 requirement 只含 text、dimensions、priority |
| PROJECT | overview、technology |
| FACT | scenario、problem、action、result、technology、responsibility |

来源地址、来源说明、附件 ID／原文、关联对象、表达稿、个人计划和核实理由不会附带。用户已经手工写入上述字段或任务要求的私人文字仍会发送，预览完整显示；本批不做自动隐私识别。

Manifest 追加可空 `preparationChecks`，每条为现有 `PreparationDtos.SourceCheck={kind,itemId,versionId,state,sourceGeneration,projectGeneration}`。准备项必须与 sources 一一对应、状态 CURRENT，来源代次和 FACT 所属项目代次参与授权摘要。核对信息不发送给模型。来源改版、撤回／重新确认、归档／恢复及父项目更正会使原授权失效；收藏、目标关注不改变代次。

创建、重试、排队恢复、领取、最终发送、结果接纳及采用前均按同一规则核验。已发后失效按既有终态规则保留实际／未知费用，不通过异常回滚费用事务。数据库故障不能伪装成来源撤回。历史清单和候选保留当时内容；当前可读不等于旧授权仍有效。

## 3. 请求、兼容与存储

旧 `PreviewRequest`、`CreateTask`、`SourceLink` 和 `Citation` 字段保持原样。纯知识请求继续走旧路径；含准备版本的请求使用独立 DTO 与路径，避免改变旧原键回放的请求摘要。

| 方法／路径 | 请求与响应 |
|---|---|
| POST `/api/v1/ai/preparation-drafts/preview` | PreparationDraftPreviewRequest → Preview，只读 |
| POST `/api/v1/ai/preparation-drafts/tasks` | CreatePreparationDraft → Task，201；Idempotency-Key |

`PreparationDraftPreviewRequest={purpose,instruction,sources,preparationSources}`。purpose 只能 KNOWLEDGE_DRAFT／QUESTION_DRAFT；sources 是 0–4 个知识 SourceLink，preparationSources 是 1–5 个 `{kind,itemId,versionId}`，两数组均须显式提供且合计最多 5。instruction 去除首尾空白后最多 1000 UTF-16 码元，禁止 NUL。CreatePreparationDraft 再增加 expectedManifestHash 和 consentConfirmed=true。

Manifest 仍使用原用途、instruction、sources；training、evaluation、contextChecks、materialQa 均为 null，仅新 preparationChecks 非空。规则版本分别为 `preparation-knowledge-draft-1`、`preparation-question-draft-1`；纯知识保留 `knowledge-draft-1`／`question-draft-1`。旧任务缺 preparationChecks 时按 null 读取，不将缺失字段补成准备授权；旧任务回执和摘要不重算。尚未创建任务的旧预览可能需要重新预览。

V20 新建 `ai_preparation_source`，创建任务时保存 owner、task、准备对象／版本、kind、number、title 和合并清单内序号，使用 owner 复合外键、来源／顺序唯一约束及源版本查询索引。任务、尝试、来源关系、通知游标和幂等回执同事务。现有采用知识来源表仅保存 NOTE／CONCEPT，准备项不能进入知识外键列。

采用历史仍先按目标版本查询已采用任务，再合并知识和准备来源；未采用任务不出现在采用历史中。OriginSource 追加可空 kind；旧缺字段按历史知识来源兼容。state 扩展 WITHDRAWN、PROJECT_ARCHIVED、UNVERIFIED；当时标题／版本保持固定，状态仅表示当前可用性，不证明原授权代次仍有效。候选、正文引用、准备事实和概念关系分别保存。

## 4. 网关、界面与恢复

网关只发送原用途、要求及明确 Source 字段，不序列化整份 Manifest。准备规则明确区分岗位要求、项目描述、用户确认事实与个人知识；不增加模型工具、外部请求或新协议。固定输入最多 32 KiB，沿用既有预算和输出上限，不截断、不自动扩展来源。

候选沿用现有 Candidate／QuestionCandidate。Citation 的 itemId／versionId 必须来自本次清单，UTF-16 `[start,end)` 和 quote 逐字对应固定 body，不能拆开代理对。准备 body 的引用基准是上表投影文本，不是整个 content JSON 或附件原文。定位校验和用户采用均不表示技术／事实已经由系统核实。

前端支持三种准备类型和知识混选；外发清单直接显示完整固定 body，不用会自动展开附件的准备详情组件替代。候选和采用历史按实际来源 kind 打开确切版本；缺匹配来源时提示重读，不默认跳往知识库。题目采用不把准备来源写成知识关联。

选择、要求、用途、配置变化废弃预览与勾选；拒收迟到预览。创建命令固定原路径、请求和幂等键；断网、重登或守卫变化保留选择、要求、采用改写和费用输入。来源当前性变化使采用失效，但不改写用户输入。选择器切换只切展示范围，不丢已选来源。所有新入口、历史任务和回放均受既有独立训练资料守卫约束。
