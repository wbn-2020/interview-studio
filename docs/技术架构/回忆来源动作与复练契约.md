# 回忆来源动作与复练契约

日期／版本：2026-11-08 · v1.1。状态：S6 第六批代码、独立静态复核与前后端构建通过，待服务器验收。承接[面后回忆](面后回忆记录与题目来源契约.md)与[独立复练](独立复练与来源判断契约.md)，覆盖 PRD EVENT-04、RET-03。进度以[开发记录](../开发记录/开发阶段与进度.md)为准。

## 1. 同一套动作与复练

个人回忆可以产生一个改进动作，也可以直接开启空白补练。回忆有回答片段时标为 RECOLLECTION，无片段时标为 NONE；已有正式提交保持 ANSWER。三种基线共享动作、训练、新答、对照和逐来源人工判断，不把回忆转换成正式提交或技术结论。

新增动作和复练只接受 ACTIVE 当前回忆版本及确切对象修订。新建动作一次产生一条回忆来源，后续多来源使用既有合并命令。合并可以包含正式回答和不同回忆的来源，但一次复练只选择同一基线的 0–10 条来源；不能把不同版本合成一份旧回答。

| 新接口（前缀 `/api/v1`） | 请求与响应 |
|---|---|
| POST `/review/recollections/{id}/actions` | `{expectedRevision,versionId,title,detail,observation,verification}`；201 返回既有 Action |
| POST `/review/recollections/{id}/repractices` | `{expectedRevision,versionId,title,timeBudgetMinutes,questionMode,variant,contextLinks,sources}`；201 返回扩展后的 Repractice |

title 1–200、detail 0–2000、observation 1–5000、verification 1–2000，沿用 Unicode／严格字段检查。其余复练字段沿用现有 Create 的取值与数量上限。保留所有旧写 DTO、命令名称及其序列化字段，避免改变旧幂等请求摘要；两个新入口独立命令名，原键恢复同样在 owner 命令事务内完成。

## 2. 来源与读模型

- SourceKind 新增 RECOLLECTION。ActionSource 尾部新增可空 `recollection:{recollectionId,versionId,versionNumber,baselineKind,observation}`；这份人工作用观察和版本身份固定不变。该分支的 answer、feedbackId、feedbackRevision、taskId、observationId、manualKind、authorLabel、observation、decision 均为 null。旧 MANUAL／AI_EVALUATION 来源的 recollection 必须为空，旧创建端点明确拒绝新类型。
- Repractice 与列表 Summary 新增 `baselineKind:ANSWER|RECOLLECTION|NONE`。ANSWER 保留原 baseline 回答三元组；其他类型 baseline=null。Summary 只补可空 recollectionId／recollectionVersionId，不展开回忆正文。
- Repractice 新增可空 `recollectionBaseline:{recollectionId,revision,version,state}`，revision 为创建时对象修订，version 为确切不可变回忆版本，state 为读取时 CURRENT／SUPERSEDED／ARCHIVED。状态不写入不可变动作来源快照。
- Comparison 的 baseline 在回忆／NONE 分支为 null，旧侧通过 repractice.recollectionBaseline 阅读；current 始终是真正的已结束训练正式提交。回忆分支 differences 返回空数组，界面解释旧模式、计时、参考和辅助未记录，不能用假零或 changed=false 冒充条件相同。
- SourceProgress 尾部新增可空 `recollectionState`；旧来源为 null，回忆来源为实际状态。旧判断只有来源仍 CURRENT、原有验证条件／跟踪规则仍成立时才 applicable；无判断仍为 false。不把不适用误报为已处理。
- 历史读回执可能缺少新增尾字段。只有完整、有效的正式回答三元组且无回忆身份时才允许解释为 ANSWER；缺字段不推断为 NONE。旧来源快照可缺 recollection，等价 null。新增 JSON 不改写旧历史或旧回执。

## 3. 空白训练与人工判断

SAME 直接把确切回忆的 title／question／type／conditions 投影为一个 REPLAY 题实例，无须先创建题库。回答片段、反馈、不确定性及知识缺口不进入训练题面或安全查询；答案文字和图从空白开始。VARIANT 使用用户明确选择的有效题库版本。背景仍由本次显式选择。

创建时与开始 DRAFT 时核对回忆当前版本和对象修订，以及来源当前归属／跟踪／验证条件；变化后要求重新创建，不静默更新旧草稿。已经开始的训练可以继续保存和结束，不因后续回忆更正而丢失新答。题面明确提示来自个人回忆、曾接触题面；没有题库曝光记录不能写成首次见题。训练中仍由现有资料守卫阻止读取回忆片段和复盘。

对照仍由用户在训练 ENDED 后选择确切新提交。RECOLLECTION 显示“个人回忆片段”，NONE 显示“无旧答，本次补练记录”；不计算提升分、不虚构旧提交日期。保存判断复用原 Judge：已处理／部分处理须有新答引用，核对来源、动作和全局判断修订，不自动关闭动作。

回忆被补记或归档后，旧来源和判断可读，但禁止追加该旧来源的判断，也不允许用它新建复练；允许停止跟踪。恢复且仍为同一当前版本后可重新读取使用。新版本需要新来源，旧 sourceId 不迁移。改写验证条件、合并、恢复跟踪沿用既有历史规则；恢复跟踪要求回忆来源当前可用。

AI ANSWER_COMPARISON 继续只允许 ANSWER。服务端在读取比较来源时明确拒绝 RECOLLECTION／NONE，前端也不提供双答案比较候选入口；仍可对本次真实提交使用既有单答评价。

## 4. 数据与兼容

V33 扩展原 review_action_source 与 review_repractice，不改 V1–V32。来源增加回忆及版本身份和固定 JSON（最多 65,536 字节）；正式回答三元组按来源类型互斥可空，原 observation_json 对回忆分支为空。复练增加 baseline_kind（旧行默认 ANSWER）、回忆身份及创建修订，正式基线字段按类型互斥。所有新关联使用 owner 复合外键和显式 CHECK；MySQL NULL 不得使互斥约束意外放行。现有比较／判断表继续使用，迁移仅编写，服务器显式执行。

两类新创建均保留原 owner 锁、幂等和原子提交。旧接口、旧模型输入／摘要和正式提交访问确认不降级。读取历史回忆允许已归档版本，但须核对 owner、对象与确切版本，禁止跨用户借身份。
