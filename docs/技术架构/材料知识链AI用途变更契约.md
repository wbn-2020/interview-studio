# 材料知识链 AI 用途变更契约

版本：v1.0 · 2026-11-12。状态：静态检查通过待服务器验收，适用S8第二十五批；累计OpenAPI 7.54.0及生成类型配套，无新增接口或载荷。实际实施及检查以[开发记录](../开发记录/开发阶段与进度.md)为准。下列服务器场景全部未执行。

## 1. 许可与内容分开

固定材料摘录的`REVOKE_AI／ALLOW_AI`只改变AI用途许可和单调revision；不改变摘录、已采用知识的正文或本地内容正确性。用途撤回不等于知识更正，不新增内容待复核影响、不暂停回忆卡、不替用户作内容判断。归档／恢复影响本地可用性，本批不放开已采用内容的这两个动作。

既有[材料生命周期](材料摘录生命周期契约.md)的状态、事件及命令载荷保持。V73的Event11是真实用途／状态根，不是摘录正文更正证明；普通摘录仍为固定原文。后续正文更正须建立真实旧新摘录或更正声明关系，不能只保存reason就宣称正文已改。

## 2. 命令准入

复用`POST /api/v1/materials/excerpts/{id}/lifecycle/changes`及Change4／State8，没有新接口、请求字段、响应字段或迁移。参数、理由规范化、登录、本人、资料模块与独立训练资料守卫、CSRF、幂等和no-store保持。

在原owner写锁与命令事务内，依次核expectedRevision、实际状态转换及安全整数上限，再核本次动作允许的原始材料绑定。只有用途二动作可把已完整核验的`KNOWLEDGE_DRAFT + ADOPTED`作为受支持采用；未采用合法AI登记及IGNORED沿原规则。直接准备、题目、事实、正式关系材料证据、审阅及不支持的任务／决定仍拒绝。关系补充和已归档／移除目标不抹历史登记。

随后重新构建[实际知识采用链](材料知识采用链预览契约.md)，复用原始登记、真实源／目标版本、采用版下限、循环／菱形去重及一次严格历史祖先证明；不能信任客户端先前GET。材料根与生命周期身份须匹配，历史缺失、损坏、额度及SQL错误不吞成空链。反向200知识版／500边／2500原始登记及正向证明的独立额度保持；新写命令继承原命令事务边界，不另开读快照。

对闭包中不同知识itemId分别检查全部历史版的原始出口；不按当前版本、采用版下限、归档、父对象存在或决定状态过滤。该规则保守拒绝部分更早版本的无害登记，以避免在尚未覆盖全部派生路径时漏放。检查不是完整删除传播，也不证明每条被阻塞登记均已外发或正式物化。

题目、卡片、准备、带知识依据的关系、白板快照、训练固定题面／图、审阅依据、面试材料、知识来源问答、回忆历史和安排等未支持出口由原始EXISTS检查，不能用引用目录的INNER JOIN空结果放行。纯主题、概念笔记、主笔记、普通语义边及正文链接是组织／结构关联，不自动当作内容派生。

全部核验通过后，才CAS更新生命周期、追加V73事件及保存原键回执，revision加一。任一未支持出口以`409 MATERIAL_HAS_REFERENCES`拒绝，其他明确历史／预算错误保持；不部分提交、不创建内容影响或清除登记。归档／恢复继续使用原严格采用阻塞规则，不走用途例外。

## 3. AI 与历史

例如固定摘录E在revision0被采用为K1，再由K1采用为K2：

1. 撤回AI用途后E为REVOKED／revision1，K1／K2正文保持；旧任务的祖先check0失配，新用途捕获被拒绝。
2. 重新允许后E为ALLOWED／revision2，旧check0仍失配；必须重新预览并以check2形成新的授权范围。
3. 新材料绑定、知识采用与用途变更共用owner锁；先发生的操作决定后续命令能否继续，不能靠旧预览绕过。

原知识材料祖先检查参与预览、创建、重试、排队领取、发送许可、暂态读取、接纳及采用等统一当前性核对。许可恢复不改历史Manifest／hash／scope／回执，也不重新激活旧任务资格。原授权条目的存储状态不等于它能授权新代次。

已经取得发送许可的事务外请求可能继续到达供应商；已外发或已展示的正文不可收回，实际或未知费用仍保留。用途变更不承诺供应商即时取消、网络零新增字节或费用归零。

## 4. 界面

沿用材料详情四个独立动作和原请求恢复。说明中区分：无采用的原范围、受支持纯知识链的用途二动作、仍被阻塞的归档／恢复及其他出口。hasReferences只表示登记存在，不提前判命令可执行；知识链预览仅帮助核对，实际放行须服务器在命令锁内重建。

本批不新增控件或自动读取／提交，不改变收起、隐藏、会话／训练访问变化、迟到响应和未决原请求的处理。重新允许只恢复新AI用途的可能性，用户须主动重新预览授权；不显示知识已复核、复习已恢复或内容已正确。
