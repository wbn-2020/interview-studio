# 独立复练与来源判断契约

日期／版本：2026-11-23 · v1.1。状态：同版本变式拒绝、同题和不同题复练链路已完成[本批服务器验收](../审查/复审修复与服务器验收-20261123-r163.md)；其他场景的实际证据见唯一[开发记录](../开发记录/开发阶段与进度.md)。关联 [PRD](../需求文档/产品需求文档.md) RET-01–05、ARCH-04，以及[动作契约](自检反馈与改进动作契约.md)。本契约定义正式原答基线、空白新尝试、人工对照和逐来源判断；AI 比较、面后回忆／无旧答基线的后续实现与验证状态按开发记录维护。

## 1. 空白新尝试

- 从已结束训练的确切提交创建；传入 baseline 的 sessionId/questionId/answerId，不自动选择最新回答。每次复练只对应一个基线和一道新题，可选择 0–10 条与该基线完全一致的动作来源。不同原答的合并动作分次复练，不吞掉其他来源。
- SAME 保留原训练题面的确切内容，允许历史或已停用题库版本；以 REPLAY 实例表示，保留题库来源（原 AI 追问无题库来源），不复制原追问的同会话父链。VARIANT 显式选当前有效题库版本，采用 MAIN 实例；与原题不同的条件明确展示。2026-11-23补充：同一题目同一版本不得作为变式，创建及旧草稿开始前均拒绝；同题不同版本允许明确选择，仍须人工核对题面与条件差异，不自动认证其构成有效变式。
- 新会话固定 FOCUSED、AFTER_SESSION、followUpLimit=0、单阶段“独立复练”，可设 1–180 分钟预算或不设。正文、图、草稿、旧白板导入凭证完全不复制；只复制明确题面并重新选择本次当前有效背景，最多 12 项。原背景仍作为对照基线保留。
- 创建在一个 owner 命令事务中保存空白 DRAFT 和复练绑定；启动／保存／提交／暂停／结束复用训练 API。启动再次验证服务器来源与当前背景。新题面明确注明已有原答曝光；历史曝光不被重置为“首次见题”。
- 创建来源必须是 OPEN 动作中的 TRACKING 来源，核对 actionRevision；固定 actionId/actionRevision/actionTitle、稳定 sourceId 和完整 ActionSource 快照（含当时 verification、观察及决定）。后续合并、停止跟踪或改写验证条件不改变本次固定依据。

## 2. 阅读边界与对照

- 复练接口均在 `/api/v1/review` 下，继承入站、读响应与幂等回放资料守卫。训练进行期间仅现有训练页面显示新题与新草稿，复练绑定、旧答、反馈、验证条件不能借当前训练安全路径返回。
- 对照要求新训练 ENDED 且选中真实已提交 answerId；仅结束但未答不能建立对照。两端沿用 evaluations/access 明确确认，不需要启用 AI。默认结束后比较；若用户在训练中显式允许辅助，后续提交照常记录 ASSISTED。
- 对照绑定复练 ID 与新 answerId，不跟随最新提交；每对唯一、每次复练最多 20 份对照。旧答、新答、题面、图、个人参考、原背景与本次背景、模式／反馈时机／预算、回答辅助条件／既往曝光及整场时间分别展示。整场观察时间不标为单题净答题时长。
- 原文从不可变提交及确切版本读取；两场均已结束。个人参考保持未审身份，无题库来源的 REPLAY 没有标准，不挪用原追问根主问参考。差异说明按题面、参考、背景、模式／反馈时机、辅助／曝光、时间预算列出，不输出可比总分或自动“提升”。

## 3. 逐来源判断

- 用户对本次确切新提交中的所选来源记录 HANDLED／PARTIAL／UNHANDLED／UNCERTAIN（已处理／部分处理／未处理／无法判断）。必须填写 1–2000 码点依据；HANDLED／PARTIAL 至少选一处新答案文字或图元素引文，其余可无引文并说明限制。最多 6 处，引用为既有 EvaluationCitation，只允许 ANSWER_* 类型，逐字、UTF-16 半开区间及代理对边界校验复用反馈规则。
- 判断独立追加，按稳定 sourceId 全局修订 1–1000，携带 expectedRevision（无判断为 0）、currentActionId 与 expectedActionRevision，防止旧标签或其他复练覆盖最新决定。只处理请求选中的 sourceId，不批量关闭动作。
- 提交时当前来源仍须 TRACKING、归属 OPEN 动作、verification 与本次固定条件完全一致。条件变化／合并／新判断造成冲突时保留输入并核对；已改条件不能拿旧尝试的固定要求冒充新标准。
- 合并仍保留 sourceId，判断历史可以跨归属查询。停止跟踪与完成分开；当前进度仅在仍 TRACKING 且当前 verification 等于最新判断所用固定条件时适用，否则显示“待验证／条件已变化”。Action 的 OPEN／MERGED 是容器状态，不增加直接完成接口。
- 无动作来源的复练也可保存并阅读对照，不生成虚构动作或自动结论。判断历史保存每次 comparisonId、新 answerId、旧验证条件、引文和依据；后来的改判不倒改原答或旧判断。

## 4. API、类型和存储

所有写命令要求 Idempotency-Key，严格 JSON 字段和原始类型校验；业务、CAS、回执同一事务。DTO 以 `RepracticeDtos` 和 S6 OpenAPI 为准。

| 方法／路径（前缀 `/api/v1/review`） | 输入／输出 |
|---|---|
| GET `/repractices?cursor=&limit=` | RepracticePage，limit 1–20，默认 10，UUID 游标 |
| POST `/repractices` | RepracticeCreate → Repractice（201） |
| GET `/repractices/{id}` | Repractice，含绑定、来源快照、当前会话摘要和比较列表 |
| POST `/repractices/{id}/comparisons` | RepracticeCompare（answerId）→ RepracticeComparisonSummary（201） |
| GET `/comparisons/{id}` | RepracticeComparison（两侧完整内容、差异说明及来源当前进度） |
| POST `/comparisons/{id}/sources/{sourceId}/judgments` | RepracticeJudge → RepracticeJudgment（201） |
| GET `/sources/{sourceId}/judgments?before=&limit=` | RepracticeJudgmentPage，倒序修订，limit 1–20，before 1–1001 |
| GET `/actions/{id}/progress` | RepracticeProgressPage，当前动作全部来源及最近判断／适用性 |

- RepracticeCreate：baseline、title（1–200）、timeBudgetMinutes（null 或 1–180）、questionMode、variant（SAME 为 null；VARIANT 为 QuestionSelection，stage 固定）、contextLinks、sources（actionId/expectedActionRevision/sourceId）。
- RepracticeJudge：expectedRevision（0–999）、currentActionId、expectedActionRevision、outcome、reason、citations。判断身份、验证条件和新答身份由服务器从绑定读取，不接收客户端来源快照。
- V29 只扩展训练题实例 CHECK，新增 REPLAY 并保留旧约束；V30 新建 repractice、repractice_source、comparison、source_judgment 四表。来源快照总量不超过 1 MiB，单快照不超过 192 KiB；判断引文 JSON 不超过 32 KiB；沿用 2 MiB 命令回执上限。
- owner 复合外键关联确切训练题／回答、动作来源；sourceId 在合并中不变，source_judgment 的 revision 按 owner/source 唯一；comparison 按 owner/repractice/new answer 唯一。新旧提交、反馈、历史迁移不改写。
- 错误使用 404 `REVIEW_NOT_FOUND`；409 `REVIEW_REVISION_CONFLICT`、`REVIEW_SOURCE_CHANGED`、`REVIEW_REPRACTICE_NOT_ENDED`、`REVIEW_COMPARISON_EXISTS`；422 `REVIEW_LIMIT`、`REVIEW_EVIDENCE_INVALID`；400 `INVALID_REQUEST`。访问与训练来源错误沿用现有规则。无新依赖、新模型用途或配置键。
