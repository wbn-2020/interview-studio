# 正式关系面后回忆原文证据契约

版本：v1.0 · 2026-11-10。适用S5第二十九批；状态：静态检查通过待服务器验收。承接PRD KNOW-06／07、REV-06、[面后回忆](面后回忆记录与题目来源契约.md)及[正式关系反馈证据](正式关系反馈原文证据契约.md)。进度以[开发记录](../开发记录/开发阶段与进度.md)为准。

## 1. 业务位置

用户可为本人已有正式知识关系，选取一份面后回忆当前确切版本中的1–8段原文，说明理由后保存独立证据。它仍是用户事后补记：原作答模式、计时与辅助条件未知；不变成正式提交、已核实项目事实或技术结论。CURRENT仅表示来源对应，不证明回忆、理由或关系正确。

本地手工保存不创建AI任务、不授权外发、不产生模型费用，不改变原回忆或正式关系。既有资料／训练、人工反馈、AI反馈证据分别保留原表与原回执；本批新增独立回忆台账，不将回忆伪装为人工反馈或AnswerLink，不修改旧AI用途、Manifest、prompt与引文规则。

关系ID、概念端点和类型保持不变，不新增边、不改变图路径、计数或布局。删除原关系后保留以旧relationId定位的历史；同元组新建的关系具有新ID，不继承旧证据。完整删除／更正传播另按S8处理，当前历史不可变不替代未来隐私清除。

## 2. 来源选择、片段与必要限定

复用[回忆选择器](../../frontend/src/components/review/RecollectionPicker.vue)主动检索ACTIVE元数据，不在打开面板时自动读取回忆正文。选择后显式读取既有`GET /api/v1/review/recollections/{id}`，严格核对返回身份、状态、当前版本、对象修订及目录元数据。它是既有完整详情接口，可能含安排快照；创建表单只保留本批白名单，不将安排、其他未选正文或其他对象装入新证据。

请求source直接采用既有[RecollectionSelection](../../backend/src/main/java/com/wenjie/studio/ai/ReviewDraftDtos.java)：

```text
Create = {reason, source, confirmed}
source = {recollectionId, versionId, expectedRevision, fragments}
fragment = {field, start, end, quote}
```

所有字段显式提供，confirmed必须true。recollectionId／versionId均为标准小写UUID；expectedRevision为0–1000整数。首次执行须匹配本人ACTIVE回忆的当前版本与对象修订，不能以标题、最新正文或旧目录摘要代替。

| 项目 | 规则 |
|---|---|
| reason | 1–1000个UTF-16码元，保留原样；拒NUL、孤立代理项及仅由Character.isWhitespace或isSpaceChar构成的文字 |
| field | QUESTION、CONDITIONS、ANSWER_FRAGMENT、FEEDBACK、UNCERTAINTY、GAP；与人工反馈单数CONDITION不同 |
| fragments | 同一确切版本1–8项，保留选择顺序；同字段不重复／重叠，相邻允许 |
| start／end | 原字段UTF-16半开区间，0≤start<end；整数，不能切断代理对 |
| quote | end−start等于UTF-16长度，逐字匹配原字段，最多8000码元，按原Java isBlank非空白；禁NUL与孤立代理项 |
| baselineKind=NONE | 禁止ANSWER_FRAGMENT；不能从问题、安排或模型补造旧答 |

首次保存复用[ReviewDraftSources.input](../../backend/src/main/java/com/wenjie/studio/review/ReviewDraftSources.java)的回忆分支，仅作为来源适配，不调用AiService。服务端固定原版本号、当时对象修订、完整标题／题型／baselineKind／uncertainty及所选片段。完整uncertainty是必要限定，即使未选择该字段也一起保存并明确展示；其他正文只保存所选片段。

固定source沿`ReviewDraftDtos.Input`形状：kind=RECOLLECTION、feedback明确null、recollection非null。recollection九字段为`recollectionId,versionId,versionNumber,sourceRevision,title,type,baselineKind,uncertainty,fragments`。versionNumber为1–1000且≤sourceRevision+1，不与对象修订混用。title／uncertainty沿来源码点及Java空白规则，不把新理由的严格空白规则套到历史原文。

## 3. 三操作与两路径

接口前缀`/api/v1`，登录、owner隔离与独立训练资料守卫生效；写入另需CSRF及Idempotency-Key。不存在正式AnswerLink，不伪造评价访问或提前反馈许可。

| 方法与路径 | 输入 | 返回 |
|---|---|---|
| GET `/knowledge/relations/{relationId}/recollection-evidence` | cursor可选，limit默认20、1–20 | Page，只读元数据，不读取snapshot_json |
| POST 同上 | Create原始JSON | 201 Entry，回执只含元数据，不自动展开正文 |
| GET `/knowledge/relations/{relationId}/recollection-evidence/{evidenceId}` | 原relationId＋evidenceId | Detail，显式读取单条固定快照与当前来源状态 |

Entry共12字段：`id,relationId,sourceId,targetId,type,reason,recollectionId,versionId,versionNumber,sourceRevision,sourceCount,createdAt`。sourceId／targetId是关系端点；sourceCount为片段数。Page为`{relationId,relationExists,items,nextCursor}`；Detail为`{entry,relationExists,source,sourceState}`。

列表按证据UUID字典序升序，cursor为排他id，nextCursor仅在有下一页时取本页末项；不按时间排序、不提供跨请求快照。relationExists表示原边当时是否存在，不表示两端当前可编辑。没有本人边或本人历史时404；已删除原边但有历史时可读取。

原始JSON上限262144bytes，逐层拒绝重复键、未知／缺失字段、尾随JSON、错误null、字符串或浮点整数、数字枚举与隐式标量强转。固定快照按实际UTF-8 JSON最多1048576bytes，含转义与必要限定；超限整笔拒绝，不截断。JSON Schema的maxLength按码点，实际UTF-16长度、原文与非重叠校验仍由业务层执行。

[累计OpenAPI](openapi-s7.json)7.23.0增加2路径／3操作及4个具名schema：CreateRelationRecollectionEvidence、RelationRecollectionEvidenceEntry、RelationRecollectionEvidencePage、RelationRecollectionEvidenceDetail；source选择复用旧schema，固定详情在新局部shape中约束为回忆分支。旧304路径／358操作和982个schema不作语义调整，生成类型从当前规格生成。

## 4. 事务、权限与原键恢复

创建沿owner串行写锁与幂等命令。读取旧回执前仍执行通用资料守卫，并用`ReviewDraftSources.requireAccess`核对原选择的确切历史版本归属；来源补记、归档或关系删除不要求重捕获current，不自动换键、替换来源或重建边。

仅首次执行action时核原关系与两端ACTIVE概念，再从真实回忆捕获当前版本、修订及选区。写入、写后绑定复读和Entry回执同事务提交；任一步异常整笔回滚。不同键表示新的人工追加，不按相同理由或选区隐式去重；未知结果保留原请求和原键恢复。

详情先读取并核Entry，再核确切历史版本归属，之后才读取snapshot。除了严格JSON／分支和台账绑定，还对照确切不可变版本核标题、题型、baselineKind、完整uncertainty及每段原文；即使来源已经改版／归档也不跳过完整性。最后才用`ReviewDraftSources.state`计算当前性，不能因当前性早返回而接受损坏历史。

| sourceState | 含义 |
|---|---|
| CURRENT | 原版本仍当前、对象修订和固定内容对应 |
| SUPERSEDED | 已有后续内容版本，保留旧原文 |
| ARCHIVED | 回忆当前归档，保留当时性质与片段 |
| REVIEW_REQUIRED | 同版本归档恢复后修订变化，或其他已识别来源条件改变，需要重新核对 |
| UNAVAILABLE | 当前性核对明确无法取得来源；不覆盖历史归属检查或真实访问拒绝 |

确切历史版本缺失／不可访问时不返回保存正文；数据库错误、修订倒退、坏JSON、元数据或原文不匹配是错误，不伪装成普通失效。通用GET出口资料守卫继续在序列化前核验，写命令在owner锁内、旧回执读取前核验；不将全部POST笼统描述为序列化前再次核验。

## 5. 持久化

新增[V55](../../backend/src/main/resources/db/migration/V55__relation_recollection_evidence.sql)独立`knowledge_relation_recollection_evidence`台账，按owner＋evidenceId主键保存原关系元组、理由、确切回忆版本、版本号、对象修订、片段数、snapshot_json和创建时间。到`review_recollection_version(owner_id,recollection_id,id)`建立RESTRICT复合外键；不建立到可移除正式关系的外键。

CHECK约束关系类型、无自环、对称关系规范化、版本／修订／片段数范围、JSON对象及快照字节上限。领域层另核UUID、UTF-16／Unicode、来源原文、JSON shape、绑定及版本与修订关系；数据库长度检查不能代替这些校验。Mapper仅查询和追加，不提供覆盖历史命令。旧迁移与台账不重写，V55在V54后由服务器流程显式迁移，本地不执行SQL。

## 6. 界面及恢复

知识详情的“关联与出处 → 完整语义关系”中增加独立回忆证据面板。展开先读取元数据；用户另点单条才读取固定正文，保存成功不自动展开。详情始终提示个人回忆性质、原条件未知，并展示完整不确定性和所选片段，可回到确切回忆版本。

来源核对成功后才替换旧选择；同一版本重核保留选区，换版本由用户明确选择。访问、登录代次变化会遮挡并使旧核对失效，保留理由、已选／未加入片段及未决命令。恢复访问后显式重核；迟到结果不覆盖当前输入，2xx失配先交公共命令保留原键，再等待原请求恢复。

父关联页汇总dirty／locked，切换类型、翻页、移除关系和离开页面继续保护输入。创建子树置于可刷新的目录之外，不因列表重读或权限变化卸载。确认原边已删除后禁止再追加，即使后续列表刷新失败也不能复活新增入口；历史仍可读。控件沿现有Naive UI、标签和状态反馈，不另建视觉主题。
