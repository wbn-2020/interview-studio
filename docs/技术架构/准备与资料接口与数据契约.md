# 准备与资料接口与数据契约

日期／版本：2026-11-12 · v0.9。状态：S3 编码契约；既有 S5 来源与候选采用范围已静态交付待服务器验收，S8 第九批表达依据持久基线与显式复核代码及专项检查完成，整体构建阻塞与服务器欠项继续保留。不削减[完整产品需求](../需求文档/产品需求文档.md)，实现与验证状态以[开发记录](../开发记录/开发阶段与进度.md)为准。

## 1. 本批边界与业务规则

第一批接入目标／JD／要求、项目、项目事实、表达、当前关注目标和知识引用；第二批按[附件与安排契约](附件与安排接口与数据契约.md)接入附件／解析与私人面试安排。题单／训练快照依 S4，AI 要求提取、材料候选和外发授权依 S5，面后回忆依 S6，日期路线依 S7，跨模块清除与更正传播依 S8。当前手工准备内容不需要 AI。

准备内容与知识库各有独立身份；保存笔记不确认经历。目标可引用项目、事实和知识的确切版本；表达只能引用本人显式确认的当前事实版本。旧版本始终可读，不将旧事实替换成新正文。

事实的职责为 `OWNER|PARTICIPANT|FAMILIAR|UNVERIFIED`，核实为 `UNVERIFIED|CONFIRMED|WITHDRAWN`。核实绑定确切事实版本并追加决定记录；编辑任何事实正文形成新版本，核实重置为 UNVERIFIED。职责仍为 UNVERIFIED 时不能确认。确认表示用户核实所写内容，不能把 PARTICIPANT 或 FAMILIAR 自动变成 OWNER，也不构成模型外发授权。撤回必须填写原因；新表达／目标不能新增引用撤回、未核实或已归档的事实。

事实更正、撤回或归档后，既有表达保留正文与当时版本，按引用关系读取“来源变化／待复核”。编辑表达时必须重新选择当前确认事实；不提供一键把旧来源变成有效的开关。目标链接属于准备组织引用，表达事实来源属于内容依据，不能把两种关系混为知识语义边。项目归档阻止新建事实及新引用其事实，既有材料保留可读。

S5 第七批按[训练背景更正与 AI 使用契约](训练背景更正与AI使用契约.md)为准备对象增加 `source_generation`，正文、归档／恢复及核实决定变更时与 revision 一起递增，收藏与关注操作不改变它。训练保留原背景并显示当前可用性；新追问排除失效背景并固定代次。此增量不重写历史核实决定，也不等于全量派生传播已经完成。

S5 第九批按[准备版本生成候选契约](准备版本生成候选契约.md)将 TARGET／PROJECT／FACT 的固定字段投影用于知识整理和出题。只读取显式选中且当前可用的版本，不展开链接、附件或表达依据；任务单独授权，准备核实不等于外发同意。准备来源关系在 AI 任务创建事务保存，采用目标仍为知识／题库，不自动修改项目事实。

S5 第十一批按[事实生成表达候选契约](事实生成表达候选契约.md)将 1–5 个确认事实用于表达生成。AI 采用在同一命令事务中新建或追加表达版本，追加时核对目标 versionId 与 revision；最终依据为原任务事实非空子集，全部原来源代次仍须有效。普通手工编辑容量不变。S8 第九批按[表达素材依据复核契约](表达素材依据复核契约.md)为每个新表达版本捕获事实／项目来源代次；缺基线或代次不匹配时 reviewRequired=true，来源恢复不自动解除。保留当前正文须显式核对并填写理由，保存新版本则建立该版明确依据的基线；旧AI清单和历史回执不改，准备到已采用知识的传播继续待办。

S5 第十二批按[准备建议与任务契约](准备建议与任务契约.md)将一个 TARGET 确切版本用于准备建议，时间预算和缺口由用户另行明确填写；不把采集日期视为面试日期。普通准备任务使用独立身份和修订历史，手工创建可不绑定目标；已绑定目标不自动替换版本，来源变化只作提示。AI 采用要求原授权仍有效，后续任务的人工处理不以目标仍当前为前提。

S5 第十八批按[JD 要求提取与采用契约](JD要求提取与采用契约.md)新增原始 JD 窄读取及追加要求内部命令。只外发选定 TARGET 当前版本的标题、原始 JD 及明确整理要求，不改旧准备投影；初始 sourceGeneration=0 有效。用户编辑并选择候选后，在同一 owner 事务中保留原字段、既有要求 ID／顺序和组织引用资格，追加新要求和目标版本，与 AI 决定及回执一起提交。新增项严格校验 Unicode，既有手工内容沿旧规则保留，总要求仍最多50。原 JD 版本在采用后正常失效为历史来源，已采用任务及确切版本历史继续可读，不创建任务完成或能力记录。

S5 第十九批按[资料与训练事实候选契约](资料与训练事实候选契约.md)增加 AI 候选新建事实内部命令。项目只在采用时选择，核对当前 PROJECT 的确切版本和修订；任务与项目双 CAS 后，新 FACT 首版、材料关系、采用决定及回执加入同一 owner 事务。责任和核实均为 UNVERIFIED，固定来源由服务端构造；资料依据与训练生成出处分开保存。采用不修改已有事实，也不执行核实，后续责任边界的编辑与明确核实继续遵守本篇原规则。固定 Source、内容／引用边界、历史来源和服务器场景只在专项契约维护；本批独立静态复核及前后端构建通过，事务、材料关系及核实流程仍待服务器验收。

## 2. 对象、版本和容量

所有 ID 为小写 UUID，日期为 ISO 本地日期，时间为 UTC Instant，修订号沿用 JS 安全整数上限。状态 ACTIVE／ARCHIVED，版本不可变。显式“保存新版本”后才算服务端保存；页面未提交编辑暂存内存，离开和会话恢复沿用现有 dirty／locked 守卫。

准备域只有四种固定内容类型；共享身份／版本机制不使其与知识笔记共用身份。`PrepareItem={id,kind,projectId,status,revision,verification,favorite,createdAt,updatedAt,currentVersion,references,reviewRequired}`。非 FACT 的 verification 为 null；非 FACT 的 projectId 为 null。favorite 是整理状态，单独 CAS 更新，不生成正文版本、不重置核实。`Version={id,number,createdAt,content}`；历史列表返回 `{id,number,title,createdAt}` 摘要，不在每页重复长正文。

| 类型 | content 的精确字段与限制 |
|---|---|
| TARGET | `title` 非空≤200；`company`≤200；`jd`≤50000；`sourceUrl`≤2000，仅空或 http(s)；`capturedOn` ISO 日期或 null；`weeklyMinutes` 0–10080 或 null；`requirements:Requirement[]`≤50；`links:VersionLink[]`≤100 |
| PROJECT | `title` 非空≤200；`overview`≤20000；`technology`≤2000；`source:Source` |
| FACT | `title` 非空≤200；`scenario/problem/action/result` 各≤10000；`technology`≤2000；`responsibility` 上述职责枚举；`source:Source`；`tags:string[]`≤20，每项 trim 后非空≤40 |
| EXPRESSION | `title` 非空≤200；`type=INTRO|PROJECT_SHORT|PROJECT_LONG|STAR|TRADEOFF`；`body`≤50000；`factVersionIds:string[]` 1–50 个不同版本；`tags`同上 |

`Requirement={id,text,dimensions,priority}`：id 为目标内稳定 UUID，text 非空≤2000；dimensions 为非空去重数组，值限 `EXPLAIN|DEBUG|TRADEOFF|OWNERSHIP|COMMUNICATION|OTHER`；priority 为 1–5。要求随所属目标版本固定，后续引用使用 targetVersionId＋requirementId；不单独伪造可漂移的最新要求。

`Source={title,url,note,excerptIds?}`：title≤200，url≤2000、仅空或 http(s)，note≤5000；手工录入允许空 url，明确记录为用户提供，不对网址内容作联网核实，不解析或抓取 URL。第二批增加 excerptIds，最多 20 个不同的不可变摘录 UUID；缺省为空，既有历史 JSON 不重写。PROJECT／FACT 保存新版本时，在同一 owner 事务内校验摘录及 READY 附件归属、写入确切版本关系，失败则整笔回滚；空来源不依赖附件启用或磁盘可用。阅读／历史界面打开当时摘录，不用最新解析结果替换原文。摘录来源规则见[附件与安排契约第 3 节](附件与安排接口与数据契约.md#3-不可变摘录与准备内容来源)，不等于事实核实或模型外发授权。

`VersionLink={kind:PROJECT|FACT|KNOWLEDGE,itemId,versionId}`。PROJECT／FACT 引用准备对象，KNOWLEDGE 引用既有 NOTE／CONCEPT 发布版本，全部复核归属和版本与对象的匹配。新增链接须为当前活跃版本，FACT 还须当前确认且所属项目活跃；目标保留原有旧链接时允许保存，但返回状态警告，不把它升级为当前材料。表达保存则要求全部依据当前有效。

`Reference={kind,itemId,versionId,title,number,state}`；title／number 取被引用的确切历史版本；state 为 `CURRENT|SUPERSEDED|WITHDRAWN|ARCHIVED|UNVERIFIED`，优先标记撤回、归档、未核实，再判断版本更替。表达还核对持久保存基线，不能只用所有 Reference=CURRENT 判断无需复核；不复制或覆盖旧表达。事实的直接影响列表仅查询当前引用版本的表达和目标，不承诺尚未实现的训练／卡片传播。

## 3. API、幂等和并发

沿用 `/api/v1`、Session／CSRF、Problem、1 MiB JSON、2 MiB 幂等回执、owner 锁与原请求重试。所有修改要求 Idempotency-Key；更新还要求 expectedRevision。未知字段和与类型不匹配的 content 拒绝，不任意存储未校验 JSON。

| 方法／路径（前缀 /prepare） | 请求／响应 |
|---|---|
| GET `/items?kind=&status=ACTIVE&q=&verification=&favorite=&projectId=&cursor=&limit=20` | 按 ID 正序；q 已保存标题字面筛选≤100；limit 1–50；verification 仅 FACT；返回 `{items:Summary[],nextCursor}`，Summary 含 id/kind/projectId/title/status/revision/verification/favorite/versionId/versionNumber/updatedAt；确认事实筛选同时排除非活跃项目 |
| POST `/items` | `{kind,projectId,content}` → PrepareItem，201；仅 FACT 必填 projectId，检查活跃 PROJECT；首版核实为 UNVERIFIED |
| GET `/items/{id}` | PrepareItem；包含当前确切来源状态和 reviewRequired |
| PUT `/items/{id}` | `{expectedRevision,content}` → PrepareItem；不可修改类型或所属项目，正文形成新版本 |
| POST `/items/{id}/archive`、`/restore` | `{expectedRevision}` → PrepareItem；归档不清除版本；恢复事实不把未核实或撤回改成确认 |
| POST `/items/{id}/confirm`、`/withdraw` | `{expectedRevision,reason}` → PrepareItem；仅 FACT，reason≤2000，withdraw 原因非空；决定保留版本 ID，重复操作按原幂等回执恢复 |
| PUT `/items/{id}/favorite` | `{expectedRevision,favorite}` → PrepareItem；不更改内容版本 |
| GET `/items/{id}/versions?before=&limit=20` | 修订倒序摘要页 `{items:VersionSummary[],nextCursor}`；before 是版本 number |
| GET `/items/{id}/versions/{versionId}` | Version；不能用其他对象版本冒充该对象历史 |
| GET `/items/{id}/decisions?before=&limit=20` | 仅 FACT；按 createdAt／ID 倒序，before／nextCursor 为 `Instant~UUID` 联合不透明游标；`Decision={id,versionId,decision,reason,createdAt}`，不能用随机 UUID 排序冒充时间历史 |
| GET `/items/{id}/impacts?cursor=&limit=20` | `{items:Impact[],nextCursor}`，`Impact={id,kind,title,versionId,reviewRequired}`；列出引用本材料当前或旧版本的活跃表达／目标，versionId 是引用方当前版本，不携带他人正文 |
| GET `/focus` | `{targetId,revision}`，默认 null／0 |
| PUT `/focus` | `{expectedRevision,targetId:UUID|null}` → 同上；仅当前 ACTIVE TARGET；归档当前目标在同事务清空焦点并增加其修订 |

同 owner 的命令串行校验，业务版本、当前指针、依据关系、核实决定和回执同事务提交。修改正文与整理／核实共享实体 revision，客户端任何成功写入后只更新其明确提交的部分，不能覆盖别处未保存输入。分页为当前视图，不承诺并发编辑期间的历史快照。

错误沿用 `INVALID_REQUEST|REVISION_CONFLICT|IDEMPOTENCY_KEY_REUSED`，新增 `PREPARATION_NOT_FOUND|SOURCE_UNAVAILABLE|SOURCE_CHANGED|FACT_NOT_CONFIRMED|FACT_RESPONSIBILITY_UNVERIFIED|ITEM_ARCHIVED|REVISION_LIMIT`。无权与不存在统一 404，不暴露是否属于其他 owner。来源失效或冲突保留本地编辑，显示确切依据，用户换来源或另存，不自动确认／自动重发新键。

## 4. 存储边界

追加 V6，保留 V1–V5 原文：`preparation_item` 身份与当前状态、`preparation_version` 不可变有类型内容、`preparation_reference` 确切来源与用途（ORGANIZATION／FACT_BASIS）、`preparation_fact_decision`、`preparation_focus`。JSON 只用于已校验的固定结构内容，关系和过滤字段单独持久化、索引，不靠全文扫描 JSON 判权限或引用。

准备版本／关系包含 owner＋对象／版本约束；项目归属、知识版本和枚举由服务二次校验。事实决定只能绑定本事实版本。更正影响由确切关系回查，不通过关键词猜测派生链。实体身份、内容版本和核实决定分别记录，不将 revision 当作版本 ID。

## 5. S3 第二批附件与安排边界

上传意图、传输尝试、私有目录与容量、格式白名单、鉴权下载、独立解析进程、失败恢复、不可变摘录的精确规则统一放在[附件与安排契约](附件与安排接口与数据契约.md)，机器结构纳入 [S3 OpenAPI](openapi-s3.json)。文件 I/O 和 PDF／DOCX 解析不持有 owner 事务锁；原件、解析执行及摘录分开，失败保留预留额度与可追溯状态。解析文字先预览，不自动生成已确认事实。

私人安排使用确切 UTC 时刻＋IANA 时区、目标／轮次／备注、确切材料版本、改期历史与取消状态。S3 接入安排与站内提醒，路线、题单和复练任务仍依其阶段；改期不移动尚未接入的其他任务，浏览器关闭不保证推送。接口、DST 与历史边界同样以第二批契约为准。

## 6. 静态与服务器验证

本地不启动应用、不写单元测试。第一批核对 DTO／机器契约／Mapper／DDL、前后端类型和打包；运行场景以 AC-02／04／05／43／44／45 为主：JD 改版不改旧依据，事实编辑重置核实、撤回阻止新引用，表达保留旧依据并提示更正，跨 owner 及错配版本拒绝，双标签冲突和未知响应保留本地输入，归档焦点与恢复状态正确。第二批补充附件 AC-47 和安排 AC-35，具体服务器场景在开发记录维护，全部待服务器验收。
