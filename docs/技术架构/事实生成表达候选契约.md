# 事实生成表达候选契约

日期／版本：2026-11-12 · v1.2。适用 S5 第十一批；原范围静态检查通过待服务器验收，S8 第九批表达依据复核接入代码及专项检查完成，整体构建阻塞与服务器欠项继续保留。承接 [PRD](../需求文档/产品需求文档.md) MAT-04、AI-02–06、[准备内容](准备与资料接口与数据契约.md)和[准备版本外发](准备版本生成候选契约.md)。实际进度与验证证据见[开发记录](../开发记录/开发阶段与进度.md)。

## 1. 流程与事实边界

选择 1–5 个本人已确认的事实当前版本 → 选择自我介绍、简短／完整项目介绍、STAR 或技术取舍 → 核对固定外发文本及费用 → 本次授权 → 阅读表达候选与引用 → 编辑最终表达和依据 → 显式新建表达或保存为已有表达的新版本，也可忽略候选。

仅输入确切 FACT，按 itemId 去重并保留选择顺序；允许跨项目选择。本批投影不含所属项目身份，模型须逐事实独立组织，不能推断事实之间的项目归属、时间或因果联系，也不得擅自合并成同一经历。事实及其父项目必须当前可用，职责保持 OWNER／PARTICIPANT／FAMILIAR；确认“仅了解”不等于本人实施。要求只是表达方式，不能作为新增经历的依据。不得新增经历、指标、时间、组织、技术、职责或结果；信息缺失可如实说明，不能为凑齐 STAR 编造结果。模型不能满足结构即按任务失败处理，不自动扩充来源或再次调用。

使用准备来源的固定白名单正文与 sourceGeneration／projectGeneration；附带当前版本标题、版本号和身份，不发送核实原因、source、附件、其他事实、项目概况、旧表达或计划。来源及要求都视为不可信资料，不能扩展工具、权限、请求或预算。用户在允许字段中手贴的私人内容仍会发送。

本批生成表达内容；准备建议由[第十二批契约](准备建议与任务契约.md)负责，已有表达作为模型输入由[第十四批契约](表达素材输入与来源契约.md)补充，两者不改变本篇 FACT 输入范围。事实提取见[资料与训练事实候选](资料与训练事实候选契约.md)；表达保存时的事实／项目代次与显式复核见[表达素材依据复核](表达素材依据复核契约.md)。AI采用与普通保存共用基线捕获，旧版本／清单／回执不改。准备来源到已采用知识的更正传播仍未覆盖。

## 2. 请求和清单

| 方法／路径 | 请求／响应 |
|---|---|
| POST `/api/v1/ai/expression-drafts/preview` | ExpressionDraftPreviewRequest → Preview，只读 |
| POST `/api/v1/ai/expression-drafts/tasks` | CreateExpressionDraft → Task，201；Idempotency-Key |
| POST `/api/v1/ai/tasks/{id}/adopt-expression` | AdoptExpression → Task；Idempotency-Key |
| POST `/api/v1/ai/tasks/{id}/ignore` | 沿用 ChangeTask，按用途保存表达决定 |
| GET `/api/v1/ai/expression-origins?expressionId=&versionId=&beforeVersion=&limit=20` | OriginPage；按确切目标版本及更早版本查询已采用任务 |

`ExpressionDraftPreviewRequest={type,instruction,factSources}`。type 使用既有 `INTRO|PROJECT_SHORT|PROJECT_LONG|STAR|TRADEOFF`；factSources 为 1–5 个 SourceLink，禁止空、重复、跨 owner、错域或非当前确认版本。instruction trim 后最多 1000 UTF-16 码元，禁止 NUL。CreateExpressionDraft 增加 expectedManifestHash、consentConfirmed=true，所有请求字段显式提供。

用途固定 EXPRESSION_DRAFT。Manifest 尾部增加可空 expressionType；sources 全为 FACT，preparationChecks 一一对应，training／evaluation／contextChecks／materialQa／materialDraftSources 为 null。提示版本为 `expression-draft-1`；外发字段仅 purpose、instruction、expressionType、sources，固定字节投影沿用 32 KiB 上限。授权代次参与本地摘要，不外发模型。

旧请求 DTO、路径及原键摘要不变，旧用途禁止携带 expressionType；旧存储清单缺此字段按 null。Task 尾部增加可空 expressionCandidate／expressionDecision，旧回执缺字段可读，不重算历史 hash；尚未创建任务的旧预览可能需要重新预览。

## 3. 输出与采用

模型严格输出 `{title,body,citations}`。标题 trim 后非空且不超过 200 UTF-16 码元，正文 trim 后非空且不超过 12000 UTF-16 码元；禁止 NUL 和不完整代理对。citations 为 1–5 个既有 Citation，只指向清单内 FACT 的确切版本；相对固定 body JSON 文本校验 UTF-16 范围、逐字 quote、代理对及重复区间，不相对于原事实某个字段。引用合法不证明语义蕴含或经历真实。

服务端回填授权 type 及 validationNote，形成 `ExpressionCandidate={title,type,body,citations,validationNote}`。不将表达结果写入知识候选或题目候选字段。候选与所有已发送输入保留原样。

`AdoptExpression={expectedRevision,mode,targetItemId,expectedTargetVersionId,expectedTargetRevision,content,confirmed}`。mode 为 NEW／EXISTING；NEW 三个 target 字段必须为 null；EXISTING 必须是本人 ACTIVE EXPRESSION，匹配目标当前 versionId 与 revision。准备域没有独立草稿版本，不挪用知识草稿修订号。

content 使用既有 ExpressionContent。type 必须等于授权类型；title/body 遵循上述非空和 Unicode 规则；factVersionIds 为任务来源版本的非空去重子集，最多 5 项；tags 沿用准备域规则。用户可删减不相关依据，不能在采用时添加未参与本任务的事实。界面默认按候选引用选取依据，顺序沿用清单。生成来源与用户最终依据分别展示；用户改写不伪称逐句受原候选引用支持。

采用前重新校验任务全部来源及代次，包括用户最终未选的原来源。新建保存首版；追加保存用户审阅的完整新版本，不自动拼接旧正文。每任务只能采用或忽略一次；新幂等键也不能产生第二次决定。采用无需模型配置启用，不追加模型调用。忽略不要求来源当前，失效时保留改写并可复制到手工编辑。

## 4. 事务、历史及恢复

沿用 owner 锁、任务状态机、预算、尝试、取消、重试、进程恢复和 SSE 通知。创建、重试、排队恢复、领取、发送、结果接纳及采用均校验固定来源和代次；正常来源失效保留已发生的实际／未知费用，数据库故障传播。旧用途的互斥结果检查必须拒绝表达候选。

V22 扩展 ai_task 用途 CHECK，并新建 ai_expression_decision：owner＋task 主键、目标版本唯一、owner 复合外键；ADOPTED 保存 mode 和目标身份／版本，IGNORED 三者为空。事实输入继续保存在 V20 ai_preparation_source。准备域提供加入外层命令事务的表达保存入口，复用内容／引用校验、不可变版本与 FACT_BASIS 关系，不嵌套创建另一份幂等回执。

采用时表达正文、确切事实依据、当前指针 CAS、表达决定、AI 任务修订、通知及回执同事务提交，失败全部回滚。ExpressionDecision 字段为 status、mode、targetItemId、targetVersionId、createdAt。

采用来源查询先按确切表达版本分页已采用任务，再读取原固定清单与 V20 来源；核对身份、顺序、数量，保留当时标题和版本，仅状态随当前事实可用性变化。未采用任务不进入历史；CURRENT 不代表旧授权代次仍有效，也不表示人工改写的每一句都获证明。手工保存的后续表达可查看更早采用来源，但标记为历史采用，不冒称本版本由 AI 生成。

前端复用事实选择、预览、任务、来源、命令恢复与守卫。切换创建用途、任务、目标、历史、会话与配置时保护输入；预览按身份、顺序、类型和代次核对，拒收迟到响应。创建固定原路径、请求和幂等键；未知提交继续原键恢复。来源或目标冲突保留人工改写，重新读取目标只更新目标基线，不能覆盖最终编辑正文。
