# 准备建议与任务契约

日期／版本：2026-11-07 · v1.0。适用 S5 第十二批与提前接入的 S7 普通准备任务子集，状态：静态检查通过待服务器验收。承接 [PRD](../需求文档/产品需求文档.md) PRE-04、DAY-02／03、普通任务完成口径及 AI 准备建议；实际进度与检查证据见[开发记录](../开发记录/开发阶段与进度.md)。

## 1. 使用流程与本批边界

普通准备任务可以手工创建，也可以从 AI 准备建议中显式采用。每个任务有独立身份、当前修订和不可变历史；编辑日期、开始、暂停、完成或取消都保留同一身份。用户在“准备 → 准备任务”执行安排，AI 任务保留最初的建议、外发条件和采用时的最终内容。

AI 流程：选择一个当前目标版本 → 填写准备区间、时区、整个区间的时间预算及自述缺口 → 预览完整外发清单并授权 → 阅读原建议 → 修改最终安排 → 一次确认创建普通准备任务。生成成功、用户采用与准备任务完成是三个不同状态。完成只表示用户确认做完该事项，不更新掌握度、回忆卡、复练动作、面试结果或能力证据。

本批提前实现普通任务及其历史，完整今日聚合、跨来源去重、回忆排程、自动重排和面试改期联动仍属于后续 S7。PRE-04、DAY-02／03 不因本批关闭。准备任务不属于 TARGET／PROJECT／FACT／EXPRESSION，也不是题库 ROUTE 或实际 InterviewEvent；各域仍保持原身份与规则。

## 2. 普通准备任务

`Content={title,detail,minutes,plannedDate,zoneId}`：title 为非空 1–200、detail 为 0–1000 UTF-16 码元，禁止 NUL／不完整代理对；minutes 是 1–1440 整数。plannedDate 可为 null，表示尚未安排日期；非空时为严格 `yyyy-MM-dd`、有效公历日期、年份 1000–9999。zoneId 必须明确为服务端支持的 IANA 区域或 UTC，不接受固定偏移作为区域。

保存的是日期级安排，不转换为午夜 UTC 或准确起止时间。日期可以在过去，不自动顺延、完成或失败；跨午夜不会改变授权摘要和原键回执。界面可以按保存时区提示过往日期，但提示不修改记录。分钟是预计工作量，1440 为单项／单日的名义工作量上限，不是 DST 当天实际长度、空闲时段或实际耗时。

任务可绑定一个目标确切版本，或手工创建无目标任务。有目标的新建只接受本人当前 ACTIVE TARGET；固定 itemId、versionId、版本号和标题。创建后目标和 AI 来源不可改绑。目标后续改版／归档只改变详情里的当前来源提示，用户仍可处理该任务；历史不自动换成目标新版正文。

`PreparationTask` 保存 id、revision、content、status、目标快照、可空 sourceAiTaskId／sourceStep、startedAt／completedAt 及创建／更新时间。sourceStep 是最终采用列表中的序号，非模型原步骤 ID。详情为 `{task,targetCheck}`，历史只保存当时的任务快照，不把当前来源检查写回历史。

| 当前状态 | 允许的显式迁移 |
|---|---|
| TODO | IN_PROGRESS、PAUSED、DONE、CANCELLED |
| IN_PROGRESS | PAUSED、DONE、CANCELLED |
| PAUSED | IN_PROGRESS、DONE、CANCELLED；从未开始时还可回 TODO |
| DONE／CANCELLED | 终态，本批不重开或编辑 |

第一次显式进入 IN_PROGRESS 才记录 startedAt；暂停／恢复保留它，直接标记完成可以没有开始时间。只有 DONE 写 completedAt。相同状态的重复新命令拒绝；同幂等键恢复原回执。每次创建、内容／日期编辑或状态迁移写不可变完整修订，动作分别为 CREATE／EDIT／STATUS。保存与状态迁移都要求 expectedRevision，不覆盖并发修改。

| 方法／路径 | 请求／响应 |
|---|---|
| GET `/api/v1/prepare/tasks` | status、targetId、from／to、cursor 可选；limit 默认 20、最大 50 → TaskPage |
| POST `/api/v1/prepare/tasks` | `{target,content}` → TaskDetail，201；target 显式为 null 或 SourceLink |
| GET `/api/v1/prepare/tasks/{id}` | TaskDetail，包含当前目标来源检查 |
| PUT `/api/v1/prepare/tasks/{id}` | `{expectedRevision,content}` → TaskDetail |
| POST `/api/v1/prepare/tasks/{id}/status` | `{expectedRevision,status}` → TaskDetail |
| GET `/api/v1/prepare/tasks/{id}/history` | before 为修订号、limit 默认 20 最大 50 → `{items:[{action,snapshot}],nextBefore}` |

列表日期过滤必须成对提供 from／to，包含首尾且不超过 366 天；按各任务保存的 plannedDate 比较，非 UTC 时段查询。没有日期的任务仅在不使用日期过滤时出现。所有写命令使用 Idempotency-Key、owner 锁、CAS 和同事务回执。API 归入 prepare，沿用独立训练的资料访问守卫。

## 3. AI 输入、授权与输出

用途 `PREPARATION_PLAN`，提示版本 `preparation-plan-1`。专用请求为 `{target,plan,instruction}`；target 是一个本人当前 TARGET 的确切 SourceLink，plan 为 `{startDate,endDate,zoneId,totalMinutes,gapSummary}`。创建请求另加 expectedManifestHash 和 consentConfirmed=true。

startDate／endDate 均必填，包含首尾 1–90 天；使用上一节日期／时区规则。totalMinutes 为整个区间的整数分钟预算，1 至天数×1440，最大 129600；不从目标的 weeklyMinutes 或材料采集日期静默推断。gapSummary 为 0–2000、instruction 为 0–1000 UTF-16 码元，均为显式字符串，禁止 NUL／不完整代理对，保留原文。

Manifest 在尾部追加 preparationPlan；sources 恰好一个 TARGET，preparationChecks 恰好一个匹配的当前状态与来源代次。training、evaluation、contextChecks、materialQa、materialDraftSources、expressionType 均为空。旧用途禁止非空 preparationPlan，旧存储缺字段按 null 读取，不重算历史 hash。来源往返改版／归档恢复不能复活旧授权。

外发白名单只有 purpose、instruction、sources、preparationPlan；TARGET 使用现有 company／jd／requirements 固定投影及版本身份。来源检查与代次只参与本地摘要，不发送模型。目标关联知识、事实、附件、真实面试安排、回忆卡、行动、历史训练和能力画像均不自动读取。用户手填缺口仅为自述，不认证能力缺陷；instruction 是安排偏好，不能扩展事实、工具或预算。

模型严格输出单个对象 `{title,summary,steps,limitations}`，所有字段必填，不接受额外字段。title 为非空 1–200，summary 为 0–2000，limitations 为非空 1–2000 UTF-16 码元；steps 为 1–20 个 `{date,title,minutes,detail}`。每步标题非空 1–200、说明 0–1000、分钟为 1–1440 整数，日期必须位于原区间、按日期非降序排列。按天汇总不超过 1440，总和不超过授权预算，可留余量，不要求填满步骤数或预算。所有文本沿用 Unicode 约束。

服务端回填 validationNote：仅核验结构、日期与工作量限制，未验证建议有效性、用户实际缺口、每日空闲和日程冲突。模型不能输出已有任务／题目／卡片／动作 ID、提醒、完成状态或工具操作。候选保留原样；不以引用岗位要求证明学习安排或个人能力。

| 方法／路径 | 请求／响应 |
|---|---|
| POST `/api/v1/ai/preparation-plans/preview` | PreparationPlanPreviewRequest → Preview，只读 |
| POST `/api/v1/ai/preparation-plans/tasks` | CreatePreparationPlan → Task，201；Idempotency-Key |
| POST `/api/v1/ai/tasks/{id}/adopt-preparation-plan` | `{expectedRevision,content,confirmed}` → Task；Idempotency-Key |
| POST `/api/v1/ai/tasks/{id}/ignore` | 沿用 ChangeTask；记录忽略决定 |

Task 尾部追加 preparationPlanCandidate／preparationPlanDecision；新用途其他候选、决定、报告及 evaluationDecisions 均为 null，旧用途保留原语义。决定为 `{status,content,tasks,createdAt}`；采用时 content 为人工最终 `{title,summary,steps}`，tasks 为 `{step,taskId}` 列表；忽略时 content=null、tasks=[]。旧回执缺新增字段仍可读取。

字段结构、日期、时区、分钟数及 Unicode 校验失败返回 400；固定外发文本超出 32 KiB、待执行任务容量或 AI 修订号达到上限返回 422 AI_LIMIT。来源／授权变化、并发修订或费用预算冲突沿用 409；不能把学习分钟预算与模型费用额度混为一个错误条件。

## 4. 采用、事务与异常恢复

用户可增加、删减或调整最终步骤，但仍需 1–20 步，并重新满足原区间、时区与预算限制。每项采用只创建新任务，初态 TODO；任务明确绑定本次目标版本、AI 任务 ID 和最终序号。不同 AI 任务的相似标题不自动合并；同一 AI 任务只能采用或忽略一次，换新幂等键也不能重复创建。

采用前在 owner 命令事务内核对任务 revision、成功状态、未决定，以及完整原目标来源／代次。planning 提供 MANDATORY 内部入口，复用普通任务内容校验和初始历史，加入外层事务。任务、初始历史、人工最终安排、任务映射、AI 决定、任务修订、通知和原键回执共同提交，失败全部回滚，不嵌套第二份幂等事务。后续人工编辑真实任务不倒改当时的采用正文。

V23 建立普通任务及修订历史；源目标和 AI 任务使用 owner 复合外键，AI 来源任务＋序号唯一。V24 扩展 AI 用途 CHECK 并保存准备建议决定。两份迁移须在服务器显式执行，本地不运行。候选输入继续使用 V20 的准备来源关系。

沿用既有队列容量、最大尝试次数、费用预留、取消、未知恢复及 SSE。学习时间预算与 AI 按 UTC 日期记账的费用预算独立。创建、重试、恢复、领取、发送、接纳及采用核验来源；已发送后来源失效或输出不合法仍保留实际／未知费用，数据库异常不能伪装成来源失效。采用不调用模型、不要求模型配置仍启用；忽略不要求来源当前。

前端保留页面内输入、原路径／正文／幂等键和未知响应恢复；切换用途、任务、登录及资料访问状态时守卫未保存内容。来源失效、并发冲突时保留改写；刷新基线不覆盖编辑内容。迟到任务回执不得清空已知终态决定。页面内草稿不宣称刷新后持久恢复。普通任务页面及 AI 明细提供双向来源跳转；历史只读。
