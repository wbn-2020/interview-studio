# 人工反馈与面后回忆关系候选契约

版本：v1.2 · 2026-11-10。适用 S5 第二十七批及后续独立AI反馈／手工回忆证据的兼容边界，状态：本批原实现静态检查通过待服务器验收。本文定义人工反馈／面后回忆生成关系候选的实施契约，承接 PRD KNOW-06／07、REV-06、AI-02–06，以及[知识关系候选](知识关系候选与逐项采用契约.md)、[资料训练来源关系候选](资料训练来源关系候选契约.md)、[关系补充](正式关系补充理由与来源契约.md)和[候选星图](知识关系候选星图契约.md)。§10保留第二十七批源码核对及主会话提供的构建、前后端独立复核证据；静态检查不表示功能或服务器验收通过，唯一进度记录为[开发阶段与进度](../开发记录/开发阶段与进度.md)。

第二十八批[AI反馈生成关系候选](AI反馈生成关系候选契约.md)为独立第四模式，不扩本Input或V43来源种类。当前Manifest第24尾relationAiFeedback在本模式须缺省／null；旧摘要仅剥离新增空尾，reviewDraft的固定内容及提示版本保持。reviewCitations虽共用字段形状，但本模式仍以人工反馈／回忆Input校验，AI模式另用Snapshot专用规则，不能互换来源。当前出处新增relationAiFeedback及其状态在本模式为空；下文23字段与v7.21.0统计均为第二十七批基线，当前累计规格和本轮证据见开发记录。

## 1. 业务流程与边界

用户选择2–5个本人ACTIVE、当前已发布的NOTE／CONCEPT版本，其中至少两个CONCEPT，再选择一条当前自检／外部反馈修订，或一条ACTIVE面后回忆的当前版本与对象修订，手选1–8段原文。完整预览所选知识、复盘片段、必要限定、供应商／模型与费用后，单次授权生成0–10条关系候选。依据不足可以返回零候选，不为连通星图或主题共属补造关系。

本批是 `RELATION_DRAFT` 的第三种输入模式；沿用既有purpose、任务、逐项采用／补充／忽略和星图目录。知识限定端点及可引正文，人工反馈或回忆提供额外依据；只有所选CONCEPT的itemId可作端点，NOTE、反馈、答案、回忆和图元素均不能成为关系端点。

人工反馈包括SELF_CHECK与EXTERNAL_FEEDBACK，保留当时条件、依据、限制和决定；接受、争议或忽略只是用户决定。面后回忆保留记忆不确定性与有无旧答的性质，不能冒充正式训练Answer、面试实录或能力证据。候选、结构校验与引文命中均不认证反馈者身份、来源真实性、关系语义或技术正确，也不表示用户已经掌握。

本批不包含AI评价反馈生成关系候选、面后回忆手工关系证据，也不改写[人工反馈手工证据](正式关系反馈原文证据契约.md)、[AI反馈手工证据](正式关系AI反馈原文证据契约.md)或[复盘片段沉淀知识](复盘与面后片段沉淀知识契约.md)的原流程。持续范围授权、模型暂态正文流、统一检索及S8其余范围继续按开发记录推进，不因本入口完成而关闭。

## 2. 请求、确切来源与固定输入

[AiDtos](../../backend/src/main/java/com/wenjie/studio/ai/AiDtos.java)定义两个专用请求，source复用[ReviewDraftDtos](../../backend/src/main/java/com/wenjie/studio/ai/ReviewDraftDtos.java)：

```text
RelationReviewPreviewRequest = {instruction, sources, source}
CreateRelationReviewDraft = {instruction, sources, source,
                            expectedManifestHash, consentConfirmed}
sources[] = {itemId, versionId}
source = {kind, feedback, recollection}
feedback = {feedbackId, feedbackRevision, fragments}
recollection = {recollectionId, versionId, expectedRevision, fragments}
fragment = {field, start, end, quote}
```

所有请求字段必须显式提供。instruction允许空字符串，但不得为null；最多1000个UTF-16码元，禁止NUL与孤立代理，包含两端空白的原文用于预览、Manifest、外发及回执，不执行strip。知识sources按选择顺序固定，2–5个对象及版本分别不重复，至少两个CONCEPT；只接受当前ACTIVE已发布版本，不用草稿或最新版本替换用户选择。创建须提供64位小写SHA-256的expectedManifestHash和consentConfirmed=true。

source分支互斥：SELF_CHECK／EXTERNAL_FEEDBACK仅feedback非null，recollection明确null；RECOLLECTION仅recollection非null，feedback明确null。反馈revision范围1–100，须等于当前head且实际kind一致。回忆expectedRevision范围0–1000，须等于当前对象修订；versionId须为当前版本且状态ACTIVE。owner、反馈修订与原提交关联、回忆版本归属均由服务端核验。

每次明确选1–8个片段，不跨反馈／回忆混选，不默认全选。片段使用原字段绝对UTF-16半开区间，满足 `0 ≤ start < end`、`quote.length=end-start`，逐字匹配原文；每段非空白且最多8000码元，拒绝NUL、孤立代理和拆开代理对的边界。相同field的区间不得重复或重叠，相邻允许；保留所选顺序，不trim、截断、折叠或正规化。

| 来源kind | 可选field | 随选区完整固定并外发的限定 |
|---|---|---|
| SELF_CHECK／EXTERNAL_FEEDBACK | OBSERVATION、CONDITION、BASIS、LIMITATION、SUGGESTION | 完整condition、basis、limitation；dimension、coverage；该修订当时最新decisionRevision／decisionChoice；反馈身份、确切AnswerLink、answerNumber、提交时answerCondition。 |
| RECOLLECTION | QUESTION、CONDITIONS、ANSWER_FRAGMENT、FEEDBACK、UNCERTAINTY、GAP | 完整uncertainty、baselineKind、title、type；确切recollectionId、versionId／versionNumber、sourceRevision。 |

必要限定不占选区名额，预览必须完整展示；即使只选择限定的一部分，完整限定仍是本次明确授权内容。完整背景已发送不扩大模型引用权限，引用仍须落在实际选区内。baselineKind=NONE禁止选择或引用ANSWER_FRAGMENT，不能由题目、安排或模型推断补造旧答。

人工反馈未决定时固定 `decisionRevision=0,decisionChoice=null`；已决定时固定该修订的最新决定revision1–20和ACCEPTED／DISPUTED／IGNORED，不要求先接受。反馈外发不包含authorLabel、决定原因、原citations、完整原答、题面、个人参考或相邻反馈。回忆不外发关联interview／安排快照、公司、时间、目标或其他未选正文。

固定 `ReviewDraftDtos.Input` 为 `{kind,feedback,recollection}`，仅一个内容分支非null：

| 固定DTO | 完整字段 |
|---|---|
| FeedbackInput | feedbackId、feedbackRevision、answer、answerNumber、answerCondition、dimension、coverage、decisionRevision、decisionChoice、condition、basis、limitation、fragments |
| RecollectionInput | recollectionId、versionId、versionNumber、sourceRevision、title、type、baselineKind、uncertainty、fragments |
| Fragment／Citation | field、start、end、quote |

answer为原 `AnswerLink(sessionId,questionId,answerId)`；answerNumber和answerCondition来自确切不可变提交。sourceRevision是回忆对象修订，versionNumber是内容版本号，不能互换。内部为核验归属与历史可读取必要记录；授权和实际外发只能使用上述固定Input白名单。

## 3. Manifest、外发预算与兼容

Manifest仍为23字段，复用第20项 `reviewDraft: ReviewDraftDtos.Input`，不增加字段、purpose或迁移。本模式purpose=RELATION_DRAFT、promptVersion=`relation-review-draft-1`、sources保留完整六字段知识Source、reviewDraft非null；relationEvidence及其他用途专属字段均为null。旧KNOWLEDGE_DRAFT复盘整理仍为sources=[]、`review-knowledge-draft-1`，其校验与模型结果规则保持独立。

[AiSources](../../backend/src/main/java/com/wenjie/studio/ai/AiSources.java)与[ModelGateway](../../backend/src/main/java/com/wenjie/studio/ai/ModelGateway.java)须共用唯一业务投影 `{purpose,instruction,sources,reviewDraft}`，用于预览、字节预算、输入费用估算及两种协议外发。投影完整包含知识正文、选区、必要限定、固定身份、提交条件、决定和回忆修订；不附带完整答案、原反馈引文链或安排。配置与费用元数据在Manifest授权中显示，不作为来源正文混入此投影。

32KiB UTF-8上限计入整个业务投影，包括中文、补充字符、JSON转义、身份、标题、完整限定及instruction；当前配置更严格时沿该限制拒绝。超限要求用户调整选择，不截断正文、不省略限定或决定、不自动拆任务或扩大授权。

复用原 `AiSources.hash` 函数，不增加新的摘要兼容规则。reviewDraft非null时全部固定输入参与原Manifest摘要；旧relationEvidence／factDraft／cardDraftType／reviewDraft空尾兼容按既有规则继续，不全局删除null或改写历史hash。旧两种关系请求、prompt、操作字符串和幂等摘要保持；纯知识关系的strip规则不反向应用到本批instruction。

RelationSuggestion末尾增加nullable `reviewCitations`。旧纯知识和资料／训练关系候选仅接受该尾字段缺省或null，不接受[]或非空数组；原materialCitations／trainingCitations兼容规则不变。新模式必须显式有非null reviewCitations，materialCitations与trainingCitations均明确null，不能用空数组伪装分支。前后端均按Manifest、prompt及引用分支判别，不能只看purpose。

候选与迟到回执的比较保留summary、limitations、validationNote、rN、端点／类型／理由及全部引用身份、区间、quote和顺序；仅把历史允许缺省的引用尾字段与null视为等价。决定比较仅沿原supplementId缺省／null兼容，不能省略最终内容、relationId、状态或时间。归一只用于核对，不重写原候选或回执。

## 4. 模型结果与严格持久读回

模型输出精确为 `{summary,limitations,relations}`：summary为1–1000个UTF-16码元，limitations为1–2000，relations为0–10项；每项reason为1–1000。新模型summary、limitations、reason及知识引文使用严格Unicode空白规则；review引文和来源文本沿既有Java `isBlank`规则，不能用新规则改判历史来源。上述文本均拒绝NUL和孤立代理。模型不输出id、validationNote、正式relationId、决定或自动完成字段。

每项模型对象只有六字段：`{sourceItemId,targetItemId,type,reason,citations,reviewCitations}`，不允许materialCitations或trainingCitations。端点是所选sources中两个不同CONCEPT的itemId；type为PRECEDES／PART_OF／APPLIED_IN／RELATED／CONTRASTS。前三级保留方向，对称类型按小写UUID字典序归一，同规范端点＋type不得重复，不同类型可并存。服务端按原顺序赋予r1–r10。

| 引用数组 | 约束 |
|---|---|
| citations | 0–5条 `{itemId,versionId,start,end,quote}`，只引用所选确切Source.body；quote最多500个Unicode码点，坐标为原body UTF-16半开区间。 |
| reviewCitations | 1–6条 `{field,start,end,quote}`，quote非空白、最多1000个UTF-16码元；field属于该来源允许集合，原字段绝对区间必须完整落入某一个已选fragment，并逐字匹配。 |

每项两数组合计1–6条，整份最多60条；两数组必须显式存在且非null。知识引用不能替代至少一条复盘选区引用。拒绝重复引用位置、越界、跨选区空隙、选区内相对坐标、错field、NUL、孤立代理及代理对拆分；完整外发的限定或不确定性不能授权引用其未选区间。引用没有elementId、反馈ID或citationIndex，来源身份由固定Input给出。

服务端补充固定validationNote：

> AI 未审关系候选，结构、所选概念端点及知识、自检、用户录入外部反馈或面后回忆选区的原文区间已核对；保留原条件、依据、局限、当时决定与不确定性。不认证反馈者身份、来源真实性、关系语义、技术正确或用户已经掌握，回忆和无旧答不能替代正式提交。候选需逐项审阅，不会自动进入正式星图。

持久RelationSuggestion为九字段：六个模型字段加id、materialCitations=null、trainingCitations=null。读回精确核验这些字段、原rN顺序、已经归一的端点、固定说明、来源分支及全部引文，不修补损坏历史。模型接纳、任务详情、Graph、逐项命令和出处均不得因任务已成功而跳过严格候选校验。

## 5. API与访问守卫

[AiController](../../backend/src/main/java/com/wenjie/studio/ai/AiController.java)使用独立的严格请求入口：

| 方法与路径 | 请求与结果 |
|---|---|
| POST `/api/v1/ai/relation-review-drafts/preview` | RelationReviewPreviewRequest → Preview；完整清单、hash与预算，不创建任务或调用模型。 |
| POST `/api/v1/ai/relation-review-drafts/tasks` | CreateRelationReviewDraft → 201 Task；CSRF与Idempotency-Key，单次外发同意后创建任务及固定来源。 |

[累计OpenAPI](openapi-s7.json) v7.21.0新增 `aiPreviewRelationReviewDraft`、`aiCreateRelationReviewDraft`，对应AiRelationReviewPreviewRequest与AiCreateRelationReviewDraft请求schema；当前为302 paths／356 operations／980 schemas／7384 refs，Manifest仍23字段。主会话提供的旧协议比对结果为旧300 paths／354 operations原语义保持，仅12处既有schema调整和两个新请求schema；本文已直接解析核对当前统计及两个新operationId，未将全部旧schema称为逐字不变。

请求从原始字节解析，最大262144bytes。逐层拒绝重复键、尾随JSON、未知／缺失字段、错误null、数字枚举、字符串／浮点整数、隐式标量转换以及错误数组成员；UUID为标准小写格式。字段错误沿INVALID_REQUEST，来源当前性变化沿AI_SOURCE_CHANGED，创建清单摘要变化沿AI_MANIFEST_CHANGED；恢复流程不能把数据库或结构错误伪装成普通来源变化。

新入口、任务正文、Graph、出处及原键恢复沿现有登录、owner与独立训练资料守卫。人工反馈另须核对确切AnswerLink的评价区访问、当前反馈时机、提前反馈许可与访问记录；不能凭旧访问行放行，不能在后台调用grantAccess。AFTER_SESSION且会话尚未结束时，仍须在原入口明确提前反馈许可。

来源绑定、当前访问和来源当前性各自核对。任何会返回固定复盘正文的读取或原键回执，必须先核绑定与 `ReviewDraftSources.requireAccess`；不能因为知识先失效、current返回false或来源状态是UNAVAILABLE而跳过访问守卫再返回正文。GET／Preview的序列化资料守卫与写命令owner事务内、恢复原回执前的守卫分别保留，不将所有POST笼统表述为序列化前再次检查。

反馈选区器使用窄来源读取，只取得本次反馈文本、固定提交条件、限定与当时决定；不为选区加载 `/review/context` 的完整题面／原答。回忆详情或确切版本由用户显式打开，其既有读取可能含安排快照；内部读取范围不等于授权外发范围，模型投影仍严格排除安排。来源服务直接复用[ReviewDraftSources](../../backend/src/main/java/com/wenjie/studio/review/ReviewDraftSources.java)，不经ReviewService形成与AiService的循环依赖。

## 6. V43绑定、当前性与任务生命周期

本批复用[V43来源表](../../backend/src/main/resources/db/migration/V43__ai_review_draft_sources.sql) `ai_review_draft_source` 及[既有mapper](../../backend/src/main/resources/mapper/ai/ReviewDraftBindingMapper.xml)，不新增或改写表、迁移或mapper。表按owner＋task唯一，通过owner复合FK固定反馈修订、原提交、当时决定，或回忆版本及sourceRevision；其表级约束没有purpose限定。应用层须按任务用途分别接受旧知识整理与新关系模式，不能据共享表放宽其他用途。

正文保存在Manifest.reviewDraft，台账只保存完整来源身份。正常新关系任务必须恰有匹配V43行及全部原知识来源行，不写V52资料／训练关系来源；旧其他模式不得带孤立V43行。绑定与Manifest的kind、反馈revision、AnswerLink、决定revision／choice、回忆version／sourceRevision必须逐项一致。新关系绑定守卫同时经 `relationKnowledgeSources` 核对知识来源总数、从1连续的ordinal、taskId、itemId／versionId、number、title和kind；此核对不回调任务绑定或逐项决定，避免循环，并使生命周期入口均发现缺行、错序或元数据漂移。

[AiService](../../backend/src/main/java/com/wenjie/studio/ai/AiService.java)在同一owner锁事务中重建完整清单、核hash与容量、预留费用、写任务及首次尝试、写知识来源与V43绑定、写后核对，再保存修订／通知与回执。任何失败整体回滚，不留下半套来源。读取、领取、发送前、结果接纳、恢复／重试、取消／费用命令、逐项决定、出处及Graph都核任务用途、Manifest／hash与固定绑定；成功状态与候选存在性须一致。

新发送、结果接纳及首次采用／补充要求所有所选知识和复盘来源当前；未实际引用的所选知识也不能略过。本批复盘当前性使用严格 `state == CURRENT`，识别回忆sourceRevision或反馈decisionRevision倒退为完整性错误；旧KNOWLEDGE_DRAFT复盘当前性分支保持原规则。历史读取、原键恢复和忽略不要求来源仍当前，但固定完整性和当前资料访问仍为前提。关闭AI不妨碍符合条件的本地采用／补充，也不授权重新外发。

| 来源变化 | 对新执行／采用及历史状态的规则 |
|---|---|
| 人工反馈产生新head | 旧修订不再当前；历史为SUPERSEDED，文字后来改回不恢复旧授权。 |
| 同修订产生新决定 | decisionRevision变化即失效，包括只改原因或改回同choice；历史为REVIEW_REQUIRED，不改原候选或正式边。 |
| 原训练新增答案或暂停／恢复／结束 | 不替换确切AnswerLink、编号或提交时条件；当前访问与提前反馈时机仍单独核验。 |
| 回忆当前归档 | 不再可用于新动作，历史为ARCHIVED。 |
| 回忆产生新内容版本 | 历史为SUPERSEDED，不能自动切换新version。 |
| 回忆同版本但对象修订变化，包括归档后恢复 | 旧sourceRevision失效，历史为REVIEW_REQUIRED；恢复原版本不恢复旧授权。 |
| 仅关联安排改期／取消／目标变化 | 不展开安排、不替换回忆；回忆本身未变时不据安排推断片段已变。 |

人工反馈历史状态优先核确切来源正常缺失，再判head变化、决定变化，完全一致才CURRENT；回忆依次判正常缺失、ARCHIVED、版本变化、对象修订变化，完全一致才CURRENT。适配器对明确正常缺失可给UNAVAILABLE，对明确变化可给对应历史状态；前台正文读取与原键恢复的权限错误仍必须失败。后台当前性仅将AI_EVALUATION_ACCESS_REQUIRED、AI_EARLY_FEEDBACK_CONFIRMATION_REQUIRED这两个明确访问阻断转为false，使来源停止新接纳并沿原费用处理，不因访问阻断回滚已经发生的费用；这不放行正文出口。数据库、JSON、回退修订、绑定缺失／多余、模式／hash矛盾或其他异常继续抛出，不能伪装current=false、空结果或释放费用的依据。

取消、租约、UNKNOWN费用、最多三次尝试、迟到结果及配置／授权代次沿[AI任务与外发契约](AI任务与外发契约.md)。结构或引用不合法与已经发生的模型费用分别处理，不自动退款、重试或换来源。历史绑定核对与当前性判断均须保持在适用事务中，异常不得被吞掉后继续提交。

## 7. 逐项决定、历史出处与回执

新模式沿原关系adopt／supplement／ignore接口，持expectedRevision并明确确认。每个rN至多一个ADOPTED／IGNORED终态；用户可保留或互换原两个概念端点、修改type及reason，不能换第三个概念。新建沿ACTIVE、对称归一、自环、PRECEDES／PART_OF同类型无环与容量规则；同元组已存在返回冲突，不自动补充。

补充须明确选择确切已有relationId，最终规范元组一致；已删边不能自动重建或匹配同元组新边。补充表及source表继续只保存知识版本来源、人工最终内容和taskId／candidateId回链；复盘Input与V43身份留在原任务，不复制成手工反馈／AI反馈证据，不把反馈或回忆ID塞入知识来源表。正式边／补充、决定、修订、通知与回执同事务保存。忽略不新建边、不改反馈决定、不要求来源当前，也不退款。

`GET /api/v1/ai/relations/{relationId}/origin` 的RelationOrigin尾增nullable `reviewDraft`及`reviewDraftState`。新模式显式返回完整固定Input与CURRENT／SUPERSEDED／ARCHIVED／REVIEW_REQUIRED／UNAVAILABLE中适用状态；旧模式新尾字段缺省／null兼容，本模式relationEvidence及relationEvidenceState为null。该出口包含原文与必要限定，须由用户显式打开并先核绑定与当前访问，不能称为仅元数据，也不能借来源失效绕过访问。

原始出处只说明通过AI首次新建边的来源，supplementId为null；人工建边后追加AI补充不因此获得初始AI出处，补充历史回原任务。删边保留原决定、来源与原relationId；相同元组的新边不继承旧出处。来源状态不认证语义，也不表示完整间接依赖已核验。

原键恢复先在owner命令事务内核访问和固定绑定，使用原请求，不重建任务、边或授权。创建回执须对应首次QUEUED／revision0／attemptCount1，唯一number1尝试为QUEUED／RESERVED，预留金额等于获准Manifest，计费、usage、供应商请求ID、错误与发送／完成时间均为初始null；任务与尝试创建时间一致。完整Manifest、原文instruction与所选来源也须匹配，不能接受较晚任务快照或错误金额。

执行结果未知保留原请求、原键和人工稿，通过原键恢复。已知来源／修订冲突保留稿并撤销确认，重新核对后由用户明确提交，不自动换反馈修订、决定、回忆版本或relationId。迟到旧回执可解除原未决状态，但不能回退已知较新候选／决定；旧缺省引用尾与null兼容之外的任何完整引用变化仍须拒绝。

## 8. 同用途目录、星图与已实现界面边界

成功关系任务仍按RELATION_DRAFT进入同一目录；第二十七批三种输入模式保持，第二十八批另加AI反馈第四模式。目录只含状态摘要，不能凭目录存在认定来源完整性通过。用户明确选择任务后，Graph核知识及相应输入来源、候选和全部决定，过滤已决定项但保留原rN，不重新编号。
