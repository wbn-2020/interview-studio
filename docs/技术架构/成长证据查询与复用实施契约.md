日期／版本：2026-11-09 · v0.4。状态：**七来源、受审观察窄投影与21项活动已通过独立静态复核和前后端构建，最终检查见开发记录。服务器验收未执行**。

适用范围：S7 C3／C3-R，覆盖 GROW-01–05 的七类证据目录、活动、当前逐来源处理状态、跨目标复用和可调整建议。受审观察的标准与确切答案规则由[独立契约](标准审阅与受审观察实施契约.md)定义，完整运行验收仍待服务器。本文规定实施规则，实际代码和验证进度另行记录。

业务依据：[完整产品需求](../需求文档/产品需求文档.md) §5.14、§8.2；总体边界见[今日聚合与成长证据契约](今日聚合与成长证据契约.md) §7–11。本文冻结本批新增接口，不改写既有领域请求。实际开发和验证结果只维护在[开发阶段与进度](../开发记录/开发阶段与进度.md)。本地约束引用 [AGENTS.md](../../AGENTS.md)，不在这里重述或放宽。

与总体草案相比，本精确稿提出以下修正，冻结时由主会话统一相关契约和机器规格：

1. 新 C3 当前行 revision 从 0 起，范围为 0–9007199254740991；原反馈、判断等来源保留原领域上限。
2. 修改或恢复 EvidenceUse 必须进行当前预览和 CAS；SUPPORTS 与 PARTIAL 都属于正向覆盖，均受来源当前性约束。
3. 证据发现允许显式跨目标关联；活动只归属于发生时记录的目标，不因后来复用而增加新目标的训练数。
4. 新增逐来源处理目录，避免只给无法追溯的“已处理数”。
5. NextStepPreference只保存HIDDEN／VISIBLE显示意图。GROW-05的优先级调整复用原来源Placement.priority或目标Requirement.priority，界面明确将修改的对象和影响；不另建建议自身的优先级。
6. 新增按 id 读取与修改预览，使回执恢复、撤回、恢复和来源失效后的历史说明具有完整入口。

不引入后台统计服务、消息队列、全量证据正文副本、能力总分、岗位胜任认证或自动任务创建。没有运行 SQL、接口、页面或真实模型；表和索引建议不代表已测性能。

## 2. 公共类型、严格边界和时间

以下 record 为待冻结 DTO 签名，不是已创建的 Java 文件。所有响应字段显式存在；只有声明为 nullable 的字段允许 null。数组不为 null；未知不使用空字符串冒充。OpenAPI 对封闭对象使用 additionalProperties=false，前端严格解析同一联合规则。

~~~java
enum EvidenceKind {
  TRAINING_ANSWER, MANUAL_FEEDBACK, AI_OBSERVATION,
  RECOLLECTION, REPLAY_JUDGMENT, MEMORY_RATING, REVIEWED_OBSERVATION
}
enum AssessmentLevel { SELF_RECORDED, AI_UNREVIEWED, REVIEWED_OBSERVATION }
enum RecordKind {
  ANSWER, SELF_CHECK, EXTERNAL_FEEDBACK, AI_FEEDBACK,
  INTERVIEW_RECOLLECTION, REPLAY_ASSESSMENT, MEMORY_SELF_RATING, REVIEWED_CHECK
}
enum ReviewFlag { DISPUTED, REVIEW_REQUIRED, SOURCE_UNAVAILABLE }
enum LineageCheck { NOT_APPLICABLE, PARTIAL, COMPLETE }
enum Availability { READY, DEPENDENCY_PENDING, NOT_CONFIGURED, ERROR }
enum CapabilityReason {
  NONE, QUERY_NOT_INTEGRATED, REVIEWED_CHAIN_NOT_INTEGRATED,
  MEMORY_SETTINGS_REQUIRED, SOURCE_READ_FAILED, SOURCE_INTEGRITY_FAILED
}
enum CountMode { EXACT, LOWER_BOUND, UNAVAILABLE }
enum FacetBasis { RECORDED, CURRENT_CLASSIFICATION, USER_LINK }
enum TargetMode { RECORDED_ONLY, INCLUDE_ACTIVE_LINKS }
enum TopicMode { RECORDED_ONLY, INCLUDE_CURRENT_CLASSIFICATION }
enum EmptyState { HAS_RECORDS, RECOLLECTION_ONLY, NO_RECORD, UNKNOWN }
enum DirectState { AVAILABLE, REVIEW_REQUIRED, UNAVAILABLE, UNKNOWN }
enum RecordCurrency { CURRENT, SUPERSEDED, NOT_APPLICABLE }
enum Coverage { SUPPORTS, PARTIAL, CONTEXT_ONLY, INSUFFICIENT }
enum UseStatus { ACTIVE, WITHDRAWN }
enum MatchState { MATCH, DIFFERENT, UNKNOWN }
enum Visibility { VISIBLE, HIDDEN }

record TargetRef(String itemId, String versionId) {}
record QuestionRef(String questionId, String versionId) {}
record EvidenceRef(EvidenceKind kind, String objectId,
                   String versionId, Long revision, String partId) {}
record Capability(Availability status, CapabilityReason reason) {}
record Count(Long value, CountMode mode) {}
record Context(Instant asOf, Instant checkedAt, Instant serverTime) {}
record DateWindow(LocalDate from, LocalDate to, String zoneId,
                  Instant startAt, Instant endAt, Instant observedUntil) {}
record Filter(TargetRef target, TargetMode targetMode, String topicId,
              TopicMode topicMode, QuestionDtos.Dimension dimension) {}
record Scope(DateWindow window, Filter filter) {}
~~~

- UUID 为标准小写；所有 id／versionId 为 UUID，只有 AI observationId／partId 例外，精确模式 f([1-9]|1[0-2])。EvidenceRef 不适用的四个身份字段显式 null。
- 新 revision、计数、毫秒／秒值必须为非负 JS 安全整数；拒绝小数、字符串强制转换及溢出。来源 revision 的更小上限按原域执行。
- 时间为服务端 UTC、微秒精度；日期为严格公历 1000–9999，区域为现有服务校验认可的 IANA／UTC。时间字符串使用现有 Instant 序列化约定，不在浏览器改写身份。
- 日期 from／to 同传或同空，含首尾日期；默认显示区域今天及之前27天，最多366天。zoneId 必填。先由 Java 区域规则计算 startAt、endAt，再按 [startAt, min(endAt, asOf)) 查询；不得依赖 MySQL 时区表。
- endAt 是 to 下一天的日开始；无法计算下一天的极端日期拒绝400。observedUntil=min(endAt,asOf)，早于 startAt 时窗口无已发生部分，显示 FUTURE，不能写真实零。
- asOf 是首请求的事实水位，续页从游标恢复；checkedAt 是本次当前状态检查时间。跨请求不是同一个数据库快照，当前状态可能变化，不能展示成“截至 asOf 的当前争议状态”。
- Count：EXACT／LOWER_BOUND 时 value 非空；UNAVAILABLE 时 value=null。LOWER_BOUND 的0不等于“没有记录”。只有完整同范围查询可给 EXACT。
- title 只取来源保存的标题，至多200码点；不能拿反馈 observation、回答首句或回忆片段代替标题。没有专有标题时使用固定类别文案，正文仍不返回。
- 新写请求原始 UTF-8 ≤256KiB；单项用户 reason 为1–2000码点；comparability 各项 reason 为0–500码点；拒绝 NUL、孤立代理、未知字段、重复 JSON 键、尾随 JSON。普通读响应≤1MiB；仅GET /activity的ActivitySeries允许≤2MiB，按§5的有界结构执行；历史单条≤32KiB，既有2MiB回执边界不变。所有大小指序列化后未压缩的紧凑UTF-8 JSON响应体，不含HTTP头，不能依赖gzip规避上限。
- 以上字节限制超出时整体明确拒绝，不截断用户理由、条件或历史。显示标题的视觉省略属于 UI，不改协议值。

## 3. 七类证据身份、条件与元数据

### 3.1 身份和发生时间

| kind | EvidenceRef 非空身份 | occurredAt | recordKind／assessmentLevel |
|---|---|---|---|
| TRAINING_ANSWER | objectId=answerId | training_answer.created_at | ANSWER／SELF_RECORDED |
| MANUAL_FEEDBACK | objectId=feedbackId、revision=确切反馈修订 | review_feedback_revision.created_at | SELF_CHECK或EXTERNAL_FEEDBACK／SELF_RECORDED |
| AI_OBSERVATION | objectId=taskId、partId=observationId | SUCCEEDED 的 currentAttempt.finishedAt | AI_FEEDBACK／AI_UNREVIEWED |
| RECOLLECTION | objectId=recollectionId、versionId=确切回忆版本 | 回忆版本 createdAt | INTERVIEW_RECOLLECTION／SELF_RECORDED |
| REPLAY_JUDGMENT | objectId=judgmentId | 判断 createdAt | REPLAY_ASSESSMENT／SELF_RECORDED |
| MEMORY_RATING | objectId=RATE eventId | RATE occurredAt | MEMORY_SELF_RATING／SELF_RECORDED |
| REVIEWED_OBSERVATION | objectId=observationId、revision=确切安全修订 | reviewed_observation_revision.created_at | REVIEWED_CHECK／REVIEWED_OBSERVATION |

目录默认保留所有不可变反馈修订和回忆版本，不以当前正文替换旧引用；“证据条目数”是版本／事件数。活动另分“首次创建”和“修订”，不把修订次数称为新增反馈记录数。后续如增加“仅最新版”过滤，须新定义时间窗口语义，不能默默更换默认口径。

AI 只读取 purpose=ANSWER_EVALUATION、status=SUCCEEDED、固定 candidate 非空、对应 currentAttempt 成功且 finishedAt 非空的记录。一次任务内按报告的固定 observationId 分项。成功报告与尝试身份矛盾属于 SOURCE_INTEGRITY_FAILED，不跳过坏数据后声称查询完整。

- Conditions 的 kind 只允许对应七类中的一个非空载荷，其他六项为 null。ReviewedMeta 精确14字段见[受审契约§10.2](标准审阅与受审观察实施契约.md#102-领域投影与公开元数据)，不带原答、检查项文字、引文或观察自由正文；旧六类载荷内容保持原样。

- AiMeta.standard 可空；只保留此次评价输入的固定标准身份和层级，不取后来新增的标准审阅状态改写原评价。
- RecollectionMeta.interview 可空，InterviewMeta.target 可空；后者 itemId/versionId 成对。面试 startAt 不用于 occurredAt。
- ReplayMeta.currentVerificationHash 可空，仅当当前来源无法读取；其余非空。currentlyApplicable 还要求本条 judgmentId 等于稳定 sourceId 的当前最新判断 id，且原领域 progress.applicable 为真、直接依据可用；不能让旧判断借用新版判断的适用性。两个验证摘要相等也不代替完整规则。
- MemoryMeta.budget、scheduleChangeId、scheduleSequence 在 countRegular=false 时均为空；countRegular=true 时均有保存依据。ratingDay.settingsRevision 按原域可能为空；不能补成当前设置修订。elapsed 只是经过时长，不称净专注时长。
- 所有条件元数据来自确切事件或快照；缺字段且原域没有明确兼容规则时，返回该来源错误，不生成默认条件。

### 3.3 Facets、当前状态与原域入口

~~~java
record TargetFacet(TargetRef target, FacetBasis basis) {}
record TopicFacet(String topicId, FacetBasis basis) {}
record DimensionFacet(QuestionDtos.Dimension dimension, FacetBasis basis) {}
record TargetMatch(boolean recorded, boolean activeUserLink) {}
record Facets(List<TargetFacet> targets, List<TopicFacet> topics,
              List<DimensionFacet> dimensions, boolean currentTopicClassificationAvailable,
              TargetMatch selectedTargetMatch) {}
record EvidenceState(DirectState directState, RecordCurrency recordCurrency,
                     List<ReviewFlag> reviewFlags, LineageCheck lineageCheck) {}
record EvidenceStamp(EvidenceRef ref, String originHash, String currentHash) {}
enum EvidenceRouteKind {
  TRAINING_ANSWER, MANUAL_FEEDBACK, AI_OBSERVATION,
  RECOLLECTION_VERSION, REPLAY_COMPARISON, MEMORY_ATTEMPT
}
record EvidenceRoute(EvidenceRouteKind route, EvidenceRef ref,
                     String sessionId, String questionId, String answerId,
                     String comparisonId, String cardId, String attemptId) {}
record EvidenceSummary(EvidenceRef ref, Instant occurredAt, String title,
                       RecordKind recordKind, AssessmentLevel assessmentLevel,
                       Conditions conditions, Facets facets, EvidenceState state,
                       EvidenceStamp stamp, EvidenceRoute route) {}
record EvidenceResolution(EvidenceRef ref, EvidenceSummary summary,
                          EvidenceState state, EvidenceStamp stamp) {}
~~~

- facets.targets 仅列发生时保存的目标；basis 固定 RECORDED，不展开所有 EvidenceUse。selectedTargetMatch 在未指定目标时为 null，指定时非空，表示本次匹配来自原始目标或 ACTIVE 用户关联。重复命中只返回一条证据。
- topics：回答／反馈／AI／新答判断及受审观察取固定题目 topicIds，basis=RECORDED。memory 无历史主题快照；无 topicId 筛选时不全量展开卡片来源的所有当前主题，topics=[]、currentTopicClassificationAvailable=true；有主题过滤且匹配时仅返回这个主题，basis=CURRENT_CLASSIFICATION。
- dimensions：回答及受审观察取原题目固定 dimensions；人工／AI 反馈取其自身 dimension；复练判断取新答题目 dimensions。面后回忆、memory 没有结构化考察项，dimensions=[]，不从文本、派生题目或当前知识标签回填。
- 回忆目标来自固定 InterviewSnapshot。复练判断的目标／主题取新答上下文；旧基线或动作来源的目标只在原对照入口显示，不作为“本次对该目标作答”的归属。
- targets／RECORDED topics 分别沿用原来源上限；训练固定背景共最多12项，因此其中目标也最多12项，单份回忆最多1个目标；题目最多20个主题，dimensions最多6个且去重。超过来源合法上限是完整性错误，不截断。当前主题匹配最多一项。
- EvidenceRoute 不含可任意跳转 URL。前三类及REVIEWED_OBSERVATION必须有 sessionId/questionId/answerId；REPLAY_COMPARISON 还须有 comparisonId；MEMORY_ATTEMPT 仅 cardId/attemptId 非空；RECOLLECTION_VERSION 六个辅助字段均空，其身份来自 ref；未列字段为空。客户端映射到原域私有入口，并按确切 ref 定位。
- EvidenceResolution.summary 仅在“已保存关联的原证据现已不可读”时允许空；此时 directState=UNAVAILABLE、含 SOURCE_UNAVAILABLE，stamp.originHash=null。新建预览遇不到本人合法来源直接404，不能以此 tombstone 机制接受任意 id。
- originHash/currentHash 为64位小写 SHA-256 十六进制。原证据可读时 originHash 非空；currentHash 始终非空。它们是变更检测摘要，不是权限凭据。

当前状态逐来源规则：

| 来源 | 当前读取规则 | 争议、版本及直接依赖 |
|---|---|---|
| 回答 | 不可变答案和其所属会话／题目归属正确 | 原训练背景按 PreparationSources.check 检查固定引用；已知事实／项目撤回或更正提示待复核，不改变原答条件 |
| 人工反馈 | 确切 revision 存在，读取该版最新决定 | DISPUTED 标争议；被后续反馈修订替代标 SUPERSEDED＋REVIEW_REQUIRED；继承其答案直接依赖 |
| AI 观察 | 成功固定报告与尝试一致，partId 确实存在 | 读取对应观察最新决定；DISPUTED 不变成已确认缺陷；继承固定输入直接依赖 |
| 回忆 | 精确版本与固定面试快照可读 | 原 RecollectionSources 的 SUPERSEDED／ARCHIVED 标待复核，不用当前事件目标覆盖历史 |
| 复练判断 | 原 comparison／source／newAnswer 引用一致 | 原 progress.applicable 为必要条件，再叠加来源争议、直接依赖待复核／不可用；不凭旧 HANDLED 计覆盖 |
| 评分 | RATE／attempt／cardVersion 一致，读取原评分事件 | 当前卡版和 gate／Eligibility 分开显示；已知含义变更、归档、来源不可用标待复核，不改原评分及预算 |
| 受审观察 | 确切修订／原答／检查项／标准绑定完整，原答案访问有效 | 当前观察与标准修订／状态、所选检查项依据和原答直接依赖联合判断；旧修订SUPERSEDED，争议／撤回／更正保留历史标记，lineage固定PARTIAL |

directState 优先级为 UNAVAILABLE > UNKNOWN > REVIEW_REQUIRED > AVAILABLE；DISPUTED 必须使 directState 至少 REVIEW_REQUIRED。只有必要直接依赖均已核对且没有上述标志才可 AVAILABLE。普通题目出现后续版本不自动改变过去作答内容；历史题目身份仍保留，是否属于更正影响需有原域事实，不把“版本不同”一概当技术错误。原训练目标存在新版本身只表示历史目标归属，不把原答判为错误或阻止复用到另一个当前目标；事实／项目依据的更正、撤回与目标版本变动分别检查。

lineageCheck：无已建模的间接来源时 NOT_APPLICABLE；存在知识／事实／表达等派生链而 S8 未全面核对时 PARTIAL。COMPLETE 当前不开放，仅可由后续完整依赖实现和验收支撑。PARTIAL 不等于“已确认错误”，也不自动抹去个人证据；必须显示限制。直接状态 AVAILABLE 且 lineageCheck=PARTIAL 时，允许用户在限制可见并显式确认后保存个人适用性判断，不称全部依赖已认证。

共同筛选：

1. targetId/targetVersionId 同传或同空，解析成 TargetRef；必须确为本人 TARGET 的该版本。历史版本可读，不能替换成 currentVersionId。目录读取不要求目标当前 ACTIVE。
2. targetMode 默认 INCLUDE_ACTIVE_LINKS；无目标仍回显默认值，但不执行目标过滤。RECORDED_ONLY 只匹配发生时目标；INCLUDE_ACTIVE_LINKS 加入同确切目标版本的 ACTIVE EvidenceUse，包含 CONTEXT_ONLY／INSUFFICIENT 和当前失效关联，以便发现历史判断。WITHDRAWN 不参与发现。当前有效正向覆盖另算，不由发现命中推断。
3. topicMode 默认 INCLUDE_CURRENT_CLASSIFICATION；RECORDED_ONLY 对 memory 不命中，因为其历史主题没有记录。当前分类只用于该知识关系发现，必须显示 basis，不据此修改历史评分。
4. 各维度之间 AND；同证据的多个主题／目标采用 EXISTS 语义，不能联表乘法增加计数。dimension 取明确记录，未知不匹配。level、reviewFlag 在证据当前状态核对后过滤；没有这个 flag 不表示其他 flag 不存在。
5. 日期按各类 occurredAt；目录筛选不读取原文或以回忆面试时间替代记录时间。现有手工反馈／回忆所有版本可独立匹配日期。
6. 第七类沿同一真实读取规则，只有确切观察、原答访问及所选检查项直接来源均实际解析成功才返回READY；缺投影标记或其他读取故障为ERROR／UNAVAILABLE，不得生成零。其他来源请求 level=REVIEWED_OBSERVATION 可确知不匹配而给0；overview不再固定附加未接入限制，但保留间接链PARTIAL。
7. emptyState 只有所有相关来源完整可读且计数 EXACT 时才能为 NO_RECORD／RECOLLECTION_ONLY；有任何截断、未知、缺失依赖时为 UNKNOWN，已有非回忆记录可明确给 HAS_RECORDS。RECOLLECTION_ONLY 不能把训练正式回答当回忆。
8. ERROR 的领域返回空 items、UNAVAILABLE count、非空失败 capability，不保留该领域一半成功数据冒充完整；其他独立领域可正常显示。数据库、领域完整性异常须记录脱敏 trace，不能吞掉成为0。
9. 整个日期范围尚在事实水位之后（asOf≤startAt）时，七类目录与overview分组返回READY、count=UNAVAILABLE、items=[]、scanned=0且无游标；尚无可观察的时间段不记为精确零。活动整段及未来桶同样返回不可用计数；不受时间窗口限制的source-progress仍读取当前存量。

计数规则：

- 静态谓词能用同 owner／窗口的完整元数据 COUNT 时，可以 EXACT；不为追求精确而无界加载 JSON、原文或全量 id。
- 需要当前来源、主题分类或用户关联等动态核对时，每种来源最多检查500个候选；基于已核对匹配项返回 LOWER_BOUND。首请求从起点扫描且实际穷尽全部候选后才可 EXACT。
- 非首目录页即使到末尾，也不能把该页匹配数当整个查询的 EXACT 总数；若没有另行完整 COUNT，就保持 LOWER_BOUND。count 是当前已证明的查询下界，不是累计计数；客户端不得对各页 count 相加。
- overview 每类从起点独立有界查询，不使用“第一页显示条数”当完整数量。不得根据下一页没有结果把 overview 总数重置为0。
- 来源完整性检查和元数据分类属于扫描预算，不能在排序后从前端临时过滤。每页可能 items=[] 且 nextCursor 非空，前端仍必须允许继续加载。

稳定排序和游标：

- evidence 按 occurredAt DESC、evidenceKey ASC。evidenceKey 是 §9 的规范身份文本；同毫秒、同任务多观察或同反馈多个修订不会丢项。
- cursor 是规范 JSON 的 UTF-8 Base64url，无填充；最大8192字符。封闭字段：v=1、purpose、ownerFingerprint、scopeHash、asOf、issuedAt、position。purpose=EVIDENCE 时 position={occurredAt,evidenceKey}；其他目录另见各节。
- ownerFingerprint 由当前 owner 的固定散列计算；它不是授权依据。读取一律仍从认证 owner 查询。scopeHash 包含所有已解析默认值和当前接口过滤；limit 可以改变，其他 scope 不能偷偷改变。
- asOf／issuedAt 不得在当前未来；issuedAt 超过24小时返回409 GROWTH_CURSOR_EXPIRED，前端从第一页重新读且保留筛选。跨日期的旧游标继续使用原已固定 DateWindow，不重新解释默认28天。
- 解码后必须为对象，拒绝 JSON null、数组、缺字段、额外字段、非法值、重复键、尾随内容、非规范编码；重新编码必须与原字符串一致。不能先解引用再判断 null。
- 游标不承载可信计数、权限、来源当前性或已审状态；其中位置仍按类型、窗口、身份组合验证。它只是排他继续位置，不需要引入或读取额外用户密钥。
- 每次取未消费候选最多 min(剩余扫描预算,需要的条目窗口)+1；额外一项只判断后续存在。排序位置只能推进到已经纳入本次核对的候选，不能越过未展示的合格项。
- AI报告含最多12个观察，分页的消费单位是观察，不是整task；达到页上限后必须保留同报告后续partId，下一页从该task的未消费观察继续。task读取批次也受50条上限；不能取50任务展开600观察却只记50次扫描。来源revision／版本亦逐EvidenceRef计扫描，不按稳定对象合并消耗。
- scanLimited=true 表示还有尚未核对候选而预算已用尽，nextCursor 指最后已消费候选。达到 limit 提前停下则不称扫描截断，但仍返回下一页位置。
- 同请求使用一致只读事务。不同页当前争议／主题／用户关联变化可能使匹配变化；响应 checkedAt 明示，页面保存／恢复／争议变更后重开第一页，不声称跨页冻结了所有当前状态。

主题／考察项按 §4 的真实关联过滤。普通任务和面试只有其实际保存的目标关系，无主题／考察项时不臆造分类；在相应筛选下不命中，并显示 FILTERED_SCOPE_ONLY。memory 使用当前主题时标 CURRENT_TOPIC_CLASSIFICATION。

不输出单题学习时长。整场 observed／unobserved／paused 如未来显示必须独立标整场且不能拆分分配到题。memory elapsed 可以在原事件详情显示，不能宣传净专注时长。成长不建立另一套每日评分预算指标；若展示预算消耗，只能引用原 RATE 的 RatingDay、BudgetUse.firstForCardToday 和对应 NEW／REVIEW，不能按成长显示时区重新决定“首条”。

- 已保存关联来源现不可用时，CHANGE预览可返回EvidenceResolution.summary=null，并允许撤回或在目标仍当前时保存非正向说明；不能借此创建不存在的新来源关联。

- 无实际字段变化时返回现有行，不新增历史／revision；仍执行当前守卫、CAS及预览检查，幂等回执照常保存。不同requestId不会产生空修订。
- 目录targetId/targetVersionId必填；requirementId可空但必须属于该版本；status可空表示全部。默认20／最多50，按createdAt DESC,id ASC，不按updatedAt排序；首请求asOf作为createdAt水位，修改不导致已有项换位置。
- 目录游标purpose=USE_DIRECTORY，position={createdAt,id}；绑定确切目标、requirementId、status。状态改变后前端重开第一页；不承诺跨页保持旧筛选结果。
- 每条目录记录均重新读取当前source状态。源读取失败不得返回旧“有效覆盖”；对应entry应失败，整页明确ERROR或503，不回传一部分当前成功行冒充完整页。
- history按revision DESC，before排他，默认20／最大50；nextBefore为最后返回修订且确有更旧行时才有值。历史只返回不可变当时snapshot／stamp，不重写成当前状态，不携带源正文。
- 不提供DELETE。更新无条件UPDATE禁止；WHERE owner_id/id/revision精确CAS，影响行数必须为1。

by-identity精确规则：

- query必填targetId、targetVersionId、requirementId、kind、objectId；versionId／revision／partId按EvidenceRef联合需要填写，其他分支必须省略这些参数，解析后为null。不接受空字符串或字面"null"、重复参数、未知键。GET没有JSON请求体；UseIdentityLookup.identity按CreateUsePreview字段结构回显已校验的完整身份，不加入status／scope／cursor或当前stamp。
- 当前owner及资料守卫执行后，先以owner＋targetVersionId＋requirementId＋规范evidenceKey查保存行，并核对保存的targetId及完整EvidenceRef一致。命中后返回与GET /{id}同样的UseEntry，含ACTIVE或WITHDRAWN；来源已失效走现有EvidenceResolution不可用规则，不把存在的历史关联降成entry=null。目标／要求被非法移除或保存身份不一致属于完整性错误，不能作未保存处理。
- 未命中时仍核对确切目标版本属于本人、requirementId存在，以及原不可变EvidenceRef属于本人并真实存在；不要求目标当前ACTIVE、证据当前可用于正向覆盖或已有当前建议。合法来源没有关联时200，context和identity非空、entry显式null；这不是来源不存在，也不自动建默认行。错owner或不存在的目标／要求返回GROWTH_TARGET_NOT_FOUND，证据不存在返回EVIDENCE_NOT_FOUND；源读取故障返回503，不伪造null。
- GET /target-evidence/{id}的UseLookup.entry仍必定非空，id不存在404；只有by-identity的UseIdentityLookup.entry可空。两者均no-store、只读事务且序列化前复核资料权限；服务器显式注册静态by-identity路径，不将其当UUID型{id}解析。

effectiveState判定顺序：WITHDRAWN → TARGET_NOT_CURRENT → SOURCE_UNAVAILABLE → SOURCE_UNKNOWN → SOURCE_REVIEW_REQUIRED → NON_POSITIVE或EFFECTIVE_POSITIVE。只有最后一种计“本人当前正向标注”，仍不叫平台认证覆盖。目录发现命中、保存判断、当前有效性三者分别显示。

TargetCoverage 返回目标版本原顺序全部要求，最多50条；不从已加载关联页推导“未覆盖”。每次最多核对该目标版本500条关联，各要求计数在扫描穷尽后才能EXACT，未穷尽则保持LOWER_BOUND。SAVED_SUPPORTS／SAVED_PARTIAL仅计ACTIVE的保存标签，EFFECTIVE_POSITIVE按当前有效性计；INVALIDATED_POSITIVE为ACTIVE正向标签但当前不生效，WITHDRAWN单列；这些指标有明确交集，不能全部相加。noActiveLinkedEvidence：完整计数为0时true，已确认有ACTIVE关联时false，否则null。文案为“此版本要求尚无关联证据”，不得称“已证实未掌握”。currentTarget=false时解释这是历史目标版本，当前正向覆盖为0只表示不参与当前目标统计；原保存标签仍展示。源读取失败令capability为ERROR，相关计数UNAVAILABLE，不退回保存标签冒充当前有效数。

### 7.3 预览摘要和原键恢复

UsePreview.previewHash 的规范内容：

1. 固定协议标签 GROWTH_EVIDENCE_USE_V1、当前owner、intent；CHANGE还包括useId/currentRevision及保存身份。
2. TargetRef、目标当前revision/status/currentVersionId/sourceGeneration、确切requirementId、该要求原始内容的规范摘要；不能仅用要求序号。
3. 证据完整EvidenceRef、originHash/currentHash、当前directState/reviewFlags/lineageCheck和五项初始比较。
4. 当前协议限制和正向写入资格；不包含asOf/checkedAt/serverTime、UI标签、生成时间或无关计数。
5. 稳定字段顺序、显式null、数组按业务固定顺序或身份排序的紧凑UTF-8 JSON，再SHA-256小写十六进制。不能以Map迭代顺序、数据库原JSON空白或字符串拼接分隔符决定结果。

originHash包括此证据的不可变身份、发生时间、固定条件、记录标签、RECORDED分类及原引用身份；必要的确切内容一致性摘要可在源域内部计算，但正文不返回。当前主题、用户关联、最新决定和当前适用性不得进入originHash。currentHash不含本次检查时间、AI费用字段或无关活动统计；缺必要字段不得用固定摘要冒充可用。

currentHash规范输入按以下白名单组合，最后再加入统一EvidenceState；同类数组按确切身份排序，null显式保留：

| kind | 必需当前状态输入 |
|---|---|
| TRAINING_ANSWER | 固定sessionId及当前generation；原题id/status/currentVersionId（无题库来源时null）；各固定TARGET/PROJECT/FACT的SourceCheck(kind,itemId,versionId,state,sourceGeneration,projectGeneration)；各显式知识引用的itemId/versionId/currentVersionId/status及原域bodyChanged判断 |
| MANUAL_FEEDBACK | feedbackId及当前反馈revision；本ref修订的最新DecisionMeta或null；所属answer的currentHash |
| AI_OBSERVATION | taskId/purpose/status/currentAttemptId及报告originHash；该partId的最新DecisionMeta或null；所属answer和固定评价输入直接依赖的currentHash；不加入task.updatedAt或费用核对revision |
| RECOLLECTION | recollectionId/revision/status/currentVersionId及本版本SourceState；不加入当前面试时间、目标或事件revision替换固定快照 |
| REPLAY_JUDGMENT | sourceId、当前actionId/actionRevision/status、tracking、当前verificationHash、最新judgmentId/revision/outcome、原域domainApplicable、回忆当前SourceState（非回忆为空）；origin和新answer的currentHash |
| MEMORY_RATING | cardId/currentRevision/currentVersionId/status、当前gate.revision/reviewRequired/lastReviewDecisionId、逐固定来源SourceSnapshot和Eligibility；不加入后来排程due或预算设置把历史RATE重算 |
| REVIEWED_OBSERVATION | 当前观察／标准头、所选检查项直接BasisCheck／EvidenceCheck、ObservationEligibility的内部规范摘要，再组合原答currentHash与最终EvidenceState；无关检查项不进入此项摘要 |

知识引用没有已有bodyChanged判断能力时，不猜false：字段为null、EvidenceState标记相应未知／PARTIAL限制；若这个判断是本条正向当前性成立的必要条件，directState=UNKNOWN。目录当前主题匹配另对(所选topicId,实际匹配bool,依赖知识当前revision)生成分类摘要，进入本次查询判定，不改变原证据originHash。EvidenceUse预览使用不带目录筛选的resolve，因此不会因用户切换成长筛选条件改变同一证据的身份摘要。

幂等请求摘要是完整规范命令，包括用户最终coverage／comparability／reason／status及expectedPreviewHash，不是仅保存预览摘要。所有写沿用现有IdempotencyService，当前资料守卫先于旧回执；原键相同请求恢复原结果，不因当前来源后来变化重写原回执。前端恢复后立即GET当前UseLookup；失败或409保留编辑内容，不换新键静默覆盖。新执行source/target变化返回409 GROWTH_PREVIEW_CHANGED，revision变化返回409 EVIDENCE_USE_REVISION_CONFLICT；不能自动重新确认。

新增by-identity／by-subject读取和建议preferenceId只是定位能力；不进入UsePreview.previewHash、originHash/currentHash或既有写命令摘要，也不改变GROWTH_EVIDENCE_USE_V1标签。ActivitySeries响应字节例外不属于业务预览摘要。重复创建后按身份恢复出的id/revision用于CHANGE预览和CAS，不能复用CREATE预览去修改原行。

- SOURCE分支source/sourceStamp非空、requirement/targetRevision为空；只允许REVIEW_ACTION、MEMORY_CARD、PREPARATION_TASK。TARGET_REQUIREMENT分支相反，targetRevision为目标当前item revision。sourceStamp逐字段复用TodayDtos，不建立第二套状态算法。
- SubjectIdentity仅保存稳定source身份或确切目标版本＋requirementId；不存动态stamp。一个action可以有多个未处理source，但建议以action为一项，并从§6得到有依据的理由，不按来源数重复生成相同动作入口。
- REVIEW_ACTION取实际仍跟踪的UNASSESSED／PARTIAL／UNHANDLED／UNCERTAIN，或待复核来源；MEMORY取真实到期或gate待复核；PREPARATION_TASK取原域未安排TODO。不可把争议AI观点自动称为确定缺陷。
- TARGET_REQUIREMENT只从本人对该确切版本明确保存的ACTIVE INSUFFICIENT产生。仅“没找到证据”不自动认定缺陷；当前无正向覆盖不等于能力不足。
- 不创建任务、不改期、不启用排程。原事项操作走原域；目标要求入口可显式创建普通准备任务，创建前没有SourceRef，不能伪造任务ID。
- 目标过滤只取来源明确记录的确切目标，及TARGET_REQUIREMENT本身。memory没有原生目标关系时不靠题目关键词归入目标；明确目标过滤下如需发现关联评分，使用证据目录，不借建议迁移卡片归属。
- limit默认10、最多20。无分页cursor；这是推荐集合，不是完整来源目录。每类最多核对500候选、最多保留100条合格建议候选；目标要求≤50。合并后按effectivePriority DESC、reason类别固定顺序、subjectKey ASC取前limit。排序仅承诺当前已核对候选集合，scanLimited时不宣称已找出全库最高优先事项；动作来源检查共享该类500个source的预算，不按500动作再各自展开20来源绕过预算。
- 固定类别顺序为 ACTION_REVIEW_REQUIRED、MEMORY_REVIEW_REQUIRED、ACTION_PENDING、MEMORY_DUE、TASK_UNSCHEDULED、USER_MARKED_INSUFFICIENT；一个主体多理由取其中最早类别排序。
- 隐藏偏好在核对后过滤，但仍计已检查候选预算；达到预算仍有后续则scanLimited=true。matchingNotShown是已确认且未显示建议数的下界；仅所有来源都穷尽时可EXACT，不能据0下界声称没有其他建议。
- 给原域目录入口以继续查看被有界集合截断的来源；不能无限扫描直到凑满20。真正没有有据建议时允许空列表，保留写笔记、练习、建目标的普通导航，不伪造建议对象。
- SOURCE的effectivePriority取已有Placement.priority，priorityBasis=PLACEMENT；没有Placement时为3、priorityBasis=DEFAULT。TARGET_REQUIREMENT取该确切版本Requirement.priority，priorityBasis=TARGET_REQUIREMENT。已核对[TodayPlanRules.content](../../backend/src/main/java/com/wenjie/studio/today/TodayPlanRules.java)与[PreparationService.checkContent](../../backend/src/main/java/com/wenjie/studio/prepare/PreparationService.java)，两处实际都要求整数1–5；成长建议按原数值降序排列，不能对合法源值另做映射或假设其他范围。
- 界面“调整优先级”须明确说明将修改“这项来源的今日安排优先级”或“目标要求优先级”，再使用对应原域命令与并发规则；不会写NextStepPreference。前者沿用Placement在今日建议中的既有效果；后者按准备域保存产生新的目标版本，旧EvidenceUse和偏好仍绑定旧版本，不能自动迁移。修改后重读当前来源与选中的目标范围，不改已发生的训练／评分／判断记录。

规范身份文本，用于去重和稳定排序：

必要索引建议：

1. evidence_use(owner_id,target_version_id,created_at,id)及(owner_id,target_version_id,status,created_at,id)；按requirement过滤的实际EXPLAIN再判断是否增加细分索引。
2. evidence_use(owner_id,evidence_key,status,target_version_id)，支持跨目标发现EXISTS，不能先拉全部关联ID到应用。
3. preference(owner_id,visibility,created_at,id)与稳定主体唯一索引；当前表不需要独立shadow顺序字段。
4. 各来源事件按(owner_id,occurred_at,id)或实际created_at/finished_at字段及所属外键取有界候选；feedback revision／recollection version须包含完整身份兜底。已有RATE窗口索引先复用。
5. 查询执行计划、排序内存和索引收益留服务器验证，不因写出索引清单断言性能达标。

## 10. 权限、前端恢复与错误

growth全部路径加入后端TrainingAccessGuard的资料模块，并加入前端carriesReference／训练遮挡规则。统计、标题、日期、来源身份都是私有数据；独立训练期间不能先返回后用CSS隐藏。仅原training/active入口继续显示当前训练。

所有GET，以及两类UsePreview POST，在序列化前通过TrainingReadAdvice再次检查当前资料访问。正常写响应守卫在事务内，先于旧回执查询；不能以“只读取数字”豁免。身份、CSRF、幂等头及body解析沿既有接口协议。预览不写曝光、操作历史、任务或用户决定。

前端查询键包括会话代次、资料访问代次、日期／区域、所有过滤、kind、cursor。登出、重登、资料权限变化、页面离开或过滤改变使旧请求失效。写后原键回执恢复与GET当前状态分开；迟到的旧同revision响应也不能覆盖更新checkedAt的当前source状态。

字段未知／capability错误／scanLimited分别显示。失效统计不能继续以正常样式显示为当前结果；允许标注“上次读取”但图表不伪造新点。编辑理由、comparison、撤回意图及原幂等请求在409或网络失败时保留；用户重新预览后明确提交，不自动更换key或代为接受新来源。

## 11. 受审链接入边界、实施分组与验收

REVIEWED_OBSERVATION 的第七种kind与层级已按[受审契约§10](标准审阅与受审观察实施契约.md#10-成长第七种-evidenceref-的接入)冻结：observationId＋确切安全revision，其余身份显式null；Conditions仅reviewed非空，原AI评价层级保持未审。原域回链使用确切answer三元身份及reviewedObservationId／reviewedRevision，与AI observationId及反馈revision分开。

受审链提供确切题目／标准版本、正式审阅记录及其不可变修订、审核人说明／日期／可追溯依据、观察检查项与原答引用、撤回／更正后的直接适用性及原域入口。第七类接入resolve／page／activity／preview；capability=READY表示本次实际查询成功，缺必要投影标记或来源读取故障不报0。代码静态交付不表示服务器验收。S8间接派生完整检查仍独立保留，PARTIAL限制不能随第七类接通自动清除。

建议实施依赖组：

1. 冻结六类DTO、筛选、原域窄投影、活动和source处理；读查询包含真实capability及受审依赖，不能借可编译接口宣称GROW-02完整。
2. 完成EvidenceUse及偏好四张表、全部预览／命令／目录／历史／恢复，并接入实际发现和建议排序；只保存设置未影响查询不算完成。
