# 知识文本导入契约

版本：v0.10 · 2026-11-13。适用：S8第四十二至第五十一批单份文本导入、链接／元数据处理、持久记录、多文件元数据批次、目录路径／人工映射、有界ZIP、导入后链接补齐、批次链接候选及单份YAML标签持久映射。十批均**静态检查通过待服务器验收**。各节按当批范围记录，第五十一批以§15为准；明确标签采用不恢复外部身份，候选展示不自动采用或发布，逐份修订不等于整包原子导入。真实文件、数据库事务、创建、幂等恢复、权限及视觉场景尚未在服务器执行。

## 1. 普通导入流程

知识空间“导入Markdown／TXT”打开现有新笔记表单及文件预览：

1. 用户选择一份`.md`、`.markdown`或`.txt`文件，扩展名大小写均可；不接受目录、多选、压缩包或附件格式。
2. 浏览器本地检查文件、严格解码UTF-8并展示完整原文、文件名、大小、字符数和建议标题。此时不发送网络请求，不创建业务对象或调用模型。用户可以另行按§8本地预览YAML属性、按§7人工映射链接；只有主动打开知识选择器才查询本人目录。
3. 用户可明确采用处理后的标题／全文，也可完全保留文件名建议标题和完整原文再填入表单；若表单已有标题或正文，先确认替换这两项，拒绝则保留原表单和文件预览。原主题选择不变。文件预览本身可取消，已有表单输入保持。
4. 填入后用户仍可编辑标题、正文及主题；此时尚未保存。文件选择／预览模式未完成或取消前，“创建并保存”不可提交。
5. 用户点击“创建并保存”，按§9通过`POST /api/v1/knowledge/text-imports`与原`useCommand`提交原始文本及最终表单。服务器计算指纹，在owner命令事务中检查已登记重复，并复用原知识内部创建保存NOTE、首版、草稿、索引／正文引用及导入记录；不覆盖同名对象。

普通手工新建的`{kind,title,body,topicIds}`及`POST /knowledge/items`不变。文件导入请求独立为`{fileName,source,title,body,topicIds,createCopy}`，见§9；前端`TextImport`仍只是本地填入事件，另带原始文本及仅用于匹配查询的浏览器指纹。原文件不作为附件上传；只有用户确认创建后才发送原始文本及最终正文，另存的账本仅含有界元数据，不保存原文件正文副本。

## 2. 编码、边界与原文

- 文件名最多200字符，拒绝路径分隔符及ASCII控制字符；只按文件名去除末尾扩展名生成建议标题，空标题回退为“导入笔记”。用户可在填入后改名。
- 文件大小1至400000字节，读取前检查；实际缓冲区须与声明大小一致且仍在上限内。扩展名和浏览器MIME不作为内容安全证明。
- 使用`TextDecoder('utf-8', {fatal:true, ignoreBOM:true})`严格解码；损坏／非UTF-8字节明确拒绝，不用替换字符静默修复。存在的UTF-8 BOM保留为正文字符。
- 正文最多100000个UTF-16编码单元，与现有前后端编辑长度一致；拒绝不支持的ASCII控制字符（允许制表符、CR与LF）。超限明确拒绝，不截断或拆分后只保存部分内容。
- 原文预览及原文填入不修剪正文、不统一换行、不删除frontmatter；可选人工映射仅替换用户选中的原文片段。预览使用文本插值，不执行HTML、脚本或插件，也不抓取图片、相对路径、远程媒体及关联文件。
- `MarkdownEditor`外部模型赋值仅更新视图，不回传内部LF表示；未编辑正文按原模型保存。用户主动编辑后继续按既有编辑器文本输出规则处理，界面提示该区别；本批不承诺主动改写后仍逐字保留原文件。
- TXT也作为知识Markdown正文保存和阅读，Markdown符号可能影响后续排版。这里不是独立纯文本阅读模式。

## 3. 元数据、链接与身份

默认保留YAML（包括问阶可读导出元数据）、Wiki双链、相对链接及未知语法原文。§7提供可选人工链接映射，§8提供用户明确选择的title采用和整块元数据移除；不自动恢复别名／标签／主题、版本、来源资格、已审身份、模型许可、附件或布局，不执行任何插件。普通导入始终创建新ID，不能据文件中的旧ID覆盖或恢复原对象。

正文中真正的`[显示名](knowledge:UUID)`链接仍沿现有CommonMark引用规则处理：创建事务校验本人可访问的目标并登记正文引用；缺失／无权目标以原`REFERENCE_UNAVAILABLE`拒绝，超200条按原上限拒绝。不猜相对路径或同名目标，不自动修复；不将正文引用变成知识语义边。文件预览与填入后的表单提示均说明此规则。

命令的幂等键和冻结请求保持。网络结果未知时只能用原请求重试，不能换键重复创建；第四十五批在新导入命令中增加已登记原文的摘要查重，明确副本才允许另建。查重不包含此前普通创建、外部库或相似内容，不能表述为全库／语义去重。

完整产品的通用YAML属性持久映射、包内一致身份／链接映射、批量冲突预览、包级去重、Obsidian包与附件、JSON Canvas、完整导入任务及恢复继续实施。单份文件的映射及记录不认定整个DATA-04或完整文件交换完成。

## 4. 本地状态、权限与恢复

- 登录、训练资料检查／挑战／限制、训练访问命令锁及父入口启用条件共同控制文件选择和填入。选文件后立即清空原生输入值，仅保留有界内存预览，便于同一文件重新选择。
- 异步文件读取须匹配读取代次、登录代次和训练访问epoch；父级隐藏／停用、页签隐藏、会话或训练条件变化、组件卸载后丢弃迟到结果并清除预览。恢复时由用户重新选择，不自动重读或提交。
- 填入前再核对两类epoch及可见性；已有表单替换确认前后还核会话和权限，避免确认期间使用已失效的本地预览。
- 文件读取／预览接入原`create`离开保护，尚未填入字段时也会提示放弃；取消文件预览只丢弃该预览，不清空原创建表单。已经填入的输入继续沿原表单保稿／未决请求保护，不随文件预览的隐藏清理而丢失。
- 刷新页面可能丢失未保存表单及本地请求上下文，原离开提示保持；本批不新增浏览器持久存储或跨刷新恢复承诺。错误后可重选文件；创建结果未知时使用现有原键重试入口。

## 7. 单份链接人工映射 · S8第四十三批

### 7.1 触发与身份

文件全文预览后，用户主动点击“解析可映射链接”，仅在本地生成候选表，不猜目标、不发请求。逐组打开原`KnowledgePicker`时，才沿既有`GET /knowledge/library`分页查询本人有效知识目录；候选地址本身不被读取、解析到磁盘或向外请求。选择器只显示目录元数据，不读取目标正文。

支持以下有界语法；其他内容继续保留：

| 类型 | 可人工映射的子集 | 改写范围 |
|---|---|---|
| Wiki双链 | 一行内的`[[目标]]`／`[[目标\|显示名]]`，目标和显示名各1–500字符；不支持空白目标、嵌入、嵌套方括号、目标内反斜杠、标题锚点或块引用 | 整个Wiki片段转换为`[转义后的纯文本显示名](knowledge:所选ID)`；不同显示名仍按各自原文生成 |
| 相对笔记链接 | CommonMark识别的行内链接，地址以`.md`／`.markdown`／`.txt`结束，最多500字符；不含空白、反斜杠、冒号、查询或锚点，不以`/`开头；可用尖括号包围地址 | 只替换地址原文范围；原显示内容、可选title和外围语法保持 |
| 旧站内地址 | CommonMark行内链接中的`knowledge:`地址，最多500字符且不含空白、尖括号、反斜杠、第二个冒号、查询或标题／块定位；目标不必已经能通过原创建校验 | 只替换地址范围，用户明确选出当前本人知识ID；未选原地址继续接受原创建校验 |

以“语法类型＋精确原地址”分组，不做大小写、路径、扩展名、URL编码或Unicode归一化；同组全部出现位置一次映射，不同语法组单独选择，不按标题静默合并。每组展示类型、原地址、出现次数和全部原文片段，明确所选目录标题及稳定ID。选择只保存在本地预览内，重新解析会清除本次选择；可逐组恢复原文。

选择结果是目录快照，不是目标仍可用的证明。最终创建仍由现有事务按owner及目标存在性校验并登记正文引用；原SQL允许归档目标，映射入口只提供ACTIVE目录，不额外改变服务器历史规则。这里不固定目标正文版、不复制或采用其内容、不继承来源／已审身份／模型许可，不生成概念语义关系，也不是普通导入包的“外部身份→新对象”持久映射。

### 7.2 原文范围、保护与上限

- 使用直接依赖`@codemirror/lang-markdown`导出的`commonmarkLanguage.parser`，基于原文件UTF-16坐标处理；不使用渲染HTML、自动格式化或重新序列化来重建整篇正文，不引入新依赖。
- 文件开头可选BOM加独立`---`行至下一独立`---`／`...`行为不透明元数据范围，不解释YAML；没有闭合时整个映射不可用，仍可原文导入。LF／CRLF均支持并保留；存在单独CR时不给映射，不自动改换行，原文导入仍保持。
- 跳过语法树中的围栏／缩进代码、行内代码、图片、HTML标签／块、注释、处理指令、引用定义及自动链接子树。真实行内Markdown链接及引用式链接的内部不再搜索Wiki；普通Wiki的内部快捷引用节点不自行作为目标。转义Wiki、`![[嵌入]]`及不支持的标题／块引用保持原文。
- 最多200处可映射链接，重复地址也计次数；超限时整个候选表不可用，不展示或采用截断集合。此限制不是服务器全部引用数证明，原200条正文引用上限仍以创建事务为准。
- 只有选择了目标的片段被替换；按原坐标排序并核对原片段，重叠或位置失配拒绝改写。其余原文含BOM、换行、空白、代码和未知语法保持。Wiki显示名作为纯文本转义，不可注入新的Markdown链接或HTML。
- 原文全文始终可回看；处理后的标题／全文另行以文本展示数量和字符数。处理结果超过100000字符或结构校验失败时禁止填入，可减少映射或显式保留原文，不静默截断；第四十四批可选元数据移除后以最终正文长度为准。
- 两个按钮明确区分“确认处理后的标题与全文并填入”和“仅用文件名标题与完整原文填入”；后者不会采用任何映射或元数据选项。填入后仍沿原替换确认、草稿保护和另行创建操作，主题不变；第四十三批当时使用原创建请求，当前文件导入命令见§9，原键重试机制保持。
- 原文件预览的隐藏／停用／卸载／会话与训练权限清理同时清除映射、所选目录信息及选择器。所选目标事件再次核两类epoch、当前候选组及目录ID／ACTIVE快照；旧组件事件不能填入新文件。最终填入继续核epoch和可见性。

第四十三批未解析YAML属性；第四十四批的有界属性预览见§8，第四十五批的单份持久记录见§9。仍不打开包／目录／附件、不加载插件或远程媒体，不宣称已完成批量导入、外部ID恢复或全库文件去重。

## 8. YAML元数据预览与明确采用 · S8第四十四批

### 8.1 范围与解析

用户主动点击“预览YAML属性”，只解析当前文件开头已闭合的frontmatter，不上传、不查询服务器、不调用模型。元数据边界与链接解析共享`findImportFrontmatter`：可选文件BOM、独立`---`起始行、下一独立`---`或`...`结束行，支持LF／CRLF。未闭合、单独CR或没有头部时保留原文，不猜范围。这里是普通导入，不是配置加载或身份恢复。

使用原已安装／锁定的js-yaml 4.3.2完整解析器，不编写YAML语法解析器；将其明确声明为运行依赖，未下载、安装、执行其CLI或构建／测试脚本。使用`FAILSAFE_SCHEMA`，只处理字符串、序列及映射，不隐式构造日期、数字或布尔值，不注册自定义类型。显式标准字符串／序列／映射标签按该schema处理，其他类型拒绝；`json:false`拒绝重复键。YAML合并标签不启用，`<<`作为普通未采用属性处理。

所有上限按UTF-16编码单元或明确事件计数：

| 边界 | 规则 |
|---|---|
| 原文件 | 继承最多100000字符、400000字节及严格UTF-8检查 |
| 元数据内容 | 不含起止分隔行，最多16384字符；超限整份预览失败，不截断 |
| 解析深度／工作量 | `maxDepth:8`；listener的`open`事件最多512次，包含解析尝试，不等同于集合层数或最终节点数 |
| 锚点 | 任一节点`close`时anchor非null即拒绝整块，不向属性提取传递带锚点图；不递归展开未知值 |
| 顶层 | 空块可预览，非空须为属性映射；最多64个解析后属性，属性名最多200字符且无ASCII控制字符 |
| 可采用标题 | 精确小写`title`，非空字符串、最多200字符且无ASCII控制字符；不截断或拼接列表 |
| 仅展示别名／标签 | 精确`aliases`／`alias`／`tags`／`tag`，单字符串或最多50个字符串，每项非空且最多200字符、无ASCII控制字符；不按逗号或空格猜分词 |

字段名及值按解析器规则读取；复杂键可能被解析器转成字符串，原复杂键结构不作为兼容保证，始终可对照完整原文。仅处理输出属性的有界平面值，不遍历未知嵌套对象，不序列化整个解析结果；不符合展示形状的已知属性列为“不支持，仅保留原文”，其他键列为“未采用，仅保留原文”。所有属性均列出，不把格式不支持解释为已写入或已删除。

解析错误、重复键、未知类型、锚点及结构超限不回显库异常中的原文片段／堆栈，整块不提供任何采用选项；完整原文仍可查看和填入。此机制不证明所有YAML兼容或恶意输入性能已验收。

### 8.2 明确采用与组合处理

- 默认不勾选任何选项。`title`合法时可单独勾选“采用YAML title作为新笔记标题”；正文仍保留完整元数据块。别名、标签仅预览，不自动写入知识组织信息或主题。
- 解析成功时，可另行勾选“从待创建正文移除整个元数据块”。界面明确显示整块所有属性将从正文移除，只有另行选中的title成为表单标题；别名、标签及其他属性不会额外保存。此操作不修改原文件。
- 链接先按原坐标映射，再核对元数据原始前缀并移除明确选择的块；文件BOM单独保留，结束分隔行之后的正文和换行不修剪。没有头部、解析失败或前缀无法核对时禁止移除。
- 三类选择共同生成一份最终结果：将填入的完整标题、元数据保留／移除状态、映射次数、最终字符数及完整正文。最终正文超过100000字符或任何步骤失败，禁止采用处理结果；不回退到部分处理或截断正文。
- “确认处理后的标题与全文并填入”采用全部当前选择；“仅用文件名标题与完整原文填入”完全忽略元数据及链接选择。两个入口均再核权限／epoch／可见性；若原创建表单已有标题或正文，仍先确认替换，原主题保留，拒绝则原表单和文件预览都保持。
- 清除文件预览、更换文件、隐藏／停用／卸载、会话或训练条件变化时，同时清空元数据结果、选项及链接选择。重新解析YAML只清元数据选项，重新解析链接只清链接选择；二者共用同一份未修改原文件。
- 第四十四批填入只发本地`TextImport`事件，用户须另点“创建并保存”，未新增别名／标签字段或后台任务。第四十五批额外保留原始文本和浏览器摘要，并按§9切换独立导入命令；原手工创建DTO及幂等／回执机制不改。

外部旧ID、版本号、来源、已审状态、授权、费用等字段始终只是文件文本。移除或保留它们均不恢复系统身份；选择title也不转移其来源资格。§9的文件登记不成为证据来源账本；通用属性持久映射、批量任务、附件和完整包仍未完成。

## 9. 单份文本持久记录与精确去重 · S8第四十五批

### 9.1 原始输入与明确创建

本批只登记经新文本导入命令成功创建的单份笔记，不扫描知识库、不补猜历史文件、不建立包级映射或自动更新已有笔记。源文本与最终正文由用户确认对应；服务器不重演YAML／链接处理，不认证磁盘文件、外部作者、转换算法或原有“已审”身份。

浏览器严格解码成功后，以所选原始缓冲区计算SHA256；异步计算后再核读取代次、两类epoch和可见性。该摘要仅用于用户主动匹配查询，写命令不接收客户端摘要作为身份。填入后原始文本及摘要随表单保留；成功、取消整个表单或重新开始普通新建时清除，未决命令按原`useCommand`冻结请求，页签隐藏不自动丢失已填入表单。未保存输入及未决键仍无跨刷新持久化承诺。

`POST /api/v1/knowledge/text-imports`必须提供六个字段，不接受查询参数：

| 字段 | 规则 |
|---|---|
| fileName | 原所选名称，最多200 UTF-16单位，支持.md／.markdown／.txt；拒绝路径分隔符、控制字符及未配对代理项 |
| source | 未修改的原始文本，最多100000 UTF-16单位，严格UTF-8编码为1–400000字节；BOM及CR／LF原样参与指纹 |
| title | 当前表单确认标题，最多200 UTF-16单位，沿原创建strip且非空；拒绝ASCII控制字符及未配对代理项 |
| body | 当前表单确认全文，最多100000 UTF-16单位，可为空串；拒绝不支持的ASCII控制字符及未配对代理项，不截断 |
| topicIds | 原本人主题列表，0–20个不同小写UUID；原创建事务核归属 |
| createCopy | 必传boolean，界面默认false；true表示明确允许相同原文另建独立副本，不覆盖旧对象或修改旧映射 |

source／body允许TAB、CR、LF，其余禁止控制字符与原文件读取一致。Java编码器使用`CodingErrorAction.REPORT`，不能用默认替换行为合并不同无效Unicode输入。source严格编码后由服务器计算小写SHA256，文件名、最终标题／正文、主题及元数据选项不影响源指纹；只改文件名仍匹配，改BOM／换行／任意源字节产生不同指纹。所有JSON仍受原实际输入流1MiB限制；重复／未知／缺失字段、类型强转、尾随JSON、过深结构及超限拒绝，不回显源内容。

### 9.2 事务、重复与未知结果

新命令复用原`IdempotencyService`：登录／CSRF／资料守卫、owner工作区行锁和原键回执恢复在前，新请求的去重及创建只在action内执行。按owner及原文指纹查询**全部已登记记录**，包括目标后来归档的记录；非唯一摘要索引允许明确副本，串行正确性依赖同一owner写锁。

- `createCopy=false`且命中登记时返回409 `TEXT_IMPORT_EXISTS`；不建知识、不追加成功记录。表单保留，可主动检查原记录或选择明确副本后发新命令。
- 未命中或`createCopy=true`时，调用原`createWithinCommand`创建新NOTE、首版、草稿、主题、正文引用及outbox，再插入仅元数据导入记录，最后保存201回执；任一失败同事务回滚。
- 相同幂等键／相同请求恢复原`Saved{item,record}`，不再次进入查重或追加记录；其内容是当时保存的回执，不冒充后来当前状态。同键不同请求仍409。跨标签并发的新键默认导入相同源，只允许一个提交成功，后一个在锁内命中；原响应丢失时不能靠副本开关绕过原键恢复。
- 原手工`POST /knowledge/items`及DTO完全保持。旧单份导入实际使用过此接口，没有原始文件见证，不自动补填本账本；“没有匹配记录”不等于全库无重复。用户再次从普通创建手写相同正文，也不属于本批去重承诺。

### 9.3 元数据账本与历史读取

V76新增`knowledge_text_import`：稳定记录ID、owner、文件名、源SHA256、源字节／UTF-16字符数、目标知识ID、确切创建首版ID、是否明确副本及登记UTC时间。目标通过`(owner_id,item_id,version_id)`复合外键绑定原知识版本，一篇新笔记只登记一条记录；不额外保存source正文、附件副本、令牌、旧外部ID、组织属性或许可。源文本不单独留存，不能据指纹重建；若最终正文已转换，恢复未保存的原始部分需用户另行提供原文件。该表不是完整备份或独立删除／撤权账本。

`GET /api/v1/knowledge/text-imports`只读元数据，支持可选`sourceSha256`、`cursor`、`limit`（默认20，1–50），拒绝未知、重复及非法参数。服务在REPEATABLE_READ内按owner查询，时间倒序及ID倒序分页；cursor为上一页末记录ID，须属于同owner及当前源筛选，由服务器恢复原时间。每页只读`limit+1`，不以标题猜重复；新记录在刷新首页后读取，不承诺跨分页快照。

响应`Page{items,nextCursor}`，Entry共有11字段：`id,fileName,sourceSha256,sourceBytes,sourceCharacters,itemId,versionId,title,itemStatus,createCopy,createdAt`。title从确切首版读取，itemStatus为知识当前状态；列表不读任何正文。记录按钮打开确切首版；在创建表单内打开时沿原离开确认，取消确认保持表单和当前匹配结果。后续改标题、发布新版本或归档不改源指纹／首版绑定、不抹去去重记录，不自动恢复排程或AI资格。未来物理清除须单独设计处理该身份关系，本批没有清除命令或级联删除。

列表及创建均`Cache-Control:no-store`。新路由位于knowledge域，沿原HTTP资料守卫；GET输出前再次检查，写回执恢复前仍核当前训练条件。前端仅用户主动展开才读记录，不把源文本放URL；展示／打开前核可见性与两类epoch，隐藏、停用、卸载、会话或训练条件变化清除本地记录并丢弃迟到结果。正式首版正文仍走既有确切版本出口。

## 10. 多文件文本导入持久批次 · S8第四十六批

### 10.1 流程与数据边界

知识空间新增“多文件导入”独立入口，每批1–20份不同**精确文件名**的`.md`／`.markdown`／`.txt`，不合并大小写或按标题猜身份。浏览器先核全体文件边界，再顺序严格UTF-8解码、核实际字节、字符及原文摘要；一份失败则整批本地选择不保留，不截断或显示可提交的部分清单。单份仍按§9的400000字节／100000 UTF-16单位限制，保留BOM及换行。

选择本身不发请求。用户可检查文件名、大小及指纹，再明确“保存批次”：只发送有序元数据，不发送source或body，不创建笔记。清单指纹和大小此时是**客户端声明**，不是服务器已经见过原文件的证明。不同名称可以声明相同源，界面提示同批同源；服务器已有同源提示来自启用账本后的记录，包含归档目标，不涵盖未知历史或语义相似。

保存后，用户逐份核对原文、标题及可选主题，再明确导入或跳过。本批前端按完整原文作为最终正文，不增加YAML／链接转换选项；需要处理单份文件时仍使用§7–9原入口。机器单项导入允许用户确认的不同body，服务器沿§9验证，不认证转换算法。文件名来自固定清单，不允许提交时更名；服务器严格UTF-8重算source的摘要、字节和UTF-16数，须三者全部一致后才可创建。

服务器只保存批次及条目的有界元数据和处理结果，不持久化未提交原文／标题／最终正文／主题选项，不建立文件附件副本。刷新、隐藏或访问条件变化后，可主动读历史及批次详情，重选符合文件名／摘要／字节／字符数的原文件继续；不能由摘要恢复未提交文本，不承诺保存尚未提交的标题／主题选择或跨刷新原幂等键。未决写入的冻结请求在原组件存活期间按既有`useCommand`保留，不因只读视图清理而解除结果未知锁。

清单不预分配知识身份，不建立包内链接或主题映射；目录、ZIP、Obsidian库、附件和完整机器恢复不在本批范围。没有后台worker、自动连续提交、AI调用、外发许可或已审身份继承。

### 10.2 对象与状态

V77新增：

| 对象 | 保存内容与不变量 |
|---|---|
| `knowledge_text_import_batch` | 稳定id、owner、revision、1–20文件数及UTC创建时间。revision初0，每份实际导入或明确跳过加1，不超过file_count |
| `knowledge_text_import_batch_entry` | 稳定id、owner／batch、1起连续ordinal、精确文件名、声明SHA256／字节／字符数、状态、可空成功导入记录ID。批次内ordinal和二进制文件名唯一；成功导入记录只属于一个条目 |
| 既有`knowledge_text_import` | 仅成功创建后登记，源身份由服务器实际计算，固定创建首版；通过owner复合外键与条目相连，原§9规则保持 |

条目只有`PENDING → IMPORTED`或`PENDING → SKIPPED`，已处理项不能在原批次重开；需要另做时新建批次并重新面对原文查重。`IMPORTED`必须且仅能有成功记录，`PENDING`／`SKIPPED`必须为空。批次状态不另存，全部非PENDING时推导`COMPLETE`，其余为`OPEN`；完成只表示清单处理完毕，不证明知识掌握、技术审阅或完整产品已验收。

详情在一致读取中核文件数量、连续ordinal、合法状态、记录空值组合、成功登记的名称／源身份及`revision=已处理数`，缺损明确失败，不把缺行当成功或空批次。成功项只读取固定首版标题和当前知识状态；后续改稿／归档不改条目原绑定。记录、条目及批次外键均RESTRICT，无删除／清除或级联命令。

### 10.3 接口与事务

累计OpenAPI 7.70.0，新增四条路径、五个操作及八个schema，旧路径／schema和手工创建DTO保持：

| 方法／路径（省略`/api/v1`） | 输入 | 输出 |
|---|---|---|
| POST `/knowledge/text-import-batches` | `{files:[{fileName,sourceSha256,sourceBytes,sourceCharacters}]}`，1–20项 | 201 `Detail`，revision=0且全PENDING，尚无笔记 |
| GET `/knowledge/text-import-batches` | 可选cursor、limit默认20且1–50 | `Page{items:Summary[],nextCursor}` |

所有对象字段必传，严格拒绝未知／缺失／重复键、错误标量和数组类型、尾随JSON、过深结构及实际请求超过1MiB；POST及详情拒绝查询参数，列表拒绝未知／重复参数。源、标题、正文、主题和副本验证沿§9。请求revision沿原安全整数约束0–9007199254740991，合法但不匹配时409；实际响应revision不超过20。

`Detail{id,revision,state,createdAt,entries}`；Entry为`{id,ordinal,fileName,sourceSha256,sourceBytes,sourceCharacters,state,hasRegisteredSource,record}`。`record`为原§9成功记录或null；`hasRegisteredSource`仅是本次读取快照，不能替代提交查重。`Summary{id,revision,state,total,imported,skipped,createdAt}`。列表先限批次再聚合条目，按创建时间／ID倒序，cursor为同owner批次ID，由服务器恢复固定时间；有界`limit+1`，不承诺跨页快照。新Mapper语句显式5秒，最多20个成功记录的窄元数据查询，不扫描正文。

三种命令均由原`IdempotencyService`持owner锁、核资料权限并优先恢复原键回执，之后才执行新决策。新单项命令依次检查本人批次、预期修订、本人待处理项、原文完整身份；默认去重仍在同一owner事务中，`TEXT_IMPORT_EXISTS`不自动改副本选项或跳过。明确`createCopy=true`才另建独立NOTE和首版。

共享`KnowledgeTextImportService.createWithinCommand`要求MANDATORY现有事务，只复用验证与创建，不另建内层回执。知识、首版、草稿、正文引用、outbox、单份导入记录、条目IMPORTED、批次修订及外层回执**同事务提交**；失败保留PENDING及原修订。SKIPPED只记录决策和修订，不产生知识或导入记录。所有项独立提交，某项失败不回退此前已成功项，也不伪装整批原子导入。

主要新错误：

- 404 `TEXT_IMPORT_BATCH_NOT_FOUND`／`TEXT_IMPORT_BATCH_ENTRY_NOT_FOUND`：不存在或不属于本人／本批。
- 409 `BATCH_REVISION_CONFLICT`，带currentRevision：其他请求已推进，用户主动重读再作决定；不自动以新修订重放。
- 409 `BATCH_ENTRY_RESOLVED`：使用当前修订仍不得重复处理已完成项。
- 409 `TEXT_IMPORT_SOURCE_MISMATCH`：实际严格编码身份与清单不一致，不写半份。
- 沿原`TEXT_IMPORT_EXISTS`、幂等键重用、主题／引用及资料权限错误。

旧键同请求可恢复当时`Detail`，不重新处理状态，不把旧回执当当前快照。硬刷新丢失原键时，先重读持久进度；已处理项即使用新键也不能再创建，仍PENDING时可核原文后新命令。创建清单结果未知在当前组件内用原键；硬刷新后从历史主动查找已保存清单，不自动再建或自动重放。

### 10.4 页面与访问保护

全部接口no-store，knowledge域沿原HTTP／GET输出前及命令资料守卫，无元数据豁免。前端读／展示／写回调核本地generation、session及training epoch、当前可见性与访问条件；隐藏、停用、卸载或条件变化清空文件及只读结果，拒绝迟到读取和旧选择。未知写结果保持原请求锁，恢复后显式原键重试，并以本次重试上下文核回调，不能永远被旧epoch阻断。

批次模态及路由离开接入既有changes守卫，未决请求禁止离开；本地选择未提交时先确认丢弃。切换文件、重读详情也先确认丢弃已改标题／主题／副本选项；取消保持当前输入。跳过须另行确认不可重开，完整原文须逐份确认后才能导入；记录首版打开沿相同离开保护。原文、清单及标题为纯文本展示，不加载远程资源或执行HTML。

## 11. 目录相对路径与批次内人工链接映射 · S8第四十七批

### 11.1 目录选择与稳定身份

“多文件导入”新增独立的文本目录选择，普通多文件入口保持。通过浏览器原生`webkitdirectory`取得文件集合，`File.webkitRelativePath`保存从所选根目录名开始的相对路径；例如所选`面试笔记`下两份`Java/锁.md`及`数据库/锁.md`，分别登记`面试笔记/Java/锁.md`和`面试笔记/数据库/锁.md`。同名文件不再混配；这不是服务器上的目录、自动主题或知识节点。

每次目录返回的文件总数必须为1–20，**全部**符合§2及§9原文／文件名边界。不得用`accept`筛掉附件后把剩下文件冒充完整目录；任一附件、不支持格式、无效路径、超数量或原文读取失败都拒绝整批本地选择，不保留可提交的部分清单。空目录不是文件，不形成笔记；本批不包含ZIP解包或关联附件读取。目录选择能力依赖浏览器，实际文件枚举、权限及支持情况仍待服务器浏览器验收；不支持时可使用普通多文件入口，不承诺恢复目录结构。

新目录命令每份仅发送原四项元数据与`sourcePath`：

| 字段／规则 | 约束与含义 |
|---|---|
| `sourcePath` | 1–600 UTF-16单位、最多32段，有效Unicode；末段逐字等于`fileName` |
| 不可接受 | 绝对路径、空段、`.`、`..`、反斜线、冒号、ASCII控制字符和未配对代理项 |
| 精确比较 | 不做大小写、Unicode规范化、百分号解码或标题推断。不同路径同名允许，完全相同路径拒绝 |
| 不可变身份 | 保存后不随导入重命名或修改；原文匹配同时核路径、名称、SHA256、字节及UTF-16数 |
| 原文查重 | 路径只区分清单项，不改变同owner源指纹账本；同源不同路径仍默认拒绝重复创建，明确副本才另建 |

路径不参与文件系统解析、读写或联网，不表示磁盘文件已经上传、来源已认证、知识已审或允许AI外发。普通平面创建仍只传原四字段，其`sourcePath`由服务器填为`fileName`；不会把新字段塞入旧请求并改变其canonical摘要。

### 11.2 持久元数据与兼容迁移

V78只扩展`knowledge_text_import_batch_entry`：新增`source_path VARCHAR(600) COLLATE utf8mb4_0900_bin`，先允许null，再按旧`file_name`逐行回填，随后改NOT NULL；以`(owner_id,batch_id,source_path)`唯一键替换原文件名唯一键，其余状态、ordinal、成功记录及owner复合外键保持。V1–V77不重写。该迁移尚未执行；DDL、回填、唯一索引及锁影响须在服务器备份与迁移流程中验证。

迁移需维护窗口：先停止旧版应用写入并保留可恢复数据库备份，再执行V78并切换配套后端；旧版不会提供source_path，不能在NOT NULL变更后继续写入。MySQL DDL不作为本业务事务内可整体回滚的操作；失败时先盘点实际结构与Flyway状态，不能盲目重放或删数据。回退须使用经验证的迁移前备份及配套旧制品；已有不同路径同名数据后，不能直接恢复旧文件名唯一键。

旧平面项只知道原文件名，回填不虚构历史目录。原文件名规则允许冒号，因此**回读`sourcePath == fileName`采用原文件名规则**；不能用新目录的禁冒号规则使旧批次失读。新目录POST仍严格拒绝冒号，不以旧兼容分支放宽新输入。不同目录同名项对应不同稳定entry ID，单份成功记录仍绑定该条目确切名称与源身份。

不新增未提交正文／标题／主题／链接选择的服务器存储。刷新或隐藏清理后，主动读取持久清单并重选原文件；目录根名改变也会使路径不匹配，不能只按同名文件猜选。旧平面批次用普通多文件选择重新提供原名文件。

| 方法／路径（省略`/api/v1`） | 输入 | 输出 |
|---|---|---|

### 11.4 人工映射与完整正文确认

## 12. 有界ZIP文本包 · S8第四十八批

### 12.1 选择、检查与提交

“多文件导入”增加单份`.zip`选择。用户选择后只在浏览器内存读取和检查，不发网络请求、不写磁盘、不执行包内脚本、不加载远程媒体。整个包的结构及全部文本通过检查后，才保留可预览的文件清单；任一失败则不保留可提交的部分结果。目录条目不产生笔记，附件及不支持文件不会静默跳过。

通过检查的每份文本沿原严格UTF-8解码、BOM／换行保留、100000 UTF-16单位与控制字符规则，再计算原始文件字节SHA256。单份、目录及ZIP共用相同正文准备出口，不通过Markdown渲染或重序列化改写源文本。浏览器将完整原文展示后，用户按§11保存目录元数据清单，再逐份明确导入、创建副本或跳过，亦可人工映射本批已成功目标。

ZIP条目路径原样作为sourcePath，**不额外加ZIP文件名或推断根目录**。包名、压缩方法／时间戳／注释及ZIP原始字节不作为服务器来源身份，不发送或存储ZIP附件。相同包内文本改换压缩参数不产生新的文件指纹；仍须核确切路径、名称、源SHA／字节／UTF-16数。重新选择ZIP也可为已保存批次提供完全匹配的文件，不能由元数据重建缺失正文。

没有新增后端路由、DTO、表、迁移或模型调用；复用OpenAPI 7.71.0及V78目录批次。元数据保存仍只发送原五字段，原平面请求与原键回执保持；ZIP结构检查是本地选择边界，服务器仍独立重算实际提交source身份、核最终正文与owner引用。客户端CRC／SHA检查不认证作者、磁盘来源或外部资格。

### 12.3 结构、完整性与生命周期

解析器先检查EOCD与中央目录范围／计数，再检查每条中央记录和相应局部头：名称原始字节、版本、方法、标志、大小、CRC及可选数据描述符须对应；非描述符模式局部值与中央目录完全一致，描述符模式要求局部CRC／大小全0，再按12／16字节完整边界和数值核对描述符。各局部数据区按实际偏移覆盖、无重叠或空洞，拒前缀／尾部杂项以及不支持结构。不将文件声明大小直接用于不受限分配，不使用条目路径访问磁盘。

只有全体元数据检查成功，才逐条读取内容。Deflate输入分块不超过1024字节，输出在已校验的声明上限内预分配并逐块计数；实际解压超过声明或硬上限立即失败并取消读取。方法0同样核大小及CRC32。所有文件都须核CRC、严格正文边界及实际源摘要，不能因文件扩展名或清单声明正确就接受包。

选择、解压、正文解码及SHA计算均按本次generation、session／training epoch和可见性复核。隐藏、停用、卸载或条件变化清只读选择和包名，拒绝迟到结果；原未决写请求仍按既有`useCommand`冻结恢复，不因只读清理解除。替换选择须确认丢弃标题、主题、副本及映射；取消保持输入。失败不提交元数据，不产生服务器知识或部分成功批次。

ZIP只增加受限的文本读取来源，不补齐前向／循环身份、自动包内链接转换、YAML组织信息持久映射、图片／附件、概念／卡片／证据恢复或完整备份。不能将本入口描述为完整Obsidian库兼容；原包保留在用户选定位置，页面不修改它。

## 13. 导入后链接补齐 · S8第四十九批

### 13.1 两遍处理与当前正文

原导入流程先让各份笔记获得真实知识ID；对`IMPORTED`项，用户可主动“读取当前发布版并补齐本批链接”。无须重选原文件，读取`GET /api/v1/knowledge/items/{itemId}`的当前`ItemDetail`，核ID、发布版ID／版号和ACTIVE，且草稿标题／正文须与当前发布版逐字相同。有未发布草稿时先去知识详情处理，不覆盖或自动发布它。

只在用户主动读取后解析**当前发布版完整正文**，不从ledger首版或原文件重建最新内容。沿原链接解析器、原文坐标、200处上限和完整改写预览；下拉只选同一批次已`IMPORTED`的其他记录真实itemId，不按标题／路径自动猜配，未映射保留。用户勾选采用全文及追加版本／失效传播确认后，才提交这一份修订。映射增删、更换目标或读取基线后须重新确认。

例：A和B先保留原文分别导入；再读取A当前版、明确将`[[B]]`映射到B，发布A的新版本；然后读取B当前版、明确将`[[A]]`映射到A，发布B的新版本。每份独立事务；第二份失败不撤销第一份。双方都是普通正文结构引用，不是PRECEDES／PART_OF语义关系，不套用后者的DAG规则。

### 13.2 严格命令与事务

`POST /api/v1/knowledge/text-import-batches/{id}/entries/{entryId}/publish-links`需要原幂等键、CSRF与资料守卫，响应`200 ItemDetail`、`no-store`。请求恰三个字段：

| 字段 | 含义 |
|---|---|
| expectedVersionId | 主动读取时的当前发布版ID；不使用导入首版ID替代 |
| expectedDraftRevision | 同次读取的草稿安全非负修订号 |
| body | 用户明确确认的完整新正文；严格UTF-8、100000 UTF-16／400000字节及原控制字符限制，不可空白 |

拒未知／缺失／重复字段、标量强转、查询及原1MiB请求上限。正文校验临时计算的摘要不替换原文件指纹。进入原`commands.execute`的owner命令锁，原键同正文先恢复当时回执；新命令才核本人完整批次快照与确切条目／ledger绑定。无此条目404；`PENDING`或`SKIPPED`为409 `TEXT_IMPORT_ENTRY_NOT_IMPORTED`，不替它导入或重新打开。`OPEN`与`COMPLETE`批次均可对已导入项进入此命令。

取绑定知识当前发布标题，沿原`publishWithinCommand`核ACTIVE、发布ID及草稿修订两份基线、草稿与发布版逐字相同，再同事务新增版本、更新草稿、索引结构引用、执行回忆／受审依据／采用来源失效传播、写outbox和回执。标题、主题、源指纹、导入ledger首版、批次决策／revision及路径均不改；此操作不消费清单决策，故不传batch revision。正文与当前正文逐字相同先返回400 `INVALID_REQUEST`，不新增无效版本；其余变化请求沿原409版本／草稿冲突及归档守卫。

**服务器接受的是本人明确确认的后续正文发布，不认证客户端“只改了链接”的算法或全部引用均来自同批。**客户端提供上述窄映射交互，服务器仍执行普通正文／owner引用校验；已存在其他合法引用可保留，目标归档沿原存在性／owner规则处理，不赋予技术审阅、证据或AI许可。不能将此入口当成服务端认证的包内转换报告。

### 13.3 恢复、离开与范围

创建表单再次列出所选标签，可主动取消标签映射而保留标题／正文。标签纳入脏状态、重置／成功清理和原未决写锁；没有选标签时仍调用旧六字段入口，有标签才调用下节新命令。解析／填入不发送请求或调用模型，最终“创建并保存”才发送原source、最终表单和所选标签。移除元数据块时明确提示：只有选中的title／标签另存，别名和其他未采用属性会从正文移除，不被隐藏保存。

客户端预览原始声明；保存以服务端组织规则为准：先核每项原始长度／Unicode／控制符和总数，再按Java `strip()`去首尾空白、`Locale.ROOT`忽略大小写去重，保留首个写法与顺序。例：`tags: [Java, " java ", Redis]`明确采用后保存`Java`、`Redis`；`tags: "Java, Redis"`是一个标签，不自动拆成两个。示例是规则说明，不是运行验收结果。

### 15.2 新命令与原子边界

`POST /api/v1/knowledge/text-imports/with-tags`需要原Idempotency-Key、CSRF及本人资料守卫，无访问豁免；返回`201 SavedWithTags`、`no-store`。请求恰七个字段：

| 字段 | 规则 |
|---|---|
| fileName／source／title／body／topicIds／createCopy | 完全沿§9旧单份导入校验；不以tags变化绕过原source查重 |
| tags | 必须为1–20个字符串，原始每项1–40 UTF-16、严格Unicode、无全部ASCII控制符且`strip()`后非空；原始重复允许，保存时按上述规则去重 |

拒绝重复／未知／缺失字段、标量强转、标签null／空数组／错类型、查询参数及1MiB实际输入上限。OpenAPI 7.73.0仅增加本路径、`KnowledgeTextImportCreateWithTags`及`KnowledgeTextImportSavedWithTags`两个schema，原接口、DTO及回执形状保持。

原`commands.execute`在owner命令锁内先核当前资料权限并恢复原键回执；新命令才执行source去重、原NOTE内部创建及首版／草稿／主题／引用索引、导入ledger，再调用`MANDATORY`的组织标签初始化。内部方法核实际写事务、本人ACTIVE／NOTE、版本1／知识metadataRevision0、无既有组织行及关联；调用方只传本次创建ID，不接受客户端已有目标ID。组织修订0→1，别名、收藏、关联／主笔记保持空值，规范化标签、METADATA outbox、所有创建结果和外层回执在**同一事务**提交；任一失败整体回滚，不额外调用组织save或创建第二份幂等命令。

回执为`{item, record, organization}`，其中`organization`是当时保存的规范化标签和组织修订，非永久当前状态。响应丢失只能用原键／原请求恢复；即使之后用户已修改标签，恢复也返回当时回执，不覆写当前组织。最终界面沿原详情读取当前状态。`createCopy=false`命中旧／新入口任一已登记source时仍409 `TEXT_IMPORT_EXISTS`；明确副本才新建独立笔记，不向既有笔记追加标签。

**服务器接受用户明确确认的标签初始化，不解析YAML，也不证明tags一定从source提取。**标签不是知识主题、概念别名、技术审阅、来源证据或模型许可；新命令不授予这些身份。未另存原始YAML副本或映射审计对象，原source仅参与原账本身份；标题／正文／标签均可在创建后按各自版本／组织修订规则继续修改。
