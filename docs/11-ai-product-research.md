## 1. 结论

**AI生成／选题、模拟面试和反馈已是常见组合。问阶应把它们放进首个用户版本，而不是只提供静态自检；差异化放在事实边界、技术条件、原答证据和下一次独立复练。**

本轮核对有四个关键区别：

1. **生成题单不等于面试官。**Huntr明确生成问题与答案，但该帮助页没有用户作答、连续追问或AI评价流程。面试官还需要轮次、上一份回答依据、阶段、停止和反馈时机。
2. **动态追问不等于文字流式。**Huru、Yoodli明确说明追问；本轮所读8个产品页面均不足以证明逐token／逐段文字流式或SSE实现。问阶采用文字流式是本产品设计决定，不标为已亲测的竞品惯例。
3. **表达评价不等于技术判题。**语速、填充词、STAR、眼神或回答长度不能证明Java推理成立；题目的条件、允许的替代方案和证据必须单独设计。
4. **反复练习不等于跨尝试证据。**Huru明确提供同步转录、回答定位和历史；其他页面常只说明可再练。本轮没有证据证明其普遍具备“原动作＋旧答＋独立新答＋条件变化”的对照闭环。

首个用户版收敛为：**AI生成／选题 → Java基础或项目文字专项／短模拟 → 有原文依据的AI评价 → 接受或争议 → 独立复练 → 新旧对照**。无AI路径是内部可靠性里程碑和用户退路，不冒称AI能力。语音、代码执行、自由画布、公开运营不作为本次AI设计的附带承诺。

## 4. 问阶采用的AI能力

| 能力 | 本轮设计决定 | 约束／用户得到的结果 |
|---|---|---|
| **AI生成／选择题目** | 首个AI用户版；基于Java主题／级别、目标及选定事实，单次1–3题 | 一起产生题干、条件、能力目标、参考条件、合理替代路径、标准版本与来源标签；先预览采用，不当权威题库或企业押题；选已有题零模型调用 |
| **AI文字专项面试官** | 一个主问题＋最多2个受控追问；用户主动推进 | 澄清假设、责任、结果验证和取舍；每次引用确切已提交回答；每轮一个主要问题，不替用户编经历，不无限聊天 |
| **AI文字短模拟** | 3个主问题、每主问题最多1个追问、总计不超过6问；不计时 | 技术基础→项目深挖／无材料技术情景→故障判断；过程只提问和必要澄清，结束后评价。完整限时／语音压力模拟后续 |
| **文字流式** | 问题可逐段暂态展示；结构化评价显示进度，校验完整结果后再展开 | 暂态不等于正式题目或报告；取消、断线、重连、格式失败、迟到和未知费用都有明确状态，重连不触发新付费生成 |
| **AI评价／判题辅助** | 自动读取本次确切答案，不要求用户先写缺口才生成评价 | 技术／事实／结构／表达分开；证据＋条件＋限制＋动作，允许多解与信息不足；没有代码沙箱时不宣称测试通过，不输出录用率或精确总分 |
| **复练与AI辅助对照** | 反馈经用户处理后生成来源动作；新Attempt空答；结束后可请求比较建议 | 原答／新答／动作／条件与提示并排；建议不自动结项、不认定掌握；同题与受控变式分开 |
| **数据与成本控制** | 单固定供应商适配、服务端密钥、显式发送动作、有限预算、一次在途任务 | 不收集密钥于原型；供应商／地区／模型／价格和真实材料授权另审；断线或取消不承诺零费用 |
| **自检退路** | 始终可用 | AI未启用或失败，已保存原答、预设参考、用户自检、行动与对照不丢；界面明确模式，不将预设文案伪装模型产物 |

## 5. 后续与排除

- **后续验证：**语音ASR／TTS、行为／HR专项、获准文件解析、完整计时模拟、架构图追问。每项先验证必要性、中文技术语义、权限、费用和失败退路；不因竞品音视频就捆绑首期。
- **明确排除：**正式面试暗中代答、隐身／监考规避、自动投递、招聘爬取、商业题库复制、企业必考预测、录用／薪资成功率、以模型猜测代替代码测试执行。
- **待取得真实证据：**模型产生的追问是否优于预设；中文Java反馈是否有条件且可执行；事实不失真；流式／取消是否可用；不同输入长度下真实成本与未知费用；用户是否愿意独立复练。市场功能不能代替这些检查。
