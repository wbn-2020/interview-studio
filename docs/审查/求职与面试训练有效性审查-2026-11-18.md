# 问阶能否帮助 Java 求职者准备下一场面试？

2026-11-18 · 产品设计与技术架构审查。取证范围为 PRD v1.0、当前工作区正式 Vue 与 Java 实现、既有服务器验收记录。取证时 Git HEAD 为 `cc17283`，判断以已读的工作区文件为准。下文的反例是按源码推演的人工验收场景，真实用户表现和模型反馈质量仍待验证。

## 产品判断

对已有题库、知道弱点、愿意自行编排练习的人，问阶提供了明确的用途：保存每版回答、找回反馈依据、重做并对照。对拿到一份 JD、三天后面试、只有一小时可用的人，找题、选优先级、组织追问和判断自己是否真的会了，仍有相当一部分工作要由本人完成。我建议把后一类用户的整场经历作为下一次产品验收的主线。原设计确实要求同时服务这两种情境，并且明确把操作负担与学习收益列为待验证假设。[PRD §2、§15](../需求文档/产品需求文档.md#L38)

### 1. 空工作区把第一道题的出题责任交给了求职者

PRD 允许不填材料、选择主题直接练习。正式首页 `/` 默认进入知识星图。即使用户找到“今日 → 开始文字训练”，仍须填写训练名并选择至少一道已有版本的题。题库为空时，选择器引导他先去保存一道题。通用 AI 出题入口也要求 1–5 个已发布知识对象。手动建题、导入或使用自己已有的题都能绕开这个前置条件，但这些路径更适合已经知道要练什么的人。[冷启动规格](../需求文档/产品需求文档.md#L133) · [根路由](../../frontend/src/main.ts#L17) · [知识默认视图](../../frontend/src/views/KnowledgeWorkspace.vue#L27) · [今日入口](../../frontend/src/views/TodayWorkspace.vue#L230) · [建训练校验](../../backend/src/main/java/com/wenjie/studio/training/TrainingInput.java#L35) · [选择器空态](../../frontend/src/components/bank/CollectionQuestionPicker.vue#L75) · [通用出题输入](../../backend/src/main/java/com/wenjie/studio/ai/AiSources.java#L102)

**产品取舍。** 给首次进入的人一组来源明确、技术上经过审阅的 Java 诊断题，按基础、故障排查、项目职责和系统取舍选一题即答。题目可由用户主动启用，个人题库仍可为空。第一题就检验“能不能说明如何判断故障恢复”，有了答案再推荐要补的材料。题库契约里“不注入示例”的约束可以保留。[题库契约](../技术架构/题库与学习路线接口与数据契约.md#L73)

### 2. 面试迫近时，“今日”仍优先让人把已开始的事情做完

准备路线的原始承诺包含面试日期、可用时间和缺口。正式分钟预算建议先分“继续、到期、其他”三组，再在组内比优先级和显示顺序，最后依次消耗时间。假设同一目标下两项准备任务均符合推荐条件，一个是进行中的低优先级资料整理，另一个是今天到期、为明天面试准备的最高优先级排错练习。两项各需 60 分钟，可用预算为 60 分钟。按代码，旧任务获推荐，排错练习得到 `OVER_MINUTES`。用户可以重新选候选，但单独调高排错题的优先级无法解决这次冲突。[准备路线 PRE-04](../需求文档/产品需求文档.md#L161) · [进行中任务归组](../../backend/src/main/java/com/wenjie/studio/today/TodayPlanService.java#L361) · [排序](../../backend/src/main/java/com/wenjie/studio/today/TodayPlanService.java#L414) · [预算分配](../../backend/src/main/java/com/wenjie/studio/today/TodayPlanService.java#L314)

**产品取舍。** 平常可以沿用继续优先。用户选定某场面试冲刺时，让他看到近期轮次的关键缺口、为什么值得占用今天的时间，以及继续旧任务会挤掉哪项练习。允许他直接决定这一次冲突。

### 3. “文字模拟”默认给候选人看主问题，也默认关闭追问

自选题适合专项练习。正式模拟沿用同一个设置流程，从题库或题单选择主问，在计时前预览题干并勾选确认。曝光统计记录创作、查看参考、打开评价区，单凭这些计数看不出是否在本次预览里读过题。短模拟的 PRD 默认每道主问最多一次追问，实际表单初始额度为 0，切换到模拟只改反馈时机。沿默认值保存后，前端和后端的额度检查都会挡住第一道 AI 追问。手工调整高级设置可以启用追问。[短模拟约定](../需求文档/产品需求文档.md#L248) · [表单默认值](../../frontend/src/api/training.ts#L59) · [模式切换](../../frontend/src/components/training/TrainingSetup.vue#L79) · [开始前预览](../../frontend/src/components/training/TrainingSession.vue#L362) · [曝光口径](../../backend/src/main/resources/mapper/training/TrainingMapper.xml#L48) · [追问限额](../../backend/src/main/java/com/wenjie/studio/ai/TrainingFollowUps.java#L136)

**产品取舍。** 明确区分“我要练这道题”和“请面试我”。后者可先展示岗位、能力范围、时长与资料授权，开始后逐题揭示题干。允许追问的额度、实际费用预览和外发同意分别处理。没有启用 AI 的用户也能用受审的人工追问走完一轮文字模拟。

### 4. 系统存下了上轮回答，评价追问时却看不到它

生成追问时，服务端会绑定父题与产生追问的那一版原答。给追问的回答做评价时，输入仅包含当前题面、当前提交、作答条件及适用的题库参考。举例说，候选人在主答里说“看重复订单数是否归零、积压是否持续下降”，接着回答“沿用刚才两项指标，再观察十分钟”。评价模型仅凭后一句无从核对“刚才两项”是什么。换用更强模型也补不回这份原文。是否真的出现误评、出现多少，仍需用获准模型核实。[父题与原答绑定](../../backend/src/main/java/com/wenjie/studio/ai/TrainingFollowUps.java#L174) · [评价输入构造](../../backend/src/main/java/com/wenjie/studio/ai/TrainingEvaluations.java#L123)

**架构取舍。** 给跨轮评价单独列出必要的父题和父答片段，绑定确切版本，由用户预览并授权。缺少授权时明确指出哪一项缺乏上下文。用同一段追问回答配两种不同父答做人工验收，评价要能区分“此前确已给出”与“始终没有说明”。

### 5. 完全相同的原题可以增加“变式复练”次数

正式变式选择器没有排除原题，服务端校验只要求选择有效的题目和版本。只要原题仍有效且原版本仍为当前版，选它就能满足这条变式校验。成长页按保存的 `questionMode` 计数。于是一次重做可以在对照中显示“相同的确切题面”，同时增加“变式复练开始”次数。对照逻辑、空白答题和辅助条件记录值得保留，问题在于上层统计对“变式”的解释已经超出输入能支持的范围。[变式选择器](../../frontend/src/components/review/RepracticeCreate.vue#L215) · [变式校验](../../backend/src/main/java/com/wenjie/studio/review/RepracticeRules.java#L93) · [题库版本读取](../../backend/src/main/java/com/wenjie/studio/training/TrainingSources.java#L294) · [活动计数](../../backend/src/main/java/com/wenjie/studio/review/ReviewGrowthQuery.java#L118) · [题面对照](../../backend/src/main/java/com/wenjie/studio/review/RepracticeService.java#L410)

**测量取舍。** 原题同版归入同题复练。对不同题，记录改变了哪个约束、是否曾向用户展示，以及本次想验证的能力。比如原题给出消息重复消费，变式改为“外部调用已超时，事后无法确定是否执行成功”，观察候选人是否会改变核查与恢复步骤。单纯改标题或新建题目 ID 都不足以表明这项能力有进步。

## 下一次验收怎样同时检验产品和模型

建议先保留 Java 模块化单体、版本记录、用户外发授权和独立知识库。给一组目标用户一份获准使用的 JD 和一段脱敏项目经历，从正式入口做以下人工观察。优先把时间投在首次作答和陌生题表现，之后再决定是否投入模型升级。以下是建议的验收方法，本次没有执行。[系统架构](../技术架构/系统架构与数据边界.md#L11)

| 场景 | 观察什么 |
|---|---|
| 空工作区、关闭 AI、三天后面试 | 让用户自行开始第一道排错题。记录从登录到首次有效提交的时间，以及在哪一步需要别人解释或先供题。可先把 5 分钟作为观察门槛。 |
| 给一小时和两项相互竞争的准备任务 | 使用上文第 2 项的两项任务。让用户先独立说出今天最该练什么，再对照系统选择、推荐理由和调整成本。 |
| 一场真实文字模拟，含跨轮省略 | 开场前只给能力范围，提交首答后追问。获准人工评审者按能定位问题、说明本人职责、给出恢复判据三项核对。分别放入“首轮已经解释”和“首轮确实遗漏”的答案，统计模型遗漏、误指缺项、无依据扩写职责的案例。 |
| 隔天测同一能力 | 保留原答并做一次同题复练，再给一道预先留出、改变关键约束的题。由不了解作答先后的评审者按同一标准独立判断。分别记录记住原题、运用到新情境、证据不足三种结果。面后回忆另记用户当时的处境与主观感受。 |
| 回访一条已纠正的反馈 | 先标记已处理，再补录争议或更正。查看今日和成长是否给出相容的当前状态，整理知识时能否看到并按授权带入纠正意见。 |

学习效果观察可参考 Andrew C. Butler（2010，DOI `10.1037/a0019902`）分别用原题和新推断题检验表现的实验设计。岗位检查项与评分标准可参考美国 OPM 的 *Structured Interviews*。这两项资料提供验收方法，问阶自身的效果仍须用本产品收集的材料判断。
