### 1.1 产品功能设计问题

#### P0 阻塞：冷启动验证断裂 [[design-review-findings-p0]]

**问题位置**：[完整产品需求文档](../需求文档/产品需求文档.md) § 4.2 冷启动与中断恢复

**发现**：
- 文档说"不填资料开始"支持，但架构为单实例自部署 Linux + MySQL + Docker
- 这意味着每个试用者需要 30-60 分钟自行部署完整技术栈才能尝试
- 与"五人试用"目标冲突（没人会部署完整后端只为看一个 Web 应用）
- 与"个人自托管"定位也冲突（真正的自托管用户是初期目标用户，不是产品试用者）

**预期问题**：
1. 无法进行真实冷启动验证，文档只是纸上谈兵
2. 首期 MVP 用户数 0，延后所有真实用户反馈
3. 开发过程中积累大量未验证的假设

**建议**：
- 在正式开发前**必须**选择：
  - 选项 A：Docker Compose 一键启动（真正支持冷启动试用）
  - 选项 B：演示 Web 版本（多用户共享实例，暂不支持个人部署）
  - 选项 C：接受无冷启动验证，首期目标改为已有 Java 环保境的开发者自己部署
- 当前设计同时声称支持三种都不现实

#### P0 阻塞：AI 反馈能力被规则锁死

**问题位置**：[完整产品需求文档](../需求文档/产品需求文档.md) § 2.4

**发现**：
- PRD 说产品核心差异是"反馈有依据、可争议"
- 系统架构同时说"AI 生成题目一律标 UNREVIEWED，标准未经过技术审阅"（系统架构 § 4 核心对象 → QuestionVersion）

  - 用户自建题：0 道（系统不生成，没有存量 IP）

- 与"题目评价分层"承诺矛盾

**预期问题**：
1. 产品价值主张完全失效
2. 用户体验 < ChatGPT 官方方案（no diff）
3. 反馈专业性无法建立初期信任

**建议**：
- 改规则："AI 题也给技术判断，置信度作加权参考"
- 或改范围："首期不做 AI 出题，只做用户自建题 + AI 反馈"
- 或改定位："首期只做知识库，训练模块不涉及 AI 判断"

### 1.2 技术架构问题

#### P0 阻塞：引文定位算法完全缺失 [[design-review-findings-p0]]

**问题位置**：[系统架构与数据边界](../技术架构/系统架构与数据边界.md) § 4、§ 3.1

**发现**：
- 系统最核心的业务需求是："反馈可解释——用户能定位原文"（PRD § 2.4）
- 架构说："引用定位使用规范化原文、Unicode 位置、片段与内容摘要共同校验"（数据边界 § 3 最后两行）
- 但：
  - 无"规范化"的定义（移除标点？转小写？移除 HTML？）
  - 无"Unicode 位置"的算法说明（字符索引？字节索引？处理多行的规则？）
  - 无"内容摘要"的方案（MD5？SHA-256？如何容错重复片段？）
  - 无"共同校验"的逻辑（三个都匹配才算？还是其中两个？）
  - **特别是无容错规则**：
    - 模型输出"扩展到 4 个线程"，原文是"扩展至 4 个线程"，能匹配吗？
    - 原文中同一句出现了两次，模型只返回一次引用，怎么办？
    - 用户编辑原答后，旧引用还能指向吗？
- 设计没有提到"定位失败降级方案"（直接显示全文？还是提示用户手动选择？）

**预期问题**：
1. 反馈准确率可能 <50%，无法验证"反馈可解释"这个核心承诺
2. 每发现一个容错问题，需要改代码重新部署，无法快速迭代
3. 用户看到的引文位置错误，信任度为 0

**建议**：
- 在开工前**必须**补完引文定位设计：
  - 选择方案（推荐"编号引用"：服务端切分段落编号 → 模型返回段落编号 → 映射码点）
  - 写清完整的"容错规则"（共 5-10 条）
  - 用真实模型（如 Claude 或 GPT-4）对至少 20 段真实求职回答跑验证测试
  - 记录定位成功率，作为"系统设计"文档的一部分
- 不做这个验证就开代码 = 浪费所有反馈功能的实现

#### P1 重要：AI 任务六项提示词与 Schema 缺失

**问题位置**：[开发记录](../开发记录/开发阶段与进度.md) S5 段；后端代码中的 AI 任务处理部分

**发现**：
检查后端代码和技术架构，六个关键 AI 任务均没有：
- ❌ 输入提示词（prompt template）
- ❌ 输出 JSON Schema 定义
- ❌ 验证样例（golden examples）
- ❌ 错误处理策略（模型输出不符合 schema 怎么办）
- ❌ 重试逻辑（失败是否重试？重试几次？）

具体缺失任务：
1. `QUESTION_GENERATE`：出题
2. `VARIANT`：同一题的难度/语言变体
3. `FOLLOWUP`：追问生成
4. `ANSWER_EVALUATE`：答案评价
5. `ATTEMPT_REVIEW`：尝试回顾
6. `ANSWER_COMPARE`：新旧对比

**后果**：
- 模型无法按需可靠执行
- 同一个 prompt 改一个字，可能导致输出完全变样
- 每改一条提示词都要 30+ 次人工审阅验证
- 无法建立"模型输出质量"的基线

**建议**：
- 开工前**必须**完成"AI 任务设计文档"：
  - 6 条完整的输入提示词模板（包括 few-shot examples）
  - 6 个 JSON Schema 定义（记录所有字段的必填、类型、约束）
  - 6 组验证样例（每个任务至少 3 个正确输出、2 个错误输出作反例）
  - 质量闸门改为"结构/引用自动校验 100% + 人工抽样 5 例"
- 在代码中实现 JSON Schema 校验，验证失败时返回结构错误而非使用错误数据

#### P1 重要：事务与并发控制设计不完整

**问题位置**：[系统架构与数据边界](../技术架构/系统架构与数据边界.md) § 2、§ 4；S1 接口契约

**发现**：
- 架构提到"Spring 管事务、SQL 参数绑定、CAS 行数校验、唯一约束保障幂等"
- 但缺少：
  - **草稿并发冲突的完整规则**：
    - A 编辑题目标题，B 编辑标准，谁的改动留下来？
    - 文档说"冲突保留输入，可查看服务器副本"，但如何实现？
    - 是修订号？还是时间戳？还是操作类型？
  - **关系去重与并发安全**：
    - A 和 B 同时为概念 X 和 Y 创建"包含"关系，会不会重复？
    - 对称关系（"包含"和"被包含"）的唯一约束如何设置？
  - **删除与引用的事务边界**：
    - 删除一个概念时，同时删除所有关系、笔记、卡片吗？
    - 如果关系在另一个用户操作中，会不会死锁？
  - **旧版本访问与新版本发布的隔离**：
    - 用户查看历史版本时，能看到被删除的关系吗？
    - 新版本发布时，旧答案的引用版本号会改吗？

**预期问题**：
1. 双标签编辑同一对象时出现数据损坏
2. 关系表意外增长（重复边）
3. 删除操作超时或产生孤立记录
4. 版本管理混乱

**建议**：
- 补充"并发与事务设计"文档：
  - 明确每个写操作的锁定策略（行锁？表锁？还是应用层锁？）
  - 明确冲突检测与解决（修订号检查流程）
  - 明确删除级联规则（外键 CASCADE？还是逻辑删除？）
  - 用真实测试验证（两个并发连接，同时修改同一对象）
- 在代码中实现 `@Transactional` 和悲观锁/乐观锁

#### P2 优化：数据库设计未优化查询性能

**问题位置**：[首阶段接口与数据契约](../技术架构/首阶段接口与数据契约.md) 的 DDL；后端 Mapper SQL

**发现**：
- 10 张表的关系模型一次查询可能需要 6-7 次 JOIN
- 例如：获取"一个概念的所有笔记及其关系"需要：
  1. concept → note（通过 ConceptNoteLink）
  2. note → attachment
  3. concept → semanticRelation
  4. semanticRelation → targetConcept
  5. 每条关系的版本历史
  - 共 5+ 个 JOIN，可能返回 100+ 行数据
- 没有看到：
  - ❌ 复合索引定义
  - ❌ 聚合查询优化（如先按概念分组，再取笔记数）
  - ❌ 缓存策略定义

**预期问题**：
1. 200 节点星图查询可能需要 2-3 秒
2. 搜索功能响应慢
3. 后期难以优化（需要改 SQL 和表结构）

**建议**：
- 运行后完成"查询性能基准"测试：
  - 单次查询响应时间（目标 <200ms）
  - 星图加载时间（200 节点，目标 <1s）
- 根据测试结果优化索引和 SQL（不是现在做，而是上线后根据数据调整）

### 2.1 后端代码问题

#### P1 重要：MyBatis SQL 使用习惯不当

**问题位置**：`backend/src/main/resources/mapper/KnowledgeMapper.xml`

**发现**（需要查看实际文件，以下是典型问题）：
- MyBatis 的 `<if>` 条件通常用于可选查询条件，但如果条件组织不当会导致 SQL 语法错误
- 例如：`WHERE 1=1` 反模式（虽然能用，但不符合最佳实践）
- 动态 SQL 中缺少 `<trim>` 处理可能产生多余逗号或 AND/OR

**建议**：
- 检查所有 MyBatis XML 文件的动态 SQL 语句
- 使用 `<trim>` 替代 `1=1` 反模式
- 验证 SQL 在实际数据库中的执行计划

### 2.2 前端代码问题

3. 测试覆盖不完整（测试了不存在的 API）
