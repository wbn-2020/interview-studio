## 1. 审查结论

**方向值得继续，但要把“可靠的准备资料系统”收敛为“能完成一次有效复练的训练产品”。**原稿的事实边界、版本、保存和数据控制很扎实；主要缺口不是少几个热门模块，而是首批用户、首用价值、参考条件、反馈语义质量和复练效果的判断方式。

推荐主线：

> 有真实项目的 Java 后端求职者，围绕一个问题独立作答 → 找到有条件、有原文依据的缺口 → 接受一个具体动作 → 独立再答并对照。

这不是“市场没有”的空白，也不能仅凭竞品存在就推断付费需求。问阶应验证的是：这个闭环是否比用户现有的“题库＋笔记＋通用聊天”更可信、更省整理成本，并使用户愿意主动再练。

### 1.1 原稿的优点与实质缺口

| 审查项 | 原稿判断 | v0.2 的处理 |
|---|---|---|
| 事实真实性 | 已明确区分本人负责／参与了解／待核实，不把润色当真实性确认 | 保留，并在反馈例子中避免把待核实接口性质当确定前提 |
| 保存与历史 | 原答、岗位、材料、图版本和删除规则细致 | 保留；明确模型关闭时不提前建设计费／多模型平台 |
| 核心用户 | 基础准备、首次跳槽、复杂项目、架构等并列，首批对象偏宽 | 优先验证有真实项目、需要深挖准备的 Java 后端用户；约1–5年仅为招募假设 |
| 差异化 | “工作台／有证据”方向正确，但仍像功能集合 | 将交付单元明确为“原答→有条件判断→动作→新尝试”，不竞争题库规模、AI聊天数量或准备总分 |
| 第一次使用 | 模块和原则完整，首次十分钟做什么不够具体 | 新增一题直达路径；不先填完整 JD／简历／密钥；默认短专项而非无限对话 |
| 内容可用性 | 首期仅写小批题，题目可判定条件不足 | 补题干／技术版本／假设／参考条件／常见误区／标准版本；轻量筛选、自建题、练后笔记前移 |
| 反馈可信度 | 正确强调引用，但“有出处”仍可能“判断错” | 区分明确冲突、条件缺失、未观察到、开放取舍、表达建议；增加人工语义闸门和错误阻断 |
| 自检价值 | 无模型也可闭环，但容易把固定清单当个性化诊断 | 明确自检由用户选原文并确认缺口；若只能给通用清单，不宣称差异化已成立 |
| 复练有效性 | 有新旧答案，但未充分区分看过提示、同题记忆与迁移 | 记录提示和上下文；新答不自动结项；同题与变式分开，条件变更标不宜直接比较 |
| 商业与验证 | 不虚构效果是优点，但缺可用的观察口径和停止条件 | 补首次价值／复练／反馈／可靠性定义，建议小范围观察；不预先建设支付、不作无限量承诺 |

### 1.2 优先级结论

- **必须保住：**真实事实、可靠原答、一项可判断动作、独立再答、原始依据、导出删除。
- **低成本前移：**题包主题／题型筛选、单道自建题、练后短笔记、提示使用标记、技术适用条件。
- **下一项价值试验：**一条受控项目专项的动态追问和反馈；授权与质量闸门通过后再启用，不同时铺所有题型。
- **暂缓：**完整计时模拟、自由白板、语音、多目标排程、批量简历解析、课程／社区／投递 CRM／收费体系。
- **明确不做：**正式面试暗中代答、隐身与监测规避；这些不是问阶的竞争缺口。

### 3.3 横向结论

1. **“生成题目＋模拟＋反馈”已经是常见组合，不能单独构成问阶定位。**值得验证的区别是个人事实边界、判断条件、原答定位、争议与下一次对照。
2. **学习、专项和完整模拟应分工。**课程／题单帮助建立知识，专项练一个缺口，完整模拟训练串联与时间压力；不能用一个聊天框同时替代所有任务。
3. **语言支持需要拆开。**中文界面、中文对话、中文技术术语理解与Java条件判断是不同能力。未注明支持不等于不支持，多语言宣传不等于专业正确。
4. **反馈时机与内容比打分丰富更重要。**专项可按需反馈，完整模拟可结束后报告；表达、技术与事实分开，不把“未观察到”断言成“不掌握”。
5. **免费／付费和人工服务持续变化。**暂不照抄金额、订阅机制或“无限量”；问阶先验证复练意愿、调用成本和内容维护成本。

### 5.1 首版是否应该完全没有模型？

**建议区分“可靠文字底座”和“面向用户的差异化验证”，而不是二选一。**

1. 保存、事实、动作和独立新尝试必须在模型关闭时成立；这是可靠性底线。
2. 无模型产品应如实称自助训练／自检工具。若只有一份静态清单，它未必足以使用户从现有笔记或题库迁移；本轮研究不能证明它能形成留存或付费。
3. 因此下一项验证优先放在一条项目专项中的受控追问与反馈，而不是先扩充全套页面、完整模拟、白板或语音。
4. 启用不自动发生。供应商、地区、费用、材料外发授权和语义质量分别过关；失败退回文字，不把低质量候选包装成正式报告。

### 5.2 技术反馈为什么必须“有条件”

例如线程池题，是否先建线程、入队或拒绝取决于线程数量、队列类型／容量、最大值、运行状态与拒绝策略。关键词齐全不能证明推理成立。

[Oracle JDK 21 官方文档](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/concurrent/ThreadPoolExecutor.html)分别说明：低于 core 时创建线程；达到 core 后优先入队；入队失败再考虑扩到 maximum；拒绝后的行为由处理器决定。无界队列配置下，`maximumPoolSize` 对文档所述增长行为没有作用。

产品应先记录适用版本和条件，再区分“明确错误”与“未交代”；不把有限原答当成用户知识全貌，也不把某一参考答案当所有配置下的唯一答案。

### 5.3 复练与自动评价的证据边界

- [Roediger 与 Karpicke，2006，Test-enhanced learning](https://pubmed.ncbi.nlm.nih.gov/16507066/)的实验支持特定材料上提取练习的延迟记忆收益，但研究不是 Java 面试、临场表达或录用实验。它支持先独立回忆再看参考的设计动机，不构成问阶效果承诺。
- [Zheng 等，Judging LLM-as-a-Judge，2023](https://arxiv.org/abs/2306.05685)讨论位置、篇幅、自我偏好和推理局限；[正文3.3节](https://arxiv.org/html/2306.05685v4)提供具体案例。该研究不能直接代表当前模型的面试判断准确率，更不能以通用偏好一致性代替 Java 技术正确性。
- 所以问阶先做技术条件、事实忠实度、动作可执行性和合理不确定性的人工复核；跨模型重复输出、换顺序比较只是辅助检查，不是自动认证。

## 6. 修订落点与仍待验证的决定

### 6.1 本轮已经写入 PRD 的结果

1. 定位改成面向 Java 后端求职者的证据式训练与复练，收窄首批用户假设。
2. 增加第一次一题闭环、默认有限追问、明确结束与下一步来源。
3. 补小题包、自建题、练后笔记及技术适用条件，不扩建全套知识平台。
4. 明确自检、预设参考、模型候选和人工审阅的标签；新增具体反馈示例与语义类别。
5. 补提示使用、同题／变式、上下文变化和动作结项规则，不用一次提交表示掌握。
6. 增加模型质量闸门、人工技术检查、错误阻断与版本回归；明确不提前建设通用AI平台。
7. 补首次价值／复练／可靠性指标定义、小范围观察建议、商业化假设及停止扩张条件。
8. 新增 AC-17–22，将首用、自建题、条件判断、比较和模型质量纳入验收。

### 6.2 没有被这次研究证明的事情

| 未决项 | 为什么不能现在下结论 | 最小验证方式 |
|---|---|---|
| 核心用户是否真的更愿意复练 | 官网和开源项目不能代表本产品用户需求 | 经同意的核心用户观察、一次后续回访；记录现有替代做法 |
| 静态自检能否产生独立价值 | 有清单不等于能发现具体缺口 | 看用户是否能自行指出原文缺口并保存可判断动作 |
| AI追问是否比固定题有用 | 没有付费运行、没有同输入质量比较 | 单项目专项、合成／获准案例、人工语义检查 |
| 中文技术评价是否稳定 | 多语言宣传不等于中文 Java 题质量 | 单列中文术语、长项目、待核实事实与合理多解样本 |
| 有多少“进步”不是记忆或提示作用 | 同题变长、换上下文不能直接比较能力 | 记录提示；同题与受审变式分开，保留条件差异 |
| 是否值得收费、如何收费 | 没有付费意愿和真实成本样本 | 先看复练意愿与实际调用成本，不提前搭支付 |
| 哪个画布组件最终采用 | 本轮仅文档与许可核对，没有可用性／性能原型 | 正式开发获准后做最小交互验证与版本依赖审查 |
