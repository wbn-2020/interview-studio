## 1. 可直接用于产品设计的结论

1. **完整产品需要持续积累的准备上下文。**岗位要求、材料、知识和历史训练应可复用，同时每次训练保留当时版本；不能让上下文只存在于一次聊天中。岗位关联训练的直接参考为 P03、P04，日程和材料组织参考为 P08。
2. **“有题可答”与“知道下一步练什么”是不同模块。**题库要支持条件、题型、来源、路线和个人收藏；今日安排要考虑目标、时间预算及已产生的改进动作。P05–P07 提供内容组织和路线的参考，P08 提供任务组织的参考。
3. **反馈应该产生下一次行动。**P02 提供会后可执行反馈，P04 明确把 debrief 接到 re-drill。问阶建议进一步要求动作能回到原答证据，并从空白开始复练；这是本产品设计，不是已经核实的竞品能力。
4. **学习、独立训练、模拟应区分作答条件。**参考资料可见性、提示、计时和反馈时机应在开始前明确；看过参考后继续练可以，但要记录辅助状态。P03 的逐题练习与时间预算可以借鉴，不能照搬其所有评分维度到纯文字场景。
5. **知识库必须有独立价值。**本组调研主要覆盖训练和准备，不能据此声称这些产品具有问阶所需的知识星图。问阶的概念、笔记、关系、回忆卡及训练证据联动需要单独设计，并与知识管理专项调研一起判断。
6. **完整产品不等于同类产品功能并集。**语音、实时面试代答、教练撮合、公共社区和自动投递不进入本次完整产品范围；保留目标管理、知识资产和训练闭环的完整体验。

## 2. 代表性产品与流程

### 2.1 Pramp／Aced Practice：同伴练习的结构

**官方可核实内容（P01）：**Pramp 当前页面以 “Pramp by Aced” 呈现，说明新会话由 Aced Practice 承载，并提供对应链接。页面描述按可用时间、经验、主题等配对；双方轮换面试官与候选人，使用给定问题及面试提示，结束后互相反馈。涉及算法、系统设计、行为等类别。

**可借鉴：**开始前明确本次考察范围；问题与评价提示分开；复盘区展示观察来源，让用户理解反馈来自自检、AI 或手工录入的他人意见。

**不纳入：**真人匹配、视频通话、社交关系和撮合运营。可以支持用户手工录入外部反馈，但不将其标记为平台认证评价。

**限制：**Aced Practice 当前目标页面返回 403；没有验证配对、登录后的实际流程或 AI 功能。本条不把 Pramp 官网页面等同于 Aced 全产品实测。

### 2.2 interviewing.io：专业训练与可执行复盘

**官方可核实内容（P02）：**官网描述预约匿名模拟、技术面试官反馈、算法／系统设计／行为等训练类型；也介绍 coding 与 system design 的 AI Interviewer。真人会话使用音频与聊天，结束后给出改进建议。

**可借鉴：**将训练形式、主题和反馈来源显式区分；一次训练结束后提供具体需要改进的事项，而不是只显示总分或鼓励语。

**不纳入：**专家市场、薪酬谈判服务、真人预约和匿名通话。问阶不宣称文字 AI 训练可以等价替代真人压力环境。

**限制：**官网对反馈效果、面试官水平等描述属于服务方声明；未登录使用 AI Interviewer，也未验证模型的引用、错误处理或评价稳定性。

### 2.3 Interviews by AI：最接近本项目的文字训练入口

**官方可核实内容（P03）：**可从 JD、常见问题或用户自带题开始；支持口头或文字回答并提供计时；展示 STAR 等框架下的分项反馈、改写示例、简历关联建议和历史练习记录。

**可借鉴：**不强制先完善全部资料；一个清楚的问题、一个独立回答区、提交后反馈；保留自带题与无 JD 入口。简历信息用于提示可用经历，但不替用户确认事实。

**问阶应加强：**原答与改写分开；建议必须标记来源；技术判断不能直接套 STAR；文字场景不评价语速、语调或口头停顿；示例回答的使用会改变之后练习的独立性。

**限制：**读取的是官网公开页面及演示文案，未验证登录后的文字交互、中文 Java 内容质量、保存恢复或其分数是否可靠。

### 2.4 Final Round AI Practice Interview：目标与复练相连

**官方可核实内容（P04）：**当前官方页面将 AI Mock Interview 称为 Interview CoPilot 内的 Practice Interview；从 Goal、岗位、简历和材料建立上下文，选择场景，结束后生成 debrief 和可再次训练的薄弱点。该页明确练习以口头对话进行，并列出技术、系统设计、行为等场景。

**可借鉴：**同一个岗位准备空间承载材料和多次训练；复盘中的改进对象能够直接进入下一次练习；“生成报告”不是流程终点。

**不纳入：**语音练习、live copilot、屏幕帮助、隐身或正式面试实时辅助。本次只借鉴准备阶段的对象复用和练后任务衔接，不采用其整套产品边界。

**限制：**没有实际使用桌面客户端；不得从官网描述推导它具备原文证据绑定、不可变版本、独立复练或可靠费用管理。

### 2.5 roadmap.sh：从主题目录到学习路线

**官方可核实内容（P05）：**官网按角色与技能组织路线、指南和项目；Java 页提供逐步学习路线、项目入口和 AI Tutor 入口。其公共内容覆盖 Java、Spring Boot、数据库与系统设计等相关主题。

**可借鉴：**知识点可以属于多条学习路线；路线应说明依赖和学习顺序；岗位视角与技术主题视角可切换，不能为每个视角复制一套知识正文。

**问阶应加强：**路线进度、个人记忆自评和面试表现证据分别存储。浏览过一个路线节点不等于能解释、能设计或能在项目中证明掌握。

**限制：**本次读取的是公开首页和 Java 页；没有验证登录后进度、AI Tutor 的具体行为或学习效果。源码中的名称或资源链接不作为功能验收证据。

### 2.6 JavaGuide：Java 内容覆盖与来源导航

**官方可核实内容（P06）：**JavaGuide 官网把 Java 基础、集合、并发、JVM、Spring、数据库、缓存、分布式、高并发和系统设计组织为面试主线，并提供计算机基础和学习路线入口。

**可借鉴：**建立覆盖 Java 后端的主题骨架；题目、笔记、项目追问可以关联到同一概念；支持外部资料链接并保留获取日期、适用版本和用户笔记。

**不照搬：**把公开文章或现成问答整批变成本产品题库；把资源知名度、GitHub 星数或“面试高频”当成标准答案正确性的证明。

**限制：**官网可读取；本次 GitHub 仓库请求未成功，因此没有核验具体 commit、许可证或内容复用条件。后续如需导入正文，必须按具体资源核验许可；本轮只借鉴分类与入口组织。

### 2.7 Tech Interview Handbook／Grind 75：时间约束下的路线组织

**官方可核实内容（P07、P07a）：**Handbook 组织简历、编码、系统设计、行为和面后阶段的资料；Grind 75 的 About 页描述按可投入时间、难度、主题偏好定制题目安排，可按主题、难度或周查看。

**可借鉴：**用户可以给出面试日期和可用时段，系统提出准备安排；允许只练当前薄弱主题，也允许跨主题混合练习；改变时间预算时先预览调整，不改写已完成记录。

**问阶应加强：**常规记忆复习与面试冲刺安排分开；计划完成不自动升级成知识已掌握；用户可以跳过、延期、暂停，并保留原因与来源。

**限制：**Grind 75 主工具只取得页面外壳；具体个性化功能以作者 About 页描述为证，没有运行交互或验证其排程效果。LeetCode 本次直接访问受限，不能借该来源声称已核验 LeetCode 的所有功能。

### 2.8 Huntr：岗位、材料、日程和私人笔记的组织

**官方可核实内容（P08）：**官网描述 Job Tracker、Interview Tracker、岗位详情、日期、任务与私人笔记；提供简历材料、岗位匹配建议和逐项接受／拒绝改进建议的功能入口。

**可借鉴：**岗位卡保存来源与当时 JD，面试安排关联该目标；准备任务与日程入口使用同一对象；材料改写先显示差异和理由，由用户采用。

**不纳入：**全量投递 CRM、联系人经营、自动填写申请、招聘网站抓取和复杂简历排版。问阶的材料区聚焦真实项目事实与面试表达。

**限制：**匹配分与 AI 审阅水平是服务方描述，未证明能判定岗位胜任力；不能将其关键词分照搬为问阶的能力总分。

## 4. 从调研到可验证的使用例子

**情境：**用户三周后准备 Java 后端岗位面试，JD 提到缓存和分布式事务，个人项目中只参与过缓存排查。

1. 在准备空间保存 JD 和目标日期，将“解释缓存一致性的条件与故障恢复”设为考察项；不自动把关键词命中当成已具备能力。
2. 在材料区保存实际参与范围；从知识库关联缓存、消息重试与幂等概念，可以先写一篇自由笔记，再关联多个知识点。
3. 从路线或星图选择问题，开始独立文字专项；作答过程中打开参考会记录为辅助，原答继续保留。
4. 复盘指出原答中未说明失败后的恢复条件，并允许用户查看引用原文、接受或争议该判断。
5. 用户采用一个改进动作，并把解释整理为笔记候选；采用笔记不顺带确认项目中做过该方案。
6. 今日安排出现复练任务。用户从空白独立重答，比较时同时呈现题目条件、提示使用和原动作。
7. 用户记录“部分处理”；未解释的条件继续保留。知识回忆卡完成不替代这条项目复练任务。

这条完整旅程结合了岗位上下文、路线、材料、训练和后续行动。它是问阶设计建议，尚未进行用户试用或服务器验收。

## 5. 仍需产品设计明确的事项

- 每种反馈的审阅层级：AI 候选、自检、外部意见、经过技术审阅的标准应分别展示，不共用权威标签。
- 原答、题目、知识笔记和项目事实之间的引用类型、版本及更正传播规则；这组公开页面没有证明如何解决。
- 用户不想填简历、没有 JD、AI 不可用时的入口，以及中断训练后能否继续。
- 知识星图的节点语义与大规模降级；“好看”不能替代可搜索、可编辑和可恢复。
- 每日任务冲突、面试改期、复习积压和用户主动延期的处理；不要以无限增加任务制造负担。
- 内容的技术准确性与权利来源；本轮不将任何竞品文章直接变成已审题包。
- 中文长文与 Java 场景的模型质量；不能由英文网站上的 STAR 演示替代实际评估。
