# 问阶：后续开发边界

## 设计与应用分离

`prototype/` 是离线交互参考，`docs/` 是设计基线。正式代码建议放 `apps/web/` 与 `apps/server/`，原型不作为正式服务的数据存储方案。

本轮未构建应用骨架、执行DDL、导入真实简历、连接模型或部署网站。

## 起步技术

| 层 | 推荐 | 原因与边界 |
|---|---|---|
| Web | Vue 3 + TypeScript + Vite | 与已有经验匹配，界面采用本原型的内容与训练工作区布局 |
| 架构白板 | Vue Flow节点模型 | 与可验证节点／边引用结合；自由绘画后置评估 |
| 资料编辑 | 标准表单／轻量编辑器 | 事实卡与出处优先，完整PDF简历设计不在首阶段 |
| 服务端 | Spring Boot模块化单体 | 岗位、证据、会话、图版本、报告和复练分包 |
| 数据 | MySQL＋版本快照 | 保留原回答、已确认事实、图版本和报告依据 |
| AI | OpenAI-compatible统一适配＋SSE | 经用户授权连接现有API，快照与失败状态明确 |
| 语音 | 后续ASR／TTS API适配 | 先文字闭环，再增加录音许可、打断与恢复；不要求本地模型 |

AI集成不必先用多Agent框架。先定义任务输入、结构输出、证据引用和停止条件，再根据实际需要引入编排。

## 分阶段交付

**当前仅讨论产品并完善初版原型，尚未正式开工。**以下正式工程阶段是后续参考路线，不是当前执行任务。先讨论 → 初版可点击原型 → 用户评审与修改；只有用户明确确认正式开工，才创建前后端工程、数据库或接入服务。原型或设计方案通过不自动进入正式开发。

产品八模块完整覆盖见 [产品范围](01-product.md#5-范围安排)。阶段是落地顺序，不是按页面、代码量或接口量裁剪产品。

### 阶段0：原型验收与 UI／白板设计基线

先在 1440／1280／360 宽度逐页验收现有八视图，并走通问答／白板 → 复盘 → 复练。核对目标隔离、材料确认、原文保存、图版本、去重、导出、重置和存储失败；原型测试与修复分开。UI 改进覆盖字体、留白、内容密度、信息组织、状态与白板专项设计。

可控浏览器不可用时，记录阻塞；保留被测原型不动，独立设计预览不能替代浏览器验收。现阶段阻塞与证据见 [验证记录](06-validation.md)。只有真实截图已查看、主链路实际操作完成，才可把阶段0标为验收通过。

### 阶段1：可靠文字准备闭环

首条正式链路：**一个目标岗位 → 确认项目事实 → 项目文字练习 → 保存原回答 → 有依据的复盘 → 一项复练 → 新尝试与原回答对比。**未填写完整简历仍可直接做基础知识训练。

在 `apps/web/`、`apps/server/` 建立正式工程。目标／事实录入与版本、题目、会话／草稿、证据式自检、复练来源／尝试、导出同时落地；模型未接入时明确显示自检清单或参考要点，不把模板伪装成实时评价。

验收：真实 MySQL 保存；浏览器刷新和服务重启不丢记录；失败保草稿、重复请求不重复；岗位／事实修改不倒改历史；UI 与完整任务一起通过。

### 阶段2：丰富训练与授权模型

题单、路线、专项与多轮次配置覆盖自我介绍、技术／知识、项目、行为和 HR。经授权 API 使用必要的 JD、确认事实与回答快照，生成追问及反馈候选；校验证据，处理取消、超时、格式错误、重试和预算。

验收：待核实材料不进入个性化评价、职责不扩大；缺依据可降级；反馈回到原文并转复练；模型失败仍可文字练习。服务商、凭据、费用和真实材料外发需单独授权。

### 阶段3：结构化架构演练

按阶段0的 [白板专项设计](02-ui.md#白板专项设计) 实现节点／边／属性／布局、解释与版本；接入同一会话、证据、模型和复练，支持约束变式与方案比较。

验收：图和解释可靠保存；追问绑定确切图版本及节点；查看历史不覆盖草稿，删除不破坏历史回放；报告定位正确节点／解释；桌面画布与窄屏替代均可用。

### 阶段4：语音与训练增强

文字与图可靠后增加 ASR／TTS、转写校正、打断／恢复、录音保留／删除；完善间隔复习、变式、更多岗位和自愿的面试后回忆复盘。

验收：音频单独授权；语音失败回文字；转写修订不污染原记录；复盘定位文本或时间证据。

每阶段三道独立验收：**UI／交互、数据保存、业务闭环**。只维护简洁的 [PROJECT_STATUS.md](../PROJECT_STATUS.md)，记录完成状态、证据、关键决定与下一步，不堆叠重复文档。

## 核心数据契约

- 材料可以是共同资产，但事实确认绑定内容版本；每目标、每次训练显式引用获准使用的事实版本，编辑后重新确认。
- 会话使用创建时的岗位和材料快照；原问题、回答修订、反馈和依据有稳定 ID。结束时引用冻结，后续编辑不倒改历史。
- 图保存节点／边／坐标／属性／解释，追问绑定 `diagramVersionId` 与节点 ID；历史只读定位与当前编辑草稿分开。
- 复练任务保留反馈来源和改进动作，去重不丢来源；每次练习创建独立尝试，新旧回答均保留。
- 保存、生成与复练请求分别有幂等边界；多标签冲突可见，不能默默覆盖。暂存、持久保存和同步状态分开。
- 原型 `reviewItems()` 读取当前内容、复练按题目 ID 合并、两套预置图切换等简化，不作为上述正式数据契约的实现证明。

## 旧项目资产评估

CodeCoachAI／Orbit已有岗位、材料、面试、报告和复习等实现，可按实际模块核对后选择性参考。OfferLab当前公共社区定位与本产品不同，不整体迁移社区和治理系统。

复用前核对：许可证和权属、依赖、接口、真实运行行为、数据迁移成本。当前方案不包含删除旧项目、整体搬迁或复用其私有配置。

## 测试与数据纪律

- 验证待确认事实不进入个性化上下文、用户角色不被模型扩大。
- 同一保存／生成请求去重，重试不产生重复问答、报告或复练。
- 岗位与图版本修改不倒改历史报告。
- 反馈引用无效或依据不足时明确降级，不伪造精确评价。
- 模型超时、格式错误、语音不可用时保护用户回答，允许文字继续。
- 密钥在服务端受控保存；模型传输范围需用户可见。
