# 问阶：界面与交互

## 视觉方向

专业但不行政化的训练工作台。暖白、墨蓝、深青绿为主，雾蓝用于内容分层。主页突出一个当前目标和一个下一步动作；不使用虚构评分、录用率或多张统计卡制造产品感。

**UI 美观、信息组织和完整可演示体验是核心验收标准。**配色正确、没有溢出或构建通过都不等于审美通过；每阶段都要真实截图和操作走查。白板在设计基线阶段就重点设计，不等正式功能结束后再美化。

中文系统字体与一致的间距层级，英文品牌字标可用衬线或几何字形。材料与问答保持可读，架构图给足空间。

### 设计尺度

- 沿用原型 `--paper`、`--ink`、`--jade` 的色彩角色；暖白作为工作背景，墨蓝承载正文与结构，青绿突出主要动作／选中状态，雾蓝区分证据与辅助信息。错误使用独立、克制的警示色。
- 正文以 15–16px、辅助信息以 12–13px 为设计起点；标题层次清晰，避免用大量 8–10px 英文标签和浅色小字制造精致感。长回答与材料保持舒适行距。
- 采用一致的间距、圆角、图标与边框体系，主要区块用留白和比例分层；阴影只用于浮层或必要层级，不做卡片墙。
- 八模块按准备、演练、复盘组织，模型与数据位于辅助区。顶部保留目标与可信保存状态，不能把内存暂存显示为服务端已保存。
- 岗位／材料用索引＋正文，题库用题单＋作答，模拟围绕问答进程，复盘围绕原文证据和行动。不同任务不套同一后台卡片模板。
- 所有主动作有正常、禁用、加载、成功与失败状态；缺依据、历史版本、冲突和确认删除均需可读、克制的反馈。
- 对比度、焦点、触达范围是可用性底线，构图、排版、密度与视觉一致性单独评审。参考 [WCAG 2.2](https://www.w3.org/TR/WCAG22/)，不凭少数检查声称整体无障碍合规。

## 八个视图

### 准备空间

当前目标、最近练习、一个继续动作。提供知识／项目／架构三种入口；视觉主图展示可进入的演练场景，而不是静态装饰。

### 目标岗位

岗位列表和 JD 内容、技能要求、简单阶段。切换目标影响全局上下文。匹配建议回链原文，不展示未经校准的精确匹配百分比。

### 个人材料

简历摘要、项目事实、STAR表达框架。事实有确认状态与角色边界。输入与可用于提问的证据同时可见，避免材料填完后不知道会被怎样使用。

### 题库与练习

列表筛选与单题工作区。题干、用户答案、提示、参考解析和复练状态区分清楚；先答再看并保留记录。首批自拟 Java 后端题，不填充大量未经审核 AI 题。

### 模拟面试

知识与项目模式，共享岗位上下文。问题、作答、追问和进程清楚分层。原型以文字示例展示；正式语音状态和录音授权另行实现。

### 架构演练（特色主屏）

题目约束在左、图在中央、选中节点相关追问在右。保存解释与图版本；用户改图后能看见反馈是否仍对应旧方案。

原型可切换初版／修订示例并点击节点；正式自由绘制和连线尚未实现。图中的外部调用和存储关系需要说明，不能用漂亮连线掩盖语义缺失。

#### 白板专项设计

白板是正式画布工作区，不是节点卡片配一个聊天框。采用“约束／假设 → 画布 → 属性／追问／证据”的结构；全局导航可收窄，题目面板可折叠。画布占主要空间，不用三层侧栏挤压设计区域。

```text
题目 / 训练阶段 / 当前编辑版本 / 保存状态 / 结束演练
┌───────────┬────────────────────┬────────────────┐
│需求与约束 │节点、边、分组与注释 │选中元素的属性  │
│假设与估算 │轻量工具栏          │本轮追问与回答  │
│待解决问题 │缩放、适配、小地图  │事实与版本依据  │
└───────────┴────────────────────┴────────────────┘
版本时间线 / 本轮设计解释 / 变更对比（抽屉）
```

- **视觉：**低干扰点阵、暖白画布、墨蓝标题与正文；青绿用于主动作和焦点。服务、数据库、缓存、消息、外部系统、边界容器有一致且有语义的形态，不把每个节点涂成不同颜色。边有方向、标签及同步／异步语义，选中与反馈引用有不同状态。
- **画布交互：**创建／编辑／删除节点和边、拖动、多选、连接、边标签、吸附／对齐、撤销重做、缩放／平移／适配、小地图、聚焦模式。节点内部文本编辑不触发画布快捷键；工具与选中反馈清楚可见。
- **训练上下文：**需求、必要估算、API／数据模型、取舍和未解决问题与图共存。追问根据当前节点、约束及当时解释形成，而非只发送一张图或通用题。
- **版本：**当前编辑图与本轮引用图分开。每条追问显示确切版本；改图后旧追问不改指新图。报告引用在只读历史版本定位节点与解释，查看历史不能覆盖草稿。删除节点后历史仍可回放。
- **解释与复练：**用户回答、设计解释、图结构、模板／模型反馈来源区分；无依据时明确需补充。反馈转复练保留来源及旧方案，可比较新解释或新方案。
- **窄屏：**1280 优先收起题目面板，保留画布和可切换上下文；360 采用节点／关系列表、约束／追问分区，不把整个桌面画布缩成不可读的小图。完整自由编辑以桌面优先。
- **导出：**明确整图／选区／图数据／解释范围，导出不等于备份恢复。历史版本、保存失败与未同步都显示真实状态。

本阶段提供独立白板设计预览供布局与交互讨论，预览中的节点／版本／追问为合成数据，不写入原型或正式存储。可选三栏讲解与聚焦画布布局；它不是现有原型的浏览器验收，也不代表 Vue Flow 或模型已接入。

成熟画布参考见 [市场与白板调研](04-research.md#ui-与画布参考)。Vue Flow 承担画布，图版本、保存、语义引用和追问属于应用责任。

### 复盘与复练

原问题、回答引用、问题定位、建议和下一步并列。对架构反馈可回到图节点；对项目反馈可回到已确认材料。加入复练后更新准备空间和练习状态。

### 模型与数据

原型仅说明未来连接机制和导出本地数据，不收集真实 API Key。正式版在服务端处理密钥与调用授权，前端只展示连接状态和可见配置。

## 一次完整演示

```text
准备空间
→ 进入扫码领奖架构题
→ 选择预算节点，看到“超时是否等于失败”的追问
→ 保存自己的解释，查看修订示例
→ 打开复盘，定位仍未解释的一致性窗口
→ 加入复练
→ 返回题库或准备空间继续
```

## 状态与细节

| 状态 | 正式设计要求 |
|---|---|
| 新用户 | 默认岗位模板与基础训练入口，材料可后补 |
| AI不可用 | 保留文字作答、题目、材料整理和历史 |
| 回答保存失败 | 显示未同步，保护草稿，可重试 |
| 评价缺依据 | 不强行打分，指明需补充的信息 |
| 图版本变化 | 旧追问指向旧图，新轮次使用新快照 |
| 重复加入复练 | 去重，保留问题来源与已有进度 |
| 资料删除 | 提示关联影响、按明确策略处理历史快照 |
| 窄屏 | 导航和面板重排，图可切为可读节点列表 |

## 评审时建议看的四件事

1. 首页是否能直接回答“我现在要练什么”。
2. 目标、材料、题目、白板和报告是不是同一段准备流程。
3. 反馈是否具体到回答或图节点，而不是一段通用评语。
4. 架构演练是否真正用图理解方案，而不是白板旁边放聊天框。

用户可先评价原型的主线和视觉，再补充模块范围；不用先提供完整需求清单。
